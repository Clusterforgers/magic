# Protocol

Wire protocol of `mtg-protocol`: messages, per-seat state projection, hidden-information rules and the sync contract between `mtg-server` and its clients. Engine types are in [engine.md](engine.md), server behavior in [server.md](server.md).

## Messages

- Both families are flat JSON objects tagged with `type`. `PROTOCOL_VERSION` (1) rides in `Join` and `Welcome`.
  - `ClientMessage`: `Join`, `Ready`, `NotReady`, `Answer`, `Preview`, `Chat`, `Concede`, `Resync`, `AutoPass`, `Yield`, `CancelYield`, `SetStop`, `FullControl`.
  - `ServerMessage`: `Welcome`, `Lobby`, `Decision`, `Forecast`, `Events`, `Snapshot`, `Chat`, `Error`, `GameOver`, `Yielding`, `Stops`, `FullControl`, `Bank`.
- TypeScript bindings come from ts-rs into `web/src/protocol/generated/`. `MTG_UPDATE_BINDINGS=1 cargo test -p mtg-protocol bindings::` regenerates them, and the drift test fails while they are stale.
- `mtg-core` and `mtg-engine` derive `TS` behind an optional `ts` feature that only this crate enables. ts-rs inlines the flattened table, so the TypeScript `StateView` is `TableView`'s fields plus `objects`.

## State projection

- `StateView` is what one seat may know: a `TableView` (turn, priority, players, zone lists, combat, forecast, result) plus `objects`, as one flat JSON object. `StateView::for_player` is the only way a whole state leaves the server; it builds the table with the same `TableView::of` as batches.
- `TableView.house_rules` is the `HouseRules` the game's creator set ([engine.md](engine.md), House rules), the same for every seat, and is left out when none is set. It includes the `handicaps` of single seats; the life of a seat in `PlayerView` is its own. A client reads the tax a commander carries in `CommanderView.tax` and the commander damage a player has taken in `PlayerView.commander_damage`, both already worked out under the rules; the lethal amount is the rule's `commander_damage` when set, else the format's 21.
- `project_events(before, events, viewers, from_seq)` returns one `EventBatch` per viewer:
  - `events`: `EventView::Public | Hidden`, one per log event, for the log and animations. A client never folds them.
  - `table`: the whole `TableView` after the last event. It replaces the client's copy.
  - `objects`: every visible object that is new to the viewer or differs from how they saw it before.
  - `gone`: ids the viewer could see before the batch and cannot see after it.
- The object diff compares the viewer's objects before and after and is never read off the events, because changes can name no object: a lord leaving changes every creature's power and toughness, `DamageCleared` resets damage everywhere, a new turn lifts summoning sickness. The batch at `from_seq` 0 lists every visible object because no view precedes it.
- `StateView::apply` is the reference client fold: replace the table, upsert `objects`, remove `gone`, keep `objects` sorted by id. `StateView::from_first_batch` starts a view from the batch at `from_seq` 0. The web ports `apply` to `web/src/play/view.ts`.
- An ability on the stack is an `ObjectView` of its own with `kind` `Ability`, the `source` id and its `targets` (one list per target specification). It is named after its source and has none of the source's types, colours, cost or abilities. A spell on the stack shows its `targets` too. `kind` (a card when absent), `source` and `targets` are left out of the JSON while they say nothing, so the wire form of a game without spells is unchanged; the web checks them in `net/parse.ts`.
- `ObjectView.manual` lists the clauses of an object's rules text that the engine does not run (`ManualClause {text, reason}`, from `CardDefinition.manual` of the face in use) to every seat that sees the object, so the table follows them as the card's own text; it is left out of the JSON while empty and for a face-down object a seat may not look at. A manual action travels as `Answer::Priority(PriorityAction::Manual(ManualAction))` to the pending priority decision of the seat that holds priority; the engine refuses an action the state does not allow as any illegal answer (`Error{IllegalAnswer}`).
- `ObjectView.keywords` lists the names of the keywords an object has (`Flying`, `First strike`), once each in the order of its rules, from `keywords_of`; an ability on the stack has none. It is left out of the JSON while empty, so the wire form of a game without keywords is unchanged. `PermanentView.summoning_sick` says whether sickness holds the permanent back, so a creature with haste is not sick.
- `ObjectView.counters` lists `(kind, number)` for the counters on a permanent in the order of the kind (`+1/+1`, `-1/-1`, `loyalty`, `poison`, `charge`, then the others by name); `attached_to` names the permanent an Aura or Equipment is attached to, `attached_player` the player an Aura enchants (`PlayerView.enchanted_by` lists the Auras on a player, in id order), and `attachments` the permanents attached to this one, in id order. Both belong to permanents, which every seat sees, so every seat gets the same values and no id names an object the viewer cannot see; a host that left the battlefield holds nothing. Each field is left out of the JSON while empty. A planeswalker's loyalty is its loyalty counters, public like the rest; `ObjectView.loyalty_abilities` lists the loyalty abilities of a planeswalker on the battlefield, each as `{ ability, cost }` with the address `PriorityOptions.abilities` offers while the holder of priority can activate it and the cost as `{ Plus: n }`, `{ Minus: n }`, `"Zero"` or `"MinusX"`, the same for every seat and left out while empty. A planeswalker with no loyalty goes to the graveyard as a `ZoneChanged` with the cause `StateBased`.
- `ObjectView.copy` is set while a permanent is a copy of another object (CR 707): the name, types, colours, power, toughness, abilities and keywords of the view are the copiable values of the copy effect with the other effects over them, and `copy.of` names the original while the viewer can see that very object (a permanent on the battlefield, or an object in a visible zone) and is left out once it has left. A copy adds no hidden information: the original is public, and the question that asks what to copy is a `ChooseCards` over the battlefield. `Event::BecameCopy { object, of }` reaches every seat as logged (the copiable values are left out of the generated type, as for `TokenCreated`); `TokenCreated.copy_of` names the object a token copies. The field is left out of the JSON for an object that is no copy.
- A copy of a spell on the stack (CR 707.10) is an `ObjectView` with `kind: Token`, the name, types and `targets` of the original and `copy.of` naming it; a copy of an ability on the stack is a `kind: Ability` view with the same marker. Both show what the stack shows of the original and no more. `Event::SpellCopied { object, of, controller, choices }`, `Event::AbilityCopied { object, of, controller, choices }`, `Event::CopyEnded { object }`, `Event::CardCopied { object, of, owner }` (a token copy of a face-up card in exile, cast by cipher; once cast it is a spell copy that names the card in `copy.of`) and `Event::CopyCeased { object }` reach every seat as logged (the copiable values of a copied spell are left out of the generated type). The new targets of a copy are asked as `ChooseTargets` with `can_cancel` off, preceded by a `YesNo`, and logged as `ChoiceMade { Choice::Targets }`; targets are public.
- `PlayerView.companion` is `{stage, name?, object?}` for a seat that named a companion (CR 702.139) and left out otherwise. Every seat sees that it exists; the card's `name` goes to its owner from the start and to every seat once the stage is `revealed` (an opening event, `CompanionRevealed`). A card outside the game is no object. `CompanionBrought { player, object }` is public: the card becomes an object in the owner's hand, which only the owner may identify and the others count like any card of a hand, and `companion.object` names it from then on. `PriorityOptions.companion` is left out of the wire form while the action is not offered, and `PriorityAction::BringCompanion` answers it. `tests/it/companion_view.rs` checks all of it at two to four seats.
- In Commander, `PlayerView.commanders` lists the seat's commanders as `{object, casts, tax}` (times cast from the command zone, and the generic mana the next cast from there costs more) and `PlayerView.commander_damage` the combat damage dealt to the seat as `{commander, damage}`, one entry for each commander that dealt any; both are public, the same for every viewer, and left out of the JSON while empty. `PlayerView.commander_lethal` is the combat damage from one commander that makes a player lose at the table (the table's `commander_damage` rule, else 21), the same on every seat so a client never derives it; it is left out when the rule is off and in a Normal game, whatever the table sets (`GameState::commander_lethal`). The command zone lists its cards to every seat. `LossReason::CommanderDamage` and `Event::CommanderStayed {object}` (the owner left a commander in a graveyard or exile) reach every seat as logged. A viewer that is no seat (a spectator) is told the same commanders, tax and damage and sees no hand (`tests/it/commander_spectator.rs`, 2 to 6 seats).
- `PlayerView.counters` lists `(kind, number)` for the counters on a player (poison, energy, experience and the like), in the same order of kinds, left out of the JSON while empty; every seat sees the same counters of every player, a player who lost keeps them, and `LossReason` has `Poison` (ten or more poison counters). `CountersChanged` reaches every seat as logged.
- `TableView.combat_forecast` is `Some` while combat damage is ahead. Combat is public, so every seat gets the same value, naming only battlefield objects every seat can see. `TableView::of` derives it from `pending_combat_forecast`, so it rides in `table` and `apply` needs no extra rule. It covers the damage steps still to come, a creature that deals damage in two of them has one packet, and the life after of an attacked player counts what a lifelink blocker gains. The amounts are what the replacement and prevention effects leave (doubled, stopped, regenerated; [engine.md](engine.md)), and the optional `depends_on_choice` is `true` when a player's choice among those effects would change them: the numbers then show the first option.
- `DamageOptions` (the `AssignDamage` decision) carries `lethal`, the lethal damage of each blocker in the order of `blockers`, and, for an attacker with trample, `excess`, the player or planeswalker attacked. The answer lists the share of each blocker only; without `excess` the shares add up to `power`, with it they add up to at most `power` and the rest goes to `excess` once every blocker has its `lethal` damage. `BlockOptions.min_blockers` lists `(attacker, fewest blockers)` for the attackers that need several (menace). `AttackOptions.required` and `BlockOptions.required` list the creatures among the options that a rule requires to attack or block (CR 508.1d, 509.1c); the declaration names each of them, or the engine refuses it. Each field is left out of the JSON while empty.
- A batch carries the whole table (1.2 to 1.8 KB, 11 to 21% of a snapshot of the same moment in seeded games), which keeps the client fold trivial. A snapshot does not grow with libraries or opponents' hands (about 53 KB for a 4-player board with 175 visible objects). Projection builds two full views per seat per batch.

## Visibility

- Phasing is public: a permanent that is phased out (CR 702.26) has `ObjectView.zone` `PhasedOut` and is listed in `GameView.phased_out` (left out of the JSON while there are none) instead of `battlefield`; it keeps its `permanent` state, counters and attachments. `PermanentPhasedOut { object, controller, indirect }` and `PermanentPhasedIn { object }` reach every seat as logged.
- A prepared permanent (a prepare card, `docs/engine.md`) is public: `PermanentView.prepared` is true for every seat while it holds the designation, `Prepared` and `Unprepared` go to every seat, and the spell face its controller can cast is a `PriorityOptions.faces` entry for that seat alone (`FaceOption.card` is the permanent, `face` 1) answered by `PriorityAction::CastPrepared`; the copy that is cast is a `CardCopied` that shows what the exile zone shows.
- Libraries show a count to everyone; hands list their cards only to the owner; battlefield, stack, exile, graveyards and command zones list their cards to everyone, except that a face-down card is identified to the seat that may look at it alone (below). The view never carries the seed, RNG position or library order.
- A seat also identifies the cards its resolution showed it and the cards it is asked about, wherever they are (`Sight` in `project.rs`, the engine's `GameState::is_shown_to` and `sight::offered_cards`): the cards a seat looked at, found, scried or surveilled are listed in its `objects` until the resolution ends; the cards a reveal names are listed in every seat's until then; and the cards of a pending `ChooseCards` or `OrderCards` (the matches of a search, the top cards of a scry) are listed in the objects of the seat asked, so a prompt can name them. Such a card is an `ObjectView` with the zone it is in (a library card keeps `Library` and is in no zone list of the table, which still shows a count). It leaves the view (`gone`) when the resolution ends, the question is answered or the card changes zones and the zone hides it. The same function builds snapshots and batches, so a seat that reconnects mid-question gets the same objects. The owner of a library learns nothing from another seat's look at it.
- The top card of a library whose owner plays with it revealed is public: every seat lists it in `objects` (as the engine's `is_shown_to` says), and `PlayerView.revealed_top` names it, so the zone list of the library still shows a count only. It leaves the view when it is drawn, moved or shuffled away, and the card below it is named from then on. A draw of it is still a `HiddenEvent::CardDrawn` to the other seats.
- The house rules of the table ([engine.md](engine.md), House rules) change what is revealed, through `zone_is_visible_in` and the engine's `revealed_top`, and nothing else:
  - `open_hands`: every hand lists its cards in every view, a spectator's included, and every card of a hand is an object of every seat. `HandDealt`, `CardsBottomed` and `CardDrawn` reach every seat as logged, as they reach the owner; an event that moves a card between a hand and a zone the viewer cannot see into is whole too. The library order stays hidden: `LibraryShuffled` and `MulliganTaken` are as they were.
  - `revealed_library_top`: the top card of every library is named by `PlayerView.revealed_top` and listed in the `objects` of every seat from the end of the opening shuffle on, so each batch closes on the card that is on top after a deal, a draw, a shuffle or a move. Nothing under it is named.
  - `opening_hand_smoothing`: the deal is one `LibraryShuffled`, a count to every seat, then `HandDealt`. The hand that was drawn and not kept appears in no event and no view of any seat, its owner included.
  - `mulligan_style` `vancouver`: the card a seat scries after keeping a mulligan hand is listed in the `objects` of that seat only while it is asked; its `Scried` reaches the other seats as counts.
- `MulliganTaken`, `LibraryShuffled` and `LibraryRefilled` (a graveyard shuffled into an empty library under the house rule, shown as `HiddenEvent::LibraryRefilled {player, count}`) are hidden even from their owner because they carry library order; `ManaBurned` is public. Other seats see draws, opening hands and bottomed cards without ids.
- `redact` names every `Event` variant, so adding one forces a visibility decision. `EffectCreated` and `RuleCreated` are public; an effect that references a hidden object needs its own rule. `Cycled` is public like the `CardDiscarded` it follows: the card reaches a graveyard.
  - Private to one seat: `LibraryLooked`, `CardsFound`, `Scried` and `Surveilled` reach the seat that did them as logged and every other seat as `HiddenEvent` with counts. `Revealed`, `Proliferated`, `Explored`, `Connived`, `Amassed`, `Monstrous`, `Devoured` (the permanent and how many it devoured), `Adapted`, `Bolstered` and `Crewed` (the Vehicle or Mount, its controller and the creatures tapped to pay) are public. `ChosenAtRandom` (the cards of a graveyard, the battlefield or exile that a pick at random took) is public too. `LibraryBottomed` reaches every seat as `HiddenEvent::CardsBottomed` with a count, since the cards are in a library by then.
  - Whole only when everything it names is visible to the viewer: `ZoneChanged` (when both zones are hidden to the viewer it becomes the `HiddenEvent` with the zones and the cause), `ChoiceMade` (the seat that answers always sees it) and `StepDone` (hidden to the position when it bound or moved a card the viewer cannot see).
  - Whole only when the card they are about is visible to the viewer: `AbilityTriggered`, `AbilityPutOnStack` (of a triggered ability), `TriggerRemoved` and `DelayedTriggerCreated`. A trigger whose cause or source snapshot names a card in a zone the viewer cannot see (a card drawn, still a card in hand when the ability was photographed) becomes a `HiddenEvent` with the source, the ability and who controls it.
  - A keyword a static ability gives to a card of a hand (`docs/engine.md`, Continuous effects) is read in the `keywords` of that card for its owner alone: no other seat lists the card, and no event names the keyword, but the ability it adds (a cycling, a miracle trigger) names its source card when it goes on the stack, as a printed one does (`tests/it/card_grants_hidden.rs`, `granted_miracle_hidden.rs`, `card_grants_games_hidden.rs`). A grant to the cards of a public zone is read by every seat.
  - An ability whose source is a card in a hand or a library (an activated ability with a cost that keeps the card there, a trigger from a hand) names that card to every seat when it goes on the stack: the ability is an object named after its source, as at a table. `tests/it/hidden_info.rs` allows those cards and no other hidden one.
  - `ManualAction` (the first event of a manual action, [engine.md](engine.md), Manual actions) is public as logged, except a `Move` of a card from a place the viewer cannot identify it in to a place the viewer cannot see into, which `HiddenEvent::ManualMove {player, to}` tells without the card, as `HiddenEvent::ZoneChanged` tells the move that follows. The other actions name no hidden card: a `MoveTop` and a `Draw` name a count, and the events that move the cards follow the rules above (a card drawn or put into a hand is `HiddenEvent::CardDrawn` or `HiddenEvent::ZoneChanged` to the other seats; one that lands in a library is named to nobody, its owner included). A `Discard` names a card that reaches a graveyard.
  - Public as logged: the other events of abilities and of the resolution (`AbilityActivated`, `TriggersOrdered`, `DelayedTriggerExpired`, `ResolutionBegan`, `ResolutionEnded`), life, counters, tokens, `Entered`, `Attached` and `Unattached`.
  - "Visible to the viewer" in the rules above means identifiable as just described: a card a reveal named is known to every seat, so a choice among revealed cards reaches them whole.
- `zone_is_visible` is the single zone rule, used for snapshots and for a batch's `table` and `objects` alike. It says which cards a zone lists; whether a listed card is identified is judged object by object (`Sight::look` in `project.rs`, asking the engine's `GameState::may_look_at`), so every face-down rule lives in one place.
- A merged permanent (a creature a mutating creature spell merged with) is one `ObjectView` with the characteristics of its top card; `merged` lists its cards from the top down (`MergedCardView { id, name }`) for every seat, since the permanent is face up, and `Event.Mutated` is public.
- A face-down object (a foretold card in exile, a face-down spell or creature) is listed in its zone for every seat. The seat that may look at it (its owner, for a foretold card) gets the whole `ObjectView` with `face_down` set; every other seat, a spectator included, gets an `ObjectView` with `face_down` set, its owner, controller and zone, and no name, cost, types, colours, power, abilities or counters. A face-down creature (morph, megamorph, disguise) is shown to every seat with the characteristics of its 2/2 (type, power and toughness, tapped state, damage, counters, attachments, ward) and no name, and its controller reads the card on it (name, cost, printed subtypes, abilities and keywords) with `face_down` set; its events are public (`TurnedFaceUp` names no card) and the view after them tells which card it is. When the object changes zone it is a new object: the seat that saw it face down gets the whole view, or the id in `gone` when the new zone is hidden to it.
- The events of a face-down object follow the same rule. A `ZoneChanged` is a `HiddenEvent::ZoneChanged` with the zones and the cause (`ZoneCause::Foretold` for a foretell) when the viewer cannot identify the card before the move and cannot see it after it: a hand or library, or a face-down arrival they may not look at. A cast or a move to a place the viewer sees into is whole, so the card is named to everyone as it is cast. A snapshot (`Snapshot.face_down`) of a face-down card is judged the same way for `StepDone` and the trigger events.
- A manifested or cloaked card (`ZoneCause::Manifested{by}`, `Cloaked{by}`) is judged by the seat that controls it after the move (`ZoneCause::enters_under`), not by the owner of the library it came from: the move is whole for `by` and a `HiddenEvent::ZoneChanged` for every other seat, the owner of the card included, and the permanent is a 2/2 for everyone with the card behind it for `by` alone (ward {2} shown for a cloak). An ability on the stack of a permanent that lies face down and that the seat may not look at has no name, so a ward trigger does not name the card.
- `TurnView.extra` says the turn is an extra turn (CR 500.7) and `TurnView.extra_turns` lists the players who still have one to take, the one taken first last; both are public and left out while false or empty. `TurnBegan { extra }`, `ExtraTurnAdded`, `ExtraTurnSkipped` and `PhasesAdded` are public events (`tests/it/extra_turn_view.rs` sends them to every seat unchanged).
- `TurnView.monarch` names the monarch (CR 724) to every seat and is left out while nobody is; `MonarchChanged` is a public event (`tests/it/monarch_view.rs`).
- `TurnView.active_left` says to every seat and to a spectator that the turn goes on without an active player (CR 800.4): the seat `active` names has left the game and the turn runs out without it. It is set while turns are being played (not in the mulligan stage or in a game that has ended, where `result` speaks), clear in the next turn, which belongs to the next player in turn order, and left out of the JSON while false. `tests/it/active_left_view.rs` checks it at 3 and 4 seats for each seat that leads a turn and each step the turn can be in, for a spectator, in the batches, in a game resumed from its log and over seats that left before; `active_left_fuzz.rs` plays bot games with random concessions under the engine's invariants and checks the flag against the event log at every step.
- A card with several faces (CR 708 to 715) is public in every zone that lists it: in a hand its owner sees the front face (both halves, named `A // B`, for a split card), and the stack and the battlefield show the face in use. `ObjectView.face` is that face's position, left out for the card as a whole; a transformed permanent shows its back face (`Some(1)`) with that face's name, power, toughness and keywords, and a fused split spell shows the position after the last half. `TurnView.day_night` says day or night (CR 726) and is left out while the game is neither; `Transformed` and `DayNightChanged` events are public. `PriorityOptions.faces` lists the faces its holder may cast or play with their costs, and `PriorityAction::PlayLandFace` plays a back face land.
- `gone` holds only ids the viewer saw before. A hand shuffled into the library (a mulligan) is told as ids in `gone`, a drawn card arrives in full in `objects`, and a card that stays hidden appears nowhere, so another seat's draw changes only a count in `table`.

## Sync contract

- A socket opens with one of two credentials, both checked before the upgrade: `/ws/{game}/{token}` (a seat's link; the token names the seat) or `/ws/{game}` with the `mtg_session` cookie (a signed-in user's own seat in that game). The cookie rides the upgrade request because scripts cannot read an `HttpOnly` cookie; the server's `Origin` check applies.
- `Join` follows either way: `game` must equal the game in the address and `Welcome.player` says which seat the credential opened. A client never names its seat.
- The server passes `project_events` the state from before the batch; it folds the events over a clone to get the state after and to judge what each object was.
- It sends the batch, then the `Decision` it leads to, so the decision's ids are already in the client's view. A `Decision` goes only to the seat it names, and answers with a stale `DecisionId` are rejected. `GameState` and raw `Event` are never serialized to a client.
- Client rule: state is the `Snapshot`, then `apply(batch)` for each `Events` message in order.
  - The next expected `from_seq` is the snapshot's `seq`, then the last batch's `from_seq + events.len()`.
  - Any other `from_seq` means the client missed something: send `Resync` and apply nothing until the new `Snapshot` arrives.
- A seat that joins the lobby gets `Welcome` and the roster but no `Snapshot` (there is no engine yet); it starts its state from the first batch, at `from_seq` 0. A seat that joins a running game gets `Welcome`, `Snapshot` and its pending `Decision`.
- Decision ids come from a per-game counter that restarts at 1 after a resume. A client never carries one across a reconnect to a restarted server; a fresh `Decision` always follows the snapshot.

## Lobby

- `Ready` says the seat is set to play and `NotReady` takes that back. Both are ignored once the game runs.
- `Lobby { seats, needed }` is the roster before the start: name, connected, ready and deck per seat in seat order, and `needed`, the seats still to press Ready. A ready seat whose client left stays ready.
- A seat's `deck` is `SeatDeck {name, format, manual_cards}`: the deck's name, its format key (`normal` for a built-in deck) and the number of copies of its main deck and commanders that the game does not run whole ([deck-check.md](deck-check.md), Decisions), never the name of a card. It is left out of the JSON while the seat has no deck and for an open seat, and the TypeScript field is optional. `manual_play(seats)` says whether any seat's deck holds such cards, so the table plays with manual cards; a deck in the `manual_play` state is allowed ([server.md](server.md), Choosing a deck). A seat without a deck cannot press Ready: the server answers `Error{BadMessage}` to that seat alone, and a seat that is ready keeps its deck until it sends `NotReady`. The deck is chosen over REST ([REST bodies](#rest-bodies)), never over the socket.
- It follows `Welcome` and goes to every connected seat when a seat joins or leaves or a ready flag changes. A message that changes nothing sends nothing, and the `Ready` that starts the game is answered by the opening `Events` instead.
- It is never sent to a running game: a client drops its lobby view when the first batch or a snapshot arrives.
- `GET /api/games/{id}` lists the ready seats as `ready` beside `connected`, so a page can show the lobby before its socket opens.

## Decisions

- `PriorityOptions.can_act` says whether the holder can do anything useful; the rule is in [engine.md](engine.md). `PriorityOptions.abilities` lists the abilities (`{ object, ability }` and a `source`, left out while it is `Printed`) the holder can activate, of their permanents and of the cards they own in their hand, graveyard, exile and command zone (the zone is the one the object stands in, in the views); it is left out while empty, and a client that does not know it still plays a game of cards without abilities.
- The decisions of spells and abilities are `ChooseTargets`, `ChooseMode`, `ChooseNumber`, `DivideAmount`, `ChooseCards`, `OrderCards`, `YesNo`, `ChooseOption`, `ChooseCosts`, `OrderTriggers` and `ChooseReplacement`, each with an `Answer` of the same name. Every one carries `source`, the object that asks. A target is `{ Player }` or `{ Object: { id, counter } }`.
  - `ChooseTargets` is sent today: `spec` is the specification's index, `wording` what it asks for in the words of a card ("target creature you control"), `legal` the targets to pick from, `min` and `max` the count and `can_cancel` whether the answer may be `Cancel`, which backs out of the cast with no event. For a triggered ability that goes on the stack `triggered` is true and `can_cancel` false: the answer `Remove` chooses no target and removes the ability (CR 603.3d).
  - `OrderTriggers` is sent when a seat has two or more triggered abilities to put on the stack together and the order can matter: `triggers` lists them in the order they triggered, each with its source, its ability and `when`, the event it waits for in the words of a card. The answer lists the positions in the order they go on the stack, the last on top.
  - `YesNo` carries `text`, the question in the words of a card ("Pay {1}?"), and `only_no`, left out unless true, when the payment asked for cannot be made: No is the only answer and a Yes is refused with `IllegalAnswer`; only the seat asked is sent it; `ChooseOption` carries `options` (`{ Player }`, `{ Color }` or `{ Label }`) and `text` ("Choose a color."; "Choose the damage Mending Hands prevents first." with one `Label` per damage event, which the replacement step asks of the player the damage happens to); `ChooseMode` carries `modes` (`{ index, label }`, `index` being the place among the ability's modes, `label` the card's name for the mode or else the wording of what it does, and null when neither exists), `min`, `max`, `repeat` and `can_cancel`. `text` is left out while empty. The answers are `true` or `false`, the option's position in `options`, and `{ Modes: [index, ...] }` in the order the modes happen or `Cancel`, which backs out of the cast like `ChooseTargets` and needs `can_cancel`. The web has their prompts and the server their clocks.
  - `ChooseCards` carries `from`, the cards to pick from, `min`, `max` and `text` ("Discard a card."); `OrderCards` carries `cards`, in their current order, and `text` ("Put the cards on the bottom in any order."). `text` is left out while empty. The answers are the chosen cards and the cards in the order chosen. The web has their prompts and the server their clocks; no card asks them yet.
  - `ChooseNumber`, `DivideAmount` and `ChooseCosts` are the announcement's other questions, sent to the seat that casts or activates. `ChooseNumber` carries `min`, `max` (null for no limit), `except` (the numbers between them that are not allowed: an X with no legal target; left out while empty) and `text` ("Choose a value for X."; "Choose how many times to pay Multikicker {G}." for the times a cost is paid); `DivideAmount` carries `total`, `among` (the targets, each of which gets at least one) and `text` ("Divide 3 damage among the targets."); `ChooseCosts` carries `optional` (`{ index, label }`, only the costs the player can pay for). Each carries `can_cancel` (left out while false: a triggered ability cannot be backed out of). The answers are `{ Number: n }`, `{ Division: [[target, share], ...] }` and `{ Costs: [index, ...] }`, or `Cancel` (needs `can_cancel`), which backs out of the cast like `ChooseTargets`. The web shows a placeholder prompt that offers nothing until M5; no card asks a number or optional costs yet.
  - `ChooseReplacement` goes to the player an event happens to, or who controls what it happens to, when two or more replacement effects apply to it: `candidates` lists the effects (the object with the effect and the index of the ability) and `text` the event in words; the answer is the index of the effect that applies first. Its prompt is a placeholder until M5. The answer is not an event: the batch of events it is about waits in the engine, and only the events that happen are logged (a replaced event is never in the log). `Entered` carries `chosen` (a colour or a creature type) when the permanent chose as it entered, and `ZoneChanged` the cause `Discarded` for a discarded card that a replacement effect sent elsewhere.
- `DecisionKind::Mulligan` carries `free_mulligans`, `bottom_if_keep` and `bottom_if_mulligan` beside `mulligans_taken` and `can_mulligan`, so a client never derives the bottom count. `bottom_if_keep` is the `count` of the `BottomCards` decision that follows a keep.
- `Decision.deadline_ms` is the time the seat has left, in milliseconds, when the message is sent. It is a duration, so the client starts counting when the message arrives; a decision sent again after a reconnect or `Resync` carries what is left.
  - Present for every priority decision of a seat that is not the active player and for its target, trigger-order, replacement, yes-or-no, option, mode, number, optional-cost, division, card and card-order decisions (10 s, `MTG_RESPONSE_SECS`), for declaring blockers (45 s, `MTG_BLOCK_SECS`), and for keeping or bottoming (every seat), paying for a spell, dividing combat damage, declaring attackers and discarding (a seat that is not the active player) (60 s, `MTG_THINK_SECS`), and for every decision of the active player after the opening (`MTG_ACTIVE_SECS`; absent while it is 0, the default). The table in [server.md](server.md), Response clocks, names the answer at zero for each kind.
  - The priority clock ignores `can_act`: an idle window would hold the table for nothing, and a clock that depended on it would tell the table what a hand holds.
  - At zero the server answers for the seat (a pass, no blocks, keeping the hand, ...) through the normal path. The decision id goes stale and the events of that answer arrive as a batch, so a client drops the prompt at zero and expects them.
  - The field is omitted from the JSON rather than sent as `null`; the TypeScript type is `deadline_ms?: number`.
- `Decision.show_after_ms` is the time in milliseconds after the message arrives at which the client starts to show the countdown (`MTG_CLOCK_GRACE_SECS`, 3 s). The clock runs from the moment the decision is issued all the same, so a short clock shows nothing for its first part. It is omitted when there is no clock or the countdown shows at once (grace 0, a clock no longer than the grace, a clock that was extended), and a decision sent again after a reconnect carries what is left of the delay. It follows the kind and the seat as the clock does, never whether the seat can act. TypeScript: `show_after_ms?: number`.
- A seat that holds an extension spends it at the deadline instead of being answered for ([server.md](server.md), Response clocks): it is sent the same `Decision` again (same `id`) with the new `deadline_ms` and no `show_after_ms`, and the client replaces the clock of the prompt it shows. Every seat is sent `Bank { seat, bank }`, the extensions the seat has left.
- `PlayerView.bank` (0 to 3) is the extensions a seat holds, public, the same for every viewer. The engine does not know it: the server writes it into the table of every snapshot and event batch, so an extension earned at the end of a turn arrives with the batch of that turn and a spent one with `Bank`.

### Payments

The payment rules are in [engine.md](engine.md); the wire facts are:

- `PayOptions.can_cancel` says whether `PayChoice::Cancel` is legal. A cancelled cast produces no events, so the server sends no `Events` batch and stores nothing, only the caster's `Priority` decision again with a fresh id. The log never records a cast that was not paid.
- `PayChoice::Complete(Payment)` sends part of a payment (floating mana and taps) for the engine to finish. A rejected answer leaves the decision pending.

- Mana that may be spent only on some things is told in the pool (`ManaPool.restricted`, one entry for each mana with what it allows: a public fact like the pool) and in the events (`ManaAdded.only`, `ManaSpent.restricted`); a payment names it in `Payment.restricted`, and `PayOptions.spend` says what the payment is for. All of them are optional on the wire.
- Mana that stays past the step is public too: `ManaPool.kept` (`Kept`: the mana lost with the combat phase and with the turn, by type, a part of `counts`), `Restricted.lasts` and the events `ManaAdded.lasts` and `ManaPoolEmptied.through`; all are left out while they are the step.
- Help in a payment is offered beside the mana sources: `PayOptions.convoke` (each creature with the colours it can pay beside {1}), `PayOptions.improvise` (the artifacts that can pay {1}) and `PayOptions.delve` (the cards of the graveyard); `Payment.convoke` (a creature and the colour it pays, none for {1}), `Payment.improvise` and `Payment.delve` name what is used. All are left out while empty. The taps are public events and the cards exiled leave a graveyard every seat sees.

- `ManaCost` is `Array<ManaSymbol>` in canonical order (shapes in the generated `ManaSymbol.ts`).
- Life pays Phyrexian symbols. `Payment.life` is optional on input and read as 0, `PayOptions.life` is the payer's life total and `max_life` the most this payment may take, so the prompt offers up to `max_life / 2` symbols paid with life and shows the total left.
- The cast's events start with one public `LifePaid { player, amount }` before `SpellCast`; the client reads the new total from the batch's table.

## Pace of play

### Auto-pass

- `AutoPass { enabled }` is the Full Control mode `Held` when `enabled` is false and `Off` when it is true (a seat in `NextWindow` stays in it). The change is told as a `FullControl` message. `Welcome.auto_pass` is true unless the seat is in `Held` (the server default after a restart).
- A client must not rely on seeing every priority window: outside Full Control the server asks a seat only at its windows (below). The events of the passes arrive in the batch of the answer that led to them, except the pass for a seat that cannot act in a combat window or while a spell waits on the stack: it comes in a batch of its own after a wait of 0.25 to 0.7 s (`server.md`, Dwell), so the pace does not tell the table what a seat holds.

### Yields

- `Yield { until }` (`Resolve`, `EndOfTurn` or `MyTurn`) asks the server to pass priority for the seat until something happens. `CancelYield` ends it and a new `Yield` replaces the old one.
- While a yield lasts the server answers each `Priority` decision of the seat with a pass, through the same path as an answer, and never sends it; the pending one is passed at once. The passes arrive as events in the batch of the answer that led to them.
- It ends, and decisions come as usual, when:
  - an opponent puts an object on the stack that the seat has not passed on yet;
  - its target is reached: `Resolve` when the stack is empty, `EndOfTurn` when another turn has begun, `MyTurn` when another turn of the seat's own has begun;
  - the seat holds a stop at a window (not in the step of the window it asked at);
  - the seat leaves the game or the game ends, or sends `CancelYield`.
- Other decisions (attackers, blockers, a discard, a payment, damage division) are always sent and leave the yield as it is.
- The end rules look at the table only, never at what the seat could do, so the pace reveals nothing about a hand. They live in `yields.rs` in `mtg-server`.
- A client asks for `Resolve` only over a stack: over an empty one the yield ends at once, passes nothing, and the same window returns with a new decision id.
- Yields live in memory per seat, so a resumed game has none. A seat that is out of the game or in Full Control (`NextWindow`, `Held`), or a game that has not started or is over, gets `Error{BadMessage}`; turning Full Control on ends a yield.
- `Yielding { until }` (`null` for none) reports every change of the seat's yield, whatever the cause; `Welcome.yielding` gives it at join.
  - It follows the events of the step that changed it and precedes the `Decision` that follows, so a prompt never appears under a "passing" line. A yield that starts and ends inside one step is never told.
  - A client that sees `Yielding` with a yield drops the `Priority` decision it still shows (the server passed for it); other decisions stay.
- A yielding seat is sent no `Priority` decision, except when the server cuts a run of 500 passes in one step at its decision: the yield ends first and `Yielding` says so.

### Stops and Full Control

The design is in [arena-flow.md](arena-flow.md).

- A `Stop { side, step, keep }` is a step at which a seat asks to be given priority. `side` is `Own` (the seat's turns) or `Opponent` (any opponent's turn). `keep` false is a one-turn stop (until that step has passed once), true a lasting one (until cleared).
- `SetStop { side, step, on, keep }` sets (`on` true) or clears (`on` false) the stop at a side and step. `keep` is the new stop's and is ignored when clearing. A seat holds one stop per side and step, so setting a held stop again replaces its `keep`.
- Only a step where a player gets priority can hold a stop. `Untap` and `Cleanup` are refused, set or cleared alike, with `Error{BadMessage}`. The refusal changes nothing and needs no resync, unlike `StaleDecision` and `IllegalAnswer`: the shape is valid, so the socket stays open and counts no bad message.
- `FullControl { mode }` (`Off`, `NextWindow`, `Held`) sets how much of the game the seat plays by hand: `NextWindow` until the seat has passed once, `Held` until it turns the mode off.
- `Stops { stops }` and `FullControl { mode }` report what the server holds whenever it changes, whatever the cause. They follow the events of the step that changed it and precede the `Decision` that follows, as `Yielding` does. `Welcome.stops` and `Welcome.full_control` give the values at join.
  - `Stops` is the whole list and replaces the client's: each side and step once, own side first, each side in turn order (`keep` never decides the order).
  - A request that changes nothing gets silence. One that only changes a held stop's `keep` is a change and is told as the whole list.
- Both live in memory per seat from the lobby on and survive reconnects and `Resync`; a resumed game starts with no stop and the server's default mode (`Held` when auto-pass is off by default).
- A seat that leaves the game, and every seat once the game is over, loses them and is told (`Stops` empty, `FullControl` `Off`) before its decision or `GameOver`. Requests from such a seat, or in a game that is over, get `Error{BadMessage}`.
- The server asks a seat at a priority decision only at its windows and passes for it elsewhere (the rules are in `windows.rs`, see `server.md`):
  - in `NextWindow` and `Held`, at every window;
  - at a stop, whether the seat can act or not;
  - at the default windows, only if it can act: the seat's own main phases, the declare attackers and declare blockers steps, and any moment an object of another seat is on the stack; a seat that cannot act is passed for there after the wait above, except in its own main phase with an empty stack, where it is passed for at once.
- A one-turn stop goes once the game has left its step. `NextWindow` goes back to `Off` when the seat has passed.
- The web checks both messages and the `Welcome` fields in `net/parse.ts` (a step only has to be a step; whether it may hold a stop is the server's rule) and keeps them in the store as `stops` and `fullControl`.

## Preview

- `Preview { decision, answer }` asks what combat damage would do if `answer` were given to the pending DeclareAttackers or DeclareBlockers decision `decision`, without giving it. `Forecast { decision, forecast }` is the reply, `forecast` a `CombatForecast` or null.
- The engine builds it (`Engine::preview_forecast`), so it equals the `combat_forecast` every seat's table carries right after the same answer is really given. It describes the moment of the declaration; the batch that follows can run past it, because with auto-pass on the server can pass for the following seats and deal the damage before the batch is cut.
- Exactly one `Forecast` answers each `Preview`, to the seat that asked, in order. It is null when there is none to give: the decision is not that seat's pending one, it is not an attack or a block, the engine would refuse the answer, an attack names nobody, or the seat previews faster than the server allows. A client cannot tell the reasons apart and does not need to.
- A preview never produces an `Error`: the stale-decision treatment of `Answer` (a notice and a `Resync`) would be wrong for advice that routinely races with the real answer or a new decision.
- Combat is public, a forecast names only battlefield objects every seat can see, and a seat can preview only its own pending legal options, so a seat learns nothing it could not learn by answering.
- A client matches replies to requests by order, keeps the reply to its latest request and ignores one whose decision is no longer pending. A `BadMessage` reply to a `Preview` means the server does not know previews; the web client then stops asking.

## REST bodies

The account, card and deck endpoints of `mtg-server` take their bodies from `mtg_protocol::rest`, so the web gets them from the bindings.

- `Credentials {username, password}` is the request of `register` and `login`. Unknown fields are refused and `Debug` prints the password as `<redacted>`.
- `PasswordChange {current_password, new_password}` is the request of `POST /api/auth/password` and `AccountDeletion {password}` that of `DELETE /api/auth/account`; both refuse unknown fields and print every password as `<redacted>`. A wrong password for either is the 401 `invalid_credentials`.
- `UserView {id, username}` is the answer of `register`, `login` and `GET /api/auth/me`.
- `AuthErrorCode` is the snake_case `error` string of a failed account request. `as_str` is the wire text and `ALL` lists every code; a test keeps `as_str`, serde and the generated union equal.
- The length limits are constants (`USERNAME_MIN_CHARS` 3, `USERNAME_MAX_CHARS` 32, `PASSWORD_MIN_CHARS` 10, `PASSWORD_MAX_CHARS` 128), so server and tests share one number. ts-rs does not export constants, so the web repeats them for its forms and the server stays the judge.
- `GET /api/me/games` answers `MyGames {games}`: the newest 100 games, newest first. A `MyGame` has `game` (what `GET /api/games/{id}` and the socket take), the user's own `seat` and `name`, `status` (`lobby`, `running`, `finished` or `failed`), `created_at` (`YYYY-MM-DDTHH:MM:SSZ`, UTC), `others` (`MyGameSeat {seat, name, user}`, `user` null for a guest), `result` (null until finished) and `reason` (one sentence for a `failed` game, null for the other statuses). A failed game has no Play route: `/ws/{game}` answers 404 for it.
- `DELETE /api/me/games/{id}` takes a `failed` game off the signed-in user's list and answers 204 with no body; 404 `not_found` for an id that is no game, a game that is not in the list, one that did not fail and one removed already; 401 `unauthenticated` without a session.
- `GET /api/cards` answers `CardSearchPage {cards, total, page, per_page}` and `GET /api/cards/{oracle_id}` a `CardDetail`; a `CardHit` has `oracle_id`, `name`, `mana_cost`, `mana_value`, `type_line`, `colors` and `color_identity` (`CardColor`: `W`, `U`, `B`, `R`, `G`), `images` (`CardImages {card, faces}` of `ImageLinks`) and `support` (`verified`, `partial`, `manual`, `stale`, `unplayable`). A `Reason {face, span, text}` names a clause the game cannot run and the span of the face's oracle text it covers. `DEFAULT_PER_PAGE` (40), `MAX_PER_PAGE` (100) and `MAX_PAGE` (10 000) are constants of `mtg_protocol::rest`.
- The deck endpoints take and answer `DeckBody {name, format, notes, cards: [DeckLineBody {zone, oracle_id, printing_id, count}]}`, `DeckView` (lines as `DeckLineView {zone, count, printing_id, card}`, the stored `check: StoredCheck`, the `report: DeckReport`, `state: DeckState`, `verified`, `changed`), `DeckList {decks: [DeckListItem]}`, `CheckRequest {deck | format, cards, game?, table?}` (`deck` is a stored deck of the account or `precon:<code>`, which needs no account; `game` is the id of a game, `table` is `TableRules {format, house_rules?}`; either one makes the report the verdict at that table, never both), `ImportRequest {text, source, format}` and `ImportResult {source, cards, unresolved, problems, ignored}`. `DeckReport`, `Issue`, `ReportCard`, `Summary`, `Counts`, `DeckZone` (`main`, `sideboard`, `commander`, `companion`), `DeckState` (`verified`, `manual_play`, `blocked`, `unchecked`) and `StoredCheck` come from `mtg-cards` (`docs/deck-check.md`). `DeckErrorCode` is the snake_case `error` string of a failed card or deck request (`as_str` is the wire text, `ALL` lists every code; `rate_limited` is the 429 of a precon check over the address's budget). The limits are constants of `mtg_protocol::rest` (`MAX_DECKS_PER_USER` 100, `MAX_DECK_LINES` 250, `MAX_DECK_CARDS` 250, `MAX_DECK_NAME_CHARS` 100, `MAX_DECK_NOTES_CHARS` 10 000, `MAX_IMPORT_CHARS` 100 000, `MAX_IMPORT_LINES` 1 000).
- The precon endpoints answer public data ([server.md](server.md), Precons):
  - `GET /api/precons` answers `PreconList {precons: [PreconListItem]}`. A `PreconListItem` has `code` (lower-case words joined by hyphens, unique, the name of the precon in paths and behind `precon:`), `name`, `set`, `deck_type`, `release_date`, `commanders` (names), `card_count` (copies of the commander and main boards), `format` (`commander` or `freeform`, the format of the check), `state` (`DeckState`: `verified`, `manual_play` or `blocked`), `verified`, `playable` (whether a game of this server takes the deck today) and the `summary` of the check.
  - `GET /api/precons/{code}` answers `PreconView {precon, issues, boards}`: the list item, the `Issue`s that keep a game from taking the deck (legality and the game's format, empty for a `playable` deck) and `PreconBoard {board, copies, cards}` per board that holds cards, each card a `PreconCardView {name, count, printing_id, card, support, reasons}` (`card` is a `CardHit` in the art of the deck's printing, null for a card the database does not hold, which is `unplayable`).
  - A deck is named by `PRECON_DECK_PREFIX` (`precon:`) and the code wherever a request names a deck. `PreconErrorCode` is the `error` of a failed precon request (`not_found`, `rate_limited` with `Retry-After`, `cards_unavailable`, `unavailable`, `internal`); a precon chosen as a deck fails with the codes of `DeckChoiceErrorCode`.
- The game browser takes its bodies from `mtg_protocol::rest` too ([server.md](server.md), Open games):
  - `GET /api/lobbies` answers `LobbyList {games: [LobbyGame {game, host, format, house_rules?, manual_play, filled, total, created_at, age_secs}]}`; `format` is `normal` or `commander`. `manual_play` is whether some seat plays a deck with cards the game does not run whole, as the roster says now. `created_at` is `YYYY-MM-DDTHH:MM:SSZ` (UTC) and `age_secs` the age at the moment of the answer, so a client counts on from its own clock and never compares the server's. `house_rules` is the `HouseRules` the host set and is left out when none is set. A row has no token, join code or link.
  - `POST /api/games/{id}/join` takes `JoinRequest {name?, deck?}` and `POST /api/join` takes `JoinCodeRequest {code, name?, deck?}`; `deck` is the id of a built-in deck, `precon:<code>` or the id of one of the signed-in visitor's stored decks. Both answer `Joined {game, seat, token}`, where `game` is the id of the game the seat is in (the only place a visitor with just a code learns it) and `token` is null for a signed-in visitor who already held a seat and opens it through its session. `Debug` of `Joined` never prints the token.
  - `GET /api/games/{id}` answers `GameInfo {format, started, seats: [GameSeat {seat, name}], connected, ready, result, visibility, manual_play}`: the facts anybody who knows the id may learn, with no token or code. `manual_play` is the roster's answer while the game is in its lobby and what it was when the game began once it runs. `format` is `normal` or `commander`, as in the lobby row. An open seat has an empty name, and `visibility` is the one in force, so a lobby page that reloads knows whether the game is listed. The web checks it in `net/parseLobbies.ts` and types it with the generated `GameInfo`.
  - `PATCH /api/games/{id}` takes and answers `VisibilityBody {visibility}`; `Visibility` is `public` or `invite` (the default) and is the type the server stores.
  - `DELETE /api/games/{id}` has no body and answers 204: the host closes a game that is still in its lobby, and every socket of the game ends with the close code 4002 ([server.md](server.md), Transport). Its failures are `forbidden` (not the host), `started`, `not_found` and `unavailable` of `LobbyErrorCode`.
  - `LobbyErrorCode` is the snake_case `error` string of a failed game browser request (`as_str` is the wire text, `ALL` lists every code); a request that carries a seat token sends it as `Authorization: Bearer <token>`.
  - `PUT /api/games/{id}/seats/{n}/deck` takes `ChooseDeck {deck}` (a built-in deck's id, `precon:<code>` or a stored deck's UUID) and answers the `SeatDeck {name, format, manual_cards}` the table now sees: the holder of seat `n` chooses the deck it plays until the seat is ready ([server.md](server.md), Choosing a deck).
  - `DeckChoiceErrorCode` is the `error` of a request that names a deck, beside the codes of `LobbyErrorCode` that the same requests keep: `unknown_deck` (404, or 400 when a game is made; a deck of another account looks like a deck that does not exist), `deck_blocked` (422) and `seat_ready` (409). A blocked deck answers `DeckBlockedBody {error, message, issues}`, the `Issue`s of the deck check for the game's format; they name cards and go only to the account whose deck it is. The codes are a type of their own so that clients built before them still handle every `LobbyErrorCode`.
- `POST /api/games` has a hand-written body on both sides (`web/src/net/api.ts`): it binds seat 0 to a signed-in creator, takes `format` (`normal` or `commander`; Commander has 2 to 6 seats and its decks carry their commanders, [server.md](server.md), Choosing a deck), `visibility`, `held` and `house_rules` (a `HouseRules`, [engine.md](engine.md); a value out of range is 400 `invalid_request` with the rule's name in `field`) beside `seats`, a `deck` per seat that may be left out (a built-in deck's id, `precon:<code>`, or for seat 0 a stored deck's: with a precon the one request makes the lobby), and answers the join `code` beside `game` and `seats`.
