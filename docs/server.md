# Server

The `mtg-server` crate: one actor per game behind an axum REST and WebSocket transport, with Postgres persistence, accounts and the pace of play. The wire contract is in [protocol.md](protocol.md), the client in [web.md](web.md). Routes are registered in `server.rs`; request and response bodies are the types of `mtg-protocol` (REST bodies); this file holds the rules behind them.

## Shape

- `spawn_game(id, setup, store)` starts a game in its lobby and `resume_game(store, id, setup)` rebuilds one from its log; both return a cheap-clone `GameHandle`. `status()` carries the state hash and is for tests and admin views, never for clients.
- One task per game owns the `Engine`, the `EventStore` and a bounded queue per seat. A full or closed queue drops that client, which reconnects and gets a snapshot, so the actor never waits for a client. The actor trusts the seat it is given: the transport maps a credential to one seat.
- A step checks the seat, the `DecisionId` and engine legality, applies the answer, projects for the connected seats, appends to the store, then sends the events, the next `Decision` (only to its seat) and `GameOver`. A store or projection failure restores the engine from its `Checkpoint` and answers `Error{Internal}` without details.
- Snapshots and batches are built for a `PlayerId`; a viewer past the last seat gets the spectator view (`StateView::for_spectator`). Every socket is a seat's, so no client gets it yet.
- The lobby has no engine until every seat has sent `Ready`; readiness is never stored and outlives a connection. The last `Ready` creates the engine and broadcasts the opening events from seq 0; if that fails, a repeated `Ready` retries. Chat (500 characters at most) goes to the connected seats and is never stored.
- The roster (`ServerMessage::Lobby`) lists every seat and is sent after each change. An open seat is listed with an empty name, not connected and not ready, so it counts in `needed` and the game cannot start while one is open; nothing sent as an open seat counts.
- Presence (`presence.rs`): after every command the actor compares the connected seats with what the table was last told and sends each change to the other connected seats as `Presence`, with the time left on the away seat's sent decision. Event batches and snapshots carry the flag. Presence is never stored or hashed.
- A game made from a recipe keeps one deck per seat in the lobby (`SeatDecks`, [Choosing a deck](#choosing-a-deck)): a `Ready` from a seat without one is answered `Error{BadMessage}` to that seat alone and changes nothing. A game made from a bare setup (`Registry::register`, `spawn_game`) needs no decks.
- `Registry` holds the live games by random v4 `GameId`. A seat token is 256 random bits kept only as its SHA-256, and `authenticate` compares every seat so timing does not say which one matched. `MTG_MAX_GAMES` caps creation.
- The janitor sweeps every 30 s and drops finished games after 10 min, lobbies that never started after 1 h and started games with nobody connected for 24 h (`Retention`). It closes their sockets with 1001 and marks the record `expired` or `finished`.

## Transport

`Server::new(config)` keeps games in memory, `Server::open(config, pool)` also records them in Postgres, and `serve(listener, shutdown)` runs axum. Errors are `{error, message}`, and every response is `no-store` (a picture sets its own rule) and `nosniff`, because it can hold tokens and live state.

- `POST /api/games` takes `{format, seats, visibility?, held?, house_rules?}`: two seats or more in any format, a body of at most `GAME_BODY_LIMIT` (256 KiB, the one ceiling on a game's seats), unknown fields refused, a server-random seed. `visibility` is `public` or `invite` (the default). `held` is how many seats from seat 0 get a token (every seat by default); the others are open and `seats` lists only the held ones. A seat's `deck` is a demo deck id (Normal games), `precon:<code>` (any seat) or, for seat 0, a stored deck of the creator; none leaves the seat to choose. A deck nobody has is 400 `unknown_deck`, a blocked one 422 `deck_blocked`, an unknown `format` 400 `unsupported_format`.
- `GET /api/games/{id}` reports the lobby facts (format, started, seats, connected, ready, result, visibility, manual play, house rules when set); a malformed and an unknown id are one 404.
- The origin guard (`origin.rs`) keeps other sites from acting with a visitor's cookie: no `Origin` (a bot) passes, otherwise it must be in `MTG_ALLOWED_ORIGINS` or name the `Host` authority, else 403 `forbidden_origin`. It covers both socket routes and every request that changes something (any method but GET, HEAD, OPTIONS). CORS answers listed origins only, with credentials.
- `GET /ws/{game}/{token}` is a seat's link (the token picks the seat before the upgrade); `GET /ws/{game}` is the seat bound to the session cookie's user. A socket checks the origin, then the credential (an unknown game, a malformed id and a wrong token share one 404), then expects `Join` first ([protocol.md](protocol.md), Sync contract): a wrong version gets `Error{UnsupportedVersion}`, a foreign game id `Error{UnknownGame}`, anything else `Error{BadMessage}`, each closing with 1002.
- A second socket for a seat replaces the first. A closing socket drops its queue and never calls `leave`, which would close the connection that replaced it.
- Shutdown (SIGTERM, ctrl-c) stops accepting, sends every socket 1001 and waits up to 5 s; what is still open then is abandoned, so a stalled request cannot hold the process.

Limits per socket: `Join` within 10 s of the upgrade; frames and messages of 64 KiB; a burst of 40 messages, then 20 per second (the client paces under it, `web/src/net/pacer.ts`); 5 malformed messages in a row, each answered `Error{BadMessage}`; a ping every 20 s and a close after 60 s without a pong.

| Close code | Meaning |
|---|---|
| 1001 | Server stopping, or the game left the registry |
| 1002 | Bad handshake or protocol error |
| 1007 | Text frame that is not UTF-8 |
| 1008 | Policy: rate limit, malformed run, no `Join` in time, no pong |
| 1009 | Frame too big |
| 1011 | A server message could not be serialised |
| 1013 | Dropped as too slow: reconnect |
| 4000 | Replaced by a newer socket of the same seat: do not reconnect on your own |
| 4001 | The seat was taken away (its player left or the host removed them): its token opens nothing, do not reconnect |
| 4002 | The host closed the game before it started: links and code open nothing, do not reconnect |

## Persistence

- `PgEventStore` implements `EventStore` over `game_events`, primary key `(game_id, seq)`. An append is one transaction under a per-game advisory lock that checks the log ends at `from_seq`, so a gap, a repeat or a lost race returns `OutOfOrder` and a failure midway leaves no rows. Reads check for gaps and undecodable events (`StoreError::Corrupt`). `game_events` has no foreign key to `games`, so a log can be stored first.
- Migrations (`crates/mtg-server/migrations`) are tracked in `_mtg_server_migrations`, not `_sqlx_migrations`, which `mtg-db` owns, so both crates migrate one database in any order, repeatedly and concurrently. The table name is an on-disk contract; `mtg_server::migrate(&pool)` runs them.
- `games` holds each game's recipe, result, status (`lobby`, `running`, `finished`, `expired` when the janitor dropped it or the host closed the lobby, `failed` when boot could not load it), `failure` (for the operator), `failure_reason` (for the players), visibility and the digest of its join code. `seats` holds each seat's name, state (`issued`, `open`, `claimed`), token digest (null while open), account, and whether that account removed a failed game from its list (`hidden`).
- `Registry::create` writes the game and seats in one transaction before the actor exists, so a failed write creates nothing (503 `unavailable`). The actor's `Recorder` notes each seat's first join, the start and the end; a failed write is logged and never stops a game, because the log is the truth and boot repairs a status that lags behind it.
- `GameRecipe` is the only way the server builds a `GameSetup`, for a new game and a resumed one, because a `GameSetup` holds an `Arc<dyn FormatRules>` and cannot be stored. Its JSON is an on-disk contract: unknown fields and variants are refused, and a field added later is left out of the JSON while it holds its default, so older recipes read as they did. It is written when the game is made and rewritten once, when the game starts with decks its seats chose.
- A seat's `DeckRef::Oracle` names the library, the commanders and the companion by oracle id, and the printing each deck line chose. The printing labels the card (`ObjectView.identity.printing_id`) and changes no rule: the fingerprint and the state hash are those of the deck without printings (`CardIdentity` hashes its oracle id alone). A Commander seat that has not chosen a deck holds a stand-in (`DeckRef::Demo {id: "commander-stand-in"}`, a legendary creature and 99 Forests, or `commander-stand-in-<n>` for another deck size); it cannot be ready with it, and the table passes its own deck check before anybody has chosen.

### Resume

- `Server::open` loads every `lobby` and `running` game oldest first, rebuilds the setup from the recipe, checks the seat rows against it and calls `resume_game` with the stored digests, so old tokens open the same seats. A game whose log shows it ended is only corrected to `finished`.
- A recipe, seat rows or log that do not load (a replay panic included), a changed deck, a deck or card the server lost and a started game with a seat nobody holds mark the game `failed`, and boot goes on; only an unreachable database stops it. A `failed` game is not retried (fix the row and set it to `running` by hand) and is not loaded, so its tokens, lookup and sockets answer 404.
- A failure has two texts. `failure` is the operator's detail (error, seat, fingerprints), also logged. `failure_reason` is one sentence for the players from `Cause` (`registry/cause.rs`), such as "The deck of Friend has changed since this game was made, so it cannot continue.": what happened to the game, with no id, error, fingerprint or other internal. A game marked `failed` before reasons were kept has none, and My games says "This game could not be restored, so it cannot continue." for it.
- A lobby returns with its visibility, join code and claims and nobody ready, and keeps its age: past `Retention::lobby_after` (by the database clock) it becomes `expired`. A started game with an open seat does not load. A running game gets a fresh 24 h without a connection. `MTG_MAX_GAMES` limits creation only.
- Choices made in a lobby are not stored until the start: a restarted lobby reads its recipe, so a seat comes back on its built-in deck, and a seat whose recipe names a stored deck is without one until it chooses again.

### Deck check

- A new game's recipe stores a `DeckFingerprint` per seat: the SHA-256 of a canonical, versioned text of the ordered cards the engine is given (`v1:<64 hex digits>`), followed by the seat's commanders and companion when it has any. `Engine::resume` applies stored events as facts, so without the fingerprint a log would replay under other cards without failing.
- `GameRecipe::build` recomputes it and fails with `RecipeError::DeckChanged` for the first seat whose cards differ in any field, order or size; resume marks the game `failed` before replaying anything. A recipe without fingerprints resumes unchecked, with a warning at every boot.
- It covers the definitions the engine is given, so an edited card record, a changed rules file, a compiled row written again or removed (`card_rules`) or an engine that carries more of a card fails the game at the next boot; a game that runs keeps its definitions, whatever is stored meanwhile. A changed seed or format rule is not detected. A new `CardDefinition` field changes every fingerprint unless it is left out of the JSON while it holds its default (the pinned values in the tests fail otherwise).
- A deck of oracle ids is assembled by `CardSource` ([cards-dsl.md](cards-dsl.md)); an id with no row fails with `CatalogError::NotFound`.

### House rules

- `POST /api/games` takes `house_rules` (`HouseRules`, [engine.md](engine.md), House rules): every rule is optional and an absent rule keeps the format's value. A value out of range, or a handicap for a seat beyond the request's `seats`, is checked before anything is made and is 400 `invalid_request` with the rule's name in `field` (`deck.deck_size`, `handicaps[1].starting_life`); an unknown rule or a value of the wrong type is 400 without one.
- The rules are part of `GameRecipe` (`games.recipe`, `jsonb`, so no migration), left out of the JSON while none is set. A resume and a replay build the setup from the recipe and play under the rules the game was made with; a stored recipe whose rules are out of range fails with `RecipeError::Setup`.
- A game checks its decks with the rules when it starts (`GameSetup::validate`); the server judges a seat's deck with the same rules when it is chosen and for the lobby's deck check ([Decks](#decks)). The lobby row and the table view show the rules to every seat.

## Accounts

- `username_key` is the lower case and unique, so names are unique ignoring case. A session is the SHA-256 of its cookie token. Without `DATABASE_URL` every account endpoint answers 503 `accounts_unavailable` and games are guest-only. A database failure is 503 `unavailable`, and a login it stops costs no throttle budget.
- A username is 3 to 32 ASCII letters, digits, `_` or `-` (no Unicode, so no look-alikes); a password is 10 to 128 characters, compared byte for byte and never normalised. Passwords are Argon2id, stored as the PHC string so the cost travels with the hash; the default is the OWASP minimum (19 MiB, 2 passes, 1 lane). Hashing runs on `spawn_blocking` behind a semaphore (`AuthConfig::hash_jobs`), so a burst cannot exhaust memory.
- Login does not reveal whether a username exists: an unknown name, a wrong password and a name or password that breaks the rules get one byte-identical 401, and an unknown name costs one Argon2 check against a stand-in hash. Registration does say "taken"; that cannot be avoided. `register` answers 403 `registration_closed` before the body is read when `MTG_REGISTRATION=closed`.
- A body that does not parse on a route that carries a password is 400 `invalid_request` with one fixed message that quotes nothing, since a parse error can repeat what was sent; other routes name the missing or unknown field. Error messages state the rule, never the input. Passwords, tokens, digests and hashes never reach logs or `Debug` output; failed attempts are logged without the name tried.
- The cookie `mtg_session` holds 256 random bits as hex and nothing else: `HttpOnly; SameSite=Lax; Path=/; Max-Age=2592000` (30 days), no `Domain`, plus `Secure` when `MTG_COOKIE_SECURE=1`. Expiry is absolute and judged by the database clock; an upkeep task purges expired rows hourly. A sign-in that presents a session ends it, so a browser holds one.
- Guessing is throttled in memory per process (`throttle.rs`) in 15-minute fixed windows: failed logins per client address (30) and per username (10, whether or not the account exists), registrations per address (10); join code misses per address (5) and requests for the lobby list per address (30) have a one-minute window each. A login counts when it starts, so parallel guesses cannot slip under the limit, and is handed back on success or a server failure. Over the limit the answer is 429 with `Retry-After`, even for the right password. IPv6 counts by /64; past 50 000 counters, untracked keys go unlimited until a sweep frees room.
- The client address is the socket's peer. Behind a reverse proxy, `MTG_TRUSTED_PROXIES=n` takes the `n`-th entry from the right of `X-Forwarded-For`, which the nearest trusted proxy wrote, so forged entries to its left are ignored; with 0 the header is ignored, because anybody can send it.
- `GET /api/auth/options` is the one public hint about the instance: whether registering is open.

### Admin

- `users.is_admin` marks the one account that makes the others. `MTG_ADMIN_USERNAME` names it (a valid username or the server refuses to start, compared ignoring case). At start, after the migrations, `Server::open` runs `UPDATE users SET is_admin = (username_key = lower(name))` over every row: at most one admin exists, a changed or removed setting demotes the old admin, and without the setting nobody is admin. A name that belongs to no account promotes nobody and logs a warning; there is no bootstrap path, so a fresh install registers the owner first, then sets the variable and closes registration ([deploy.md](deploy.md)).
- Every admin route reads `is_admin` from the database for the session's account on each request, never from the cookie or the client, so a demotion applies at once. The checks run in one order, all before the body is read: 503 `accounts_unavailable`, 401 `unauthenticated` (a cookie the server does not honour is cleared), 403 `forbidden` for a signed-in account that is not the admin.
- `POST /api/admin/users` follows the rules and errors of `register`, works whether registration is open or closed, starts no session, and shares the Argon2 semaphore. It hashes behind a budget of its own per admin account (`AttemptLimits::admin_creates_per_account`; a try the rules refuse costs nothing, a taken name counts) that never touches the registrations counted per address.
- `POST /api/admin/users/{id}/password` and `DELETE /api/admin/users/{id}` act on a friend's account after the checks above and, before any body is read, 404 `unknown_account` (the id is not a UUID or names no account) and 409 `admin_account` (the admin's own account: its password changes only in Account settings, and nothing makes another admin). A reset sets a fresh Argon2id hash and deletes every session of the account in one transaction (`Accounts::reset_password`); the removal is `Accounts::delete_user` then `Registry::forget_user`. Both draw on the admin's creation budget, and the log names the admin and the account by id.
- `Accounts::delete_user` and `reset_password` lock the account's row first (`SELECT ... FOR UPDATE`) and stop with `Outcome::Admin` or `Outcome::Gone`, so a promotion or a second removal cannot slip in between the route's check and the change.
- The two settings routes (change password, delete account) act on the session's account, checked before the body is read, and are confirmed with its current password, checked and counted as a login is: the same counters, the same Argon2 cost, 429 even for the right password once the budget is gone, and a right password gives its try back. A password that breaks the rules is refused as a wrong one, unhashed and uncounted. Changing the password updates the hash and deletes the account's other sessions in one transaction, so a leaked cookie dies with the password.
- The admin's account cannot be deleted: `DELETE /api/auth/account` answers 409 `admin_account` for it before the body is read and counts no password try. A mistyped `MTG_ADMIN_USERNAME` leaves nobody admin; [deploy.md](deploy.md) says how to recover.
- Deleting an account is one transaction in `Accounts::delete_user`: the owner's lock, `DeckRepo::delete_all_of` (decks and their lines; none when the deck tables are not migrated), `FixMarkRepo::delete_all_of`, `ReadRepo::delete_all_of`, then the `users` row, which takes the sessions with it (`ON DELETE CASCADE`) and unbinds its seats (`ON DELETE SET NULL`). A test scans every uuid, text and json column of the schema for the account id and finds none afterwards. Game records keep the seat names they were played under. Tables that reference the account without a foreign key (`decks.owner`, `card_fix_marks.user_id`) must be deleted here.
- After the commit `Registry::forget_user` takes the account out of the live games as a leave: a seat a join took in a lobby is released, the lobby the account hosts is closed, and any other seat it held (a game that runs, or a seat made with the game's link) stays with its token and no account while its connection is closed, so the game waits for it on its clock like for any player who left. A seat the database refuses to change is logged and counted in `Departure::failed`. The username is free to register again and the new account holds nothing of the old one.

### Seats and accounts

- `seats.user_id` is unique per game, so an account holds one seat of a game. A signed-in `POST /api/games` binds seat 0 to the creator, and the first signed-in join through an unbound seat's link binds that seat before the upgrade; both need a recorded game, and guests bind nothing. One `UPDATE .. WHERE user_id IS NULL AND NOT EXISTS (the user's other seat)` decides, so racing accounts get one winner and a bound seat never changes hands (`Registry::bind_seat`). A failed binding is logged and never stops the join.
- Binding adds a way in and takes none away: old links keep working, and another signed-in account that uses a bound seat's token plays like a guest and is not bound.
- `GET /ws/{game}` answers, after the origin check, 404 for an address that is not a game id, 503 `accounts_unavailable`, 401 `unauthenticated` (a bad cookie is cleared), then one 404 for an unknown game and for a game the user holds no seat in, so a stranger learns nothing about which games exist.
- `GET /api/me/games` lists the user's `lobby`, `running`, `finished` and `failed` games, newest first, at most 100. It reads the database, so a finished game stays listed after the registry dropped it. A failed game carries its `failure_reason` for the accounts that hold a seat in it and nobody else; the lookup, the sockets and the game browser answer 404 for a failed game as for one that never existed.
- `DELETE /api/me/games/{id}` takes a failed game off the signed-in user's list (204) by marking the user's own seat `hidden`: the other players keep the game and the record stays with every seat bound, so a repaired game (`running` again) shows for all of them. A game that is not in the list, did not fail or was removed already is 404.

## Open games

A game has a visibility and each seat a state, so a visitor can claim an open seat by the game's id or with its join code ([ui-design.md](ui-design.md), Game browser and lobby).

- `Visibility` is `public` or `invite` (`invite` by default, for old rows too). A public game in its lobby is listed; an invite game is reached only by its seat links and its join code. `Registry::set_visibility(game, by, visibility)` is for the host (seat 0) and works before the start.
- A seat is `Issued` (its token was made with the game: the seat link), `Open` (no token, no account, an empty name) or `Claimed` (a join took it and was given a token). A `CHECK` ties an open seat to a null `token_digest` and no account.
- `Registry::claim` gives the first open seat under a trimmed name of 1 to 32 characters, makes its token and returns it, the one time the token exists in clear. An account that holds a seat of the game is handed it again with `token: None` and opens it through its session; guests may take several seats. `Entrance::Listing` (a game id) reaches public games only and answers `NotFound` for others, as for an unknown id; `Entrance::Code` reaches any game. `ClaimError::Started` is judged before `Full`. A claim sets name, token and account; the seat plays the deck the visitor brings, else the deck it was made with.
- `Registry::release(game, seat, by)` opens a claimed seat again: the holder leaves, or the host removes a player. The token stops working, the account is free, the connection closes, `Ready` and the stops are reset and the table is told. Only seats a join took can be given back (409 `not_claimed` for the host's seat, an open seat and a seat made with the game); a seat number over 11, or written with a sign or a leading zero, is a 404.
- `Registry::close(game, by)` ends a game that is still in its lobby, for the host alone. In order: the actor promises that no `Ready` starts the game from then on (`close_lobby`; `TableError::Started` when it already runs, so a close and the last `Ready` have one winner); the record becomes `expired`, so a closed game is not loaded at boot, not listed under My games and frees its code (a failed write takes the promise back with `reopen_lobby` and changes nothing); the entry leaves the registry, so the listing, the lookup, the code and every token stop reaching the game at once. The `Removal` channel says `ClosedByHost` before the entry is dropped, which is how a socket picks 4002 over the 1001 of a plain drop. The 204 of `DELETE /api/games/{id}` comes after that.
- Claims, releases, visibility changes, closes and `bind_seat` of one game run one at a time (`Entry::turn`). A claim writes the row first (guarded by `state = 'open'` and the lobby status, so racing claims get one winner), then names the seat in the actor (refused once the game runs), then the registry's slot. A release empties the seat in the actor first: a lobby with an open seat cannot start, so nothing begins under the change. A failed write leaves table, row and slot as they were.
- The join code is eight symbols of `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (capitals and digits without `I`, `O`, `0` and `1`; 40 bits) from the OS CSPRNG, returned in clear only in `Created::code`. The registry and `games.code_digest` keep its SHA-256 (unique among `lobby` and `running` games). `Registry::find_by_code` ignores case, spaces and hyphens, compares every game's digest without stopping at a match and answers the game id or `None`; text that cannot be a code is the same `None`. Misses are counted per client network; a hit hands its count back, and over the limit the answer is `Err(Blocked)`, even for a right code.
- `Registry::lobbies()` returns the public games whose actor has not started, newest first, at most `MAX_LISTED_LOBBIES` (50), as `ListedGame`. It holds no token, code, digest or link, and a full lobby stays in it.

### Game browser endpoints

`lobbies.rs` puts the registry's calls on HTTP.

- The routes that act on a seat (`PUT .../seats/{n}/deck`, `leave`, `release`, `PATCH`, `DELETE`) need a credential; listing and joining are open to anyone, and a session binds the seat it joins. A seat is named by `Authorization: Bearer <token>`, which needs no database, or else by the session cookie. A token wins over the session; another `Authorization` scheme (a proxy's) is ignored. With neither, a server without a database answers 503 `accounts_unavailable` and one with accounts 401 `unauthenticated`. A token or session that opens no seat of the game, an unknown game and a malformed id are one 404.
- `release`, `PATCH` and `DELETE` are for the host (seat 0) alone, whatever state the game is in (403 `forbidden`); a player gives their seat back with `leave`. Once the game starts, `leave`, `release`, `PATCH`, `DELETE` and a join that may reach the game answer 409 `started`. A second `DELETE` finds no game (404). These calls are not throttled.
- A join checks the body and the name before it looks at the game or the code, so the answer to a missing name says nothing about either. A signed-in visitor is named after the account unless a `name` is sent; a guest needs 1 to 32 characters without control or invisible marks (400 `invalid_name`).
- An unknown id, a malformed id, an invite game reached by its id (started or not) and a wrong or malformed code are one byte-identical 404, so a visitor cannot find an invite game by trying ids. A code reaches any game, so a right code for a full or started game says 409 `full` or `started`. The game's id comes back only in the answer of a join that succeeds: no refusal and no 429 carries one, so a right code is the one way to learn the id of an invite game.
- `POST /api/join` counts wrong codes per address (5 a minute); the sixth try is 429, even for the right code. A bad body or name is refused before the code is counted. `GET /api/lobbies` counts every request, a 304 too (30 a minute per address, `AttemptLimits::lobby_requests_per_ip`); the precon endpoints count apart (`precon_requests_per_ip`, 60). The address is the one the throttle uses everywhere.
- The lobby list's `ETag` is a strong tag: the SHA-256 of the rows (each field length-prefixed) cut to 128 bits, so it holds nothing secret and does not change as games age. `If-None-Match` is read as a list, with `W/` prefixes ignored and `*` matching any listing. A client that gets a 304 keeps its rows and counts their age on from the time it received them. 503 `lobbies_unavailable` is a registry that cannot list, which is a server shutting down.
- A seat that is taken away closes its connection with 4001; the actor tells the socket apart from a replaced or dropped one by the seat being open (`GameStatus::open`). A game that leaves the registry closes every socket of every seat at once: 4002 when its host closed it, 1001 otherwise.

### Choosing a deck

The holder of a seat chooses the deck it plays while the game is in its lobby: the host when the game is made, a joiner when joining or after (`seat_deck.rs`, `deck_choice.rs`, `lobbies.rs`).

- A choice is a snapshot (`ChosenDeck`) taken when it is made: the cards the engine is given, the commanders, the companion, the recipe's name for them (`DeckRef::Demo` or `DeckRef::Oracle`) with their `DeckFingerprint`, and the three facts the table is told (`SeatDeck`: name, format, `manual_cards`). Editing or deleting the stored deck later changes nothing.
- The companion is the one card of the stored deck's companion zone whose rules carry a companion ability; a card without one is no companion for the game, and a second companion card is refused by the deck check. It is a card outside the game, so the table is told nothing of it (not in the roster, the lookup or the listing); `manual_cards` counts it like a card of the deck. Its name reaches the other seats with the opening's reveal. A seat given back, or that chooses another deck, takes its companion with it.
- A deck id is a demo deck's id, `precon:<code>` (public, so no account) or the UUID of a stored deck. A stored deck is found under the signed-in account of the request (the session cookie, which a seat token does not replace), so another account's deck, a deck that does not exist and a caller without a session are one 404 `unknown_deck` (400 at creation). Only the creator's seat may start with a stored deck.
- The check is `deck_report` in the deck's own format, plus the rules of the game's format (`format_issues`): a Normal game has no command zone and wants 60 cards with at most four copies; a Commander game takes the engine's `Commander.validate_seat` on the deck's command zone and main deck under the table's house rules, so a `commander` or `freeform` deck is played as it stands and a `modern` deck with a command zone is still refused by its own report (`no_commander_zone`). A demo deck has no commander, so a Commander game refuses it with `commander_count`. A companion is judged after the deck by the format's `validate_companion` (`companion_condition`, `color_identity`).
- A table that relaxed a deck rule lifts the issues of the deck's own check that the rule replaces (`IssueCode::lifted_by`: `copies`, `color_identity`, `deck_size`, `commander_pair`), so a deck the report refuses only for those is judged by `validate_seat` under the table's rules instead. Every other issue (an unknown card, a ban, a commander that cannot lead, a card the game cannot play) refuses the deck at once. A chosen deck keeps the lifted-or-not issues of its own check (`ChosenDeck::with_own_issues`) and the table decides (`issues_in`). At creation the rules are judged with the deck; a join or `PUT` judges them in the registry after the game is found, so a refusal tells only a visitor who may see the game its format.
- Any issue, or a `blocked` state, refuses the deck with 422 `deck_blocked` and the issue list; `manual_play` and `verified` are allowed. The issues name cards and go only to the account whose deck it is. The main deck and the commanders are played; `manual_cards` counts the copies in them that are not verified, never the sideboard or the companion.
- `PUT /api/games/{id}/seats/{n}/deck` is for the seat's holder (another seat's holder is 403, a stranger the 404 of `leave`). The actor decides in its order of commands: a seat that pressed Ready answers 409 `seat_ready` and keeps its deck until it sends `NotReady`, a game that runs 409 `started`. The roster is sent to the table after each change.
- A seat made without a deck has none until its holder chooses, and its `Ready` is refused. A seat given back returns to the deck the game was made with, or to none, and an open seat is listed without a deck, so the next player never sees the last one's.
- The recipe holds the decks the game was made with. When the game starts with other decks, the actor stores the recipe with them and `games.manual_play` (`GameRecords::set_start`, one statement, only while the record is a `lobby`) before it stores the first event; a start that cannot store it is refused with `Internal` and tried again by the next `Ready`. A started or resumed game rebuilds from the recipe alone, with each fingerprint checked ([Deck check](#deck-check)).
- `GameStatus::manual_play` says whether the table plays with manual cards: some seat that somebody holds plays a deck whose `manual_cards` is above zero. In the lobby it follows the roster (a choice, a claim with a deck, a release); the start decides it, and `games.manual_play` (`boolean NOT NULL DEFAULT false`) keeps the value the game started with, so a resumed game needs no roster. A lobby never reads the column.

## Cards and decks

`Server::open_with(config, pool, cards)` takes the `CardSource` (database, rules, `Caps`) that the games, the card endpoints and the deck check share; `Server::open` makes one. The rules are the embedded files and the rows of `card_rules` that `mtg-cli compile` writes ([data-sources.md](data-sources.md)): the library is built again whenever a row was added, written again or removed (one cheap query per request tells), a file wins over a row for the same card, and a row this build cannot read is left out and logged. Every card of a request is judged under one snapshot. A server without a database answers 503 `cards_unavailable` and 503 `decks_unavailable`.

### Cards

Public and read-only (`card_api.rs`). `GET /api/cards` searches the deck cards (tokens and emblems are never listed), `GET /api/cards/{oracle_id}` returns one card with its legality, printings, rulings and `reasons`, the clauses the game cannot run. A malformed and an unknown id are one 404; capitals in the id make no difference.

- With `q` the order is by relevance (name equal, name starting with, name containing, rules text only), then by name; without it by name. Ties break by oracle id, so every order is total and pages never overlap or skip. `page` counts from 1 up to 10 000, `per_page` defaults to 40 and is lowered to 100.
- Parameters: `q` (name contains it, accents and case ignored, or rules text in web-search syntax), `colors` with `colors_match` (`includes`, `exactly`, `within`, `overlaps`; letters of WUBRG or `C`), `identity` (the card's identity lies within the letters), `type` (words that must each appear in the type line), `cmc` (`3`, `2-4`, `5+`), `format` (a Scryfall format key; legal or restricted), `page`, `per_page`.
- Blank values are no filter; an unknown parameter or a malformed value is 400 `invalid_request` whose message names it.
- A hit carries the art of the card's default printing (the newest paper one) and `support`, the state `Library::support` gives with the server's rules and `Caps`.

### Pictures

`images.rs` and `images/` serve the picture of a card identity from a disk cache that fills from the Scryfall CDN as pictures are asked for. Public and read-only like the card endpoints: no account, 503 `cards_unavailable` without a database. A picture is shown as Scryfall serves it: never cropped, re-encoded, resized or marked (Scryfall's image terms); `art_crop` is Scryfall's own crop.

- `GET /api/images/oracle/{oracle_id}/{face}/{size}` is the newest paper printing that has a picture (digital ones only when no paper one has); `/printing/{printing_id}/{face}/{size}` is one printing, as the deck chose it; `/token/{face}/{size}?name=&type=&colors=&power=&toughness=` is a token by name, fitted to the other facts. The stored token that answers is, in order: one with every fact given; one with the same type line and colors; any token of that name, where the one that shares the most facts (power and toughness first) wins. A tie goes to the smallest oracle id, so a URL always gives the same picture and `ETag`.
- `face` counts from 0. A printing with a picture per face answers face `n`'s own; a printing with one picture answers it for each of its faces. Any other face is a missing picture. `size` is `small`, `normal`, `large`, `art_crop` or `png`; any other size or a face that is no number is 400 `invalid_request`.
- A picture answers 200 with `Cache-Control: public, max-age=604800` and a strong `ETag`, a digest of the cache key, so it changes when the stored link does. `If-None-Match` answers 304 without reading the cache or asking the CDN. Every other answer keeps `no-store`.
- An unknown identity, a malformed id, a face or size the printing has no picture for, a CDN that has no such picture and a token name no stored token has are one typed 404, `no_image`: the web draws the card's text face. A CDN that fails or answers something else than a picture is 502 `image_unavailable`.
- The link comes from the database, never from the client, and is checked all the same: `https`, a host that is `scryfall.io` or under it, no port or credentials, a path of plain segments ending in `.jpg` or `.png`. A stored link that fails is a missing picture and nothing is requested.
- **Cache.** One file per picture in `MTG_IMAGE_CACHE`, named by the link's path and query (the time the picture changed), so a changed picture is another file. Files are written to a temporary name and renamed, so a reader or a crash never sees half a picture. The directory is read when first used: older files count as less recently used, leftovers of an interrupted write are deleted. After each write the least recently used files go until the total is at most `MTG_IMAGE_CACHE_MIB`; a read counts as a use.
- **Upstream.** One fetch per link at a time: requests that arrive while the CDN is asked wait for that answer, a failure included. Requests send `User-Agent: mtg-cli/<version>`, follow no redirect, give up after 30 s, and start at least 100 ms after the previous one ended, for the whole server. Timeouts, 408, 425, 429 and 5xx are tried three times with waits of 2 s and 4 s, or the `Retry-After` (at most 20 s); 404 and 410 are a missing picture, any other status a failure. An answer is kept only when it starts like a JPEG or PNG and is at most 8 MiB.
- **Warm-up.** When a game starts, a task of its own fetches the `normal` picture of every face of the cards the seats play (commanders and companions included), in the printing the deck line chose and else in the card's newest paper printing, once per card and printing, two at a time through the same cache and spacing. The game never waits for it and a failure is only logged.

### Decks

`decks.rs`, `deck_cards.rs` and `deck_import.rs`. Every route needs a signed-in account: 503 `decks_unavailable` without a database, then 401 `unauthenticated`. A deck of another account is a 404, like an unknown id. Bodies are `application/json` of at most 64 KiB (640 KiB for an import). The tables `decks` and `deck_cards` belong to `mtg-db` (`DeckRepo`): `owner` is the account id with no foreign key, since `users` is the server's own table, so deleting an account has to delete its decks; a line's card is a foreign key and its printing is set to null if the printing goes.

- A save is refused with 400 `invalid_deck` for a name outside 1 to 100 characters or with control characters, notes over 10 000 characters, a format outside `SUPPORTED_FORMATS`, more than 250 lines or 250 cards, a count outside 1 to 999, an id that is no id, or a printing that is not the card's; with 400 `unknown_cards` for oracle ids that are no deck cards of the database. An account stores at most 100 decks (409 `deck_limit`); the count and the insert run under an advisory lock of the owner, so racing saves cannot pass it.
- `PUT /api/decks/{id}` replaces name, format, notes and every line in one transaction and runs the check again.
- Saving runs the check (`mtg_cards::deck::deck_report` with the server's rules and `Caps`) and stores `{deck_hash, coverage_hash, checked_at, summary}` in `decks.last_check`. A deck's state is never stored: every read runs the check of the moment and shows its state ([deck-check.md](deck-check.md)), so a release that changes rules or the engine shows its result on the next read without a save, and `verified` is true exactly when that state is. Reading writes nothing.
- `POST /api/decks/check` takes `{deck}` (a stored deck of the account, or `precon:<code>`, which needs no account) or `{format, cards}` (an unsaved list, under the rules of a save), and optionally the table that judges it: `game` (an id) or `table` (`{format, house_rules?}`), not both. It saves nothing. With a table the report's legality is replaced by the table's verdict (`judge_at_table`): the issues the table's deck rules lift are gone, and a deck nothing else is held against is judged by the engine's `validate_seat` in the table's format under its house rules, the same verdict a seat choosing the deck there gets. A game is found by its id alone; an unknown or malformed id is 404 `not_found`, naming both `game` and `table` or a format other than `normal` and `commander` is 400 `invalid_request`, and a rule out of range is 400 with the rule in `field`.
- Import (`POST /api/decks/import`, nothing saved) reads a pasted list in any format `mtg-import` reads (`source` detected when absent; `format: commander` makes Moxfield's first line the commander, and the second line too when it can pair with it), at most 100 000 characters and 1 000 lines. The answer holds the resolved `cards`, the `unresolved` lines with suggestions that are never applied, the `problems` and the `ignored` parts. Lines are tied through the stored card index ([data-sources.md](data-sources.md), Name resolution). `CardSource` keeps the index and builds it again when `CardRepo::index_version` changes, so an ingest shows in the next import.
- Export (`GET /api/decks/{id}/export?format=text|arena|mtgo`) writes split cards as the format does and other multi-faced cards by their front face; printings are written where the format has them. A deck the format cannot hold, MTGO text with a commander and nothing else, answers 422 `export_failed`.

### Precons

`precon_api.rs` and `precons.rs`. Public and read-only like the card endpoints: no account, 503 `cards_unavailable` without a database. Every request counts per address (`AttemptLimits::precon_requests_per_ip`), unknown codes too; over it the answer is 429 `rate_limited` with `Retry-After`. `GET /api/precons` lists every precon, newest release first; `GET /api/precons/{code}` returns one with its issues and cards by board. The code is read in lower case; an unknown and a malformed code are one 404 `not_found`.

- A code is the set code and the slug of the name (`c18-adaptive-enchantment`: lower-case ASCII words joined by hyphens, cut at 80 characters). A set holds several precons, so the set alone names none; a code another deck already has ends in the deck's id.
- One function judges a precon (`Judge::judge`), so the list, the view and a seat that takes the deck agree. A deck with a commander is checked as `commander`, any other as `freeform` (a product, not a tournament format), with `deck_report`; an entry that matches no stored card is an `unknown_card` issue and blocks the deck. `state` is the verdict of the moment (`verified`, `manual_play` or `blocked`, never `unchecked`: nothing is stored). `playable` is true when the report's legality is clean, no card is `unplayable` and the engine accepts the deck in the format it is for: a Commander precon in a Commander game, any other in a Normal game (60 cards, at most four copies). A card the game plays by hand does not keep a deck from being playable.
- The judgments of all precons are kept in an index (`CardSource::precon_index`), built again when `PreconRepo::version`, `CardRepo::index_version` or `CardRulesRepo::version` changes. The first request after a change waits for the build; one precon is read and judged again per request.
- A seat plays a precon by `deck: "precon:<code>"` in a create, a join or `PUT .../deck`, with the same snapshot, fingerprint and recipe as a stored deck: the library is the main board in deck order, the commanders are the commander board. The refusals are those of any deck: 422 `deck_blocked` for a deck that is not `playable` or that the game's format does not take (a Commander precon in a Normal game: `no_commander_zone`; a Normal precon in a Commander game: `commander_count`), 404 `unknown_deck` (400 at creation) for a code nobody has. One-click play is a create with the precon as seat 0's `deck`.
- `POST /api/decks/check` with `deck: "precon:<code>"` needs no session and answers the precon's `DeckReport`; with a `game` or a `table` the verdict equals what a seat that chooses the precon there is told (`judge_cards_at_table`). A `format` or `cards` beside the precon is 400 `invalid_request`. The request counts against the address's precon budget, an account's too. Any other body needs a session and without one is 401, a malformed body included.

### Favourite precons

`favourites.rs`. Every route needs an account (401 `unauthenticated`; 503 `cards_unavailable` without a database). A favourite is a pointer to the precon, never a copy, so it follows the precon's cards and check. `PUT` and `DELETE /api/favourites/precons/{code}` are idempotent (204); an unknown and a malformed code are one 404 `not_found`. Stars and unstars count per account (`AttemptLimits::favourite_writes_per_user`; 429 `rate_limited`). `PreconListItem.pictures` and `DeckListItem.pictures` name the cards that stand for a deck in a list: its commanders, else its first card.

### Account preferences

`prefs.rs` and `mtg-db`'s `PrefsRepo` (`user_prefs`, one row per account, deleted with the account). The default stops and "End my turn by hand" follow the account to every browser. `PUT /api/me/prefs` stores them sorted, each side and step once, all lasting and at steps that grant priority, at most `MAX_DEFAULT_STOPS`; otherwise 400 `invalid_request`. Needs an account (401 `unauthenticated`; 503 `cards_unavailable` without a database). Bodies are at most 8 KiB.

### Fix marks

`fix_marks.rs` and `mtg-db`'s `FixMarkRepo` (`card_fix_marks`). A player marks a card the game does not run whole, or any card that misbehaves, as important to fix; the owner reads the marks ranked. Every route needs a signed-in account: 503 `cards_unavailable` without a database, then 401 `unauthenticated`. Bodies are at most 4 KiB.

- One row per account and card (`PRIMARY KEY (user_id, oracle_id)`), so marking twice counts once; a second `PUT` replaces the note and keeps the time. `user_id` has no foreign key, like `decks.owner`: `Accounts::delete_user` calls `FixMarkRepo::delete_all_of` in its transaction. A card deleted from `cards` takes its marks (`ON DELETE CASCADE`). A card the database lacks, or an id that is no uuid, is 404 `not_found`.
- A note is trimmed; an empty one is none. It holds at most 280 characters (`MAX_FIX_NOTE_CHARS`; the table checks the same limit) and no control character but a line break, else 400 `invalid_request`.
- No endpoint shows another account's mark. `FixMarkRepo::ranked(limit)` counts accounts per card, the most marked first, ties by the newest mark and then name; `mtg-cli fix-marks` joins the support state and prints it ([data-sources.md](data-sources.md)), and `check-rules --gaps --marks` weighs gaps by the marks of the cards they free.

### Reads

A draft is a stored reading of a card's Oracle text that runs when it is trusted ([cards-dsl.md](cards-dsl.md)). `mtg-db`'s `DraftRepo` (`card_drafts`) and `ReadRepo` (`card_reads`) hold drafts and verdicts; the server has no endpoint that writes a verdict directly, and `mtg-cli reads` prints them.

- `card_drafts (oracle_id, read_hash, rules jsonb, retired, ...)`, primary key `(oracle_id, read_hash)`, is written only by `mtg-cli compile` from the drafts the build embeds (`DraftRepo::insert` makes a draft its card's current one and retires the card's other); a card's current draft is its one row not `retired`, and `DraftRepo::get` reads pinned drafts, retired ones too. `source`, `oracle_matches` and `proof` come from `drafts/meta/`.
- `card_reads (id, user_id, oracle_id, read_hash, verdict, note, created_at)` is append-only (the database refuses an update; only `ReadRepo::delete_all_of` removes rows): an account's newest row on a hash is its verdict, `user_id` is null for the server's own verdict, which is always `wrong`, and a `wrong` always has a note (the fix-mark note rules).
- A trusted Forge draft (source `forge`, `oracle_matches`) reads as approved without a verdict until a `wrong` counts, so its card runs automatically for everyone as `forge`.
- `CardSource` loads the current drafts with their read state beside `card_rules` and builds the library again when `DraftRepo::version`, a digest of the current drafts and the verdicts, changes, in the same cheap query as `CardRulesRepo::version`. A verdict reaches the card endpoints, the deck check and the precon index at once, and a game when it starts.
- Fix marks close the loop: `PUT /api/fix-marks/{oracle_id}` on a card that plays on a draft (state `read` or `forge`, or a proved partial draft in state `partial`) also appends the account's `wrong` verdict on the card's current draft (the mark's note, else "marked to fix") in the same transaction, so the card is played by hand from the next game; a card in another state only gets the mark. An `AbilityLeftToTable` event ([engine.md](engine.md), Fail-soft resolution) appends the server's `wrong` verdict on that card's pinned hash with the error as its note; `mtg-cli fix-marks` lists those verdicts beside the marks.
- **Pinning.** When a game starts, its recipe stores `reads`, the `read_hash` of every card it plays on a draft (left out of the JSON while empty). Resume and replay build those cards from their `card_drafts` rows, whatever the verdicts are now, so a verdict never changes a game that runs or its resume. Every seat of a game plays one definition per card. A resume fails, like a lost card, when a pinned row is gone, when a card's printed text changed or when its compiled rules were replaced under a hand-written or compiled card the game plays, so the stored fingerprint no longer matches.
- **Conjured cards.** `CardSource::conjured_in` resolves every name that the cards of a game's decks conjure through the card index and assembles it like a deck card (a card without rules arrives as its printed side and is played by hand), with its draft reads pinned. `GameRecipe.conjured` keeps the fingerprint of each by name (left out while empty); a resume builds exactly those and fails the game with `ConjuredChanged` when one differs. A name the index does not resolve to one card is not conjurable and its conjure does nothing.

## Pace of play

At each priority decision the actor asks the seat, passes for it at once or passes for it after a short wait. Every pass takes the path of the seat's own answer (`Running::answer`), so it is checked, logged, saved and projected like a click.

### Windows

`windows::verdict` returns `Ask`, `Pass` or `Dwell` from the step, whose turn it is, the stack, the seat's stops, mode and yield, and `can_act`; auto-pass off is the `Held` mode. A seat that is passed for is never sent the decision, and a decision that is not a priority decision is asked unless the engine gives its one answer (below). The first matching rule wins:

| # | Condition | Verdict |
|---|---|---|
| 1 | Full Control (`NextWindow`, `Held`) | Ask at every window |
| 2 | A running yield (a stop of the seat ends it, except in the step it was asked at) | Pass at once |
| 3 | A stop of the seat for this side and step, or a by-hand window | Ask, whether it can act or not |
| 4 | A default window and the seat can act | Ask |
| 5 | A default window and the seat cannot act | `Dwell`; pass at once in its own main phase with an empty stack |
| 6 | Anything else | Pass at once, whatever the seat holds |

The default windows are both main phases on the seat's own turn, declare attackers and declare blockers on any turn, and any step with an object of another seat on the stack. `Own` stops are for the seat's turns, `Opponent` stops for any other seat's.

A question that leaves one legal answer and lists only options in sight of every seat (`mtg_engine::choose::sole_answer`: the targets a triggered ability must take, the only modes, number, option or replacement effect) is answered with it for a seat in `Off` mode, in the same run of passes; in Full Control it is asked. A discard, a search, a payment and every other question whose one answer could come from a hidden zone is always asked.

### Stops, Full Control and yields

- Stops and modes live in the actor per seat (`Stops`), never stored: a reconnect keeps them, a resumed game starts every seat in the default mode with no stop. Setting one takes no engine step, so nothing is saved and the pending decision keeps its id.
- A one-turn stop goes once the game has left its step: a step entered and left in one go counts, one never entered does not. `NextWindow` returns to `Off` when the seat passes, itself or at its clock or dwell.
- A by-hand window: once a spell or ability of the seat whose card has clauses left to the table that a resolution calls for (`CardDefinition.manual`; `ManualClause::owed_at_resolution`) resolves, the seat holds a stop at every window until it passes, so it can apply them; it is never told and reads only public facts. The objects it holds a seat for are those `ObjectView.manual_owed` flags (`CardDefinition::manual_owed`, one rule for the hold and the wire), which the client follows without reading clauses ([web.md](web.md), By hand).
- Turning Full Control on ends a running yield and `Yield` is refused while it is on; turning it off at a priority decision that the windows then pass for passes at once.
- `Yield` and `CancelYield` set and end a per-seat yield (`Yields`), never stored. Its end rules ([protocol.md](protocol.md), Yields) are all in `Active::ends_at` and read the table alone, never `can_act`, so a seat that can respond and one that cannot are passed for and stopped at the same moments. If a started yield ends at once the decision is issued again with a new id, so a client that dropped its prompt is never left without one.

### Passes and saves

- An answer, the passes after it and the save are one unit (`publish_with`): copies of the yields and stops, `Running::skip_idle` (the passes, appended to the step), one projection, one append, one batch per seat. The copies replace the seats' own only once saved, so a failed save restores the engine and keeps yields, stops and modes.
- A run of passes stops at the first decision the windows ask or that waits for a dwell, at any other decision, at the game's end and after `MAX_IDLE_PASSES` (500), where the decision is sent as it is and its seat's yield ends with a notice. `start_up` settles a resumed game before any client connects.

### Manual actions

- `ClientMessage::Manual {action}` is accepted at any time from a seat in the game (`running/manual.rs`), whoever the pending decision belongs to: the actor handles one message at a time, so an action always lands between two engine decisions. A seat that lost or a finished game gets `Error{BadMessage}`, a refused action `Error{IllegalAnswer}` with the engine's reason, and nothing changes.
- The step is `Engine::manual` published like a concession: one projection, one append, one batch for every seat, then the passes the windows make. While a replacement question holds a batch the action waits in `Running.deferred` and is applied in order after the next command or clock expiry that leaves the engine settled.
- A decision the change leaves equal keeps its id and clock and is not sent again; one whose options changed is sent again under a new id, so an answer to the old id is stale. A decision of the same seat and kind keeps the clock it had (`carried_clock`): a manual action never starts, resets or extends a response clock, and the acting seat learns nothing of the other seat's decision.

### Response clocks

- A decision gets its clock when issued (`Running::settle`, `Pace::clock_for`). The rule reads the decision kind and the seat alone, never the options, the hand, the mode, the stops or Full Control, so a clock shows nothing a client does not already hold: a `Priority` decision gets its clock whether the seat can act or not. The match names every kind, so a new kind cannot be added without choosing its clock and its answer.
- Four lengths, each `0` for none: response (`MTG_RESPONSE_SECS`) for what a seat answers at the table; blocks (`MTG_BLOCK_SECS`) for declaring blockers; think (`MTG_THINK_SECS`) for what takes thought; active (`MTG_ACTIVE_SECS`) for every decision of the active player's turn. A seat that is not the active player is hurried by the class (`Class::of`), the active seat by `active`, and the opening (keep or mulligan, bottoming), asked before any turn exists, by `think` for every seat.
- The countdown shows after `MTG_CLOCK_GRACE_SECS`: the clock runs from when the decision is issued, and `Decision.show_after_ms` tells a client how long to wait before it shows the countdown. It is absent when the countdown shows at once, also for a clock no longer than the grace. A reconnect is told what is left of the delay.
- **Timer bank** (`bank.rs`). A seat that finishes three turns of its own in a row without a clock reaching its deadline earns one extension, at most three (`BANK_TURNS`, `BANK_MAX`); a clock that reaches its deadline, on any turn, starts the run again. At the deadline of a clock that was sent, a seat holding an extension spends one instead of being answered for (`Running::extend`): the deadline moves by `MTG_EXTENSION_SECS` (`0` turns the bank off), the seat is sent the same decision again with the same id and the new `deadline_ms`, and every seat is sent `Bank { seat, bank }`. Only an empty bank lets `Running::fall_back` answer. The bank is public: `PlayerView.bank` carries it for every seat (the actor stamps it, because the engine does not know it). It lives in memory and is not stored.
- The clock ignores the mode, runs while the seat is away, stops with any answer and restarts when a game is resumed. A reconnect is told what is left and the deadline does not move.
- At the deadline the actor answers with `Running::fall_back` through `Running::answer`: checked, saved and sent like the seat's own, a late answer is the ordinary `StaleDecision`, and the table logs at info, once per answer, `clock ran out; the table answered for the seat` (or `clock ran out; an extension was spent`) with the game, the seat and the decision kind (never a card). The loop selects between the next command and the pending `due` time, commands first, because a command already waiting was sent before the clock ran out. A failed save restores the engine and retries a second later. A decision with no answer to give (a choice with no option, a damage with no blocker to take it, a payment only the player can make) stops its clock and waits.
- The fallback answer is the one that decides least and shows nothing, from the kind and its options alone, never the seat (`pace.rs` holds the table of every kind): keep at the opening, the first cards offered when bottoming or discarding, pass at priority, `Cancel` where a cast can be taken back at no cost (`PayMana` without `can_cancel` takes the engine's own payment), only the attackers and blockers a rule requires, lethal damage in the order offered, no target (`Cancel` for a spell, `Remove` for a triggered ability whose target cannot be chosen; a seat's own `Remove` is refused with `IllegalAnswer`), the first option, mode, effect or card, the lowest number, no optional cost, an even division, and "No" to a yes-or-no even when the payer cannot pay.

### Dwell

- A seat that cannot act at a default window, other than its own main phase with an empty stack, and holds no stop, Full Control or yield is neither asked nor passed for at once, because a pass at once shows that it holds nothing. The windows are declare attackers and declare blockers, any window with an object of another seat on the stack, and its own main phase with any object on the stack.
- The decision is held back (`Running::settle`): it is never sent, a join or `Resync` sends the snapshot alone and an answer for it is stale. At its `due` time `expire` passes through `fall_back` as a step, an append and a batch of its own, so every other seat sees the stream of a seat that could act and passed.
- The wait is uniform between 250 and 700 ms (`MTG_DWELL_MS`), drawn from a generator the operating system seeds, independent of the game seed and the state; every idle seat draws its own. It is wall clock only: the log, event order and state hash are those of a game without a dwell. With `Dwell::OFF` (also `Pace::MANUAL`) `Dwell` is a pass at once.
- A stop at the window, Full Control or auto-pass off ends the wait and sends the decision at once; a yield passes at once; a concession that removes the seat ends it. Chat, `Resync`, a stale answer, a stop elsewhere and other seats' commands leave it.
- It hides whether a seat could act in a combat window or while a spell waits on the stack, in the batches and arrival times every other seat sees. It does not hide a seat's own main phase with an empty stack (what is played there is in plain sight), how long a seat that can act takes, a pass at a response-clock deadline, or a choice of stops, Full Control or yield.

## Previews

The actor answers `Preview` itself (`preview.rs`) with one `Forecast`; `Engine::preview_forecast` judges the answer for the seat's pending decision. Everything else gives `forecast: null` and never an `Error`, because the stale-decision treatment of `Answer` would raise a notice and a resync in a client whose preview raced its real answer. A token bucket per seat (`PREVIEW_BURST` 20, then `PREVIEWS_PER_SECOND` 10) lives as long as the game, so a reconnect does not refill it; a preview over the limit gets a null forecast without touching the engine. Answers have no bucket, and a preview costs one state clone, so a flood cannot starve an answer.

Blank values count as unset; any other malformed value refuses to start (`ConfigError`). `ServerConfig` holds more values (queues, socket limits, retention, hash cost) that only tests set.

## Testing

- Actor tests drive games through `GameHandle` with bot and manual clients (`tests/it/common`) and compare the log, state hash and result with the same game on a bare engine (`mtg-testkit`); `roomy()` runs under `Pace::MANUAL`, `windowed()` under the default windows alone. `Windows` in `mtg-testkit` is the window rule written plainly and apart from the server, and `tests/it/windows.rs` compares the actor with it for 2 to 4 seats.
- Clocks, the dwell and the leak tests run on tokio's paused time. The leak tests (`pace_leak.rs`, `pay_leak.rs`) play two games that differ in one hidden fact and require every other seat to be sent the same messages in the same batches. The clocks and fallbacks of every kind, seat, setting and shape of options are tables in `pace.rs`; each kind has an actor case or a table row.
- Transport tests (`tests/it/net`) use a real listener on port 0, raw TCP for hostile HTTP and tokio-tungstenite for sockets; `FlakyStore` fails writes on demand.
- Each HTTP area has a test pair: a file over a fake registry and one over Postgres (`pg_*.rs`), including scans of answers for tokens, codes and card names that must not appear. Postgres tests need `docker compose up -d db` and use `#[sqlx::test(migrations = false)]` with `migrate`, because the default would use `_sqlx_migrations`. Pictures use a fake CDN (`tests/it/common/cdn.rs`); no test asks Scryfall. `pg_commander_real.rs` is ignored and needs a database loaded by `mtg-cli ingest` and `compile`, named by `MTG_REAL_DATABASE_URL`.
