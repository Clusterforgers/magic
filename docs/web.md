# Web client

The browser client: game creation, lobby, table, decision prompts and accounts, on the wire contract of [protocol.md](protocol.md) and the transport of [server.md](server.md). The design rules are in [ui-design.md](ui-design.md).

## Stack and layout

React, Vite, Tailwind, shadcn/ui on Base UI, TanStack Router and zustand. Commands are in `CLAUDE.md`.

- Pages live in `src/features`, one folder per area; `src/routes` only picks them. The Vite plugin rewrites `routeTree.gen.ts` on `pnpm dev` and `pnpm build`; commit it with the route change.
- `src/net` (REST, socket) and `src/play` (session, store) hold the client. `src/components` has the shell and the pieces pages share; `src/components/ui` is shadcn (`pnpm exec shadcn add <name>`) and is edited to the tokens. `src/protocol` has the ts-rs bindings and the transcripts Rust writes.
- Each page is a chunk of its own (`autoCodeSplitting`), fetched while the pointer rests on a link to it (`routerOptions.ts`, `defaultPreload: 'intent'`). React and the router sit in a `vendor` chunk whose name survives a release (`vite.config.ts`). The build preloads the Latin font from the page and writes a level-9 `.gz` beside each text file for nginx. `bundleBudget.test.ts` holds each chunk to a gzip budget: the entry 70 kB, `vendor` 105 kB, the table 250 kB, any other 52 kB.
- Long lists stay cheap: `DeckRow` is memoised on stable props, and a row off screen is not laid out (`content-visibility: auto`).
- The dev and preview servers proxy `/api` and `/ws` to `MTG_SERVER_URL` (default `http://127.0.0.1:8080`) and keep the browser's `Host`, which the server's Origin check compares with the page's `Origin`.

## Design system and shell

Roles, scales and rules are in [ui-design.md](ui-design.md) (Design system). `src/index.css` holds the tokens as CSS variables that `@theme inline` maps to Tailwind classes; the `dark` class on `<html>` swaps the colours.

- `PageShell width` is one of the page widths of [ui-design.md](ui-design.md) with the gutters and sets no `max-w` of its own (`pageWidths.ts`). Play, Precons, My games and Create are `wide`; the builder is `wider`; Decks, the lobby and game over `page`; sign-in and register `narrow`.
- `Button` `loading` shows a spinner and ignores presses while staying focusable (`aria-disabled`). `Popover` has `keepMounted`. `Sheet` is a non-modal dialog (full width on a phone, 24 rem from `sm`) that only Escape or Close shuts. `Loading` is a polite status at once and the skeleton after 300 ms (`useAfterDelay`). An error is an `Alert` with an icon, a title and a Retry where retrying works.
- Press and hit areas (`src/feel.css`, [ui-design.md](ui-design.md) Feel): every `button` squashes to 0.97 in the frame it is pressed and springs back past 1 (`--ease-spring`), in the base layer so a button's own utilities win; the `press` utility adds the colour transitions (`Button`, `Switch`). `hit-area` grows a positioned control to 44 px under a coarse pointer with an `::after`, never the layout (every `Button`, the stack chips and the lands chip). The primary pass button swells once when it comes to the viewer and an attacked pod or tile flinches once. All of it is motion-safe only; `feel.test.tsx` holds it.
- Theme (`hooks/useTheme.ts`): `createThemeStore` keeps `light`, `dark` or `system` in `localStorage` (`theme`), sets the `dark` class and follows `prefers-color-scheme` and other tabs; it works when storage or `matchMedia` is missing or throws. A script in the head of `index.html` sets the class before the first paint (`themeScript.test.ts` holds it equal to the store).
- `components/AppShell` frames every route: a skip button that focuses `main` (a `#main` link would replace a game address's seat token), the header (navigation, `ThemeMenu`, `AccountNav`), `AuthNotice`, `OfflineNotice`, then `main`. Under 640 px the navigation drops to a second row. Review cards (`/review?mine=true`) carries a badge of the account's deck cards waiting for a read (`features/reads/useToReadCount`), hidden at none.
- `useFullBleed` (`components/appChrome`) draws no header and makes the root the window high with `overflow: hidden` (the game table). `useFitWindow` makes the root the window high so the page scrolls one region inside itself (Play, My games, Precons, Decks, the builder, game over).

## Data flow

- `net/api.ts` checks REST bodies at runtime; a failure is an `ApiError` with a code of `crates/mtg-server/src/api.rs` or a local `unknown`, `network` or `bad_response`. `net/parse.ts` `parseFrame` is the only door from the wire (JSON, known `type`, required fields, 1 MiB cap); garbage is a `FrameError`, never a throw.
- The game browser calls of `net/api.ts` reject with a `LobbyError {code, status, retryAfter, issues}`, worded by `describeLobbyError` (`net/lobbyErrors.ts`). `listLobbies(previous)` sends the `ETag` and on a 304 resolves with that very object. A seat token goes in `Authorization: Bearer` beside the session cookie, so a call with no token acts for the signed-in user's own seat.
- `net/socket.ts` `GameSocket` sends `Join` first and once per connection. `net/pacer.ts` holds sends to a burst of 30, then 15 a second; the server allows 40 and 20 and closes a socket over it with 1008.
- `play/view.ts` holds pure ports of `StateView::apply`; unchanged objects, players and zones keep their identity. `play/session.ts` `createSession({game, token, name})` owns the socket, applies the client rule of [protocol.md](protocol.md) and writes the zustand store (`play/store.ts`) that screens read with `useStore(session.store, selector)`.

The session's rules:

- A Snapshot sets the base and `seq`; its log fills what the page lacks (`mergeHistory`), and a `rewound` one replaces what the page holds from the log's first position on. A batch whose `from_seq` is not `seq` (or any batch but the one at 0 while there is no view) sends one Resync; nothing is applied and decisions are ignored until the next Snapshot.
- A `Decision` replaces `pending`. `answer()` sends once per decision id; a Snapshot or a lost connection forgets answered ids, so the server's repeat can be answered.
- `GameOver` sets `result` and makes a later close final. `StaleDecision` and `IllegalAnswer` give a notice and a Resync; an `IllegalAnswer` with `refusal` says why in the card's sentence (`features/table/whyWords.ts`, `refusalNotice`). `BadMessage` and `Internal` only a notice.
- A wrong token is a refused upgrade, which a browser reports as 1006, so the client retries forever.

| Close or message | Socket status |
|---|---|
| 1001, 1006, 1013 and any code not listed below | `reconnecting`: retry after 250 ms doubling to 15 s, less up to 50 % jitter; a Welcome resets it |
| 4000 | `replaced`, no retry; `connect()` takes the seat back |
| 4001 | `stopped`, notice "You were removed from this game." |
| 4002 | `closed`, notice "The host closed this game."; the lobby ended |
| `EndedByAdmin`, 4003 | `closed`, notice "Ended by an admin: <reason>" ("Ended by an admin." without one) as the page title; the session drops the pending decision |
| 1000, 1002, 1007, 1008, 1009; `Error` UnsupportedVersion or UnknownGame | `stopped`, reason in `notice` |
| any close after `GameOver` | `stopped`, no notice |

## Create and game pages

- `/` (`browser/PlayPage`): the open games of `GET /api/lobbies`, Create game and "Join with a code". `useOpenGames` polls 5 s after each answer with the `ETag`, pauses while the tab is hidden and keeps stale rows dimmed beside an error. `useJoinGame` runs one Join at a time: an account joins in one click, a guest gives a name (`GuestJoinDialog`); the answer opens `/game/$gameId#seat=n&token=…`, and a seat that is gone reloads the list. A running game (`LobbyGame.running`) follows the lobbies with a Running pill and a Watch link to `/watch/$gameId`. Each game is a card (`OpenGameRows`): its commanders' art crops by seat, edged in the seat colours and named by the seat dots; a game without commanders, or a picture that fails, shows the felt with the format's mark or the seat's ground.
- `JoinWithCode` checks the code (8 symbols of the server's alphabet, any case, spaces and hyphens allowed) and joins through the same hook. A 404 reads "No open game with that code."; failures a guest can retry stay in the dialog with the name kept.
- `/join/$code` (`JoinCodePage`) is where the invite link leads: the code as `K7M2-9QXA` and one Join button through the same hook; a guest gives the name on the page. Text that is not a code makes no request, and a dead code ends with links to Play and Create a game.
- `/new` (`create/CreateGamePage`, `CreateForm`): format (Commander by default, `formatRuleWords`), seat count (2 to `MAX_FORM_SEATS`, 256), the creator's name (and deck in a Normal game), house rules and Visibility (`lib/visibility.ts`). The request holds only the creator's seat; the others choose a deck in the lobby. `BotsField` sets how many seats after the creator's bots play (`botsOf` keeps it below the seat count): held with `bot: true`, a Normal bot on its seat's deck, a Commander bot on a playable precon, Verified first (`pickBotPrecons`; none usable stops the form with a sentence); their tokens are never kept as invites. `AdvancedOptions` (Normal only, no bots) names and decks every seat, makes the game invite only and lists the links (`GameCreated`). From 768 px the form has two columns, the Create button in a sticky footer. `create/form.ts` repeats the server's checks; `create/apiErrors.ts` words every `ApiError` code.
- Teams (`lib/teams.ts`, pure): the one module for team play: the team of a seat, its label, colour classes (`team-1` to `team-4` tokens) and members, the default teams of a mode (`defaultTeams`, as the engine's `Teams::even`), whose turn a seat shares (`sharesTurn`: the team's in Two-Headed Giant, the player's own in Teams), the start's check on gap-free numbers (`teamsProblem`), a seat's move in the lobby (`withSeatTeam`: that seat alone, nothing else moves), the lobby's columns (`teamChoices`: two in Two-Headed Giant, one per two seats in Teams), the seat that shows a shared life (`lifeHolder`) and the seats a result names (`winningSeats`). `components/TeamBadge` draws a team's label. The create form's `GameModeField` sets `Draft.mode`; `toRequest` adds the default teams to `house_rules.teams`.
- House rules (`lib/houseRules.ts`): one `RuleSpec` per rule, shared by the form, the lobby (`LobbyRules`) and the table (`TableRules`). An empty field keeps the format's rule (shown as placeholder), so the request carries only what was filled in; `describeRules` names the rules that differ. Take-backs is a switch that is on by default; only off is sent (`take_backs: false`) and named ("No take-backs"). Blocker timer is a switch that is off by default: on is sent and named ("Blocker timer"). Timers is a choice whose blank option reads "Relaxed (default)" (`RuleInput.blank`) beside Quick and Off; its help line gives each setting's lengths, and only quick and off are sent and named ("Quick timers", "No timers"). The Delves new-run form (`NewDelveForm`) has its own Timers select, Relaxed first, sent as `CreateDelve.timers`, and the run header names it. Handicaps (`HANDICAP_FIELDS`, `handicapId`) are a row per seat with its life and opening hand, read in seat order into `handicaps`. The Mulligan prompt names the new hand size and the scry.
- Rules lexicon (`lib/glossary/`): `TERMS` gives every keyword, ability word and rules term a one-line reminder; `glossary.test.ts` and `vocabulary.test.ts` fail on an engine name or enum variant without words; `engine.test.ts` sorts every `Effect`, `CostItem` and `TriggerPattern` variant and every player and turn view field into keyword actions and designations (each with its term) or ordinary game text, and fails on one in neither list, on a counter kind of the engine or of ten or more cards without a term, and on a predefined noncreature token without one. Rules terms are grouped by topic; `Players` holds the Ring, the city's blessing, speed and the player counters. `KeywordText` marks terms (of the rules terms only `MARKED_RULES`) in ability texts and log lines with a popover into the lexicon. `LexiconDialog` (`features/table/lexicon`) is the searchable list, filtered by kind.
- Help (`HelpMenu` in the top bar) opens the lexicon and the table tour (`tour/TableTour`, `tourSteps.ts`): one part of the table lit at a time with a card placed by `placeCard`, Back, Next, Skip, the arrow keys and Escape. It starts once per browser (`localStorage` `table-tour`), never under automation, vitest or the dev route (`TableOptions.tour`).
- `/game/$gameId#seat=<n>&token=<token>` (`game/GameRoute`) reads the fragment from the raw `location.href`, since the router's `hash` is percent-decoded. A seat token lives only in the fragment, which a browser never sends; `components/SeatLinkRow` prints it only inside a `data-share-link` anchor, and `test-utils/leaks.ts` scans for tokens elsewhere. `lib/invites.ts` keeps the host's seat links and join code in `sessionStorage`.
- `/watch/$gameId` (`game/WatchRoute`, `WatchPage`): a signed-in visitor watches a running game. `GamePage` with `watch` opens `/ws/{game}/watch` (`socketUrl`) and sends only `Join`; signed out it asks to sign in (`/login?next=`). A spectator's table (`TableView.spectator`) is drawn from seat 0's side with that hand face down and "Watching: you hold no seat" in place of the pass controls. A player's top bar counts the watchers (`SpectatorCount`, from `Spectators`, `PlayState.spectators`).
- `game/GamePage` makes one session per (game, seat, token) and connects one microtask after mount, so StrictMode opens one socket. With a seat link it joins by token; without one and signed in it opens `/ws/{game}` with no token and the upgrade's cookie picks the seat. `game/gameContext` gives `useGame()` and `usePlay(selector)`; `lookup` is `GET /api/games/{id}`, polled every 3 s in the lobby.

| Store                               | Screen (`connectionOf`, `game/connection.ts`)                                          |
| ----------------------------------- | -------------------------------------------------------------------------------------- |
| no seat link and not signed in      | `SeatLinkMissing`; no socket                                                           |
| `phase` over                        | `GameOver`; no connection notice                                                       |
| `status` replaced or stopped        | `ConnectionNotice` alone: the reason and a button to connect again                     |
| `status` closed                     | `ConnectionNotice` alone, with Back to Play and Create a game, no way to connect again |
| idle or connecting, never welcomed  | "Connecting to the game…"                                                              |
| `reconnecting`, `attempt` below 5   | "Connection lost. Reconnecting… (attempt N)"                                           |
| `reconnecting`, `attempt` 5 or more | "Cannot reach the game" and "Try again now"; the socket keeps retrying                 |
| welcomed                            | `Lobby` while `phase` is lobby, `GameTable` while playing                              |

After a Welcome the lobby or table stays under the reconnect notice. A `notice` shows above any other screen as a dismissible alert.

## Lobby

- The `Lobby` message is kept whole as `lobby` (`{seats, needed}`) and dropped when the connection goes or the game starts. `game/lobbyModel.ts` (pure) makes the rows: the roster wins; before it and while reconnecting the REST lookup stands in. `removable` says which rows get Remove.
- A polite live region announces what changed (at most three changes, none for this seat's own connection). `LobbyVisibility` reads the lookup, so a reload keeps it; the host gets `VisibilityToggle`, which keeps a new value until the lookup agrees (`useVisibility`). From `COMPACT_LIST_FROM_SEATS` (13) the seat list scrolls in its own box.
- Every named seat shows its deck to the table (`LobbySeatRow`, `deckWords.ts`) as name, format and a count of cards played by hand, never a card name.
- Layout: a `wide` page, one column under 1000 px and two from it. Left, the game (`lobby-game`): title, house rules, visibility, the seats under a progress headline (on the first screen at 1400 × 900, beside the deck chooser), the host's invite link and code (`JoinInvite`), and Close game or Leave game last. A tournament match (`tournament_match` in the lookup) has no player host: its seat 0 gets what every player gets. Right, the sticky deck column (`lobby-deck`): "Your deck" and `ReadyBar`, which sticks to the bottom on a phone.
- `DeckChooser` is on this seat until it is ready; then one line says the deck is locked until Not ready. Tabs "Your decks" (`useDeckList`), "Built-in" (Normal games, `useDecks`) and "Precons" (`GET /api/precons`), each filtered by the game's format and fetched on first open.
  - `RandomDeckChoice` (`randomDeck.ts`) above the tabs: "Random precon", and for a signed-in player "Random from my decks" with a "Draw from" group list when groups exist; the draw in force reads as pressed and no check is asked for it. The Delves `DeckPicker` has the same buttons. `DecksRevealed` adds a table line per drawn deck to the chat ("Ann drew …", `ChatLine.table`).
  - Master and detail (`DeckList`, `DeckOption`, `DeckPane`, `deckEntries.ts`): a listbox (arrows, Home, End; Enter or double click chooses) under a search and filters. A row shows commander pictures, name, facts, colour discs and its support chip. "Sort by" is kept per browser (`deckSort.ts`). Pictures load in view, four at a time (`imageQueue.ts`). A starred precon (`useFavourites`) is listed under "Your decks". With deck groups (`useDeckGroups`), "Your decks" shows them as collapsible listboxes: the group of the chosen deck, else the last used one (`lastGroup.ts`, per browser), else the first is open; a search opens every group with a match, a deck in several groups is listed in each, and the arrows move through the open groups' rows only.
  - The selected deck's preview sits beside the list (a dialog under 1000 px): `DeckPreview` with the table's verdict (`useVerdicts`) as its legality, "Use this deck" (disabled for a deck the table cannot take) and a link to the cards played by hand (`notValidatedWords`).
- `features/decks/preview` is the shared deck preview (the builder reuses it): `DeckPreview` over `DeckPreviewData` (`previewFromDeck`, `previewFromPrecon`, `previewFromDraft`): commanders large, legality, colour identity, support counts with a bar, the mana curve without lands, type bars and the cards grouped by type (`groupByKind`) as small pictures with counts.
- `useDeckChoice` sends one `api.chooseDeck` at a time: the deck pressed shows a spinner and keeps focus, and a polite line reports the result. 422 `deck_blocked` (no card the game knows, the one refusal) lists the issues to the owner. Legality never refuses: the owner sees "Not legal in <format>: ..." (`LegalityWarning`) and every seat "Not legal at this table (N)" (`SeatDeck.warnings`).
- `ReadyBar` holds the Ready button (always in the window) and its words (`readyState`). The button follows the server's roster; a reconnect sends no Ready, and the second click of a double click is ignored.
- Teams: the roster's `teams` (the lookup's `house_rules.teams` before it) group the seats into `TeamColumns`, one column per choice headed by the team's badge and players (side by side where the panel is wide, else stacked), each `LobbySeatRow` with its team. The host's select on any seat and a player's on their own call `setSeatTeam` (`PUT /api/games/{id}/seats/{n}/team`) through `useTeams`, which holds the new teams until the roster agrees, sends any grouping (the server keeps it as chosen), names what keeps the game from starting (`teamsProblem`, `data-slot="teams-unready"`), puts the old teams back on a 400 or 403 in the words of `describeLobbyError(..., 'teams')`, and stops the lobby on a 409.
- `useLobbyControls` sends the controls' calls one at a time with the seat's token: every button waits while one is out, and the one pressed shows a spinner and keeps focus. A 409 `started` takes the controls away with one line that says why.
- Remove is offered on each taken seat but the host's and those this tab holds a token for. `LobbyQuestion` (words in `lobbyQuestions.ts`) asks before Close, Leave and Remove: the safe answer is first and focused, Escape does nothing while the request is out, a refusal keeps the question up and focus returns to the asking button. Close and Leave flash a notice (`lib/flash.ts`, `FlashNotice`, 10 s) and go to `/`.
- `JoinInvite`: the invite link `/join/<code>` and the code, each with a `CopyButton`, from this tab's `sessionStorage`; a guest never sees either.

## The table

`features/table/GameTable` takes no props: it reads with `usePlay(selector)` and starts from `TableOptionsContext` (`mode`, `focus`, `effects`, `effectsSlow`, `cues`, `viewport`; only the dev route and tests set it). The table is exactly the window high and never scrolls the page.

Teams: `table/teamLife.ts` (`useSeatTeam`) reads the view's `house_rules.teams`; in Two-Headed Giant the active player's teammate has the turn too (`isActiveSeat`, `isYourTurn`, the sorcery window, the pass words, the stop side, the turn cue), and the badge says "Your turn" to both and "Ann and Bo's turn" to the others (`turnTeammate`); `SeatPanel` and `SeatTile` add the seat's `TeamBadge` and `data-team`, and in Two-Headed Giant the team's first seat shows the shared life large and the teammate small with "shared" (`data-shared-life` `team` or `teammate`, words "Team life, shared with Ann"). Team sight: a hand the view lists of another seat (a teammate's under `team_hands`, any under open hands; `shownHandOf`) is a Hand chip on that seat's pod instead of a count, opening `ZoneDialog` zone `hand` titled with the owner's name, in the hand's order and with the preview, saying only they can play the cards (`their-hand`); none is the viewer's to play. A board drawn without a pod (a Delves hero's frame, a phone's board under a tile) carries the same chips at its top (`BoardZones`, `board-zones`): that hand, then the graveyard, exile, command zone and Satchel that hold a card, so a teammate's zones open in every layout; a tile is one button and holds none.

## Fit and grouping

`features/table/fit.ts` and `group.ts` are pure (no DOM, no store) and decide how big a zone's cards are and which permanents share a box.

- `fitRows(box, groups, limits)`: each group is a row with its stacks and card shape (`aspect` 7/5; `scale` 1, or `LAND_SCALE` 0.8). It answers with the largest width from 112 px down to the 44 px floor at which every row wraps inside the box; a bigger box never gives a smaller card.
- Whole pixels: boxes and card sizes are rounded and components draw exactly those sizes; every stack takes one box, tapped or not (`FIT_LIMITS`). When the floor does not fit, `scrolls` is true and `hidden` counts the stacks cut off (the "+N" of the edge fade).
- `groupPermanents(permanents, { groupOthers })` merges permanents equal in everything a face shows into a `Stack` (`key`, `count`, `members`). Tapped and untapped never share. Lands and tokens always merge, other cards only with `groupOthers`, set when the fit is under `GROUP_OTHERS_BELOW` (64 px). A permanent in combat never merges.
- Stacks keep the order of their first member. A merged stack's key is its face and a lone card's its id, so joins and leaves change no other stack's key, count or place. `expandStack` returns the members.
- Attachments: an attachment whose host is on the battlefield takes no box; it is tucked behind its host (`tuckedOf`: Auras, Equipment, Fortifications), and `LaneCounts.tucked` gives `fitLanes` the deepest tuck of each lane (`tuckOf`).
- Use: `battlefieldStacks` (`rowStacks.ts`) groups a seat's rows once per view, both ways. `layoutSeat` fits the measured content box (`useContentBox`) with `fitLanes`, merging every identical card under `GROUP_OTHERS_BELOW`. `Battlefield` writes `--card-w`, `--card-h` and each lane's width; a face is whole from 76 px. `fitPerf.test.ts` holds the cost for 6 and 12 seats.
- `fitLanes(box, counts, facing, limits)` (`laneFit.ts`, pure): lanes are lands, creatures and other permanents (`rowOf`), stacked in bands of shape `one`, `two` or `three` from the middle of the table outwards. Creatures take the card width, the others 0.8 of it (`scaleOf`); a band may fan its lands (`fanLane`) where that is lower. A binary search over `LANE_LIMITS` (224 px to 44) finds each shape's largest card; the largest wins, ties to `two`, then `one`. Without a fit at the floor the lowest shape scrolls, creatures first.

## Holding still

The table moves only when a change needs a new layout, and then in one step.

- Card size (`holdFit.ts`, pure): a board steps between the rungs of `CARD_RUNGS` (224 px down to 44, each about 8 % under the last). `fitHeld` keeps the width and shape the board drew last (`FitHold`, kept by `Battlefield`) while they fit; it steps down to the largest rung that fits as soon as they do not, and up only when a fresh fit is `GROW_SHARE` (15 %) larger and that larger rung still holds one permanent more in every lane, so one permanent more or less never flips a size back and forth.
- Bands (`holdBands`, `heldBands`): while the card width and shape hold, each band keeps the most height it was drawn at (`BandHold`, a band that emptied keeping its room in its place), so a line that empties or a pile that shortens moves no lane beyond it, an opponent's lanes above the middle of the table included; a size step, a new shape, a scrolling board or held heights over the box start afresh (`bandHold.test.ts`).
- The lane of other permanents stands at the band's right and runs from its own right edge (`CardRow` `fromRight`, the arrow keys mirrored), so a new artifact joins at its left and the cards already there stay in place (`otherLane.test.tsx`).
- Board split: `holdSplit` keeps the rows `useBoardSplit` drew while the room is the same and both rows still fit their boards at the floor, unless a fresh split gives a board a card `GROW_SHARE` larger even with one permanent more in every lane; where neither has a fit, held rows stay while the fresh split lies within `SPLIT_DRIFT_SHARE` (8 %) of the room of them. Boss mode does the same with its three rows (`holdBoss`).
- Prompt sheet: the band never changes height for a prompt, so no board moves and the sheet lies over no card (`sheetClear.test.ts`: every layout from a duel to the boss with six heroes and the phone; `e2e/prompt-band.spec.ts` measures it).
- Slides (`useFlip.ts`): a card a redraw puts elsewhere (a neighbour left, a lane wrapped, a size step) slides in `FLIP_MS` (220 ms) on the Web Animations API from where it stood inside the list just before the redraw (read during the render), so a move of the whole list or a table that settled after the last draw slides nothing and a pressed card never runs from under the pointer; nothing waits for it, and under reduced motion it stands at once.
- Measure: `/dev/table?script=layout` steps through thirty states of `dev/layoutScript.ts` (`window.__tableScript.go(i)`); `node scripts/layout-jumps.mjs --base <dev server>` counts, per table and window size, the boxes of the hand dock, the strip, the board rows, each board and the first card of each lane that move more than 4 px from one state to the next (the sheet apart). `layoutJumps.test.ts` holds the split and the card sizes of the script under a budget.

## Prompts

`features/table/prompt/` answers the decision this seat faces.

- `PromptHost` (in `SharedStrip`, in place of the waiting line while `ownDecision` is set) renders `PROMPTS[kind]` keyed by decision id, so a new decision starts with an empty selection. `registry.ts` has an entry per `DecisionKind` (`kinds/<Kind>.tsx`); a new kind stops compiling until it has one, and `kinds.test.tsx` fails on an `UnsupportedPrompt` stand-in. A kind the client does not know gets the generic prompt.
- `usePrompt()` gives `{ id, name, decision, asking, answer, selection }`. `answer(a)` wraps `session.answer`: once per decision, false when already sent, refused by the socket (a retry is allowed) or superseded. `PromptLayout` draws the shared shape: the decision's name for a screen reader, the lead chip, one polite live sentence, the `meter`, the `choices` and the answers (`children`), the primary answer first. The answers stand right to left (`prompt-answers`), so the primary sits at the band's right end in every prompt and Tab reaches it first.
- Decision detail (`prompt/detail/`): a decision of every kind but Priority, Mulligan, BottomCards, Discard and the two combat declarations (`hasDetail`) has its detail beside the band. In a side column the Stack tab comes forward (`SideProvider`) and returns to the tab the viewer had `DETAIL_HOLD_MS` (700 ms) after the last answer, unless they chose another meanwhile; the column never changes size. `StackPanel` then draws `DecisionDetail`: a kicker ("Resolving now · asks you", "Going on the stack", or the cause and "trigger 2 of 3"), the asking card as a card frame with its tag, name and rules text with the asked clause marked (`asked-clause`; the server's `AskingView.text` and `clause`, for a spell the card's own text with `mayClause`), a run of triggers as rows (done with a tick and the outcome this seat gave, `runMemory.ts`; the asking one expanded; the next ones numbered with their effect), the element the prompt's `choices` are portalled into (`decision-choices`, `SideContext.detail`), and "Already on the stack" (`StackRest`) without the asker and its run. Where no column holds it (a phone, a rail, a folded column) the same detail is `DecisionSheet`, a sheet over the hand at most 330 px high whose grab handle folds it to one line; it starts folded for a prompt answered on the table (`PromptLayout` `folded`: targets, a choice of cards) and is folded while the choice overlay is open, and short choices go to it too in a narrow window. `asking.ts` holds the pure rules; `useAsker` joins the server's `asking` with the view. `/dev/table?prompt=ask-may`, `ask-chain`, `ask-chain-first`, `ask-order`, `ask-pay` and `ask-departed` (`dev/askScene.ts`) show them on a board of their own.
- Asking marks (`detail/AskMarks.tsx`, `boardBadges.ts`): the asking card glows on the board with an "asking" badge, what triggered it has "just entered" (or "cause"), a prompt's own badges (the numbers of triggers being ordered) and the card a hovered or pressed chip or row points at (`lightCard`) are drawn as style rules by object id, so no card redraws; the pulse of a pointed-at card stops under reduced motion. A source the view does not hold is named in the chip and the column and pointed at nowhere.
- Card marks (`prompt/marks.ts`): `useCardMarks` takes a map of `legal`, `dimmed` and `selected` from `markCards` (`HIGHLIGHT`: legal glows in the primary colour, dimmed only loses a fifth of its colour, so a board never reads as switched off); a click or Enter/Space on a legal or selected card calls `onSelect`. Each `Card` subscribes to its own id. A legal card wears `ring-2 ring-primary`; a chosen card or player turns to `selected` with `ChosenMark`'s check. Prompts that choose among cards dim the viewer's other cards.
- Cancel (`UndoButton.tsx`, `undo.ts`): every announcement step of a cast or activation with `can_cancel` shows "Cancel the spell" or "Cancel the ability" with its Esc hint, which Escape presses unless something outside the prompt takes the key. It sends `Undo`, which also untaps the mana tapped just before the cast ([protocol.md](protocol.md), Decisions); a combat tax goes "Back to attackers" or "Back to blockers".
- Prompt cards carry `data-candidate`, never `data-object-id`. Letters and digits are hotkeys outside fields, menus and dialogs (`usePromptKeys`, `KeyHint`). Focus starts on the answer the response clock would give (`useDefaultFocus`).
- Hand abilities and special actions (`prompt/activations.ts`, `kinds/Priority.tsx`): `abilityPlays` turns `PriorityOptions` (`abilities`, `unlockable`, `endable`, `suspendable`, `foretellable`, `turnable`, `faces`) into plays (a mana ability only when `announced`, such as a die-rolling one); `AbilityChooser` asks which when a card has several (`playsOf`). Rooms (CR 709.5): each door of `PermanentView.doors` is a mark with its face's name and a lock (`useDoorFaces`).
- Zone marks: a graveyard or exile chip or picture holding a legal card wears the legal ring and a play badge (`LegalBadge`, `useLegalCount`, `legalWords`).
- The preview lists the card's activated abilities (`ObjectView.activated`, `activatedLines`), tags those offered "Can activate now", and lists clauses left to the table under "Played by hand:". A stack entry's preview (`stackPreview.ts`) names it, its rules and its targets, a gone one marked, with the source card large.
- Card prompts (`CardChoices.tsx`: choose cards, targets): in the Stack column the cards stand three to a row with the quick buttons, a search box and a target prompt's players above them; where there is no column (`ChoiceOverlay.every`) and for a long list they stand in the choice overlay, quick buttons included. Scry, surveil and ordering cards draw their piles in the column or the sheet. A player offered as a target shows their commander's art crop in their seat's colour (`PlayerFace`).
- Choice overlay (`prompt/choiceOverlay.ts`): where `wantsOverlay` holds (every choice of cards at a table without a side column, more than `FILTER_FROM` cards anywhere) `CardChoices` draws its cards through a portal into `choice-host`, an overlay over both boards that `CHOICE_AREAS` puts next to each other with the strip under them (`gridRows(regions, true)`) and that dims them (`bg-scrim`); the strip keeps the stack, the sentence and the buttons. The overlay carries `data-decision` and holds one centred plaque sized to its cards: at most `PANEL_SHARE` (80 %) of the room `useChoiceOverlayHost` measures (the whole room on a phone), the search box, then the players row (`lead`), then the cards, of which only the grid scrolls. `overlayLayout` (`prompt/overlayLayout.ts`) picks the layout from the room: whole cards one tenth of the room's width wide between 120 and 160 px (80 on a phone), shrunk to a floor of 104 px so that all fit the plaque's height, kept readable and scrolling below it (down to 88 px where a low window cannot show one whole row). Where several seats control cards they stand in one block per seat (`groupByController`: seats in order, each block led by the seat's name and dot in its colour), blocks side by side where the width allows, with the columns that stack them lowest; a search keeps the plaque's size. Number keys and Tab follow the drawn order. A card prompt draws every card it asks for, so covering your board hides nothing it needs. `/dev/table?prompt=targets-many` offers sixteen creatures and every player.
- Phone boards (`boardFloor.ts`): `GameTable` gives a phone's boards `PHONE_FLOOR_PX` (64) as the floor of `layoutSeat` (`least`), below which a board scrolls and merges identical cards instead of shrinking.
- Mulligan: the sentence reads `bottom_if_keep`, `bottom_if_mulligan` and `free_mulligans`; the client derives no count. `OpeningHand` draws the hand being judged whole under Keep and Mulligan, seven to the row up to 7 rem wide, `aria-hidden` (the dock holds the same cards).
- Priority sentence (`priorityText.ts`): one short line as Arena words it, "Play a land, cast a spell or tap for mana, or pass.", led over a stack by the spell answered ("Responding to Bo's Giant Growth: …, or pass to let it resolve."); the strip's status says who holds priority while the seat waits.
- Attack lines (`combat/plan.ts` `mine`): an attack by the viewer or at the viewer (a planeswalker of theirs too) draws strong, one between two other seats at 35 %; a spectator sees them all faint. The viewer's party counts as the viewer in every layout (`useCombatPlan`: the teammates of `house_rules.teams`, and `AttackLinesContext`, the heroes below in boss mode), so every attack by or at a teammate draws strong.
- Nothing to do: the newest `NothingToDo` of this turn shows "You have no creatures that can attack" (or "block") until the viewer answers something, only in the steps it speaks for (declare attackers and blockers; blockers only for a block note) and never beside the decision it denies; beside a prompt it is one short status line ("No creature can block") with the sentence in its tooltip and for a reader.
- A play taken back: the viewer's newest `AnnouncementRewound` shows "<card> could not be played: <reason>" (`prompt/rewound.ts`) until the next answer; other seats read only that the seat could not finish a play.
- PayMana (`payment.ts`, read as `mana_cost.rs` does; `PayColumn.tsx`, `paySlots.ts`): the column holds one circle for each mana owed (`paySlots`: a generic part a circle each, a source's own cost such as a Signet's {1} after a divider), filled with what paid it and captioned with its source, a press taking it back; then the sources as rows under what they make (`groupByMade`: "Makes {W}", "Makes {W} or {U} · you choose", "Makes {W}{U} · costs {1}"), equal permanents sharing a row with a count, one button for each kind a source makes, Untap and a switch of colour on a row in use, and why a row is off. A source or floating mana is offered only while the payment can still be finished (`completable`); restricted mana is spent against `PayOptions.spend` (`spendRules.ts`); floating mana, convoke, improvise, delve and life switches follow as rows (`PaymentSummary` `aside`). Board cards click as before, and a land of several kinds pressed on the board lights its row, which then asks the kind (a folded sheet opens). The band holds the chip of what is paid for, the symbols as a meter (`PayMeter`), Undo (the last choice), "Pay for me" ("Pay the rest for me" after some picks, with the reason in the column when `auto_available` is off), Confirm while `covers` holds, and Cancel. `toPayment` sends `{ pool, restricted, taps, life }`. A mana ability that does more than add mana (`PayOptions.announced`, Vexing Puzzlebox) is a row with Activate and a legal card that sends `{ Activate: ref }` at once; the payment comes back with its mana floating.
- Mana shows what it is (`manaMade.ts`, `ManaStrip.tsx`): what a source gives is read from its `ManaOption`s or its mana abilities' `ways`, never from words (`sourceMarks.ts`, `paySwap.ts`; `ManaChoice` asks the kind of a mana ability at priority). The pool shows each kind as its symbol and `×N`, rider mana with a sparkle, restricted mana with a lock and kept mana with an hourglass. A card that can tap for mana now draws `ManaStrip`; the preview has a "Taps for" line.
- ChooseNumber (`numberChoice.ts`): starts on the smallest allowed number; Less, More, arrows and the slider skip `except`; Confirm is off with the reason for a number not allowed. With `cost` and `per_x` the total cost is drawn. An open range stops at 99.
- Attack by clicking (`kinds/DeclareAttackers.tsx`): a click toggles a creature in the attack. With several defenders the creature clicked last (`data-cue="active"`) goes to the next defender clicked: a pod, a tile, the bare board (`combat/defender.ts`) or a planeswalker or battle; the row's "Attack at" list does the same by keyboard. A `required` creature (goad) starts in the attack marked "Must attack" and No attack is not offered. Where teams share their turns (Two-Headed Giant, Delves) each player of the team gets this prompt for their own creatures, which opens with what the teammates before chose and why the team's last choice was refused (`prompt/partyAttack.ts`).
- Block by clicking (`kinds/DeclareBlockers.tsx`): a click on a blocker with one possible attacker blocks it, otherwise the blocker is chosen and then the attacker; a second click takes the block back. A `required` blocker reads "Must block"; `can_block` alone decides who may be blocked. An attacker in `BlockOptions.min_blockers` (menace) reads "Needs 2+ blockers", then "Needs 1 more", and Confirm waits (`blockersNeeded`).
- AssignDamage: without trample any whole split that adds up to `power` is accepted; the first split (`damageSplit.ts`) gives lethal (`DamageOptions.lethal`) in order and the rest to the last. With trample (`excess`) the rest goes to the attacked player or planeswalker (`damage-excess`) once every blocker has lethal. With `unblocked`, "Assign as though unblocked" sends all of it to the one attacked.
- ChooseTargets (`targetText.ts`): the sentence names the source and gives the engine's `wording`; a click on a chosen target takes it back; the list holds every legal target, players included. A triggered ability has no Cancel; its way out is the clock's `Remove` ([server.md](server.md), Response clocks). With a `total` a target that would go over it is neither marked nor taken (`fitsTotal`).
- DivideAmount (`divideText.ts`): one row per target, each at least `MIN_SHARE`, summing to `total`; it starts at the server's even division and Confirm is off until nothing is left.
- Quick selection (`QuickSelect.tsx`, `quickSelect.ts`): a ChooseTargets or ChooseCards prompt with room for several and two or more choices has "Select all", "Select all owned" (what the viewer controls, the viewer as a player), "Select all allied" (teammates' alone, only in a team mode, `useAllies.ts`) and "Unselect all". Each adds its group to the choice so far; one that would pass the most or a rule of the prompt (a total, one per name) or adds nothing is `aria-disabled` with the reason in a tooltip. A DivideAmount divides among targets a ChooseTargets chose, so its quick buttons come first.
- ChooseCosts (`costsText.ts`): a toggle per optional cost; one gift only (`SEAT_BASE + seat`), a second refused with the reason. Confirm costs sends the taken indices in ascending order and is focused, so a press made without looking pays nothing extra. Costs paid several times (multikicker) are a `ChooseNumber`.
- Loop (`loopText.ts`): names the cards and what one iteration does; presets 10, 100 and 1,000 (off past `max`) and a number field repeat it, Stop (S) plays on, and a loop that never ends by itself offers "Let it loop (draw)". Focus starts on the clock's answer (Stop, or the draw). A batch with `folded` events moves `seq` past them (`batchEnd`); the log shows the shortcut as one line, and a draw by loop names its cards on the result screen (`describeResult`).
- Generic prompt (`genericChoices.ts`, `GenericAnswers.tsx`): a kind with no prompt of its own says "This decision is not supported in the UI yet" and offers a button per answer its options allow (at most 12), led by the clock's answer. A decision that needs a set made by hand has no button and says so.
- OrderTriggers (`orderText.ts`, `kinds/OrderTriggers.tsx`): rows of the column in resolution order, the top one tagged "first", each with its number, its source's picture and name and its effect (`TriggerEntry.text`, not the event), moved by ▲▼ or dragged; under a coarse pointer the rows are pressed in the order they resolve and take numbers, the last by itself, with Start over in the band. The sources carry the same numbers on the board and what triggered them its badge. The answer is the list reversed, the order they go on the stack.
- YesNo, ChooseOption and ChooseMode (`choiceText.ts`) ask in the engine's `text`. A YesNo of a run shows its place in the band (`RunDots`), keeps No at the right end with the focus, and offers "Always Yes" and "Always No" under the asking card. ChooseMode lists its modes one to a line in the column; optional costs, divided amounts and damage do the same; with exactly one choice it answers at once; otherwise modes toggle, Confirm waits for `min`, and the answer lists the chosen indices in card order.
- ChooseCards (`cardsText.ts`, `PromptCard.tsx`): the cards of `from` in the column (a long list in the choice overlay), a face-down stand-in for a card the view lacks. From 13 cards, or 2 in a library search, `CardSearchField.tsx` narrows by name, type line or rules text and shows "N of M"; Escape clears it before Escape undoes, and a hidden choice still counts. The manual Search (`TutorBody.tsx`) shares it. With `one_per_name` or `groups` ("with different names", "with different powers"), a card of a name or group already chosen is closed until that card is put back. Surveil (`kinds/ScryCards.tsx`) draws two piles.
- ChooseName (`kinds/ChooseName.tsx`): searches the catalog by what is typed; `looked` (the hand looked at just before naming) is a row of those names, each one click to name.
- OrderCards (`kinds/OrderCards.tsx`, `lookText.ts`) and Scry (`kinds/Scry.tsx`, `scryPiles.ts`): pictures with a place number, moved by buttons, Alt and an arrow or a number key, the scry piles also by drag; a line previews the result. An untouched scry sends every card on top, as the clock does. `CardChoices.tsx` is the one picture grid for every card choice (`useRestingPreview`).
- ChooseReplacement (`kinds/ChooseReplacement.tsx`, `replacementText.ts`, `oracleWords.ts`): a row per replacement effect with its source's picture, name and its own effect's words (the rules text from `useOracleText` only when the candidate has none).

## Combat overlay and previews

`features/table/combat/` draws what combat will do from the engine's `combat_forecast` in the table view ([engine.md](engine.md), [protocol.md](protocol.md)); `net/parse.ts` checks it down to its leaves. The client never works an outcome out: it shows the engine's numbers and hides them when they cannot hold.

- The seam: `useBlockPreview()` (`forecast.ts`) is the table's forecast while no choice is pending and the engine's preview of the choice being made otherwise (`previewFor`). Marks go the moment the choice changes and return with the reply.
- `CombatOverlay` is an SVG over the table column (`aria-hidden`, no pointer, mounted only while a line exists): lines under the centre strip and a faint copy above it. `plan.ts` (pure) draws attacker to player, planeswalker or battle (muted) in every layout, blocker to attacker (strong, coloured by outcome) and unsent choices dashed.
- Attack badges (`AttackBadges`, `attackGroups`; `TableOptions.attackBadges`, on except under vitest): beside the arrow from each attacker, the defender's pod, tile or name row carries a badge per attacking seat in that seat's colour with the count ("⚔ 3"), dashed while the attack is still being chosen, its names for a screen reader and in the tooltip. An arrow at a player ends at the edge of the defender's pod or tile; a seat that attacks with more than `BUNDLE_OVER` creatures at one defender draws one heavy arrow with the count. `dev/combatScene.ts` `sidesAttackScene` (`?prompt=attack-sides&teams=2v2`) shows a team game with attacks at both opponents. An attacked seat, the viewer's own pod and a phone's tiles included, wears `data-attacked` and an inner red edge (`ATTACKED_EDGE`, `useAttacked`) in every layout, and the badge on the viewer's pod reads "Bo attacks you with 3 creatures".
- `rects.ts` measures when anchors appear and once per frame while something may move, never per render (tests inject a `RectProvider`). A card cut off by a clipping ancestor is replaced by its controller's pod or tile, and a tile scrolled out of its strip (or showing no more than the mark's 16 px of itself) by a small mark at the edge of the strip it went out by, before and after the strip scrolls (`phone-arrows.spec.ts`); no combat line runs over your life.
- A big attack: more than `BUNDLE_OVER` (5) attackers fold by target (`bundled`) into one heavier line (`data-count`) with a pill "4 attackers → Cy" placed inside the window, off the strip and earlier pills (`geometry.ts`). Blocks keep one line each.
- Marks: `data-doomed` and a "Dies" badge, a "-N" damage badge, and on an attacked seat a life chip (`LifeForecast`): the change in red, green when lifelink more than makes up, a skull when lethal. The key (`CombatLegend`) lists only the lines on screen. With `CombatForecast.depends_on_choice` a "≈" precedes the numbers.
- DeclareBlockers and DeclareAttackers publish their pending choice (`usePublishPending`, `pending.ts`) and end with `prompt/PreviewOutcome.tsx` for a screen reader. In a party's shared declaration the hero who chooses after teammates also publishes theirs (`PendingCombat.team`, from `AttackOptions.party.declared`): their lines and badges are drawn dashed as chosen, apart from the answer and the forecast, until the party declares and `combat.attackers` lists every hero's attackers.
- Preview ([protocol.md](protocol.md), Preview): `session.preview(decision, answer)` sends one `Preview` and keeps only the newest reply as `store.preview`, dropped with the decision, a snapshot, game over and the connection. An `Error{BadMessage}` to a preview marks an older server: no more previews this connection. `usePreviewRequest` asks `DEBOUNCE_MS` after the last change and reports `idle`, `checking`, `ready` or `unavailable`.

## Table feedback

`features/table/fx/` draws short animations for what a batch did. They decorate the true state, which the table already shows when they start: nothing waits for them, no answer is delayed, and ending one only removes an attribute.

- `watchBatches(store, fx)` (`batch.ts`) subscribes to the play store. `batchBetween(prev, next)` takes a change for a batch only when `seq` moved on by exactly the events appended to the log, so snapshots, decisions and chat never animate. `deriveEffects` (`derive.ts`, pure) returns `Effect[]` in a fixed order.

| Effect                | Comes from                                                                         | ms  |
| --------------------- | ---------------------------------------------------------------------------------- | --- |
| `attacked`, `blocked` | `AttackersDeclared`, `BlockersDeclared` and the combat diff                        | 500 |
| `damaged`             | a permanent: `DamageDealt`, else newly marked damage; a seat: the life diff        | 550 |
| `healed`              | a seat: the life diff                                                              | 550 |
| `entered`             | a permanent that was not on the battlefield                                        | 350 |
| `died`                | battlefield to graveyard, or named by `CreatureDied` (a token); at most 24 a batch | 500 |

- A `died` effect carries the card's last look, so a ghost stands where it was (`GhostCard`, `aria-hidden`); a player who loses takes their permanents out without ghosts. A lane whose last permanent died keeps its place while the ghost plays (`useGhosts`).
- `createFx` (`store.ts`) keys effects by card, seat and row; one timer per kind and batch removes them after `FX_MS`; a batch plays at most 120. `mode` (`off`, `reduced`, `full`) is read every batch; `reduced` plays still highlights only.
- `TableOptions.effects` is on except under vitest; a test turns it on with `renderTable({ options: { effects: true } })` and fake timers.
- `Card` sets `data-fx` and `data-fx-side`, `LifeFx` wraps the life figure. Durations are `--fx-<kind>-ms` in `fx/fx.css` (`fxCss.test.ts` holds them equal to `FX_MS`); `--fx-slow` stretches them.
- `fx.travel` (`travel.ts`, `places.ts`, `FxTravel.tsx`) flies the moves of `deriveMoves` with the Web Animations API on a fixed `aria-hidden` layer: sources are measured before React draws the batch, destinations on the next frame (`measurePlace`); `planFlights` staggers the legs and `keyframesOf` poses each one: a dip as it leaves, an arc (`arcBow`) to the readable top, a landing that overshoots and settles, each pose easing into the next. Nothing flies under `reduced` or `off`, and a new batch with moves ends the previous flights.
- `fx.strikes` (`strikes.ts`, `strikeLayer.ts`, `FxStrikes.tsx`, `full` only): combat damage dealt before anyone has priority is a strike, one per source and damage step; the source's picture winds up, lunges at what it damages and comes back in `STRIKE_MS` (1.1 s), holding the targets' `damaged` effects and ghosts until the hit (`splitImpacts`, `holdDeaths`).
- Moves to the stack and on, the spotlight, target arrows and the hand's reasons are designed in [ui-design.md](ui-design.md), Playing is legible. `stackTargets.ts` lists each stack item's targets with `gone` read from the view and log; `combat/stackArrows.ts` plans them as `target` lines in `CombatOverlay`'s `stack` layer, above the strip from 640 px; on a phone it runs under the sheet with a faint `stack-ghost` copy above, as the combat lines do.
- A crowded stack (`stackGroups.ts`, pure): neighbouring items that are the same ability of one source and controller, or copies of one spell, fold into one chip with "×N". `chipsThatFit` keeps the top chip and what fits; the rest go behind one "+N more" button that opens the Stack tab. A stack anchor is `data-stack-chip`, else `data-stack-members`.
- Staging: the top chip carries `fx-stage-top` (a raised shadow, and a rise and settle of `--fx-arrive-ms` once the leg to it lands); the chips under it stand at 0.8 until hovered or focused. A drawn card of the viewer rises 8 px on the same beat (`drawn`). The effects of the table above move pose to pose: an attacker winds up, lunges stretched and recoils, a hit squashes, lights and shakes 5 px, an entering card and a life total overshoot and settle, a dying ghost shrinks and tips over.
- Log wording that needs the surrounding events (`eventContext.ts`): the resolving spell ("X counters Y"), an activation's targets, and an ability's source, so a resolving ability reads "An ability of X begins to resolve".
- An ability the Ring gives (`granter.ts`) is named after the Ring in the log, the stack, the preview and the trigger order: "The Ring's ability triggers (Nazgûl, Ana's Ring-bearer): draw a card, then discard a card", "The Ring's ability begins to resolve". The line comes from the event's origin, the later lines from `EventNames.granter` (the view's `granter`, else the `AbilityPutOnStack` origin).
- Table moments (`moment/`): `watchMoments` shows public events to every seat over the table: `Revealed` cards as compact tiles with who and why (`RevealTile`: the picture and one truncated name line, at most 150 px wide, wrapping and scrolling in a list of at most 34 % of the window's height; the rules text is in the card's preview, which a hover, focus or click on a tile shows from the card as revealed, `PreviewTarget.shown`; `/dev/table?moments=1&shown=8` plays eight with long rules text), a die (`rollFaces`, the same faces everywhere) and a coin turning in 3D (`CoinFace.tsx`). A look at a library makes none. At most three stand for `momentMs`; Escape or Dismiss ends them; under reduced motion the result shows at once. A coin call is a `ChooseOption` drawn as Heads and Tails.

## Turn cues

`features/table/turn/` shows whose turn it is and what the game passed, from the batch that arrived. A cue only reads the play store: none waits for, delays or paces an answer, and each reads what every seat sees ([ui-design.md](ui-design.md), Turn and focus).

- `feed.ts`: `deriveFeed` (pure) gives `{ banner, lines, skipped, announcement }` for one batch (`feedBetween` for two play states). A step is skipped when it began and ended inside the batch with a round of priority passed. The lines are the skip note, "You had no plays" for the viewer's own main phase passed without a yield, and the newest line the log does not draw quietly. `feedLeak.test.tsx` requires equal feeds for games that differ in one hidden card or in pace.
- `timing.ts` holds the times of [ui-design.md](ui-design.md) (Turn and focus); `bannerTimes(reduced, slow)` stretches them by the dev route's `?slow=`.
- `useTurnFeed(onFeed)` calls back for every batch while the table draws its timed cues (`TableOptions.cues`, on except under vitest).
- `TurnBanner.tsx` is a band in the top bar's free room after the step ladder (`TopBar` draws it as its spacer, so nothing moves or is covered); `bannerPlace` hangs it under the bar where the room is under 112 px. It names the round; a polite live region (`turn-announcement`) says the same with the turn number. `TurnTicker.tsx` is one line in the strip's bottom row. Both are `aria-hidden`.
- Control of a player (CR 722): the turn badge adds "you control them", "Bo controls you" or "Bo controls them" while `TurnView.controlled_by` is set (`turnText.ts`), and the hand dock shows the controlled seat's hand to its controller (`handSeat`), who plays from it.
- `StepLadder.tsx`, `ladder.ts`: the step marks in runs of one phase (`phaseRuns`, `pipStates`: lit, passed, to come, skipped). They are the stop buttons; for a seat that cannot set stops the ladder is `aria-hidden` and the badge says the same in words.
- `phase.ts`, `usePhase.ts`, `PhaseTag.tsx`, `phase.css`: `phaseOf(step)` gives `{ id, name, icon }`; `TableGrid` writes `data-phase` on the table root and `phase.css` points the live tokens at that set; what takes the theme carries `data-themed`. `phaseTokens.test.ts` holds the contrast and colour-vision distances of [ui-design.md](ui-design.md) (Phase themes) with `test-utils/vision.ts`.
- `turn.css`: the banner's fades and the ticker's rise. `cueTokens.test.ts` holds the contrast of the cue tokens, seat edges and priority dot in both themes.
- Tests drive a table with `renderCueTable` (`test-utils/cueTable.tsx`) and batches from `test-utils/turnEvents.ts`.

## Sounds

`features/sound/` plays short, quiet sounds at the table, synthesized with WebAudio, so no sound file ships.

- Cues (`cues.ts`, pure): `soundCueBetween(prev, next)` gives at most one cue per change of the play store, the strongest first: `won` when the result names the viewer, `turn` when the viewer's own turn begins, `decision` when a decision for the viewer arrives while none was pending. A first view, a spectator's table and any other seat's turn, decision or win give none. `playCue` (`synth.ts`) plays one to three sine notes of 160 ms.
- The table (`tableSounds.ts`, pure): `tableSoundsBetween` reads the batch of `batchBetween` (a snapshot, a decision or chat is none) and gives the sounds of its events, each kind once, the strongest first, at most three: attack, block, hit, die, cast, counter (also a fizzle), resolve, gain, land, shuffle, draw. A draw or a shuffle of another seat is its hidden event, so every seat hears the same and no sound tells a hidden card. `playTableSound` (`tableSynth.ts`) plays the voices of `TABLE_VOICES` (tones gliding and band-passed noise, each under 400 ms) `SOUND_GAP_SECONDS` apart on the audio clock: no timer waits and no answer is delayed.
- Settings (`soundPrefs.ts`, every access in try/catch, followed by every tab): `mtg.sounds` (`off` mutes everything), `mtg.sounds.table` (`off` keeps the cues only) and `mtg.sounds.volume` (0 to 1, default 0.7, where the cues sound at their old peak of 0.05). The switches are "Play sounds" and "Play the table's sounds" in the Full Control menu; the settings page has both and a volume slider that plays a cue as it moves.
- `useSoundCues` runs in `GameTable` while `TableOptions.sounds` is on (everywhere but under vitest and the replay viewer); a browser without WebAudio, or before the page was clicked, plays nothing and throws nothing.
- Motion that goes with them: a tap lays a card down and an untap stands it up in 150 ms (`TAP_MOTION`, `motion-safe` only); the damage shake, travel, strikes and spotlight are the table effects above.

## Pace controls

The Priority prompt's controls (`prompt/PassControls.tsx`, drawn in the controls dock of the table, 44 px high), over the wire rules in [protocol.md](protocol.md) (Pace of play) and the privacy rules in [ui-design.md](ui-design.md) (Priority, stops and information leaks).

### Primary button and yields

`data-slot="primary-action"` answers `Pass` (disabled when `can_pass` is false). `primaryLabel` (`passWords.ts`) is display only; the server decides what happens. "Pass priority" is never a visible label; it is the `aria-description`. Resolve and End turn are never one button: the primary button never says "End turn", and in the last window of the viewer's turn over an empty stack (`lastWindow`) it is not drawn, so a Resolve pressed twice never ends the turn.

| Situation                                    | Label                                             |
| -------------------------------------------- | ------------------------------------------------- |
| a spell on the stack                         | "Resolve <top spell>" ("Resolve" in a short dock) |
| the viewer's turn, before the last window    | "Next: <next step>"                               |
| the viewer's turn, the End step, empty stack | no primary button; "End turn" alone               |
| another seat's turn                          | "Continue"                                        |

The dock's form (`dockForm(regions)` in `layout.ts`) sets how much the words say: `full` (a main area of `DOCK_FULL_MIN_MAIN_PX` or more) draws key hints and the whole words; `short` leaves the hints to tooltips and `aria-keyshortcuts` and writes short words; `compact` is the phone's dock.

- "End turn" (`secondary-action`, `endTurnShown`; first in a phone's menu, except in the last window) asks for `yieldUntil('EndOfTurn')`; under Full Control it shows only in the last window and passes once. The menu "More ways to pass" has "Resolve everything on the stack" (over a stack) and "Pass until my next turn".
- A yield is asked once per prompt: the buttons wait for `Yielding` or a fresh decision. The server refuses yields under Full Control, so there `yieldUntil` sends nothing and neither "End turn" nor the menu is drawn.
- `YieldIndicator` ("Passing until the end of turn", "Stop passing" for `cancelYield()`) shows while the store's `yielding` is set, which only `Welcome` and `Yielding` set.
- Take-backs (`TakeBackControls.tsx`, `takeBackText.ts`; [protocol.md](protocol.md), Take-backs): `takeBackOffer`, `takeBackRequest` and `takeBackNotice` follow `TakeBackOffer`, `TakeBackAsked`, `TakeBackEnded` and `TakeBackRefused`. The seat's offer is a "Take back casting Shock" button (`takeBack()`); a seat in `waiting` gets "Bo wants to take back casting Shock" with the seconds left, Allow and Decline (`voteTakeBack`, which drops the seat from `waiting`); the asker and the rest read "Waiting for the table…". How a request ended and every refusal are a status line that goes after `TAKE_BACK_NOTICE_MS`. The log line is "Ana took back casting Shock".
- Auto-skips (`features/table/autoSkips.ts`, set only by `Welcome` and `AutoSkips`): the "Auto-skip triggers" switch (`stops/AutoSkipToggle.tsx`, saved with the account) moves the moment it is pressed until the next `AutoChoices` from the server decides it, and stays beside the stops with a list of the auto-passed abilities and rules. A stack chip, the stack preview and a stack ability's menu offer "Auto-pass this trigger"; a yes-or-no question from the seat's own trigger adds "Always Yes" and "Always No", and the trigger-order prompt "Always use this order". Each sends `AutoSkip` before the answer.

### Stops and Full Control

`features/table/stops/` and `play/session.ts`. The server decides the windows from the stops and the mode ([protocol.md](protocol.md), Stops and Full Control); the page only asks for them and shows what the server holds.

- `stops` (`{side, step, keep}`) and `fullControl` (`Off`, `NextWindow`, `Held`) are replaced whole by `Welcome`, `Stops` and `FullControl` and survive a dropped connection until the next `Welcome`.
- The default stops (`play/flowPrefs.ts`): an account or guest that saved none gets `DEFAULT_STOPS` (the own declare attackers and postcombat main) at a fresh table's first `Welcome`; a cleared list stays cleared.
- The by-hand window (`play/byHand.ts`, `PlayState.byHand`): the server holds a seat at every window after its own spell or ability of a card flagged `ObjectView.manual_owed` resolves, an ability of its own is left to the table (`AbilityLeftToTable`) or a by-hand line of its own comes due (`ByHandDue`), until it passes; the client reads the same from the events. Meanwhile the Priority prompt reads "Apply <Card name>'s text by hand, then continue."; no other seat reads it.
- The step ladder is the stop ladder (`turn/StepLadder`, `StopMark`): for a seat that can set stops each step that gives priority is a button (`data-slot="stop"`, `aria-pressed` while the server holds a stop, `data-keep`). A held stop is an outline with a dot (a pin when lasting), apart from the current step's fill. Untap and cleanup take none (`play/stops.ts`). The ladder is one tab stop.
- `StopControlsProvider` (`stops/stopControls.tsx`) holds what the ladder and the dock share: the Keep toggle, the side picked by hand (it follows the turn until picked) and `press`. `StopLadder` (in `StopsBar`, beside `FullControlToggle`) holds `StopSideSwitch` ("Mine" or "Theirs") and the Keep toggle.
- The ladder sits in the top bar from 1024 px (`TablePlan.ladderInBar`), else in the "Stops" popover. `StopsDock` puts `StopsBar` in the dock as one row from 1600 px, else behind the "Stops" button; the popover stays mounted, so its keys keep working.
- A press sets a one-turn stop or clears a held one; Shift and press, or Keep, sets a lasting stop (`pressRequest`). The Full Control toggle asks for Held, or Off when a mode is on.
- The Full Control menu ends with the pace settings (`FlowMenu.tsx`): "End my turn by hand", the auto choices ("Order my triggers by timestamp", "Assign combat damage for me", "Stop where my permanents can act", "Always pay automatically", each `session.setAutoChoices`, saved with the account), the sounds, the always-yielded abilities and the default stops. "Always pay automatically" is answered on the server, so a payment it makes never shows a prompt and cannot race a take-back.

### Response clock

- A `Decision` with `deadline_ms` becomes `pending.deadlineMs`. The session counts it down in `PlayState.clock` and at zero clears `pending` itself: the server has answered, and a prompt left up would invite a stale answer.
- `prompt/ResponseClock` shows "Passing for you in 7 s" (`clockText.ts` words what the server answers for every kind) as a `role="timer"` that does not announce each second; the last three seconds are urgent (`data-urgent`). Its bar is `response-clock-bar` (`prompt/responseClock.css`).
- Away seats: `Presence` sets `PlayerView.connected` and its `deadline_ms` starts that seat's clock (`play/awayClocks.ts`). A seat still in with no client wears `AwayMark`, and the waiting line adds "Bo is away: the game acts for them in 12 s" (`presenceText.ts`), the seconds hidden from the live region. An eliminated seat never reads as away.
- Timer bank: every pod draws the public `PlayerView.bank` beside the name (`BankMark`, `bankText.ts`): an hourglass and the count, nothing at 0. When it drops the mark reads "N used" with a warning edge for five seconds (`data-spent`).
- Turn time (`TurnTimeMark`, `lib/turnTime.ts`): every pod draws a seat's time on its own turns as m:ss (h:mm:ss from an hour), nothing before its first turn. Every seat the table marks running ticks from `PlayState.viewAt` on one shared second interval (`useSecondTick`); under shared team turns that is the teammate whose decision it is, not the first seat of the team. The game-over list gives each seat's total.

### Keys

| Key                             | Action                                                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Space                           | presses the primary button                                                                              |
| Enter                           | presses "End turn"; where none is drawn (Full Control, the End step) the primary button (`enterYields`) |
| Shift+Enter or another modifier | nothing                                                                                                 |
| Ctrl alone                      | Full Control `NextWindow`; again, Off; nothing from `Held`                                              |
| Ctrl and Shift together         | Full Control `Held`; again, Off                                                                         |

Space and Enter act only when nothing has the keyboard (`isFocusFree`: no field, button, link, menu or dialog has focus, no modifier is held, the key is not repeating); a focused card plays itself instead. `useFullControlKeys` follows the same rule and `ModifierChords` fires on release, so Ctrl+Shift+I and Ctrl-click do not count.

## Replays

- `/replay/$gameId` (`features/replay/ReplayPage`) loads `GET /api/games/{id}/replay` (`net/replays.ts`, with the session cookie; `readReplay` checks the shape) and draws the real `GameTable` over a store it writes itself and a session that refuses every action (`replaySession`). No sound cue and no tour run; the animations of each step play as at the table.
- `createCursor(steps)` (`replayModel.ts`, pure) gives the view and the log after any step, folding with `applyBatch` and `appendLog` from a frame kept every `CHECKPOINT_EVERY` (20) steps, so a step forward costs one fold and a jump back at most twenty.
- A toolbar at the bottom right of the table, over the pace controls that a replay has no use for (the whole bottom edge on a phone), holds First, Back, Play or Pause (a step every `PLAY_STEP_MS`, 900 ms, stopping at the end), Forward, Last, a step slider, "N / M" and "Seen from": `withPerspective` turns the table to that seat and keeps the view a spectator's, so nothing at the table can act. The view keeps what the server sent: the asker's own seat's hidden cards, else none.
- A finished game in My games has a Replay link and the game-over screen "Watch the replay"; a game without a replay (not ended, not recorded, a tutorial) says so with a link to My games.

## Accounts and games pages

Sign-in uses the server's accounts ([server.md](server.md); bodies in [protocol.md](protocol.md)). A guest needs no account: a seat link opens a seat. A server without `DATABASE_URL` answers 503 `accounts_unavailable`, and the app then offers no sign-in anywhere.

- `net/accounts.ts` `createAccountsApi` sends `credentials: 'include'`. A failure is an `AccountError {code, status, retryAfter}`; `AUTH_ERROR_CODES` is a `Record` over the generated union, so a new code stops the build until it has words.
- `features/auth/store.ts` `createAuthStore` is the app's `appAuth`, started once by `AuthProvider`. `status` is `loading` until `GET /api/auth/me` answers, then `signed-in`, `signed-out` (401, network, 5xx or unreadable) or `unavailable` (503). A failed `logout` keeps the user and sets `notice`. An answer that arrives after a newer question is dropped (`round`).
- `/login` and `/register` (`AuthScreen`, `AuthForm`) check username and password (`rules.ts`, copies of the Rust constants) before sending. The password is in no React state: the field is uncontrolled and emptied after the answer. A field problem sits in an always-present polite region in `aria-describedby` and focus goes to the first wrong field; a form failure is a focused `Alert`. Every `AuthErrorCode` has a sentence and a field (`errors.ts`; a wrong sign-in names neither half).
- `next`: `sanitizeNext` (`features/auth/next.ts`) accepts only a path on this site (one leading `/`, no backslash, control character or `//` after dot segments, not `/login` or `/register`, no fragment, since a seat token must not travel in a query). `parseAuthSearch` always names the key, so the router cannot merge the unchecked value back in.
- `/register` where `GET /api/auth/options` says registering is closed shows "New accounts are made by an admin" with a link to sign in, and the header drops Register; a 403 `registration_closed` shows the same.
- `/precons` (`features/precons/PreconsPage`), public: `net/precons.ts` `createPreconsApi` (`PreconError`; 503 `cards_unavailable` reads "No card data on this server"). `PreconFilters` (search over name, set code and commanders; set; deck check; "Sort by" kept per browser) over `PreconRows` (a table from 64 rem, stacked below). A read view stays for the page's life, since the server budgets requests per address.
  - Play (`usePlayPrecon`, `play.ts`): `createGame` with the form's defaults and `deck: "precon:<code>"` for seat 1, `commander` format for a Commander deck; a guest gives a name first. Success opens the lobby; a 422 or `unknown_deck` shows "Could not start a game with <name>" with Show why.

Each stage of a run says its next step in one line (`nextStep`), and the loot before a descent names the floor it leads to in the stage, the banner and the waiting line (`Run.descending`); the end shows a summary (bosses, hearts, Heat, rooms, each hero's life, gold and relics).
- The leaderboard (`DelvesLeaderboard.tsx`, words in `model.ts`: `depthWords`, `orderBoards`): a signed-in panel with three tabs, Heroic, Seasoned and Casual, open on Heroic; each entry has its rank, player, depth ("2 floors + 1 boss"), commanders, party size and day. The page's 48rem column never moves: from the `aside` breakpoint (87rem), where the right gutter holds it, the leaderboard stands there in a 16rem column out of the flow; below that it follows the page's content (`e2e/delves-leaderboard.spec.ts`). `/dev/delve?state=list` shows the page on fixtures, `state=descent` the loot before a descent.
- A fight (`BossIntro.tsx`, model `introAbilities`): on the run page with Enter the fight, the lost-heart note (beaten back, retreated or the table closed without a result), the host's Retreat (confirmed first; it names the heart it costs) or the deck problem with Choose another deck; in the game page in place of the lobby (`FightLobby.tsx`, chosen by `GameInfo.delve`) with Ready to fight and no deck choice. The game page goes to `/delves/$delveId` when the fight ends.
- Motion: scenes fade and rise in, bars and states ease, all under `motion-safe`; `/dev/delve?state=lobby|map|fight|relics|cards|shop|campfire|event|bargain|discard|surrender|result|victory|defeat` shows each state on a fixture without a server.
- At the table a Spirit and a boss's phase show as seat chips (`campaignFacts` in `playerEffects.ts`), the phase emblems and relics as emblem chips, and the log names both events.
- A boss seat's pod and tile carry a crown chip and the `boss` edge, and the pod a phase track (passed, now, to come; the current phase named), which the abilities bar carries instead in Boss mode; a fallen hero's carry the Spirit mark (its tooltip says what a Spirit is), a ghost at the life figure, a dashed spirit edge, colour drained and "Spirit" in their names (`table/campaign/`).
- Boss mode (`BossLayout.tsx`, `layout.ts` `BossSides`): a table with a boss seat (`bossSidesOf`: the seat with `boss` and its team) opens with the boss's side on top (the boss's board wide with its pod, minions in columns beside it) and the party at the bottom: the other heroes as tiles over their boards in a band, your board below. The three rows share the height by what each draws (`bossSplit.ts` `splitBoss`, glue in `bossRows.ts`, read by `splitRegions`; `Regions.party`): the heroes' cards are the largest rung at which the allies' band and your row fit with the boss's row at its fair share of their card (`BOSS_FAIR_SHARE`, 0.66, at least `BOSS_CARD_FLOOR_PX`), so the boss's cards stay at 60 % of the heroes' or more where its board is like theirs, and a held split that leaves it under that gives way (`holdBoss`); the boss then takes what is left, its cards at most `BOSS_SCALE` of the heroes' and its row at most `BOSS_SIDE_MOST` of the room (`GridCardContext` cuts its cards to `PartyRows.bossCard`); what the rows do not need goes to those that draw permanents. The allies' columns share the band by permanents (`allyShares`; a tile press widens a hero), a tile strip replaces the band where it would be under `ALLY_ROW_MIN_PX`. A hero's frame is thin (`ALLY_FRAME_PX`) and carries its zone chips beside its tile, so its board takes the rest of the frame; three heroes at ten permanents each draw 76 px cards at 1400 × 900. A board without permanents is one line: the boss's side its abilities and pods as lines (`BOSS_LINE_PX`), an ally its tile (`ALLY_LINE_PX`), your row your pod as a line (`OWN_LINE_PX`) while your hand has nothing to play; a hand that can still fill your board keeps its room. A hand dock with nothing in it (`handIdle`: no card, commander or top card) is a slim bar of `HAND_SLIM_PX` (`planTable` `handSlim`, boss mode only) and the boards take the rest. The opening-hand decision floats in the centre overlay as at every table (Opening hands). On a phone both sides are tile strips over one board and the decision stays in the strip. The menu offers Boss, Grid and Focus; team chips are left out, the place telling the sides.
- The boss's abilities (`campaign/bossAbilities.ts`, `BossAbilities.tsx`): one row over its side that never wraps: the phase track, then a chip per ability (icon and name, the first sentence for a screen reader) in `barOrder` (phase in force, scheme, Omen, phases to come, always on), the whole rules on hover, focus or press; chips the row has no room for are counted on the "All" button, which lists every ability in full. Under the bar (`BossBarContext`) the boss's pod leaves out its phase, scheme, Omen and emblem chips. The log names a boss's trigger "Boss: ability triggers".
- When a batch turns the viewer's seat into a Spirit, a full-screen moment says "You are a Restless Spirit" in three lines (`SpiritMoment.tsx`); while a Spirit holds priority the prompt shows the Spirit panel (`SpiritPanel.tsx`): the ectoplasm as pips and each haunt action as a big button with its price, a plain sentence and its effect, or why it cannot be taken now (`haunt.ts`); a line under the title says when the table asks a Spirit (`SPIRIT_ASKED`, [delves.md](delves.md)). The log names haunt actions ("Bo haunts the fight: Wail") and a return to life; the fight panel of the run page lists the ways back (`RevivalNote`).

- A cost a rule drew anew (`ObjectView.cost_now`, the Unmaker): the card carries a pip strip with a primary ring over its picture's printed cost (`CostNowMark.tsx`), the text face draws "Mana cost now", the preview adds a "Costs now" row under the printed cost, the spoken name says both, and the hand's Mana reason and the command-zone cost line read the cost now. ## Reviewing cards

`/review` is the one place where a player reviews the cards that need attention ([cards-dsl.md](cards-dsl.md), Read tier; endpoints in [server.md](server.md), Reads): `?deck=<id>`, `?precon=<code>`, `?mine=true` (the account's decks) or none (every card waiting for a first read). `/read` with the same parameters forwards to it, and every link to reading or checking cards opens it (`readPath`).

- `net/reads.ts` `createReadsApi` is the typed client of `GET /api/reads`, `GET` and `PUT /api/reads/{oracle_id}`; a failure is a `DeckError` (`stale_read` among the codes).
- Items (`features/reads/review.ts`, pure): To read is the `ReadQueue` (drafts that run Unverified or take more reads). To check is the target's cards played partly or wholly by hand (`useCheckCards`), less those to read; with no target there is no To check.
- `ReadPage` (route `review.tsx`) sends a visitor signed out to sign-in and tells a server without accounts. `ReadView` has a header (`queueWords`), progress ("5 of 12 reviewed", `progressOf`) and the ways out; from `lg` a list beside the card (`ReviewList`), below it a "Card 2 of 12" bar with Previous and Next. A verdict or Checked opens the next open card, preloaded, announced politely; the last shows "Every card is reviewed".
- A card to read (`ReadCardView`, `useReadCard`): picture, name, state, counts, the account's verdict and `ReadSheet` (each Oracle clause beside the game's words, `engineWords`; a row's tone is an icon and words with a `support-*` edge), then "Reads right" or "Reads wrong" with a note of at most 280 characters. A card to check (`CheckCardView`): picture, line-marked Oracle text (`LineMarksList`), reasons, "Play by hand in <deck>" and "Checked".
- Wording-only bulk (`BulkApprove`): the cards `GET /api/reads/bulk` lists (every differing clause matches by wording alone) are offered as "Approve N wording-only"; its dialog shows each pair with the changed words marked, and `PUT /api/reads/bulk` approves them. `/read/bulk` (`features/bulk-reads`) lists every such card grouped by rule.
- Keys (`reviewKey`, `ReviewKeys`): C reads right or checked, W reads wrong, J or Right next, K or Left previous, H plays by hand in the card's only deck, ? shows the keys. The verdict buttons stay `aria-disabled` for `READ_DELAY_MS` (2 s) after a draft appears, so nobody judges a card unread.
- The server keeps the verdicts; the browser keeps the current card and the cards checked per queue (`localStorage`). A 409 `stale_read` shows "The rules changed" with "Load the new version". After Reads wrong the screen offers "Play by hand in <deck>" when a deck is reviewed, else a link to `/decks/unvalidated`.
- `ReadDialog` is the card to read in a dialog, without its picture. The table's pinned preview offers "Read its rules" to a signed-in player for a card on a read or with clauses by hand (`readableOf`); the dialog lives in `CardPreview` and reads its client from `ReadsApiContext`.

## Learn

`/learn` (`features/learn/LearnPage`) lists the tutorials of `tutorials.ts`, each with a description, Start or Replay and a Done mark kept per browser (`localStorage` `learn-done`). The Play page links to it. A tutorial is a guided game or a page tour; both draw with `components/tour/TourCard`, placed by `placeCard`.

- Playing a game: `POST /api/tutorial` ([server.md](server.md), Tutorial table), then the game page with the seat link; `sessionStorage` `tutorial:<game>` names the lesson, and `GameTable` mounts `LessonCoach`. `lesson.ts` is the step machine (pure): each step has a text, targets and a `done(facts)` test over `lessonFacts(PlayState)` (turn, step, the pending decision's kind, own lands and creatures, the stack, the combat, the command zone, the result), and `advance` moves past every step already done, so a step advances on the game state, never on a timer or a count. A step that waits on the player lists the decisions it is shown at and names the button to press; `lesson.test.ts` walks the server's trace of the tutorial table (`tutorialTrace.json`) and requires at every decision of the player a step for that kind that names the button or card. Steps: a land, Grizzly Bears and its payment, end the turn, the Plains, combat, the attack, pass after it, Hero in Training and its payment, resolve it and its trigger, end the turn, pass the bot's attack, block, Giant Growth with its target and payment, a land, Giada from the command zone and its payment, the winning attack and its pass. The coach does not block the table (the shade takes no pointer), shows "Waiting for you" instead of Next on a step that wants an action, and Skip ends the lesson.
- The manual panel: the same table with the `manual` lesson: open Commands, pick a card and move it by hand, then the card menu; a step is done when the panel shows or the seat's own `ManualAction` is in the log.
- The table: the table tour (`startTour`) on the tutorial game.
- Page tours (`pageTours.ts`, `PageTourHost` in the root layout): one tour per page, in parts by path. `startPageTour(id)` opens the part of the current page; a part that ends before the next page says where to go, and the next part starts when that page shows its first target. Building a deck (`/decks`, then a deck's builder), Choosing a deck and seats (`/new`, then the lobby), Reviewing cards (`/review`), The rules lexicon (the lexicon dialog on `/learn`, held open and modeless while the tour runs, `lexiconStore.held`).

## Testing

- vitest on jsdom: `scripts/check.sh web`, or `pnpm test` in `web/`.
- Clock budgets and timeouts go through `scaled(ms)` (`test-utils/loadFactor.ts`): times `1 + load / cores`, at most `MAX_LOAD_FACTOR` (12). `MTG_LOAD_FACTOR` sets the factor; `MTG_STRICT_PERF=1` keeps the numbers as written.
- A test of a timer never sleeps or races the real clock: it runs on a fake clock (`installFakeClock`, `settle(ms)`, `flushFakeClock` in `test-utils/fakeClock.ts`) or waits with `waitFor`/`findBy` on the state it asserts.
- `src/test-utils` has the fakes (`FakeNetwork`, `FakeTimers`, `startSession()`), the Rust-generated `transcripts` (replayed by `transcript.test.tsx`) and the harnesses `renderGame()`, `renderTable`/`renderLiveTable` (laid out for `TEST_VIEWPORT`; jsdom has no layout, so measured sizes are faked) and `renderApp`. A new prompt copies `Priority.test.tsx` and `PriorityLive.test.tsx`.
- Screenshots: `node scripts/ui-shot.mjs <url> <out-prefix>` (options in `CLAUDE.md`) over a dev route; `--theme dark` or `light` sets the scheme Firefox reports. Pages other than the table read their width at mount, so shoot one width per run. A stored theme needs a reload in `--wait`: `(sessionStorage.getItem('s') ? <ready> : (sessionStorage.setItem('s', '1'), localStorage.setItem('theme', 'dark'), location.reload(), false))`.
- Layout audit: `node scripts/ui-audit.mjs <url or /path>... --base <dev server>` measures pages in Chromium (`CHROMIUM_PATH` as for e2e) with the rules of `layout.spec.ts`, prints a row per page, size and theme and exits 1 on a failure; the options are in the script. It loads `e2e/layoutAudit.ts` as it is and needs Node 22.18 or newer.

## Conventions

- Cards the engine plays only in part (Partial, Manual or Stale) are "played by hand" everywhere, in the words of `lib/byHand.ts`; a card's mark keeps its support state's name, and a Read card runs whole, so it is never "played by hand" (`runsWhole`, `ON_A_READ`). `lib/byHand.test.ts` fails on any other spelling in the sources and specs.
- The words a player reads spell "color" the American way, as the rules, cards and deck issues do (`spelling.test.ts`); identifiers keep theirs.
- Server-held state is shown, never predicted: ready, yields, stops and Full Control change on screen only when the server says so.
- Colour never carries meaning alone, and live regions are polite. A row of cards, a ladder row or a list is one tab stop (arrows, Home, End); a control that must keep focus when it cannot act is `aria-disabled`, not `disabled`.
- Every animation sits inside `@media (prefers-reduced-motion: no-preference)`, and a CSS test per stylesheet (`*Css.test.ts`) fails when one leaves it; under `reduce` an effect is a still highlight, the clock bar is not drawn, the turn banner only fades, and phase themes, the focus board and the tab title change without motion. JS reads `useReducedMotion` or `prefersReducedMotion`.
- Colours are tokens with a light and a dark value (`tokens.test.ts` checks their contrast); Tailwind class names are written whole so Tailwind can see them.
