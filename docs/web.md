# Web client

The browser client: game creation, lobby, table, decision prompts and accounts, on the wire contract of [protocol.md](protocol.md) and the transport of [server.md](server.md). The design rules are in [ui-design.md](ui-design.md).

## Stack and layout

React, Vite, Tailwind, shadcn/ui on Base UI, TanStack Router and zustand. Commands are in `CLAUDE.md`.

- Pages live in `src/features` (`admin`, `auth`, `browser`, `builder`, `cards`, `create`, `decks`, `fixmarks`, `game`, `games`, `precons`, `settings`, `table`); `src/routes` only picks them. The Vite plugin rewrites `routeTree.gen.ts` on `pnpm dev` and `pnpm build`; commit it with the route change.
- `src/net` (REST, socket) and `src/play` (session, store) hold the client. `src/components` has the shell and the pieces pages share; `src/components/ui` is shadcn (`pnpm exec shadcn add <name>`) and is edited to the tokens. `src/protocol` has the ts-rs bindings and the transcripts Rust writes.
- The dev and preview servers proxy `/api` and `/ws` to `MTG_SERVER_URL` (default `http://127.0.0.1:8080`) and keep the browser's `Host`, which the server's Origin check compares with the page's `Origin`.

## Design system and shell

Roles, scales and rules are in [ui-design.md](ui-design.md) (Design system). `src/index.css` holds the tokens as CSS variables that `@theme inline` maps to Tailwind classes; the `dark` class on `<html>` swaps the colours.

- `PageShell width` is `narrow`, `page` or `wide` with the gutters; a `PageShell` sets no `max-w` of its own (`pageWidths.test.ts`). Play, Precons, My games, Create and the builder are `wide`; Decks, the lobby and game over `page`; sign-in and register `narrow`.
- `Button` `loading` shows a spinner and ignores presses while the button stays focusable (`aria-disabled`). `Popover` has `keepMounted` (content stays in the page, hidden, while shut). `Sheet` is a non-modal dialog drawn into an overlay the page sizes (full width on a phone, 24 rem from `sm`); only Escape or Close shuts it. `Loading` is a polite status at once and the skeleton after 300 ms (`useAfterDelay`). An error is an `Alert` with an icon and a title, and a Retry where retrying works.
- Theme (`hooks/useTheme.ts`): `createThemeStore` keeps `light`, `dark` or `system` in `localStorage` under `theme` (system removes the key), sets the `dark` class, and follows `prefers-color-scheme` and other tabs' `storage` events. It works when storage or `matchMedia` is missing or throws. A script in the head of `index.html` sets the class before the first paint; `themeScript.test.ts` holds it equal to the store.
- `components/AppShell` frames every route: a skip button (it focuses `main`; a `#main` link would replace the seat token in a game address), the header (Brand; navigation Play, Precons, Decks and My games when signed in, Create; `ThemeMenu`; `AccountNav` with Sign in and Register for a guest, and for an account a menu with Accounts for the admin only, Account settings and Sign out), `AuthNotice` and `OfflineNotice`, then `main`. Under 640 px the navigation drops to a second row and Register leaves the header.
- `useFullBleed` (`components/appChrome`, counted) makes the shell draw no header and the root the window high with `overflow: hidden`; the game table is the one such page. `useFitWindow` makes the root the window high and `main` a flex column, so the page scrolls one region inside itself; Play, My games, Precons, Decks, the builder and game over use it.

## Data flow

- `net/api.ts` checks REST bodies at runtime; a failure is an `ApiError` with a code of `crates/mtg-server/src/api.rs` or a local `unknown`, `network` or `bad_response`. `net/parse.ts` `parseFrame` is the only door from the wire (JSON, known `type`, required fields, 1 MiB cap); garbage is a `FrameError`, never a throw.
- The game browser calls (`listLobbies`, `joinGame`, `joinByCode`, `leaveGame`, `releaseSeat`, `setVisibility`, `closeGame`, `chooseDeck`) reject with a `LobbyError {code, status, retryAfter, issues}`; `describeLobbyError` (`net/lobbyErrors.ts`) has words for every code. `listLobbies(previous)` sends the `ETag` and on a 304 resolves with that very object, so `result === previous` means nothing changed. A seat token goes in `Authorization: Bearer` and the session cookie rides along, so a call with no token acts for the signed-in user's own seat.
- `net/socket.ts` `GameSocket` sends `Join` first and once per connection. `net/pacer.ts` holds sends to a burst of 30, then 15 a second; the server allows 40 and 20 and closes a socket over it with 1008.
- `play/view.ts` holds pure ports of `StateView::apply`; unchanged objects, players and zones keep their identity. `play/session.ts` `createSession({game, token, name})` owns the socket, applies the client rule of [protocol.md](protocol.md) and writes the zustand store (`play/store.ts`) that screens read with `useStore(session.store, selector)`.

The session's rules:

- A Snapshot sets the base and `seq`. A batch whose `from_seq` is not `seq` (or any batch but the one at 0 while there is no view) sends one Resync; nothing is applied and decisions are ignored until the next Snapshot.
- A `Decision` replaces `pending`. `answer()` sends once per decision id; a Snapshot or a lost connection forgets answered ids, so the server's repeat can be answered.
- `GameOver` sets `result` and makes a later close final. `StaleDecision` and `IllegalAnswer` give a notice and a Resync; `BadMessage` and `Internal` only a notice.
- A wrong token is a refused upgrade, which a browser reports as 1006, so the client retries forever.

| Close or message | Socket status |
|---|---|
| 1001, 1006, 1013 and any code not listed below | `reconnecting`: retry after 250 ms doubling to 15 s, less up to 50 % jitter; a Welcome resets it |
| 4000 | `replaced`, no retry; `connect()` takes the seat back |
| 4001 | `stopped`, notice "You were removed from this game." |
| 4002 | `closed`, notice "The host closed this game."; the lobby ended |
| 1000, 1002, 1007, 1008, 1009; `Error` UnsupportedVersion or UnknownGame | `stopped`, reason in `notice` |
| any close after `GameOver` | `stopped`, no notice |

## Create and game pages

- `/` (`browser/PlayPage`): the open games of `GET /api/lobbies`, a Create game link and a "Join with a code" field. `useOpenGames` polls 5 s after each answer with the held `ETag`, pauses while the tab is hidden and keeps the rows, dimmed, beside an error with Retry. `FocusKeeper` sends focus from a removed row to the next Join. `useJoinGame` runs one Join at a time. A signed-in visitor joins in one click; a guest answers `GuestJoinDialog`, a name checked by `create/form.ts` and kept in `localStorage` (`guestName.ts`, every access in try/catch). The answer opens `/game/$gameId#seat=n&token=…`. A seat that is gone (`full`, `started`, `not_found`) closes the dialog and reloads the list; `joinErrors.ts` gives a row's 404 one sentence that names no cause. The join request carries a name only (the player chooses the deck in the lobby).
- `JoinWithCode` checks the code (8 symbols of the server's alphabet, any case, with spaces and hyphens) and joins through the same hook. A 404 reads "No open game with that code."; failures a guest can retry stay in the dialog with the name kept.
- `/join/$code` (`JoinCodePage`) is where the lobby's invite link leads: the code as `K7M2-9QXA` and one Join button through the same hook; a guest gives the name on the page. Text that is not a code says "That is not a join code" and makes no request. A dead code ends the page with links to Play and Create a game.
- `/new` (`create/CreateGamePage`): `CreateForm` asks for the format (Commander by default, with a line naming its rules from `formatRuleWords`), the seat count (`SeatCountField`, a number field from 2 with no most), the creator's name (`HostFields`; a Normal game also takes the creator's deck there, a Commander game leaves it to the lobby), house rules and Visibility (words in `lib/visibility.ts`, shared with the lobby). The request carries `format` and, only when filled in, `house_rules`; it holds only the creator's seat (`held: 1`), the other seats are open and their players choose a deck in the lobby. `AdvancedOptions` ("Give every seat its own link", Normal only) gives each seat a name and a deck, makes the game invite only and holds every seat; `GameCreated` lists the links. A game with open seats opens its lobby on seat 1. From 768 px the form has two columns (the game, then the options). The Create button is in a footer that sticks to the bottom of the window. `create/form.ts` repeats the server's checks and holds the draft; `create/apiErrors.ts` words every `ApiError` code.
- House rules (`lib/houseRules.ts`): one `RuleSpec` per rule, shared by the form, the lobby and the table. A field starts empty with the format's value as placeholder and an empty field keeps the format's rule, so the request carries only what was filled in. `describeRules(rules, format)` names the rules that differ from the format's own. The lobby shows them (`LobbyRules`), the table's top bar has `TableRules`, and the Mulligan prompt names the new hand size and the scry.
- Keyword glossary (`lib/glossary/`): `TERMS` holds every keyword ability, keyword action and ability word with one-line reminder text. `glossary.test.ts` holds it against `Keyword::NAMES` of `mtg-cards` and `catalog.json`. The preview lists a reminder for each keyword a card has; `KeywordText` marks keyword words in ability texts and log lines; `GlossaryPanel`, the Keywords button of the top bar, is the searchable list.
- `/game/$gameId#seat=<n>&token=<token>` (`game/GameRoute`) reads the fragment from the router's raw `location.href`, because its `hash` is percent-decoded. A seat token lives only in the fragment, which a browser never sends. `components/SeatLinkRow` prints it only inside a `data-share-link` anchor, and tests scan the page for tokens outside those (`test-utils/leaks.ts`). `lib/invites.ts` keeps the host's seat links and the join code (shown once) in `sessionStorage` (every access in try/catch) so the lobby can hand them out.
- `game/GamePage` makes one session per (game, seat, token) and connects one microtask after mount, so StrictMode opens one socket. With a seat link it joins by token whoever is signed in; without one and signed in, `account=<username>` opens `/ws/{game}` with no token and the cookie of the upgrade picks the seat. `game/gameContext` gives `useGame()` and `usePlay(selector)`; `lookup` is `GET /api/games/{id}`, polled every 3 s in the lobby.

| Store | Screen (`connectionOf`, `game/connection.ts`) |
|---|---|
| no seat link and not signed in | `SeatLinkMissing`; no socket |
| `phase` over | `GameOver`; no connection notice |
| `status` replaced or stopped | `ConnectionNotice` alone: the reason and a button to connect again |
| `status` closed | `ConnectionNotice` alone, with Back to Play and Create a game, no way to connect again |
| idle or connecting, never welcomed | "Connecting to the game…" |
| `reconnecting`, `attempt` below 5 | "Connection lost. Reconnecting… (attempt N)" |
| `reconnecting`, `attempt` 5 or more | "Cannot reach the game" and "Try again now"; the socket keeps retrying |
| welcomed | `Lobby` while `phase` is lobby, `GameTable` while playing |

After a Welcome the lobby or table stays under the reconnect notice. A `notice` shows above any other screen as a dismissible alert.

## Lobby

- The `Lobby` message is kept whole as `lobby` (`{seats, needed}`) and dropped when the connection goes or the game starts. `game/lobbyModel.ts` (pure) makes the rows: the roster wins; before it and while reconnecting the REST lookup stands in, with "Seat N" for an unnamed seat. `removable` says which rows get Remove.
- A polite live region announces what changed between two looks (at most three changes, none for this seat's own connection). `LobbyVisibility` reads the lookup (`readGameInfo`), so a reload keeps it; the host gets `VisibilityToggle` in its place, and `useVisibility` keeps a new value until the lookup agrees. From `COMPACT_LIST_FROM_SEATS` (13) the seat list scrolls in a box of its own.
- Every named seat shows its deck to the table (`LobbySeatRow`) as name, format and a count of cards played by hand (`deckWords.ts`), never a card name; a seat with none says "no deck yet".
- Layout: `Lobby` is a `wide` page, one column under 1000 px and two from it. Left, the game (`lobby-game`): title, house rules, visibility, the invite link and code (host; `JoinInvite`, above the seats so they are in view at 1366x768), the seats with a headline over a progress bar, and Close game or Leave game last (after Ready in the reading order). Right, the sticky deck column (`lobby-deck`): "Your deck" and `ReadyBar`. On a phone `ReadyBar` sticks to the bottom of the page.
- `DeckChooser` is on this page's own seat until it is ready; afterwards one line says the deck is locked until Not ready. Tabs: "Your decks" (`useDeckList`), "Built-in" (Normal games, `useDecks`) and "Precons" (`GET /api/precons`); the game's format filters each list (a Commander game takes Commander decks and precons with a commander). A list is fetched when its tab is first opened and kept.
  - Master and detail (`DeckList`, `DeckOption`, `DeckPane`, rows are `DeckEntry` of `deckEntries.ts`): a listbox (`role=option`, arrows, Home and End, Enter or double click chooses) over a search and filters (commanders' colour identity; support). A row shows commander pictures, name, facts, colour discs and the support chip of the list's own check (`entrySupport`). "Sort by" (`SORT_CHOICES`, kept in `localStorage` by `deckSort.ts`). Pictures load when a row scrolls into view, at most four at once for the page (`imageQueue.ts`). A starred precon (`useFavourites`, `GET/PUT/DELETE /api/favourites/precons`) is listed under "Your decks"; a guest sees no star and a refused change puts the star back with the reason.
  - The preview of the selected deck sits beside the list (a dialog under 1000 px): `DeckPreview` with the table's verdict (`useVerdicts`, only the selected deck, once the selection has rested 200 ms) as its legality, "Use this deck" (disabled for a deck the table cannot take; a failed check says so with Check again and the deck can still be used, the server judging it), and a link naming the cards played by hand (`notValidatedWords`). Cards come from `GET /api/decks/{id}` or `GET /api/precons/{code}` (`useDeckDetails`).
- `features/decks/preview` is the shared deck preview (the builder reuses it): `DeckPreview({ deck, legality?, notValidated?, actions?, body? })` over `DeckPreviewData` (`previewFromDeck`, `previewFromPrecon`, `previewFromDraft`): commanders as large pictures, legality, colour identity, support counts with a bar, the mana curve (lands left out), type bars, and the cards grouped by type (`groupByKind`, `KIND_ORDER`) as small pictures with count badges.
- `useDeckChoice` sends the press through `api.chooseDeck`, one request at a time: the deck pressed shows a spinner and keeps focus, every other control waits, and a polite line reports the result. A refusal puts the old choice back with the reason; 422 `deck_blocked` lists the issues, only to the player whose deck it is.
- `ReadyBar` holds the Ready button (always in the window) and the words beside it (`readyState`). The button follows the server's roster; a reconnect sends no Ready of its own, and the second click of a double click is ignored (`event.detail`).
- `useLobbyControls` sends the calls of the controls one at a time with the seat's token: every button waits while one is out, and the one pressed shows a spinner and keeps focus. A 409 `started` takes the controls away and leaves one line that says why.
- Remove is offered on each seat somebody took, not the host's own and not one this tab holds a token for. `LobbyQuestion`, an alert dialog, asks before Close, Leave and Remove (words in `lobbyQuestions.ts`): the safe answer is first and takes the focus; Escape does nothing while the request is out; a refusal keeps the question up; focus returns to the button that asked. Close and Leave call `showFlash` and go to `/`; `FlashNotice` in the shell (`lib/flash.ts`) shows the notice for 10 s or until dismissed.
- `JoinInvite`: the invite link `/join/<code>` and the code, each with a `CopyButton`; both come from this tab's `sessionStorage`, and a guest never sees either.

## The table

`features/table/GameTable` takes no props: it reads with `usePlay(selector)` and starts from `TableOptionsContext` (`mode`, `focus`, `effects`, `effectsSlow`, `cues`, `viewport`; only the dev route and tests set it). The table is exactly the window high and never scrolls the page.

### Regions and breakpoints

`TableGrid` is one grid inside a root that clips (`h-dvh overflow-hidden`). Each region is a cell with `min-height: 0` (`data-area`); a zone that cannot fit scrolls inside itself with an edge fade (`fade-scroll`, `useEdgeFade`), never the page. The offline notice and the connection and server notices of `GamePage` (`data-slot="table-notices"`) float under the top bar.

- `layout.ts` is pure and holds the sizes: `regionSizes(viewport)`, `sidePanelRows` (the rows an open rail panel or sheet takes: from the opponents down to the strip or your board, never the bar or the hand and controls row; while this seat must answer a decision whose prompt sits in the strip it takes the opponents' row only, so the prompt and the cards it asks you to click stay in view), `gridRows`, `gridColumns` and `mainColumns` (CSS templates held equal to the numbers by `layoutRegions.test.ts`), `chooseMode`, `arrangeSeats` and `planTable`. `useViewport` follows the window.
- Mode: grid for 2 to 4 seats unless a board column would be under 280 px (`gridColumnWidth`), focus otherwise; the menu's Grid and Focus override it. A table has no most seats: focus from 5, compact cards from `COMPACT_FROM_SEATS` (8), the strip scrolls sideways and `useKeepInView` keeps the large board's tile in view. Focus draws a two-line tile per opponent and one board large: the active player, else the priority holder, else the next seat still in, following the turn until a tile is chosen ("Follow the turn" undoes it). The strip leads with the seat whose turn it is (`planTable`, `activeFirst`) and `useLeadInView` scrolls it back to its start. When the large board changes seat, `FocusBoard` keeps the old board for `FOCUS_FADE_MS` (150 ms, `useBoardFade`) and the two cross-fade; the leaving board is `inert` and `aria-hidden`; nothing fades under reduced motion.
- Seats (`SeatPlan.shape`): `duel` is a wide board beside a 168 px pod column; `columns` (3 or 4 seats) are two or three columns of a one-line pod over a board, each opponent's board in a bordered frame (`seat-frame`); a seat that lost or conceded leaves its frame for a thin strip (`left-strip`); `focus` is the tile strip over one board with a pod column. On a phone a pod is one line, yours at the foot of your board.
- Pods (`SeatPanel`, `SeatTile`, `PodParts`, `podFigures.ts`): the seat's name beside a dot in its colour (`seatHue`), life as the largest figure (red at 5 or less), the mana pool while mana floats, the untapped mana sources by colour (`UntappedSources`), and chips for hand, library, graveyard and exile, each with an accessible name; the graveyard, exile and command zone chips are buttons that open their list. A slot with nothing to say draws nothing. The root carries `data-state`, a list of `active` (the seat of a running turn) and `priority`, and the turn cues draw from the same two facts. The active seat has a 3 px edge inside the pod or tile, since a pod column clips what lies outside it: `ACTIVE_EDGE` for an opponent (with `ACTIVE_TINT` on a tile), `your-turn-cue` for yours. A seat that holds priority without the turn has a `PriorityDot`; a pod says "Active turn. Has priority." to a screen reader. Outside a running turn no seat is active.
- Commander at the table (`commander.ts`, `CommanderChips`, `commanderLog.ts`): a pod draws the commanders in its command zone in its corner (a one-line pod as a chip opening the list); yours wait at the head of the hand dock (`commandersInHand`) with a crown and the tax, and the Priority prompt marks them like the hand, so a commander is cast from there. A tax chip shows once a commander was cast. The seat that took commander damage shows a chip per commander ("Atraxa 14/21") against `commander_lethal`: muted, the warning tone from six below lethal, red from three below, filled red at lethal. A yes-or-no question about the asker's own commander is the return choice, with Return as the focused primary button. The log names a commander's combat damage to a player, a move into the command zone, `CommanderStayed` and a loss to commander damage.
- Text face (Text only, or while a picture loads or is missing): counters are chips in the art area (`counterLabels`), a planeswalker's loyalty is the number where power and toughness go, an Aura or Equipment has a dashed "On <host>" chip and its host a grant mark per attachment; a card reads all of it aloud. Further state chips come from `statusChips` (Tapped, Sick, damage, combat role, Face down, Back face, Copy, Merged, Prepared, Level). A token without a picture is drawn as a card in the colours of the card back. A card with keywords lists them as plain text (`keywordLine`). `groupPermanents` keeps permanents apart that differ in anything a face shows. A phased-out permanent is drawn ghosted (`data-phased-out`).
- Shared strip (`SharedStrip`): the ticker is the last row of its sheet; the prompt keeps its title for a screen reader only. A prompt that needs more than the strip grows into a sheet of at most 40 dvh: `useSheetOverhang` sets `--sheet-overhang` on the main area and the opponents' area pads its bottom by it, so the sheet lies over no card of a battlefield and your board, the hand dock and the controls stay in view and clickable; past 40 dvh, or on a phone past what leaves the opponents' tile strip and a row of their board (`SHEET_KEEP_PX`, `sheetMost`), it scrolls inside itself while the answer row (`prompt-actions`) stays sticky. The ways on: "Create another game", "Look at the table and log" (`ReviewBar`, the final table read only with Log and Stack, "Show result" brings the result back), "Back to Play" and, for an account, "My games". A page that never got a view of the board shows the headline and the buttons with no list.
- Battlefield lanes (`Battlefield`, `CardRow`, `CardStack`): a board draws the bands of its lane fit ([Fit and grouping](#fit-and-grouping)), each lane a list with a faint ground (`bg-lane`) and `data-lane`; an opponent's board sits at the foot of its area, mirrored. A closed stack is the card on top with two edges behind it and a ×N chip; click, Enter or Space opens it in place and moves focus to its first member; Escape or the chip closes it. A stack keeps its key while any member stays. While the active prompt marks a member legal or selected, the stack is held open and cannot be closed. `TableOptions.stacks` is on except under vitest.

Each row keeps a quarter of the room (`MIN_ROW_SHARE`); with no permanent anywhere, or no fit at the floor, the room splits 1 to 1.15. The prompt sheet's overhang counts against the opponents' row in steps of 8 px up to `SHEET_RESERVE_MAX_PX`. The rows are `fr` weights equal to the split's px (`gridRows`). The duel board (`?board=duel`) draws your creatures 150 px wide or more and the opponent's 120 at 1440x900, 190 and 160 at 1920x1080, 100 and 80 at 1280x720 (`boardSplit.test.ts`, `fit.spec.ts`); 40 permanents a seat fit both boards of a duel from 1024x768 up without a zone scrolling (`rowStacks.test.ts`).
- Rendering: a `Card` reads only its own object and combat role and is `memo`; a `Battlefield` reads its seat's stacks as ids and keys (`battlefieldStacks` through `useStable`). A batch that taps one permanent redraws that card, and its row only when a permanent changes stack (`perf.test.tsx`).
- Preview: hover and focus show a card large, a click that only looks pins it until Escape or Close, and a click that acts (the prompt marks the card) pins nothing. `previewFit` (pure) sets its size and place: from 640 px it docks at the side away from the card with a picture from 240 to 480 px; a tall narrow window docks it above or below the card. The preview of a host lists its attachments (`attachLine`); the preview of an attachment names its host or player (`hostLine`).
- Cards carry `data-object-id` and pods `data-seat`; regions carry `data-region` (`bar`, `shared`, `hand`, `controls`) and cells `data-area`; the prompt mounts in `[data-slot="decision-line"]`.

## Fit and grouping

`features/table/fit.ts` and `group.ts` are pure (no DOM, no store) and decide how big a zone's cards are and which permanents share a box.

- `fitRows(box, groups, limits)`: a group is a row with its `stacks` and card shape (`aspect` 7/5; `scale` 1, or `LAND_SCALE` 0.8 for lands). It tries card widths from 112 px down to the 44 px floor in steps of 2 and answers with the first at which every row wraps inside the width and all lines fit the height. A width that fits keeps fitting at a smaller one, so a bigger box never gives a smaller card.
- Whole pixels: the box is floored; a row's box is the card width times `scale`, rounded to the nearest px, and its height that width times `aspect`, rounded the same way. Components draw exactly those sizes. Every stack takes one box of its row's size, tapped or not. `FIT_LIMITS` puts 6 px between boxes and 4 between lines. When the floor does not fit the height, `scrolls` is true and `hidden` counts the stacks cut off, the "+N" of the zone's edge fade.
- `groupPermanents(permanents, { groupOthers })` merges permanents with the same face into a `Stack` (`key`, `count`, `members`): name, owner, controller, token or card, types, colors, power, toughness, abilities, tapped, summoning sick, damage, counters, attachments and host. Tapped and untapped never share a stack. Lands and tokens always merge; other cards only with `groupOthers`, which the caller sets when a zone's fit is under `GROUP_OTHERS_BELOW` (64 px). A permanent in combat (`role`) never merges.
- Stacks come in the order of their first member. A merged stack's key is its face and a card that stays alone has its id, so a key survives members joining and leaving and one member joining or leaving changes no other stack's key, count or place. `expandStack` returns the members, for opening a stack in place and for prompts that need each one.
- Attachments: an attachment whose host is on the battlefield takes no box; it is a `tucked` id of its host's entry (`tuckedOf`: Auras, then Equipment, then Fortifications), drawn behind the host, and `LaneCounts.tucked` gives `fitLanes` the deepest tuck of each lane (`tuckOf`).
- Use: `battlefieldStacks(state, seat)` (`rowStacks.ts`) groups a seat's rows once per view into ids and keys, twice: lands and tokens merged, and every identical card merged too. `layoutSeat` fits the zone's content box (`useContentBox`, a `ResizeObserver`) with `fitLanes` over the first and, when its cards would fall under `GROUP_OTHERS_BELOW`, over the second. `Battlefield` writes `--card-w` and `--card-h` and the width on each lane; a face is whole from 76 px, short below it, and takes the larger type from 150 px. Without a measured size (jsdom, a hidden zone) cards keep the box of their size. `fitPerf.test.ts` holds grouping and fitting 40 permanents a seat for 6 and 12 seats to a few milliseconds.
- `fitLanes(box, counts, facing, limits)` (`laneFit.ts`, pure): the lanes are lands, creatures and other permanents (`rowOf`). A shape stacks them in bands: `one` (side by side), `two` (creatures, then lands beside other permanents) or `three`; bands run from the middle of the table outwards, so an opponent's (`far`) are reversed. A band takes the fewest lines at which its lanes fit the width side by side. Creatures take the card width, lands and other permanents 0.8 of it (`scaleOf`). A band with lands may fan them (`fanLane`): the lands in the most piles that fit beside the other lanes in one line, each lying over the one before below its head; the fan wins only where it is lower than plain lines. For each shape a binary search over the ladder of `LANE_LIMITS` (224 px down to 44 in steps of 2; 6 px between boxes, 4 between lines, 12 between lanes and bands) finds the largest card at which all bands fit the height; the largest wins, a tie going to `two`, then `one`. Without a fit at the floor the shape that needs the least height scrolls, creatures first, and `hidden` counts the boxes cut off.

## Prompts

`features/table/prompt/` answers the decision this seat faces.

- `PromptHost` (in `SharedStrip`, in place of the read-only "Waiting for ..." line while `ownDecision` is set) renders `PROMPTS[kind]` with the kind's `options` in a scope keyed by decision id, so a new decision remounts the prompt with an empty selection. `registry.ts` has an entry per `DecisionKind`; a new kind stops compiling until it has one (`kinds/<Kind>.tsx`), and `kinds.test.tsx` fails while a built kind is the `UnsupportedPrompt` stand-in. `PromptHost` also draws the generic prompt for a decision whose key is no kind of `PROMPTS` (a server newer than the client).
- `usePrompt()` gives `{ id, name, decision, answer, selection }`. `answer(a)` wraps `session.answer`: once per decision, false when already sent, refused by the socket (a retry is allowed) or when the store holds another decision by now. `PromptLayout` draws the shared shape: the decision's name, one polite live sentence, a row of controls.
- Card marks (`prompt/marks.ts`): `useCardMarks(marks, onSelect, { toggles })` takes a `Map<ObjectId, 'legal' | 'dimmed' | 'selected'>` from `markCards`. A click or Enter/Space on a legal or selected card calls `onSelect(id)`. Each `Card` subscribes to its own id, so publishing redraws only the changed cards. Every prompt but Mulligan, AssignDamage, OrderTriggers, YesNo, ChooseOption, ChooseMode and OrderCards dims the viewer's other cards.
- Prompt cards carry `data-candidate`, never `data-object-id`, so the lookups of the table by id find the table's card. Letters and digits are hotkeys (`usePromptKeys`: a plain press, with focus on a button too, never in a field, menu or dialog); `KeyHint` draws the key. Focus starts on the answer the response clock gives (`useDefaultFocus`).
- Hand abilities and special actions (`prompt/activations.ts`, `kinds/Priority.tsx`): `abilityPlays` makes a play per ability, `Unlock <door>`, "Suspend X", "Foretell X", "Turn face up X" and "Cast prepared X" from `PriorityOptions.abilities`, `unlockable`, `suspendable`, `foretellable`, `turnable` and `faces`; `playsOf` lists the plays of one card and `AbilityChooser` asks which when there are several. Rooms (CR 709.5): a Room permanent has `PermanentView.doors`; the table names the halves from the card's faces (`useDoorFaces`) and each door is a mark with its name and a lock, nothing where a face has no room, which the spoken name and the preview still say.
- Zone marks: a graveyard or exile chip or picture holding a card the prompt marks legal wears the ring of a legal card and a play badge (`LegalBadge`, `useLegalCount`, `legalWords`).
- The preview lists the activated abilities of the card from `ObjectView.activated` (`activatedLines`) and tags the ones the Priority prompt offers "Can activate now"; the clauses a card leaves to the table follow under "Played by hand:". Hovering or focusing any entry of the stack adds a block (`stackPreview.ts`) that names it, the rules it resolves and its targets, with a gone target marked; an ability draws its source card large while the view holds it.
- Mulligan: the sentence reads `bottom_if_keep`, `bottom_if_mulligan` and `free_mulligans`, so the client derives no count.
- Nothing to do: the newest `NothingToDo` event of this turn shows "You have no creatures that can attack" (or "block") until the viewer has answered something.
- A play taken back: the viewer's newest `AnnouncementRewound`, while nothing went on the stack since in this turn, shows "<card> could not be played: <reason>" in the same live region (`prompt/rewound.ts`) until the next question is answered; other seats read only that the seat could not finish a play.
- PayMana: `payment.ts` reads a payment as the engine does (`netMana`, `mana_cost.rs`): a source makes `count` of its mana plus `also`, and one with a `cost` is paid from mana made before it. A source or floating mana is offered only while the payment can still be finished from what is left, life for Phyrexian symbols included (`completable`, a bounded search); restricted mana is spent by hand against `PayOptions.spend` (`spendRules.ts` ports `Spend::allows`). Convoke, Improvise and Delve are rows of buttons (`offers.ts`); a permanent is tapped once whether for mana, convoke or improvise (`usedBy`). Confirm is on exactly when `covers` holds; "Pay the rest for me" only while `completable` holds; "Pay automatically" is disabled with a sentence of reason without `auto_available`. The cost is the total after X; `payment.ts` resolves hybrid and Phyrexian symbols as `ManaCost::resolutions` does and `payment.test.ts` checks it against an independent rule. `toPayment` sends `{ pool, restricted, taps, life }`, 2 life per Phyrexian symbol paid with life.
- Mana shows what it is (`manaMade.ts`, `ManaMade.tsx`, `ManaSources.tsx`, `ManaStrip.tsx`): `Gives` is what a source gives, read from a permanent's `ManaOption`s or from the `ways` of the mana abilities in `ObjectView.activated` (`manaAbilitiesOf`, never the words). The PayMana prompt has a "Mana sources" row (`ManaSources`): one line of chips that scrolls sideways; a click does what a click on its card does, so a source with several fitting abilities opens `ManaChoice`. A chip marks what a use asks besides a tap (`sourceMarks.ts`). A chosen source with another ability that keeps the payment finishable has a switch button (`paySwap.ts`). The mana pool shows each kind as its symbol and `×N`; mana whose uses are riders alone follows as plain mana with a sparkle mark (`manaRider.ts`), restricted mana comes last with a lock, and mana that outlasts the step (`ManaPool.kept`) has an hourglass. A card the seat may tap for mana (`givesNow`) has `ManaStrip` in its bottom left corner, hidden from a screen reader; the preview has a "Taps for" line.
- ChooseNumber (`numberChoice.ts`): the field starts on the smallest allowed number, Less, More, the arrow keys and the slider step over the numbers in `except`, and Confirm is off with the reason under the field for a number not allowed. With `cost` and `per_x` the total cost for the chosen X is drawn. An open range stops at 99.
- Attack by clicking (`kinds/DeclareAttackers.tsx`): a click puts a creature in the attack and a second takes it out. With several defenders the creature clicked last is held (`data-cue="active"`) and goes to the next defender clicked: a seat's pod, its tile in focus mode, the bare board around its cards (`combat/defender.ts`) or the card of a planeswalker or battle on offer; the "Attack at" list of the row chooses too, the keyboard's way. A creature in `required` (goad) starts in the attack marked "Must attack", cannot be taken out and No attack is not offered.
- Block by clicking (`kinds/DeclareBlockers.tsx`): a click on a blocker that can block one attacker blocks it, any other blocker is chosen first and then the attacker clicked; a click on a blocker that blocks takes the block back, Escape lets go. A creature in `required` reads "Must block" and Confirm waits until it blocks. A blocker blocks one attacker, as the engine demands, and `can_block` alone decides who may be blocked. `BlockOptions.min_blockers` names the attackers that need several blockers (menace): the prompt lists each (`data-slot="block-minimums"`), their card reads "Needs 2+ blockers" and then "Needs 1 more", and Confirm blocks stays off until it has enough (`blockersNeeded`).
- AssignDamage: without trample the engine takes any whole-number split that adds up to `power`, so that is all the prompt enforces; the first split (`damageSplit.ts`) gives lethal damage in the offered order and the rest to the last, with lethal figures from `DamageOptions.lethal`. With trample (`DamageOptions.excess`) the split may fall short: the rest goes to the player or planeswalker attacked, named in the prompt (`data-slot="damage-excess"`), and Confirm waits until every blocker has its lethal damage. With `DamageOptions.unblocked` a button, "Assign as though unblocked", answers with no damage to any blocker, and all of it goes to the player or planeswalker attacked.
- ChooseTargets (`targetText.ts`): the sentence names the source and gives the engine's `wording`. A click on a chosen target takes it back; the list has every legal target because a player is not a card. A triggered ability has no Cancel; its way out is the response clock's `Remove` ([server.md](server.md), Response clocks).
- DivideAmount (`divideText.ts`): one row per target in the order of `among`, each at least 1 (`MIN_SHARE`) and the whole of `total` in sum. The split starts as the server's even division, so the common case is one press of Confirm; Confirm is off until nothing is left.
- ChooseCosts (`costsText.ts`): a toggle per optional cost; the engine accepts one gift (offered as `SEAT_BASE + seat`): a second is refused with the reason in words until the first is taken back. Confirm costs sends the taken indices in ascending order, none included; focus starts on it, so a press made without looking pays nothing extra. Costs paid several times (multikicker) are asked as `ChooseNumber`.
- Generic prompt (`genericChoices.ts`, `GenericAnswers.tsx`): the prompt of every kind that has none of its own names the decision, says "This decision is not supported in the UI yet" and offers a button for each answer its options allow (at most 12), so a seat is never left without one. They follow the answer the server gives when a clock runs out. A decision that needs a set made by hand has no button and the sentence says so.
- OrderTriggers (`orderText.ts`): the list is in resolution order (the top resolves first) and the answer is the same list reversed, the order they go on the stack. At an end a move button stays focusable and does nothing.
- YesNo, ChooseOption and ChooseMode (`choiceText.ts`) ask in the card's words: the engine's `text` ("Pay {1}?"). ChooseMode: a choice of exactly one answers at once; any other toggles modes and Confirm waits for `min`; the answer lists the chosen indices in the order on the card.
- ChooseCards (`cardsText.ts`, `PromptCard.tsx`): the cards of `from` in a grid that scrolls inside the strip; a card the view does not hold is a face-down stand-in. `min` and `max` are held to the number on offer. From 13 cards a filter box narrows the list; a choice made out of sight still counts. Surveil (`kinds/ScryCards.tsx`): a `ChooseCards` whose cards are all library cards and may be none to all is drawn as two piles (`awayOf`).
- OrderCards (`kinds/OrderCards.tsx`, `lookText.ts`) and Scry (`kinds/Scry.tsx`, `scryPiles.ts`): the cards as pictures with a place number, moved by buttons, Alt with an arrow key or a number key; the scry piles also by drag. A line beside Confirm previews the result from the top down; Original order puts the list back. With nothing moved a scry sends every card on top, which is what the clock answers. `CardChoices.tsx` is the one grid of pictures for every choice of cards, with the card under the pointer or focus large at the side (`useRestingPreview`).
- ChooseReplacement (`kinds/ChooseReplacement.tsx`, `replacementText.ts`, `oracleWords.ts`): asked when two or more replacement effects apply to one event. Each effect is a row with its source card's picture, name and the words of its own effect (the card's rules text from `useOracleText` only when the candidate has none).

## Combat overlay and previews

`features/table/combat/` draws what combat will do from the engine's `combat_forecast` in the table view ([engine.md](engine.md), [protocol.md](protocol.md)); `net/parse.ts` checks it down to its leaves. The client never works an outcome out: it shows the engine's numbers and hides them when they cannot hold.

- The seam: `useBlockPreview()` (`forecast.ts`) is the forecast to draw: the table's forecast while no choice is pending and the engine's preview of the choice being made otherwise (`previewFor`). A forecast is never drawn for a choice it does not describe: marks go the moment the choice changes and return with the reply.
- `CombatOverlay` is an SVG over the table column (`aria-hidden`, `pointer-events: none`, mounted only while a line exists) in two layers: the lines under the centre strip and a faint copy above it. `plan.ts` (pure) turns the combat view, forecast and unsent choices into lines: attacker to seat or planeswalker (muted), blocker to attacker (strong, coloured by the outcome), unsent choices dashed.
- `rects.ts` measures the DOM when anchors appear and once per frame when something may have moved, never per render; jsdom has no layout, so tests inject a `RectProvider`. A card that a clipping or scrolling ancestor cuts off entirely is not drawn, so its line runs from and to its controller's pod or tile; `fit.spec.ts` holds that no combat line runs over your life.
- Marks: `data-doomed` and a "Dies" badge, a "-N" badge for damage, and on an attacked seat a chip in its life area (`LifeForecast`, `data-slot="life-forecast"`): the change of life in red, in green when a lifelink blocker would more than make up for it, a skull when lethal. The key (`CombatLegend`) lists only the kinds of line on screen. When `CombatForecast.depends_on_choice` is set a "≈" precedes the numbers and the sentences say "depending on a choice of effects".
- DeclareBlockers publishes its pairs and DeclareAttackers the attack so far (`usePublishPending`, `pending.ts`). Both end with `prompt/PreviewOutcome.tsx` as visually hidden parts for a screen reader.
- Preview ([protocol.md](protocol.md), Preview): `session.preview(decision, answer)` sends one `Preview` for the pending decision and remembers the answer's key (`previewKey`, the answer as JSON). Replies come in order, so the client keeps only the newest question's as `store.preview`, dropped with the decision, a snapshot, game over and the connection. An `Error{BadMessage}` while a preview is unanswered means an older server does not know previews: no notice, and none are asked again until the next connection. `usePreviewRequest(decision, answer)` asks `DEBOUNCE_MS` (80 ms) after the choice last changed and returns `idle`, `checking`, `ready` or `unavailable` (after `GIVE_UP_MS`, 1.5 s, without a reply).

## Table feedback

`features/table/fx/` draws short animations for what a batch did. They decorate the true state, which the table already shows when they start: nothing waits for them, no answer is delayed, and ending one only removes an attribute.

- `watchBatches(store, fx)` (`batch.ts`) subscribes to the play store. `batchBetween(prev, next)` takes a change for a batch only when `seq` moved on by exactly the events appended to the log, so snapshots, decisions and chat never animate. `deriveEffects(before, after, events)` (`derive.ts`, pure) returns `Effect[]` in a fixed order (life by seat, then `attacked`, `blocked`, `damaged`, `entered`, `died`, each by object id).

| Effect | Comes from | ms |
|---|---|---|
| `attacked`, `blocked` | `AttackersDeclared`, `BlockersDeclared` and the combat diff | 500 |
| `damaged` | a permanent: `DamageDealt`, else newly marked damage; a seat: the life diff | 550 |
| `healed` | a seat: the life diff | 550 |
| `entered` | a permanent that was not on the battlefield | 350 |
| `died` | battlefield to graveyard, or named by `CreatureDied` (a token); at most 24 a batch | 500 |

- A `died` effect carries the card's last look, so a ghost stands where it was; a player who loses takes their permanents out of the game, so they vanish without ghosts.
- `createFx(options)` (`store.ts`) keys effects by card, seat and battlefield row; `FxState` is replaced, never changed. One timer per kind and batch removes effects after `FX_MS`; a batch plays at most 120. `mode` (`off`, `reduced`, `full`) is read at every batch; `reduced` plays only still highlights.
- `TableOptions.effects` is on by default except under vitest, so other tests see no timers and no extra markup; a test turns it on with `renderTable({ options: { effects: true } })` and `vi.useFakeTimers()`.
- `Card` sets `data-fx` and `data-fx-side` (`own` or `other`), `LifeFx` wraps the life figure, and `CardRow` puts each `GhostCard` back before the card it stood before, as an `aria-hidden` `li` with nothing focusable.
- Durations are the custom properties `--fx-<kind>-ms` in `fx/fx.css`, which `fxCss.test.ts` holds equal to `FX_MS`; `--fx-slow` stretches them.
- `fx.travel` (`travel.ts`, `places.ts`, `FxTravel.tsx`) flies the moves of `deriveMoves` with the Web Animations API on a fixed `aria-hidden` layer without a pointer: `watchBatches` calls `launch`, which measures each source at once (before React draws the batch) and each destination on the next frame (`measurePlace`: the card, else the anchor of its zone, else the move is left out); `planFlights` staggers the legs; `keyframesOf` runs a straight path inside the window. Nothing flies under `reduced` or `off`, and a batch with moves ends the flights of the one before.
- `fx.strikes` (`strikes.ts`, `strikeLayer.ts`, `FxStrikes.tsx`) plays combat damage: `planStrikes` takes a `DamageDealt` for a strike when a combatant deals it in a damage step before anyone has priority, one strike per source and damage step; a picture of the source lunges from its card at the first thing it damages and back in `STRIKE_MS` (1.5 s) while the card is hidden; `splitImpacts` holds the struck targets' `damaged` effects until the hit, and `holdDeaths` keeps a ghost still until the strike lands. Only under `full`. `/dev/table?fx=strike` strikes a player, a planeswalker and a creature.
- Moves to the stack and on, the spotlight, target arrows and the hand's reasons: [ui-design.md](ui-design.md), Playing is legible. Stack targets: `stackTargets.ts` lists each stack item's targets once with `gone` read from the player's `lost`, the view and the log since the cast; `combat/stackArrows.ts` plans the arrows as `LineSpec`s of kind `target` that `CombatOverlay` draws in its `stack` layer.
- Log wording that needs the events around a line (`eventContext.ts`): the resolving spell ("X counters Y"), the targets of an activation, and the card an ability object comes from, so an ability that resolves reads "An ability of X begins to resolve", never as the card itself.
- Table moments (`moment/`): `watchMoments` turns the public events of each batch into things every seat sees over the table: the cards of `Revealed` large with who revealed them and why, and the die of `DieRolled` or `ManualRolled` tumbling through `rollFaces` (the same faces at every seat). A look at a library is the looker's alone and makes none. They stand `momentMs`, three at most, over a panel that takes the pointer alone; Escape or Dismiss ends them. Under reduced motion a die shows its result at once.

## Turn cues

`features/table/turn/` shows whose turn it is and what the game passed, from the batch that arrived. A cue only reads the play store: none waits for, delays or paces an answer, and each reads what every seat sees ([ui-design.md](ui-design.md), Turn and focus).

- `feed.ts`: `deriveFeed(before, after, events, names, options)` (pure) gives `{ banner, lines, skipped, announcement }` for one batch, and `feedBetween(prev, next, names)` gives it for two play states through `batchBetween`. A step is skipped when it began and ended inside the batch and a round of priority passed in it. The lines are the skip note, "You had no plays" for the viewer's own main phase passed at once with no yield, and the newest line the log does not draw quietly. The viewer's own draw and moves into a hand or library read as every other seat reads them. `feedLeak.test.tsx` replays a game and a copy with one hidden card changed, and a game at the pace of an automatic pass and of a seat deciding, and requires equal feeds and cues.
- `timing.ts` holds the times: the banner fades in for 250 ms, is held 600 and fades out 150 (100, 1,500 and 100 under reduced motion); a ticker line stays 3 s, at most three lines to a batch; a skipped step is dashed 1 s. `bannerTimes(reduced, slow)` stretches them by the dev route's `?slow=`.
- `useTurnFeed(onFeed)` calls back for every batch while the table draws its timed cues (`TableOptions.cues`, on everywhere but under vitest).
- `TurnBanner.tsx`: a band in the free room of the top bar after the step ladder (`TopBar` draws it as its spacer, so the bar does not move; it covers no card, prompt, stack, control, step ladder or turn badge; `bannerPlace` hangs the band under the bar below 112 px of room, on a phone). `aria-hidden`; a polite live region (`data-slot="turn-announcement"`) says the same. `TurnTicker.tsx`: one line in the bottom row of the strip's sheet (`h-4`, kept when empty); `aria-hidden`.
- `StepLadder.tsx`, `ladder.ts`: the step marks in the top bar from 1024 px, in runs of one phase (`phaseRuns`); `pipStates` gives lit, passed, to come and skipped. `aria-hidden`; the badge says the same in words.
- `phase.ts`, `usePhase.ts`, `PhaseTag.tsx`, `phase.css`: `phaseOf(step)` gives `{ id, name, icon }`; `usePhase()` gives `null` outside the running turns. `TableGrid` writes the id as `data-phase` on the table root, and `phase.css` points the live tokens at that phase's set. What takes the theme reads those tokens and carries `data-themed`, which is what fades. `phaseTokens.test.ts` computes the contrast of every pair in both themes and the CIEDE2000 distance of the four accents under full vision and three dichromacies (`test-utils/vision.ts`); `phaseCss.test.ts` holds the 200 ms fade to the no-preference block.
- `turn.css`: the banner's fades and the ticker line's rise; only opacity changes outside the no-preference block (`turnCss.test.ts`). `cueTokens.test.ts` holds the contrast of the cue tokens, the seat edges and the priority dot, in both themes.
- Tests drive a table with `renderCueTable` (`test-utils/cueTable.tsx`: cues on, a manual clock, `deliver(events, to)`) and build batches from `test-utils/turnEvents.ts`.

## Pace controls

The Priority prompt's controls (`prompt/PassControls.tsx`, drawn in the controls dock of the table, 44 px high), over the wire rules in [protocol.md](protocol.md) (Pace of play) and the privacy rules in [ui-design.md](ui-design.md) (Priority, stops and information leaks).

### Primary button and yields

`data-slot="primary-action"` answers `Pass` (disabled when `can_pass` is false). `primaryLabel` (`passWords.ts`) is display only; the server decides what happens. "Pass priority" is never a visible label; it is the `aria-description`.

| Situation | Label |
|---|---|
| a spell on the stack | "Resolve <top spell>" ("Resolve" in a short dock) |
| the viewer's turn, before the last window | "Next: <next step>" |
| the viewer's turn, the End step | "End turn" |
| another seat's turn | "Continue" |

The dock's form (`DockForm`, `dockForm(regions)` in `layout.ts`) decides how much these words say: `full` (a main area of 1161 px or more, `DOCK_FULL_MIN_MAIN_PX`) draws the key hints (`data-slot="key-cap"`) and the whole words; `short` leaves the hints to the tooltips, `aria-keyshortcuts` and the menu's legend, writes the short words and trims the buttons; `compact` is the phone's dock.

- "End turn" (`data-slot="secondary-action"`; not drawn when the primary button already ends the turn, and in a phone's dock the first item of the menu) asks for `yieldUntil('EndOfTurn')`. The menu "More ways to pass" has "Resolve everything on the stack" (`Resolve`, only over a stack) and "Pass until my next turn" (`MyTurn`).
- A yield is asked once per prompt: the buttons stay off until the server answers with `Yielding` or a fresh decision. The server refuses a yield under Full Control, so there `yieldUntil` sends nothing and the prompt draws neither "End turn" nor the menu.
- `YieldIndicator` ("Passing until the end of turn", with "Stop passing" for `cancelYield()`) shows while the store's `yielding` is set; only `Welcome` and `Yielding` set it.

### Stops and Full Control

`features/table/stops/` and `play/session.ts`. The server decides the windows from the stops and the mode ([protocol.md](protocol.md), Stops and Full Control); the page only asks for them and shows what the server holds.

- `stops` (`{side, step, keep}`) and `fullControl` (`Off`, `NextWindow`, `Held`) are replaced whole by `Welcome`, `Stops` and `FullControl` and survive a dropped connection until the next `Welcome`.
- The by-hand window (`play/byHand.ts`, `PlayState.byHand`): the server holds a seat at every priority window from the resolution of its own spell or ability whose card is flagged `ObjectView.manual_owed` until it passes, and does not say so, so the client reads the same from the events and the flag. While `byHand` is set the Priority prompt reads "Apply <Card name>'s text by hand, then continue." in place of its options; no other prompt and no other seat reads it.
- `StopLadder` (in `StopsBar`, beside `FullControlToggle`) draws one row with a button per step in turn order (ten; first-strike damage joins while it is the current step or holds a stop) and `StopSideSwitch`, "Mine" or "Theirs". The row follows the turn and a side picked by hand holds until the turn changes hands. Untap and cleanup get none: the server refuses them, so `setStop` sends nothing for them (`play/stops.ts`). A lit button (`aria-pressed`) is a stop the server holds; `data-keep` is `turn` or `lasting`.
- `StopsDock` puts `StopsBar` in the dock as one row from 1600 px, else behind the "Stops" button. The popover stays in the page while shut, so the Keep toggle, the side picked and the Control keys keep working.
- A press sets a one-turn stop and clears a held one; shift and press, or the Keep toggle (for touch), sets a lasting stop (`pressRequest`). The Full Control toggle asks for Held, or Off when a mode is on.

### Response clock

- A `Decision` with `deadline_ms` becomes `pending.deadlineMs`. The session counts it down in `PlayState.clock` on its own `timers` and, at zero, clears `pending` itself: the server has answered for the seat, and a prompt left up would invite a stale answer.
- `prompt/ResponseClock` shows "Passing for you in 7 s" (`clockText.ts` has the words for what the server answers at zero for every decision kind) as a `role="timer"` that does not announce each second; the last three seconds are urgent (`data-urgent`). Its bar is the `response-clock-bar` utility in `prompt/responseClock.css`.
- Away seats: `Presence` sets `PlayerView.connected` (`withPresence`) and its `deadline_ms` starts that seat's clock in `state.away` (`play/awayClocks.ts`). A seat still in the game with no client wears the `AwayMark`, and the "Waiting for" line adds "Bo is away: the game acts for them in 12 s" (`presenceText.ts`); the seconds are hidden from the live region. A seat that conceded or lost reads as eliminated, never away. `e2e/presence.spec.ts` closes a seat's page mid-game and reopens it.

### Keys

| Key | Action |
|---|---|
| Space | presses the primary button |
| Enter | presses "End turn"; where none is drawn (Full Control, the End step) the primary button (`enterYields`) |
| Shift+Enter or another modifier | nothing |
| Ctrl alone | Full Control `NextWindow`; again, Off; nothing from `Held` |
| Ctrl and Shift together | Full Control `Held`; again, Off |

Space and Enter act only when nothing has the keyboard (`isFocusFree`: no field, button, link, menu or dialog has focus, no modifier is held, the key is not repeating); a focused card plays itself instead. `useFullControlKeys` follows the same rule and `ModifierChords` fires on release, so Ctrl+Shift+I and Ctrl-click do not count.

## Accounts and games pages

Sign-in uses the server's accounts ([server.md](server.md); bodies in [protocol.md](protocol.md)). A guest needs no account: a seat link opens a seat. A server without `DATABASE_URL` answers 503 `accounts_unavailable`, and the app then offers no sign-in anywhere.

- `net/accounts.ts` `createAccountsApi({fetch, baseUrl})` sends `credentials: 'include'`. A failure is an `AccountError {code, status, retryAfter}`; `AUTH_ERROR_CODES` is a `Record` over the generated union, so a new code stops the build until it has words.
- `features/auth/store.ts` `createAuthStore({api, initial})` is the app's `appAuth`, started once by `AuthProvider`. `status` is `loading` until `GET /api/auth/me` answers, then `signed-in` (200), `signed-out` (401, and a network, 5xx or unreadable answer) or `unavailable` (503). A failed `logout` keeps the user and sets `notice`. An answer that arrives after who is signed in changed, or after a newer question, is dropped (`round` counter).
- `/login` and `/register` (`AuthScreen`, `AuthForm`) check a username of 3 to 32 letters, digits, `_` and `-` and a password of 10 to 128 characters (`rules.ts`, copies of the Rust constants) before sending. The password is in no React state: the field is uncontrolled, read at submit and emptied once the answer is in. A field problem has an icon and its words and sits in a polite live region that is always in the page and first in `aria-describedby`; focus goes to the first wrong field. A failure of the whole form is an `Alert` that takes focus. Every `AuthErrorCode` has a sentence and a field (`errors.ts`; a wrong sign-in names neither half).
- `next`: `sanitizeNext` (`features/auth/next.ts`) accepts only a path on this site: one leading `/`, no backslash or control character, no `//` after dot segments, not `/login` or `/register`, and no fragment, because a seat token must not travel in a query string. `parseAuthSearch` always names the key (`next: undefined` when refused): the router merges what a route validates over the raw address, so leaving the key out would let the unchecked value through.
- `/register` where `GET /api/auth/options` says registering is closed (`AuthState.registration`) shows "New accounts are made by the admin" with a link to sign in; the header's Register button leaves. A submit that still meets 403 `registration_closed` shows the same sentence.
- `/precons` (`features/precons/PreconsPage`): the precon browser, public like the card endpoints. `net/precons.ts` `createPreconsApi` is the typed client; a failure is a `PreconError` (503 `cards_unavailable` shows "No card data on this server" with no Retry). `PreconFilters` (search over name, set code and commanders ignoring case and accents; set; deck check) and `PreconRows` (a table from 64 rem, stacked rows under it; `data-precon`, `data-status`). The badge follows `statusOf`: "Whole deck runs" (`verified`), "Runs on reads" (`read`), "N cards played by hand" (`manual_play`) or "Cannot be taken" (`blocked`, or `playable` false); a deck the game cannot take keeps its Play in place, `aria-disabled`. `PreconDialog` (`usePreconDetail`) shows the list's own facts at once and the cards of `GET /api/precons/{code}` after; each card that is not Verified lists "Played by hand:" and its clauses as the words of the card they cover beside the reason (`ClauseList`). "Copy list" copies the cards that are not Verified (`copyList`). Clause words come from `GET /api/cards/{oracle_id}` (`useCardTexts`), because the precon view carries the spans and reasons but not the text. A view that was read stays for the life of the page, since the server counts every request against a budget per address.
  - Play (`usePlayPrecon`, `play.ts`): `createGame` with the create form's defaults and `deck: "precon:<code>"` for seat 1; `format` is `commander` for a deck the check judged as Commander. A guest answers `GuestJoinDialog`. Success opens the lobby on seat 1. A 422 or `unknown_deck` shows "Could not start a game with <name>" with Show why and Dismiss.
- `/games` (`features/games/MyGamesPage`): signed out goes to `/login?next=/games`. `GameRows` draws a table from 64 rem (Players, State, Result, Your seat, Started, Action) and stacked rows under it (`data-game`, `data-status`). "Continue" opens `/game/<id>` with no fragment, which connects through the session; a finished game has none: the server drops it from memory ten minutes after it ends. A game that failed to resume (`status` `failed`) has a "Failed" badge, the server's `reason` and "Remove" (`removeGame`: `DELETE /api/me/games/{id}`, or a reload on a 404). States: skeleton rows only after 300 ms; empty with Create game and Find an open game; an error `Alert` with Retry; after a failed refresh the old rows stay, dimmed.
- `/accounts` (`features/admin/AccountsPage`, linked for `user.is_admin` only) is where the admin makes accounts, sets a new password for a friend and removes an account; any other account reads "Only the admin can make accounts." with nothing asked of the server (the server judges every request). `PasswordField` is uncontrolled with `autocomplete="new-password"` and the opt-out attributes of common password managers; "Make a password" fills `generatePassword()` (`password.ts`): 16 characters without look-alikes, bytes from `crypto.getRandomValues` with rejection sampling. `CredentialsPanel` shows what a success hands over, once: the site address, the username and the password, with "Copy both" and "Done"; the password lives only in the input and in that panel's React state, never in `localStorage`, the address or the store. A 403 `forbidden` makes the store drop `is_admin`. `AccountList` shows every account oldest first; a friend's row has "New password" and "Remove" (`NewPasswordForm`, `RemoveAccountDialog`, an alert dialog that starts on "Keep account" and says what goes); the admin's own row has neither.
- `/settings` (`features/settings/SettingsPage`): signed out goes to `/login?next=/settings`. `ChangePasswordForm` sends `changePassword(current, new)` once, empties the current password after every try and keeps the account signed in; the server ends its other sessions. `DeleteAccountSection` opens an alert dialog that asks for the password; for the admin it says the account cannot be deleted (409 `admin_account`); success shows the flash "Your account was deleted." and goes home signed out (`onDeleting` keeps the page from redirecting to the sign-in form on its way).
- `/decks` (`features/decks/DecksPage`): signed out goes to `/login?next=/decks`. `net/decks.ts` `createDecksApi` is the typed client (`DeckError`; 503 `decks_unavailable` shows a notice).   - The deck check (`report.ts`, pure) reads a `DeckReport`: a counts line from `summary.counts`; every line whose card is not Verified gets a `SupportMark` (icon, word and a left edge in the state's colour, tokens `support-*`) and the report's reasons as plain sentences; `report.legality` is a section of its own above the zones and holds no support mark. With `compact` it is an icon alone; the builder mounts it so on lines, tiles and hits that are not Verified, and the card preview mounts it when given `fixMarks`.
- The not-validated list (`features/decks/unvalidated`) is `/decks/unvalidated` for every saved deck and `/decks/$deckId/unvalidated` for one (route files `decks_.unvalidated.tsx` and `decks_.$deckId_.unvalidated.tsx`). `useUnvalidated` reads `GET /api/decks` and checks each deck whose summary counts a card that is not Verified (`POST /api/decks/check`, four at a time), or reads one deck; a deck whose check fails is named and the others still show. `model.ts` (pure) merges the cards by oracle id with the decks that hold them (`mergeDecks`) or groups them by deck (`groupByDeck`), and narrows them to Partial, Manual, Stale, Unplayable or To read. A card (`UnvalidatedCard`) shows its picture, name, `SupportMark`, its decks as links and each clause (`ClauseList`): the words of the card the span covers, quoted, beside the plain reason; a card with no clause of its own shows its whole text. `useCardTexts` reads the texts from `GET /api/cards/{oracle_id}` once per card and four at a time. "Copy as text" (`copyText`) waits, as a disabled "Reading card text…", until every card is read.
- The create page waits until it is known who is signed in; a signed-in creator gets seat 1 named after the account. The lobby shows "signed in as" on seats with an account (`useSeatAccounts`).

## Testing

- vitest on jsdom: `scripts/check.sh web`, or `pnpm test` in `web/`.
- Clock budgets and timeouts (vitest timeouts, `asyncUtilTimeout`, explicit `waitFor` timeouts, the time budgets of `perf.test.tsx` and `fitPerf.test.ts`) go through `scaled(ms)` (`test-utils/loadFactor.ts`): times `1 + load / cores`, at most `MAX_LOAD_FACTOR` (12). `MTG_LOAD_FACTOR` sets the factor; `MTG_STRICT_PERF=1` keeps the numbers as written.
- A test of a timer never sleeps or races the real clock: it runs on a fake clock (`installFakeClock` in `test-utils/fakeClock.ts`, with `settle(ms)`) or waits with `waitFor`/`findBy` on the state it asserts. `flushFakeClock` ends a fake clock by running the timers still pending.
- `src/test-utils` has the fakes (`FakeNetwork`, `FakeTimers`, `startSession()`), the Rust-generated `transcripts` (replayed through the real store by `transcript.test.tsx`) and the harnesses: `renderGame()` (fake sockets, manual clock, in-memory REST; `{ routed: true }` mounts the game page at its own address), `renderTable` and `renderLiveTable` (they lay the table out for `TEST_VIEWPORT`, 1600x1000; `options.viewport` sets another, and jsdom has no layout, so a test that needs measured sizes fakes `ResizeObserver` and `clientWidth`), and `renderApp(url, {accounts, rest})` with `startAccounts(script)`. `test-utils/lobbyControls.ts` has `openLobby`, `changesOf`, `held` and the server's `FAILURES`; `test-utils/passControls.ts` finds the primary button by its slot, since its words change. A new prompt copies `Priority.test.tsx` (table-driven) and `PriorityLive.test.tsx`.
- Screenshots: `node scripts/ui-shot.mjs <url> <out-prefix>` (options in `CLAUDE.md`) over a dev route; `--theme dark` or `light` sets the colour scheme Firefox reports. The page loads at the first width, so shoot one width per run: state read at mount does not follow a later width. The table follows `resize`, so one run may shoot several widths. The headless browser follows its system theme, so to shoot a stored choice set it and reload once with `--wait`: `(sessionStorage.getItem('s') ? <ready> : (sessionStorage.setItem('s', '1'), localStorage.setItem('theme', 'dark'), location.reload(), false))`.
- Layout audit: `node scripts/ui-audit.mjs <url or /path>... --base <dev server>` measures pages in Chromium (`CHROMIUM_PATH` as for e2e) with the rules of `layout.spec.ts` and prints a row per page, size and theme; it exits 1 when a row fails. Options: `--sizes`, `--themes`, `--fit` (pages that must not scroll down), `--action` (a primary action), `--exempt`, `--wait` (a condition that says the page is drawn; the default is any text in `main`, which a lazy dev route meets too early) and `--problems` (failures only). It loads `e2e/layoutAudit.ts` as it is, so it needs Node 22.18 or newer.

### End-to-end

`pnpm e2e` (`playwright.config.ts`) starts `cargo run -p mtg-server` (an empty `DATABASE_URL` gives the in-memory store and the built-in demo decks; `MTG_DWELL_MS=0` passes for idle seats at once, since the default wait would stretch a full game from about 8 s to between 29 and 35 s) on port 8301 and `pnpm build` plus `vite preview` on port 5301, both new for every run.

- `E2E_SERVER_PORT` and `E2E_WEB_PORT` override the ports (`e2e/ports.ts`) to run several suites at once; the Vite dev server that serves `/dev/table` to the specs listens on `E2E_DEV_WEB_PORT` (the web port plus 1000). `E2E_REUSE=1` keeps servers already listening there; `E2E_TRAIL=1` prints every answered decision; `--repeat-each=N` repeats the game.
- `e2e/seeds.ts` gives each server an engine seed (`MTG_SEED`, [server.md](server.md#configuration)): every game on it shuffles alike, so a failing game replays exactly; the servers log the seed of every game and a failed Commander or precon run attaches `seed.txt`. `E2E_SEED=<n>` replays another seed on both servers and `E2E_SEED=random` restores a random one.
- On NixOS Playwright's own browser cannot run. Point `CHROMIUM_PATH` at the Nix chromium with a glob, because the store path changes with every update: `CHROMIUM_PATH=$(ls -d /nix/store/*-chromium-[0-9]*/bin/chromium | head -n 1) pnpm --dir web e2e`.
- `full-game.spec.ts` (`driver.ts`) plays both seats through the real UI. A seat waits for a `[data-decision]` with a new `data-decision-id`, reads its legal cards (`data-highlight="legal"`) and answers with real clicks. There are no sleeps: waits are `waitForFunction` polls. A button is named as `getByRole` names it (`aria-label` before its text). A priority window counts as idle (`isIdle`) only when no hand card, commander or non-land permanent is legal: an untapped land is legal for its mana ability, which is not a play (`can_act`). A play that comes back to the same window with no prompt (the server takes the cast back) is tried twice and then left alone. `Style` options steer the seat (`aim`, `recall`, `blocks`). `driver.spec.ts` holds these helpers to fixture pages and needs no database.
- `fit.spec.ts` sweeps the six sizes of [ui-design.md](ui-design.md) down and back up in one page: in a real two-seat game at the opening hands and the first priority window, on `/dev/table` at 2, 4, 6 and 12 seats with 40 permanents a seat and on the duel board, the attachments scene, the Commands panel open under a prompt, and on the game-over screen. At each size the page does not scroll, neither dock scrolls inside itself, every region is inside the window, and the hand, the primary pass button (or Keep), your life and the way to a new game are in view and not covered (`document.elementFromPoint`); on the table no battlefield card in view lies under the prompt sheet or a shown turn banner.
- `ux-fit.spec.ts`, `ux-flow.spec.ts` and `playtest-fit.spec.ts` hold single defects on the dev routes (no server): invite link and code in view, a hand ending clear of the controls, the turn banner clear of the ladder and badge, the opening hand width, no text under 12 px (`textFloor.test.ts` reads the sources), the Mana row's start colour, the panel's countdown at its top, and overlaps of the playtest screenshots. `commander-builder.spec.ts`, `rooms.spec.ts`, `reload.spec.ts` (the log after a reload, and no animation of the fx layer for the first 1.5 s), `fx-flier.spec.ts`, `fx-spotlight.spec.ts` (`fxPlay.ts`) and `manual-panel.spec.ts` hold their named feature; `lobby-controls.spec.ts` and `join.spec.ts` hold the lobby controls and the invite link with a second browser context.
- `layout.spec.ts` is the layout gate of [ui-design.md](ui-design.md), Definition of done. Each page that needs no account and the dev routes that stand for the account pages open in a Chromium context whose colour scheme and stored theme are light, then dark, and are held to the same rules at the six sizes, down and back up (`layoutAudit.ts`, `measure` in the page and `problemsOf` over what it read):
  - No sideways scroll; no box cut off sideways by the window or by a box that clips it; no text under 12 px; no lane of a battlefield over another, nor outside a board that does not scroll; every primary action in the window and not covered. A page meant to fit never scrolls down from its `fitsFrom` width up; any other page has its action scrolled into view, and the scroll put back.
  - `exempt` names what is cut off on purpose and nothing else: on the table the art of a card, the opponents' tile strip, the stack chips and the hand fan. The letters of a mana symbol (`role="img"`) are a picture. An action is a CSS selector or `text:Words` of a button or link in `main`.
  - Two tests hand it a page that breaks every rule and require it to say so. Decks, My games and the builder with a real deck need Postgres and are held by `accounts.spec.ts` with the same run (`layoutGate.ts`).
- `accounts.spec.ts` needs Postgres. With `E2E_DATABASE_URL` set to a scratch database the config also starts a second server on port 8302 and a second preview on 5302 (`E2E_ACCOUNTS_SERVER_PORT`, `E2E_ACCOUNTS_WEB_PORT`). Without it `pnpm e2e` stays hermetic and the spec is skipped. Usernames are random per run, so one database serves many runs. Its layout gate registers two accounts once, since a server counts registrations per address (ten in 15 minutes), and gives each test the cookies of one: an empty account and one with eight decks and eight public games. The gate needs the card data in the scratch database: `mtg-cli ingest` on it, or a copy of a loaded one (`create database … template magic`, which waits for the connections to `magic` to end). The server migrates only its own tables on boot; `ingest` migrates `decks` and `cards`.
- `precon-game.spec.ts` needs the card data (`E2E_DATABASE_URL` names a database filled by `mtg-cli ingest` and `compile`). Four accounts register once; the verified pair and the manual pair play to turn 9, and four seats play to turn 6, every other seat paying by hand. The table is made through the UI too (the create form on Commander, the invite code, the chooser's Precons tab, "Use this deck", Ready). `E2E_SHOTS_DIR` saves a screenshot at the first prompt of each kind and each turn.
- `commander-four.spec.ts` needs the same card data. Four accounts play four precon Commander decks at a table made on the create form with Starting life 12 (`E2E_LIFE`). It fails with the trail unless the game ends by turn 60 (`E2E_TURN_CAP`) with one "You won" and three "You lost" and the same list of finished seats on every page, and asserts that every page reads the same turn and lives at each turn's first priority window, that a commander's tax chip reads 2 after its first cast and 4 after its second, that commander damage chips showed and the log told them, that no page scrolled, was cut off, threw or logged a console error. The seed is pinned, so the game is the same each run, about 30 turns; a run that stalls fails with the last twelve answers. `E2E_DECK=owner` plays the friends' journey with a real imported list in place of the precons: each account imports `crates/mtg-testkit/tests/fixtures/decks/owner.arena.txt` through `/api/decks/import`, saves it (`saveOwnerDeck`) and the lobby's chooser takes it from "Your decks" (`chooseSavedDeck`). Run it with `E2E_DECK=owner E2E_DATABASE_URL=… pnpm --dir web exec playwright test e2e/commander-four.spec.ts`.
- The specs that register accounts (`accounts`, `settings`, `precon-game`, `commander-four`) share one server per invocation, which counts ten registrations per 15 minutes per address: run them in separate invocations with one worker. `settings.spec.ts` uses the same second server and needs no card data.

## Conventions

- Cards the engine plays only in part (Partial, Manual or Stale) are "played by hand" everywhere: the words come from `lib/byHand.ts` (`BY_HAND`, `BY_HAND_TITLE`, `PARTLY_BY_HAND`, `cardsByHand`, `byHandCopies`), the deck state `manual_play` reads "Played by hand", and a card's mark keeps the name of its support state (Verified, Read, Partial, Manual, Stale, Unplayable; a Read card runs whole, so it is counted apart and never "played by hand": `runsWhole`, `ON_A_READ`). `lib/byHand.test.ts` fails on any other spelling in the sources and the e2e specs.
- The words a player reads spell "color" the American way, as the rules, the cards and the server's deck issues do (`spelling.test.ts` scans the strings and the JSX text of `src`); identifiers and the wire key `colour_identity` of the house rules keep theirs.
- Server-held state is shown, never predicted: ready, yields, stops and Full Control change on screen only when the server says so.
- Colour never carries meaning alone, and live regions are polite. A row of cards, a ladder row or a list is one tab stop (arrows, Home, End); a control that must keep focus when it cannot act is `aria-disabled`, not `disabled`.
- Every animation sits inside `@media (prefers-reduced-motion: no-preference)` (`fx.css`, `combat.css`, `responseClock.css`, `turn.css`, `phase.css`, `focusBoard.css`, the `your-turn-cue` utility of `index.css`); under `reduce` an effect is a still highlight, the clock bar is not drawn, the turn banner only fades, a phase theme changes at once, the large board of focus mode changes at once and the tab title does not flash. JS reads `useReducedMotion` or `prefersReducedMotion`. A CSS test per file (`fxCss.test.ts`, `combatCss.test.ts`, `responseClockCss.test.ts`, `turnCss.test.ts`, `phaseCss.test.ts`, `focusBoardCss.test.ts`, `yourTurnCss.test.ts`) fails when an animation leaves the media query.
- Colours are tokens with a light and a dark value (`tokens.test.ts` checks their contrast); Tailwind class names are written whole so Tailwind can see them.
