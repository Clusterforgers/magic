# Web client

The browser client: game creation, lobby, table, decision prompts and accounts, on the wire contract of [protocol.md](protocol.md) and the transport of [server.md](server.md). The design rules are in [ui-design.md](ui-design.md).

## Stack and layout

React, Vite, Tailwind, shadcn/ui on Base UI, TanStack Router and zustand. Commands are in `CLAUDE.md`.

- Pages live in `src/features`, one folder per area; `src/routes` only picks them. The Vite plugin rewrites `routeTree.gen.ts` on `pnpm dev` and `pnpm build`; commit it with the route change.
- `src/net` (REST, socket) and `src/play` (session, store) hold the client. `src/components` has the shell and the pieces pages share; `src/components/ui` is shadcn (`pnpm exec shadcn add <name>`) and is edited to the tokens. `src/protocol` has the ts-rs bindings and the transcripts Rust writes.
- Each page is a chunk of its own (`autoCodeSplitting`), fetched while the pointer rests on a link to it (`routerOptions.ts`, `defaultPreload: 'intent'`). `bundleBudget.test.ts` holds each chunk to a gzip budget: the entry 135 kB, the table 250 kB, any other 52 kB.
- Long lists stay cheap: `DeckRow` is memoised on stable props, and a row off screen is not laid out (`content-visibility: auto`).
- The dev and preview servers proxy `/api` and `/ws` to `MTG_SERVER_URL` (default `http://127.0.0.1:8080`) and keep the browser's `Host`, which the server's Origin check compares with the page's `Origin`.

## Design system and shell

Roles, scales and rules are in [ui-design.md](ui-design.md) (Design system). `src/index.css` holds the tokens as CSS variables that `@theme inline` maps to Tailwind classes; the `dark` class on `<html>` swaps the colours.

- `PageShell width` is one of the page widths of [ui-design.md](ui-design.md) with the gutters and sets no `max-w` of its own (`pageWidths.ts`). Play, Precons, My games and Create are `wide`; the builder is `wider`; Decks, the lobby and game over `page`; sign-in and register `narrow`.
- `Button` `loading` shows a spinner and ignores presses while staying focusable (`aria-disabled`). `Popover` has `keepMounted`. `Sheet` is a non-modal dialog (full width on a phone, 24 rem from `sm`) that only Escape or Close shuts. `Loading` is a polite status at once and the skeleton after 300 ms (`useAfterDelay`). An error is an `Alert` with an icon, a title and a Retry where retrying works.
- Theme (`hooks/useTheme.ts`): `createThemeStore` keeps `light`, `dark` or `system` in `localStorage` (`theme`), sets the `dark` class and follows `prefers-color-scheme` and other tabs; it works when storage or `matchMedia` is missing or throws. A script in the head of `index.html` sets the class before the first paint (`themeScript.test.ts` holds it equal to the store).
- `components/AppShell` frames every route: a skip button that focuses `main` (a `#main` link would replace a game address's seat token), the header (navigation, `ThemeMenu`, `AccountNav`), `AuthNotice`, `OfflineNotice`, then `main`. Under 640 px the navigation drops to a second row. Review cards (`/review?mine=true`) carries a badge of the account's deck cards waiting for a read (`features/reads/useToReadCount`), hidden at none.
- `useFullBleed` (`components/appChrome`) draws no header and makes the root the window high with `overflow: hidden` (the game table). `useFitWindow` makes the root the window high so the page scrolls one region inside itself (Play, My games, Precons, Decks, the builder, game over).

## Data flow

- `net/api.ts` checks REST bodies at runtime; a failure is an `ApiError` with a code of `crates/mtg-server/src/api.rs` or a local `unknown`, `network` or `bad_response`. `net/parse.ts` `parseFrame` is the only door from the wire (JSON, known `type`, required fields, 1 MiB cap); garbage is a `FrameError`, never a throw.
- The game browser calls of `net/api.ts` reject with a `LobbyError {code, status, retryAfter, issues}`, worded by `describeLobbyError` (`net/lobbyErrors.ts`). `listLobbies(previous)` sends the `ETag` and on a 304 resolves with that very object. A seat token goes in `Authorization: Bearer` beside the session cookie, so a call with no token acts for the signed-in user's own seat.
- `net/socket.ts` `GameSocket` sends `Join` first and once per connection. `net/pacer.ts` holds sends to a burst of 30, then 15 a second; the server allows 40 and 20 and closes a socket over it with 1008.
- `play/view.ts` holds pure ports of `StateView::apply`; unchanged objects, players and zones keep their identity. `play/session.ts` `createSession({game, token, name})` owns the socket, applies the client rule of [protocol.md](protocol.md) and writes the zustand store (`play/store.ts`) that screens read with `useStore(session.store, selector)`.

The session's rules:

- A Snapshot sets the base and `seq`. A batch whose `from_seq` is not `seq` (or any batch but the one at 0 while there is no view) sends one Resync; nothing is applied and decisions are ignored until the next Snapshot.
- A `Decision` replaces `pending`. `answer()` sends once per decision id; a Snapshot or a lost connection forgets answered ids, so the server's repeat can be answered.
- `GameOver` sets `result` and makes a later close final. `StaleDecision` and `IllegalAnswer` give a notice and a Resync; an `IllegalAnswer` with `refusal` says why in the card's sentence (`features/table/whyWords.ts`, `refusalNotice`). `BadMessage` and `Internal` only a notice.
- A wrong token is a refused upgrade, which a browser reports as 1006, so the client retries forever.

| Close or message | Socket status |
|---|---|
| 1001, 1006, 1013 and any code not listed below | `reconnecting`: retry after 250 ms doubling to 15 s, less up to 50 % jitter; a Welcome resets it |
| 4000 | `replaced`, no retry; `connect()` takes the seat back |
| 4001 | `stopped`, notice "You were removed from this game." |
| 4002 | `closed`, notice "The host closed this game."; the lobby ended |
| 1000, 1002, 1007, 1008, 1009; `Error` UnsupportedVersion or UnknownGame | `stopped`, reason in `notice` |
| any close after `GameOver` | `stopped`, no notice |

## Create and game pages

- `/` (`browser/PlayPage`): the open games of `GET /api/lobbies`, Create game and "Join with a code". `useOpenGames` polls 5 s after each answer with the `ETag`, pauses while the tab is hidden and keeps stale rows dimmed beside an error. `useJoinGame` runs one Join at a time: an account joins in one click, a guest gives a name (`GuestJoinDialog`); the answer opens `/game/$gameId#seat=n&token=…`, and a seat that is gone reloads the list. A running game (`LobbyGame.running`) follows the lobbies with a Running pill and a Watch link to `/watch/$gameId`.
- `JoinWithCode` checks the code (8 symbols of the server's alphabet, any case, spaces and hyphens allowed) and joins through the same hook. A 404 reads "No open game with that code."; failures a guest can retry stay in the dialog with the name kept.
- `/join/$code` (`JoinCodePage`) is where the invite link leads: the code as `K7M2-9QXA` and one Join button through the same hook; a guest gives the name on the page. Text that is not a code makes no request, and a dead code ends with links to Play and Create a game.
- `/new` (`create/CreateGamePage`, `CreateForm`): format (Commander by default, `formatRuleWords`), seat count (2 to `MAX_FORM_SEATS`, 256), the creator's name (and deck in a Normal game), house rules and Visibility (`lib/visibility.ts`). The request holds only the creator's seat; the others choose a deck in the lobby. `BotsField` sets how many seats after the creator's bots play (`botsOf` keeps it below the seat count): held with `bot: true`, a Normal bot on its seat's deck, a Commander bot on a playable precon, Verified first (`pickBotPrecons`; none usable stops the form with a sentence); their tokens are never kept as invites. `AdvancedOptions` (Normal only, no bots) names and decks every seat, makes the game invite only and lists the links (`GameCreated`). From 768 px the form has two columns, the Create button in a sticky footer. `create/form.ts` repeats the server's checks; `create/apiErrors.ts` words every `ApiError` code.
- Teams (`lib/teams.ts`, pure): the one module for team play: the team of a seat, its label, colour classes (`team-1` to `team-4` tokens) and members, the default teams of a mode (`defaultTeams`, as the engine's `Teams::even`), the server's checks (`teamsProblem`), a seat's move in the lobby (`withSeatTeam`: Two-Headed Giant swaps teammates, Teams renumbers an emptied team), the seat that shows a shared life (`lifeHolder`) and the seats a result names (`winningSeats`). `components/TeamBadge` draws a team's label. The create form's `GameModeField` sets `Draft.mode`; `toRequest` adds the default teams to `house_rules.teams`.
- House rules (`lib/houseRules.ts`): one `RuleSpec` per rule, shared by the form, the lobby (`LobbyRules`) and the table (`TableRules`). An empty field keeps the format's rule (shown as placeholder), so the request carries only what was filled in; `describeRules` names the rules that differ. Handicaps (`HANDICAP_FIELDS`, `handicapId`) are a row per seat with its life and opening hand, read in seat order into `handicaps`. The Mulligan prompt names the new hand size and the scry.
- Rules lexicon (`lib/glossary/`): `TERMS` gives every keyword, ability word and rules term a one-line reminder; `glossary.test.ts` and `vocabulary.test.ts` fail on an engine name or enum variant without words. `KeywordText` marks terms (of the rules terms only `MARKED_RULES`) in ability texts and log lines with a popover into the lexicon. `LexiconDialog` (`features/table/lexicon`) is the searchable list, filtered by kind.
- Help (`HelpMenu` in the top bar) opens the lexicon and the table tour (`tour/TableTour`, `tourSteps.ts`): one part of the table lit at a time with a card placed by `placeCard`, Back, Next, Skip, the arrow keys and Escape. It starts once per browser (`localStorage` `table-tour`), never under automation, vitest or the dev route (`TableOptions.tour`).
- `/game/$gameId#seat=<n>&token=<token>` (`game/GameRoute`) reads the fragment from the raw `location.href`, since the router's `hash` is percent-decoded. A seat token lives only in the fragment, which a browser never sends; `components/SeatLinkRow` prints it only inside a `data-share-link` anchor, and `test-utils/leaks.ts` scans for tokens elsewhere. `lib/invites.ts` keeps the host's seat links and join code in `sessionStorage`.
- `/watch/$gameId` (`game/WatchRoute`, `WatchPage`): a signed-in visitor watches a running game. `GamePage` with `watch` opens `/ws/{game}/watch` (`socketUrl`) and sends only `Join`; signed out it asks to sign in (`/login?next=`). A spectator's table (`TableView.spectator`) is drawn from seat 0's side with that hand face down and "Watching: you hold no seat" in place of the pass controls. A player's top bar counts the watchers (`SpectatorCount`, from `Spectators`, `PlayState.spectators`).
- `game/GamePage` makes one session per (game, seat, token) and connects one microtask after mount, so StrictMode opens one socket. With a seat link it joins by token; without one and signed in it opens `/ws/{game}` with no token and the upgrade's cookie picks the seat. `game/gameContext` gives `useGame()` and `usePlay(selector)`; `lookup` is `GET /api/games/{id}`, polled every 3 s in the lobby.

| Store | Screen (`connectionOf`, `game/connection.ts`) |
|---|---|
| no seat link and not signed in | `SeatLinkMissing`; no socket |
| `phase` over | `GameOver`; no connection notice |
| `status` replaced or stopped | `ConnectionNotice` alone: the reason and a button to connect again |
| `status` closed | `ConnectionNotice` alone, with Back to Play and Create a game, no way to connect again |
| idle or connecting, never welcomed | "Connecting to the game…" |
| `reconnecting`, `attempt` below 5 | "Connection lost. Reconnecting… (attempt N)" |
| `reconnecting`, `attempt` 5 or more | "Cannot reach the game" and "Try again now"; the socket keeps retrying |
| welcomed | `Lobby` while `phase` is lobby, `GameTable` while playing |

After a Welcome the lobby or table stays under the reconnect notice. A `notice` shows above any other screen as a dismissible alert.

## Lobby

- The `Lobby` message is kept whole as `lobby` (`{seats, needed}`) and dropped when the connection goes or the game starts. `game/lobbyModel.ts` (pure) makes the rows: the roster wins; before it and while reconnecting the REST lookup stands in. `removable` says which rows get Remove.
- A polite live region announces what changed (at most three changes, none for this seat's own connection). `LobbyVisibility` reads the lookup, so a reload keeps it; the host gets `VisibilityToggle`, which keeps a new value until the lookup agrees (`useVisibility`). From `COMPACT_LIST_FROM_SEATS` (13) the seat list scrolls in its own box.
- Every named seat shows its deck to the table (`LobbySeatRow`, `deckWords.ts`) as name, format and a count of cards played by hand, never a card name.
- Layout: a `wide` page, one column under 1000 px and two from it. Left, the game (`lobby-game`): title, house rules, visibility, the host's invite link and code (`JoinInvite`, above the seats), the seats under a progress headline, and Close game or Leave game last. Right, the sticky deck column (`lobby-deck`): "Your deck" and `ReadyBar`, which sticks to the bottom on a phone.
- `DeckChooser` is on this seat until it is ready; then one line says the deck is locked until Not ready. Tabs "Your decks" (`useDeckList`), "Built-in" (Normal games, `useDecks`) and "Precons" (`GET /api/precons`), each filtered by the game's format and fetched on first open.
  - Master and detail (`DeckList`, `DeckOption`, `DeckPane`, `deckEntries.ts`): a listbox (arrows, Home, End; Enter or double click chooses) under a search and filters. A row shows commander pictures, name, facts, colour discs and its support chip. "Sort by" is kept per browser (`deckSort.ts`). Pictures load in view, four at a time (`imageQueue.ts`). A starred precon (`useFavourites`) is listed under "Your decks".
  - The selected deck's preview sits beside the list (a dialog under 1000 px): `DeckPreview` with the table's verdict (`useVerdicts`) as its legality, "Use this deck" (disabled for a deck the table cannot take) and a link to the cards played by hand (`notValidatedWords`).
- `features/decks/preview` is the shared deck preview (the builder reuses it): `DeckPreview` over `DeckPreviewData` (`previewFromDeck`, `previewFromPrecon`, `previewFromDraft`): commanders large, legality, colour identity, support counts with a bar, the mana curve without lands, type bars and the cards grouped by type (`groupByKind`) as small pictures with counts.
- `useDeckChoice` sends one `api.chooseDeck` at a time: the deck pressed shows a spinner and keeps focus, and a polite line reports the result. 422 `deck_blocked` (no card the game knows, the one refusal) lists the issues to the owner. Legality never refuses: the owner sees "Not legal in <format>: ..." (`LegalityWarning`) and every seat "Not legal at this table (N)" (`SeatDeck.warnings`).
- `ReadyBar` holds the Ready button (always in the window) and its words (`readyState`). The button follows the server's roster; a reconnect sends no Ready, and the second click of a double click is ignored.
- Teams: the roster's `teams` (the lookup's `house_rules.teams` before it) give each `LobbySeatRow` its team; the host's select calls `setTeams` (`PUT /api/games/{id}/teams`) through `useTeams`, which holds the new teams until the roster agrees, sends nothing `teamsProblem` refuses, puts the old teams back on a 400 or 403 in the words of `describeLobbyError(..., 'teams')`, and stops the lobby on a 409.
- `useLobbyControls` sends the controls' calls one at a time with the seat's token: every button waits while one is out, and the one pressed shows a spinner and keeps focus. A 409 `started` takes the controls away with one line that says why.
- Remove is offered on each taken seat but the host's and those this tab holds a token for. `LobbyQuestion` (words in `lobbyQuestions.ts`) asks before Close, Leave and Remove: the safe answer is first and focused, Escape does nothing while the request is out, a refusal keeps the question up and focus returns to the asking button. Close and Leave flash a notice (`lib/flash.ts`, `FlashNotice`, 10 s) and go to `/`.
- `JoinInvite`: the invite link `/join/<code>` and the code, each with a `CopyButton`, from this tab's `sessionStorage`; a guest never sees either.

## The table

`features/table/GameTable` takes no props: it reads with `usePlay(selector)` and starts from `TableOptionsContext` (`mode`, `focus`, `effects`, `effectsSlow`, `cues`, `viewport`; only the dev route and tests set it). The table is exactly the window high and never scrolls the page.

Teams: `table/teamLife.ts` (`useSeatTeam`) reads the view's `house_rules.teams`; `SeatPanel` and `SeatTile` add the seat's `TeamBadge` and `data-team`, and in Two-Headed Giant the team's first seat shows the shared life large and the teammate small with "shared" (`data-shared-life` `team` or `teammate`, words "Team life, shared with Ann").

The offline, connection and server notices (`data-slot="table-notices"`) float under the top bar.

- Board split (`boardSplit.ts`, pure; `useBoardSplit`): the opponents' row and yours share the room by what their boards hold. `splitBoards` takes the largest card `w` at which your lanes at `w` and every opponent's at `THEIR_SCALE` (0.8) of it fit, each row keeping `MIN_ROW_SHARE` (else 1 to 1.15). ### Card images

## Fit and grouping

`features/table/fit.ts` and `group.ts` are pure (no DOM, no store) and decide how big a zone's cards are and which permanents share a box.

- `fitRows(box, groups, limits)`: each group is a row with its stacks and card shape (`aspect` 7/5; `scale` 1, or `LAND_SCALE` 0.8). It answers with the largest width from 112 px down to the 44 px floor at which every row wraps inside the box; a bigger box never gives a smaller card.
- Whole pixels: boxes and card sizes are rounded and components draw exactly those sizes; every stack takes one box, tapped or not (`FIT_LIMITS`). When the floor does not fit, `scrolls` is true and `hidden` counts the stacks cut off (the "+N" of the edge fade).
- `groupPermanents(permanents, { groupOthers })` merges permanents equal in everything a face shows into a `Stack` (`key`, `count`, `members`). Tapped and untapped never share. Lands and tokens always merge, other cards only with `groupOthers`, set when the fit is under `GROUP_OTHERS_BELOW` (64 px). A permanent in combat never merges.
- Stacks keep the order of their first member. A merged stack's key is its face and a lone card's its id, so joins and leaves change no other stack's key, count or place. `expandStack` returns the members.
- Attachments: an attachment whose host is on the battlefield takes no box; it is tucked behind its host (`tuckedOf`: Auras, Equipment, Fortifications), and `LaneCounts.tucked` gives `fitLanes` the deepest tuck of each lane (`tuckOf`).
- Use: `battlefieldStacks` (`rowStacks.ts`) groups a seat's rows once per view, both ways. `layoutSeat` fits the measured content box (`useContentBox`) with `fitLanes`, merging every identical card under `GROUP_OTHERS_BELOW`. `Battlefield` writes `--card-w`, `--card-h` and each lane's width; a face is whole from 76 px. `fitPerf.test.ts` holds the cost for 6 and 12 seats.
- `fitLanes(box, counts, facing, limits)` (`laneFit.ts`, pure): lanes are lands, creatures and other permanents (`rowOf`), stacked in bands of shape `one`, `two` or `three` from the middle of the table outwards. Creatures take the card width, the others 0.8 of it (`scaleOf`); a band may fan its lands (`fanLane`) where that is lower. A binary search over `LANE_LIMITS` (224 px to 44) finds each shape's largest card; the largest wins, ties to `two`, then `one`. Without a fit at the floor the lowest shape scrolls, creatures first.

## Prompts

`features/table/prompt/` answers the decision this seat faces.

- `PromptHost` (in `SharedStrip`, in place of the waiting line while `ownDecision` is set) renders `PROMPTS[kind]` keyed by decision id, so a new decision starts with an empty selection. `registry.ts` has an entry per `DecisionKind` (`kinds/<Kind>.tsx`); a new kind stops compiling until it has one, and `kinds.test.tsx` fails on an `UnsupportedPrompt` stand-in. A kind the client does not know gets the generic prompt.
- `usePrompt()` gives `{ id, name, decision, answer, selection }`. `answer(a)` wraps `session.answer`: once per decision, false when already sent, refused by the socket (a retry is allowed) or superseded. `PromptLayout` draws the shared shape: the decision's name, one polite live sentence, a row of controls.
- Card marks (`prompt/marks.ts`): `useCardMarks` takes a map of `legal`, `dimmed` and `selected` from `markCards`; a click or Enter/Space on a legal or selected card calls `onSelect`. Each `Card` subscribes to its own id. A legal card wears `ring-2 ring-primary`; a chosen card or player turns to `selected` with `ChosenMark`'s check. Prompts that choose among cards dim the viewer's other cards.
- Undo (`UndoButton.tsx`, `undo.ts`): a cast or activation with `can_cancel` shows "Undo the spell" or "Undo the ability", which Escape presses unless something outside the prompt takes the key. It sends `Cancel` (`Undo` for `ChooseOption` and `ChooseCards`); a combat tax goes "Back to attackers" or "Back to blockers".
- Prompt cards carry `data-candidate`, never `data-object-id`. Letters and digits are hotkeys outside fields, menus and dialogs (`usePromptKeys`, `KeyHint`). Focus starts on the answer the response clock would give (`useDefaultFocus`).
- Hand abilities and special actions (`prompt/activations.ts`, `kinds/Priority.tsx`): `abilityPlays` turns `PriorityOptions` (`abilities`, `unlockable`, `endable`, `suspendable`, `foretellable`, `turnable`, `faces`) into plays; `AbilityChooser` asks which when a card has several (`playsOf`). Rooms (CR 709.5): each door of `PermanentView.doors` is a mark with its face's name and a lock (`useDoorFaces`).
- Zone marks: a graveyard or exile chip or picture holding a legal card wears the legal ring and a play badge (`LegalBadge`, `useLegalCount`, `legalWords`).
- The preview lists the card's activated abilities (`ObjectView.activated`, `activatedLines`), tags those offered "Can activate now", and lists clauses left to the table under "Played by hand:". A stack entry's preview (`stackPreview.ts`) names it, its rules and its targets, a gone one marked, with the source card large.
- Mulligan: the sentence reads `bottom_if_keep`, `bottom_if_mulligan` and `free_mulligans`; the client derives no count.
- Nothing to do: the newest `NothingToDo` of this turn shows "You have no creatures that can attack" (or "block") until the viewer answers something.
- A play taken back: the viewer's newest `AnnouncementRewound` shows "<card> could not be played: <reason>" (`prompt/rewound.ts`) until the next answer; other seats read only that the seat could not finish a play.
- PayMana (`payment.ts`, read as `mana_cost.rs` does): a source or floating mana is offered only while the payment can still be finished (`completable`); restricted mana is spent against `PayOptions.spend` (`spendRules.ts`). Convoke, Improvise and Delve are rows of buttons, and a permanent is tapped once whatever the use. Confirm is on when `covers` holds, "Pay the rest for me" while `completable` holds, and "Pay automatically" says why when `auto_available` is off. `toPayment` sends `{ pool, restricted, taps, life }`.
- Mana shows what it is (`manaMade.ts`, `ManaSources.tsx`, `ManaStrip.tsx`): what a source gives is read from its `ManaOption`s or its mana abilities' `ways`, never from words. PayMana has a "Mana sources" row of chips that click as their card does (`ManaChoice` for several abilities; `sourceMarks.ts`, `paySwap.ts`). The pool shows each kind as its symbol and `×N`, rider mana with a sparkle, restricted mana with a lock and kept mana with an hourglass. A card that can tap for mana now draws `ManaStrip`; the preview has a "Taps for" line.
- ChooseNumber (`numberChoice.ts`): starts on the smallest allowed number; Less, More, arrows and the slider skip `except`; Confirm is off with the reason for a number not allowed. With `cost` and `per_x` the total cost is drawn. An open range stops at 99.
- Attack by clicking (`kinds/DeclareAttackers.tsx`): a click toggles a creature in the attack. With several defenders the creature clicked last (`data-cue="active"`) goes to the next defender clicked: a pod, a tile, the bare board (`combat/defender.ts`) or a planeswalker or battle; the row's "Attack at" list does the same by keyboard. A `required` creature (goad) starts in the attack marked "Must attack" and No attack is not offered.
- Block by clicking (`kinds/DeclareBlockers.tsx`): a click on a blocker with one possible attacker blocks it, otherwise the blocker is chosen and then the attacker; a second click takes the block back. A `required` blocker reads "Must block"; `can_block` alone decides who may be blocked. An attacker in `BlockOptions.min_blockers` (menace) reads "Needs 2+ blockers", then "Needs 1 more", and Confirm waits (`blockersNeeded`).
- AssignDamage: without trample any whole split that adds up to `power` is accepted; the first split (`damageSplit.ts`) gives lethal (`DamageOptions.lethal`) in order and the rest to the last. With trample (`excess`) the rest goes to the attacked player or planeswalker (`damage-excess`) once every blocker has lethal. With `unblocked`, "Assign as though unblocked" sends all of it to the one attacked.
- ChooseTargets (`targetText.ts`): the sentence names the source and gives the engine's `wording`; a click on a chosen target takes it back; the list holds every legal target, players included. A triggered ability has no Cancel; its way out is the clock's `Remove` ([server.md](server.md), Response clocks). With a `total` a target that would go over it is neither marked nor taken (`fitsTotal`).
- DivideAmount (`divideText.ts`): one row per target, each at least `MIN_SHARE`, summing to `total`; it starts at the server's even division and Confirm is off until nothing is left.
- ChooseCosts (`costsText.ts`): a toggle per optional cost; one gift only (`SEAT_BASE + seat`), a second refused with the reason. Confirm costs sends the taken indices in ascending order and is focused, so a press made without looking pays nothing extra. Costs paid several times (multikicker) are a `ChooseNumber`.
- Generic prompt (`genericChoices.ts`, `GenericAnswers.tsx`): a kind with no prompt of its own says "This decision is not supported in the UI yet" and offers a button per answer its options allow (at most 12), led by the clock's answer. A decision that needs a set made by hand has no button and says so.
- OrderTriggers (`orderText.ts`): the list is in resolution order and the answer is it reversed, the order they go on the stack.
- YesNo, ChooseOption and ChooseMode (`choiceText.ts`) ask in the engine's `text`. ChooseMode with exactly one choice answers at once; otherwise modes toggle, Confirm waits for `min`, and the answer lists the chosen indices in card order.
- ChooseCards (`cardsText.ts`, `PromptCard.tsx`): the cards of `from` in a grid that scrolls in the strip, a face-down stand-in for a card the view lacks. From 13 cards, or 2 in a library search, `CardSearchField.tsx` narrows by name, type line or rules text and shows "N of M"; Escape clears it before Escape undoes, and a hidden choice still counts. The manual Search (`TutorBody.tsx`) shares it. Surveil (`kinds/ScryCards.tsx`) draws two piles.
- OrderCards (`kinds/OrderCards.tsx`, `lookText.ts`) and Scry (`kinds/Scry.tsx`, `scryPiles.ts`): pictures with a place number, moved by buttons, Alt and an arrow or a number key, the scry piles also by drag; a line previews the result. An untouched scry sends every card on top, as the clock does. `CardChoices.tsx` is the one picture grid for every card choice (`useRestingPreview`).
- ChooseReplacement (`kinds/ChooseReplacement.tsx`, `replacementText.ts`, `oracleWords.ts`): a row per replacement effect with its source's picture, name and its own effect's words (the rules text from `useOracleText` only when the candidate has none).

## Table feedback

`features/table/fx/` draws short animations for what a batch did. They decorate the true state, which the table already shows when they start: nothing waits for them, no answer is delayed, and ending one only removes an attribute.

- `watchBatches(store, fx)` (`batch.ts`) subscribes to the play store. `batchBetween(prev, next)` takes a change for a batch only when `seq` moved on by exactly the events appended to the log, so snapshots, decisions and chat never animate. `deriveEffects` (`derive.ts`, pure) returns `Effect[]` in a fixed order.

| Effect | Comes from | ms |
|---|---|---|
| `attacked`, `blocked` | `AttackersDeclared`, `BlockersDeclared` and the combat diff | 500 |
| `damaged` | a permanent: `DamageDealt`, else newly marked damage; a seat: the life diff | 550 |
| `healed` | a seat: the life diff | 550 |
| `entered` | a permanent that was not on the battlefield | 350 |
| `died` | battlefield to graveyard, or named by `CreatureDied` (a token); at most 24 a batch | 500 |

- A `died` effect carries the card's last look, so a ghost stands where it was (`GhostCard`, `aria-hidden`); a player who loses takes their permanents out without ghosts. A lane whose last permanent died keeps its place while the ghost plays (`useGhosts`).
- `createFx` (`store.ts`) keys effects by card, seat and row; one timer per kind and batch removes them after `FX_MS`; a batch plays at most 120. `mode` (`off`, `reduced`, `full`) is read every batch; `reduced` plays still highlights only.
- `TableOptions.effects` is on except under vitest; a test turns it on with `renderTable({ options: { effects: true } })` and fake timers.
- `Card` sets `data-fx` and `data-fx-side`, `LifeFx` wraps the life figure. Durations are `--fx-<kind>-ms` in `fx/fx.css` (`fxCss.test.ts` holds them equal to `FX_MS`); `--fx-slow` stretches them.
- `fx.travel` (`travel.ts`, `places.ts`, `FxTravel.tsx`) flies the moves of `deriveMoves` with the Web Animations API on a fixed `aria-hidden` layer: sources are measured before React draws the batch, destinations on the next frame (`measurePlace`); `planFlights` staggers the legs. Nothing flies under `reduced` or `off`, and a new batch with moves ends the previous flights.
- `fx.strikes` (`strikes.ts`, `strikeLayer.ts`, `FxStrikes.tsx`, `full` only): combat damage dealt before anyone has priority is a strike, one per source and damage step; the source's picture lunges at what it damages and back in `STRIKE_MS`, holding the targets' `damaged` effects and ghosts until the hit (`splitImpacts`, `holdDeaths`).
- Moves to the stack and on, the spotlight, target arrows and the hand's reasons are designed in [ui-design.md](ui-design.md), Playing is legible. `stackTargets.ts` lists each stack item's targets with `gone` read from the view and log; `combat/stackArrows.ts` plans them as `target` lines in `CombatOverlay`'s `stack` layer.
- A crowded stack (`stackGroups.ts`, pure): neighbouring items that are the same ability of one source and controller, or copies of one spell, fold into one chip with "×N". `chipsThatFit` keeps the top chip and what fits; the rest go behind one "+N more" button that opens the Stack tab. A stack anchor is `data-stack-chip`, else `data-stack-members`.
- Log wording that needs the surrounding events (`eventContext.ts`): the resolving spell ("X counters Y"), an activation's targets, and an ability's source, so a resolving ability reads "An ability of X begins to resolve".
- Table moments (`moment/`): `watchMoments` shows public events to every seat over the table: `Revealed` cards large with who and why, a die (`rollFaces`, the same faces everywhere) and a coin turning in 3D (`CoinFace.tsx`). A look at a library makes none. At most three stand for `momentMs`; Escape or Dismiss ends them; under reduced motion the result shows at once. A coin call is a `ChooseOption` drawn as Heads and Tails.

## Sounds

`features/sound/` plays a few short, quiet cues at the table, synthesized with WebAudio, so no sound file ships.

- `soundCueBetween(prev, next)` (`cues.ts`, pure) gives at most one cue per change of the play store, the strongest first: `won` when the result names the viewer, `turn` when the viewer's own turn begins, `decision` when a decision for the viewer arrives while none was pending. A first view, a spectator's table and any other seat's turn, decision or win give none.
- `playCue` (`synth.ts`) plays one to three sine notes of 160 ms at a peak gain of 0.05 through one lazily made `AudioContext`; a browser without WebAudio, or before the page was clicked, plays nothing and throws nothing.
- The cues are on until muted: `mtg.sounds` in `localStorage` (`soundPrefs.ts`, every access in try/catch) is `off` while muted, followed by every tab. The switches are "Play sounds" in the Full Control menu and Sounds on the settings page.
- `useSoundCues` runs in `GameTable` while `TableOptions.sounds` is on (everywhere but under vitest and the replay viewer).

## Pace controls

The Priority prompt's controls (`prompt/PassControls.tsx`, drawn in the controls dock of the table, 44 px high), over the wire rules in [protocol.md](protocol.md) (Pace of play) and the privacy rules in [ui-design.md](ui-design.md) (Priority, stops and information leaks).

### Primary button and yields

`data-slot="primary-action"` answers `Pass` (disabled when `can_pass` is false). `primaryLabel` (`passWords.ts`) is display only; the server decides what happens. "Pass priority" is never a visible label; it is the `aria-description`. Resolve and End turn are never one button: the primary button never says "End turn", and in the last window of the viewer's turn over an empty stack (`lastWindow`) it is not drawn, so a Resolve pressed twice never ends the turn.

| Situation | Label |
|---|---|
| a spell on the stack | "Resolve <top spell>" ("Resolve" in a short dock) |
| the viewer's turn, before the last window | "Next: <next step>" |
| the viewer's turn, the End step, empty stack | no primary button; "End turn" alone |
| another seat's turn | "Continue" |

The dock's form (`dockForm(regions)` in `layout.ts`) sets how much the words say: `full` (a main area of `DOCK_FULL_MIN_MAIN_PX` or more) draws key hints and the whole words; `short` leaves the hints to tooltips and `aria-keyshortcuts` and writes short words; `compact` is the phone's dock.

- "End turn" (`secondary-action`, `endTurnShown`; first in a phone's menu, except in the last window) asks for `yieldUntil('EndOfTurn')`; under Full Control it shows only in the last window and passes once. The menu "More ways to pass" has "Resolve everything on the stack" (over a stack) and "Pass until my next turn".
- A yield is asked once per prompt: the buttons wait for `Yielding` or a fresh decision. The server refuses yields under Full Control, so there `yieldUntil` sends nothing and neither "End turn" nor the menu is drawn.
- `YieldIndicator` ("Passing until the end of turn", "Stop passing" for `cancelYield()`) shows while the store's `yielding` is set, which only `Welcome` and `Yielding` set.
- Auto-skips (`features/table/autoSkips.ts`, set only by `Welcome` and `AutoSkips`): the "Auto-skip triggers" switch (`stops/AutoSkipToggle.tsx`, saved with the account) stays beside the stops with a list of the auto-passed abilities and rules. A stack chip, the stack preview and a stack ability's menu offer "Auto-pass this trigger"; a yes-or-no question from the seat's own trigger adds "Always Yes" and "Always No", and the trigger-order prompt "Always use this order". Each sends `AutoSkip` before the answer.

### Stops and Full Control

`features/table/stops/` and `play/session.ts`. The server decides the windows from the stops and the mode ([protocol.md](protocol.md), Stops and Full Control); the page only asks for them and shows what the server holds.

- `stops` (`{side, step, keep}`) and `fullControl` (`Off`, `NextWindow`, `Held`) are replaced whole by `Welcome`, `Stops` and `FullControl` and survive a dropped connection until the next `Welcome`.
- The default stops (`play/flowPrefs.ts`): an account or guest that saved none gets `DEFAULT_STOPS` (the own declare attackers and postcombat main) at a fresh table's first `Welcome`; a cleared list stays cleared.
- The by-hand window (`play/byHand.ts`, `PlayState.byHand`): the server holds a seat at every window after its own spell or ability of a card flagged `ObjectView.manual_owed` resolves, an ability of its own is left to the table (`AbilityLeftToTable`) or a by-hand line of its own comes due (`ByHandDue`), until it passes; the client reads the same from the events. Meanwhile the Priority prompt reads "Apply <Card name>'s text by hand, then continue."; no other seat reads it.
- The step ladder is the stop ladder (`turn/StepLadder`, `StopMark`): for a seat that can set stops each step that gives priority is a button (`data-slot="stop"`, `aria-pressed` while the server holds a stop, `data-keep`). A held stop is an outline with a dot (a pin when lasting), apart from the current step's fill. Untap and cleanup take none (`play/stops.ts`). The ladder is one tab stop.
- `StopControlsProvider` (`stops/stopControls.tsx`) holds what the ladder and the dock share: the Keep toggle, the side picked by hand (it follows the turn until picked) and `press`. `StopLadder` (in `StopsBar`, beside `FullControlToggle`) holds `StopSideSwitch` ("Mine" or "Theirs") and the Keep toggle.
- The ladder sits in the top bar from 1024 px (`TablePlan.ladderInBar`), else in the "Stops" popover. `StopsDock` puts `StopsBar` in the dock as one row from 1600 px, else behind the "Stops" button; the popover stays mounted, so its keys keep working.
- A press sets a one-turn stop or clears a held one; Shift and press, or Keep, sets a lasting stop (`pressRequest`). The Full Control toggle asks for Held, or Off when a mode is on.

### Response clock

- A `Decision` with `deadline_ms` becomes `pending.deadlineMs`. The session counts it down in `PlayState.clock` and at zero clears `pending` itself: the server has answered, and a prompt left up would invite a stale answer.
- `prompt/ResponseClock` shows "Passing for you in 7 s" (`clockText.ts` words what the server answers for every kind) as a `role="timer"` that does not announce each second; the last three seconds are urgent (`data-urgent`). Its bar is `response-clock-bar` (`prompt/responseClock.css`).
- Away seats: `Presence` sets `PlayerView.connected` and its `deadline_ms` starts that seat's clock (`play/awayClocks.ts`). A seat still in with no client wears `AwayMark`, and the waiting line adds "Bo is away: the game acts for them in 12 s" (`presenceText.ts`), the seconds hidden from the live region. An eliminated seat never reads as away.
- Timer bank: every pod draws the public `PlayerView.bank` beside the name (`BankMark`, `bankText.ts`): an hourglass and the count, nothing at 0. When it drops the mark reads "N used" with a warning edge for five seconds (`data-spent`).
- Turn time (`TurnTimeMark`, `lib/turnTime.ts`): every pod draws a seat's time on its own turns as m:ss (h:mm:ss from an hour), nothing before its first turn. The running seat's figure ticks from `PlayState.viewAt` on one shared second interval (`useSecondTick`). The game-over list gives each seat's total.

### Keys

| Key | Action |
|---|---|
| Space | presses the primary button |
| Enter | presses "End turn"; where none is drawn (Full Control, the End step) the primary button (`enterYields`) |
| Shift+Enter or another modifier | nothing |

## Accounts and games pages

Sign-in uses the server's accounts ([server.md](server.md); bodies in [protocol.md](protocol.md)). A guest needs no account: a seat link opens a seat. A server without `DATABASE_URL` answers 503 `accounts_unavailable`, and the app then offers no sign-in anywhere.

- `net/accounts.ts` `createAccountsApi` sends `credentials: 'include'`. A failure is an `AccountError {code, status, retryAfter}`; `AUTH_ERROR_CODES` is a `Record` over the generated union, so a new code stops the build until it has words.
- `features/auth/store.ts` `createAuthStore` is the app's `appAuth`, started once by `AuthProvider`. `status` is `loading` until `GET /api/auth/me` answers, then `signed-in`, `signed-out` (401, network, 5xx or unreadable) or `unavailable` (503). A failed `logout` keeps the user and sets `notice`. An answer that arrives after a newer question is dropped (`round`).
- `/login` and `/register` (`AuthScreen`, `AuthForm`) check username and password (`rules.ts`, copies of the Rust constants) before sending. The password is in no React state: the field is uncontrolled and emptied after the answer. A field problem sits in an always-present polite region in `aria-describedby` and focus goes to the first wrong field; a form failure is a focused `Alert`. Every `AuthErrorCode` has a sentence and a field (`errors.ts`; a wrong sign-in names neither half).
- `next`: `sanitizeNext` (`features/auth/next.ts`) accepts only a path on this site (one leading `/`, no backslash, control character or `//` after dot segments, not `/login` or `/register`, no fragment, since a seat token must not travel in a query). `parseAuthSearch` always names the key, so the router cannot merge the unchecked value back in.
- `/register` where `GET /api/auth/options` says registering is closed shows "New accounts are made by an admin" with a link to sign in, and the header drops Register; a 403 `registration_closed` shows the same.
- `/precons` (`features/precons/PreconsPage`), public: `net/precons.ts` `createPreconsApi` (`PreconError`; 503 `cards_unavailable` reads "No card data on this server"). `PreconFilters` (search over name, set code and commanders; set; deck check; "Sort by" kept per browser) over `PreconRows` (a table from 64 rem, stacked below). The badge follows `statusOf`; an illegal precon adds a "Not legal in <format>" pill (`LegalityPill`) and Play stays enabled. `PreconDialog` (`usePreconDetail`) shows each card's picture and, when not Verified, its clauses as each reason's `quote`, or the card's `whole_text` (`ClauseList`), so it reads no card; "Copy list" copies those cards. A read view stays for the page's life, since the server budgets requests per address.
  - Play (`usePlayPrecon`, `play.ts`): `createGame` with the form's defaults and `deck: "precon:<code>"` for seat 1, `commander` format for a Commander deck; a guest gives a name first. Success opens the lobby; a 422 or `unknown_deck` shows "Could not start a game with <name>" with Show why.
- `/games` (`features/games/MyGamesPage`): signed out goes to sign-in. `GameRows` is a table from 64 rem, stacked rows below. "Continue" opens `/game/<id>` with no fragment; a finished game has none (the server drops it ten minutes after it ends). A game that failed to resume has a "Failed" badge, the reason and "Remove". ## Reviewing cards

`/review` is the one place where a player reviews the cards that need attention ([cards-dsl.md](cards-dsl.md), Read tier; endpoints in [server.md](server.md), Reads): `?deck=<id>`, `?precon=<code>`, `?mine=true` (the account's decks) or none (every card waiting for a first read). `/read` with the same parameters forwards to it, and every link to reading or checking cards opens it (`readPath`).

- `net/reads.ts` `createReadsApi` is the typed client of `GET /api/reads`, `GET` and `PUT /api/reads/{oracle_id}`; a failure is a `DeckError` (`stale_read` among the codes).
- Items (`features/reads/review.ts`, pure): To read is the `ReadQueue` (drafts that run Unverified or take more reads). To check is the target's cards played partly or wholly by hand (`useCheckCards`), less those to read; with no target there is no To check.
- `ReadPage` (route `review.tsx`) sends a visitor signed out to sign-in and tells a server without accounts. `ReadView` has a header (`queueWords`), progress ("5 of 12 reviewed", `progressOf`) and the ways out; from `lg` a list beside the card (`ReviewList`), below it a "Card 2 of 12" bar with Previous and Next. A verdict or Checked opens the next open card, preloaded, announced politely; the last shows "Every card is reviewed".
- A card to read (`ReadCardView`, `useReadCard`): picture, name, state, counts, the account's verdict and `ReadSheet` (each Oracle clause beside the game's words, `engineWords`; a row's tone is an icon and words with a `support-*` edge), then "Reads right" or "Reads wrong" with a note of at most 280 characters. A card to check (`CheckCardView`): picture, line-marked Oracle text (`LineMarksList`), reasons, "Play by hand in <deck>" and "Checked".
- Wording-only bulk (`BulkApprove`): the cards `GET /api/reads/bulk` lists (every differing clause matches by wording alone) are offered as "Approve N wording-only"; its dialog shows each pair with the changed words marked, and `PUT /api/reads/bulk` approves them. `/read/bulk` (`features/bulk-reads`) lists every such card grouped by rule.
- Keys (`reviewKey`, `ReviewKeys`): C reads right or checked, W reads wrong, J or Right next, K or Left previous, H plays by hand in the card's only deck, ? shows the keys. The verdict buttons stay `aria-disabled` for `READ_DELAY_MS` (2 s) after a draft appears, so nobody judges a card unread.
- The server keeps the verdicts; the browser keeps the current card and the cards checked per queue (`localStorage`). A 409 `stale_read` shows "The rules changed" with "Load the new version". After Reads wrong the screen offers "Play by hand in <deck>" when a deck is reviewed, else a link to `/decks/unvalidated`.
- `ReadDialog` is the card to read in a dialog, without its picture. The table's pinned preview offers "Read its rules" to a signed-in player for a card on a read or with clauses by hand (`readableOf`); the dialog lives in `CardPreview` and reads its client from `ReadsApiContext`.

## Learn

## Testing

- vitest on jsdom: `scripts/check.sh web`, or `pnpm test` in `web/`.
- Clock budgets and timeouts go through `scaled(ms)` (`test-utils/loadFactor.ts`): times `1 + load / cores`, at most `MAX_LOAD_FACTOR` (12). `MTG_LOAD_FACTOR` sets the factor; `MTG_STRICT_PERF=1` keeps the numbers as written.
- A test of a timer never sleeps or races the real clock: it runs on a fake clock (`installFakeClock`, `settle(ms)`, `flushFakeClock` in `test-utils/fakeClock.ts`) or waits with `waitFor`/`findBy` on the state it asserts.
- `src/test-utils` has the fakes (`FakeNetwork`, `FakeTimers`, `startSession()`), the Rust-generated `transcripts` (replayed by `transcript.test.tsx`) and the harnesses `renderGame()`, `renderTable`/`renderLiveTable` (laid out for `TEST_VIEWPORT`; jsdom has no layout, so measured sizes are faked) and `renderApp`. A new prompt copies `Priority.test.tsx` and `PriorityLive.test.tsx`.
- Screenshots: `node scripts/ui-shot.mjs <url> <out-prefix>` (options in `CLAUDE.md`) over a dev route; `--theme dark` or `light` sets the scheme Firefox reports. Pages other than the table read their width at mount, so shoot one width per run. A stored theme needs a reload in `--wait`: `(sessionStorage.getItem('s') ? <ready> : (sessionStorage.setItem('s', '1'), localStorage.setItem('theme', 'dark'), location.reload(), false))`.
- Layout audit: `node scripts/ui-audit.mjs <url or /path>... --base <dev server>` measures pages in Chromium (`CHROMIUM_PATH` as for e2e) with the rules of `layout.spec.ts`, prints a row per page, size and theme and exits 1 on a failure; the options are in the script. It loads `e2e/layoutAudit.ts` as it is and needs Node 22.18 or newer.

### End-to-end

`pnpm e2e` (`playwright.config.ts`) starts `cargo run -p mtg-server` on port 8301 (an empty `DATABASE_URL` gives the in-memory store and the built-in demo decks; `MTG_DWELL_MS=0` passes idle seats at once) and `pnpm build` plus `vite preview` on port 5301, both new for every run.

- `E2E_SERVER_PORT` and `E2E_WEB_PORT` override the ports (`e2e/ports.ts`) to run several suites at once; the Vite dev server for `/dev/table` listens on `E2E_DEV_WEB_PORT` (the web port plus 1000). `E2E_REUSE=1` keeps servers already listening; `E2E_TRAIL=1` prints every answered decision.
- `e2e/seeds.ts` gives each server an engine seed (`MTG_SEED`, [server.md](server.md#configuration)), so a failing game replays exactly; a failed Commander or precon run attaches `seed.txt`. `E2E_SEED=<n>` replays a seed and `E2E_SEED=random` restores a random one.
- A failed test keeps its Playwright trace (`retain-on-failure`) in `web/test-results/<test>/trace.zip`; `pnpm exec playwright show-trace <zip>` replays it.
- On NixOS Playwright's own browser cannot run: `CHROMIUM_PATH=$(ls -d /nix/store/*-chromium-[0-9]*/bin/chromium | head -n 1) pnpm --dir web e2e`.
- `full-game.spec.ts` (`driver.ts`) plays both seats through the real UI: a seat waits for a new `data-decision-id`, reads its legal cards (`data-highlight="legal"`) and answers with real clicks, with no sleeps. A window is idle (`isIdle`) when no hand card, commander or non-land permanent is legal (a land is legal for its mana ability, which is not a play). `driver.spec.ts` holds the helpers against fixture pages.
- `fit.spec.ts` sweeps the six sizes of [ui-design.md](ui-design.md) and four more, down and back up, over a real two-seat game, `/dev/table` from 2 to 40 seats in both themes, the heavy, attachments and crowded scenes, the Commands panel and game over: no page scroll, every region in the window, and the hand, primary button, your life and the way to a new game in view and uncovered.
- `combat-clicks.spec.ts` declares an attack and a block by clicks at two and four seats and checks each click's marks, that only the attacked seat is asked to block and that every log names the block. `keyboard-turn.spec.ts` walks a turn by keyboard alone at 1600x1000 and 390x844 (tab order, the ladder as one stop, H and Escape) and checks AA contrast of the by-hand mark and the "Not now" hint.
- `ux-fit.spec.ts`, `ux-flow.spec.ts` and `playtest-fit.spec.ts` hold single defects on the dev routes; the other specs (`commander-builder`, `rooms`, `reload`, `fx-flier`, `fx-spotlight`, `manual-panel`, `duel-walk`, `lobby-controls`, `join`, `presence`, `bank`) hold the feature they name. `bank.spec.ts` needs a server with `E2E_ACTIVE_SECS` (say 10; `E2E_EXTENSION_SECS`, default 4) and is skipped without it.
- `layout.spec.ts` is the layout gate of [ui-design.md](ui-design.md), Definition of done. Each page that needs no account and the dev routes for the account pages open in light, then dark, at the six sizes and `EXTRA_SIZES`, down and back up (`layoutAudit.ts`: `measure` in the page, `problemsOf` over what it read):
  - No sideways scroll or box cut off sideways; no text under 12 px; no lane over another or outside a board that does not scroll; every primary action in the window and uncovered. A page meant to fit never scrolls down from its `fitsFrom` width; any other has its action scrolled into view.
  - `exempt` names what is cut off on purpose: on the table the card art, the tile strip, the stack chips and the hand fan. A mana symbol's letters are a picture. An action is a CSS selector or `text:Words`.
  - Two tests feed it a page that breaks every rule and require it to say so. Decks, My games and the builder need Postgres and are held by `accounts.spec.ts` (`layoutGate.ts`).
  - A stop with `shots` is also screenshotted at 390x844 and 1440x900 in each theme, attached and written to `E2E_SHOTS_DIR` when set.
- `accounts.spec.ts` needs Postgres: with `E2E_DATABASE_URL` set to a scratch database the config starts a second server (8302) and preview (5302); without it the spec is skipped. Its layout gate registers two accounts once and needs card data (`mtg-cli ingest`, or `create database … template magic`). The server migrates only its own tables; `ingest` migrates `decks` and `cards`.
- `admin.spec.ts` needs the same database; the owner is marked admin with `psql`, since the server marks the admin only at start. It makes an account, signs the friend in, checks the friend has no Accounts link, and shows the closed sign-up page.
- `precon-game.spec.ts` needs card data (`mtg-cli ingest` and `compile`). Accounts register once per invocation and play precons made through the UI (create form, invite code, Precons tab, Ready): the verified and manual pairs to turn 9, four seats to turn 6. `E2E_SHOTS_DIR` saves a screenshot per prompt kind and turn; a failure attaches the trail.
- `commander-four.spec.ts` needs the same data: four accounts play four precons with Starting life 12 (`E2E_LIFE`) on a pinned seed and must finish by `E2E_TURN_CAP` with one winner, every page agreeing on turn and lives, tax and commander damage shown, and no scroll, cut-off or console error. `E2E_DECK=owner` gives every seat `crates/mtg-testkit/tests/fixtures/decks/owner.arena.txt` instead.
- `by-hand.spec.ts` (card data): two accounts play freeform decks of Partial creatures; at 1440x900 and 390x844 the by-hand mark and the `h` key open the clause list, and both logs hold the cast and "has rules to apply by hand".
- The specs that register accounts (`accounts`, `settings`, `precon-game`, `commander-four`) meet the server's ten registrations per 15 minutes per address: run them in separate invocations with one worker. `settings.spec.ts` needs no card data.

```sh
docker compose exec db psql -U magic -c 'create database magic_scratch template magic'
E2E_DATABASE_URL=postgres://magic:magic@localhost:5432/magic_scratch pnpm --dir web e2e e2e/accounts.spec.ts
docker compose exec db psql -U magic -c 'drop database magic_scratch'
```

To try the account screens by hand, run the server on that database (`DATABASE_URL=… MTG_BIND=127.0.0.1:8318 cargo run -p mtg-server`) and the dev server in front of it (`MTG_SERVER_URL=http://127.0.0.1:8318 pnpm --dir web dev --port 5318`). `ui-shot.mjs` cannot set a cookie, so a signed-in page needs Playwright.

## Conventions

- Cards the engine plays only in part (Partial, Manual or Stale) are "played by hand" everywhere, in the words of `lib/byHand.ts`; a card's mark keeps its support state's name, and a Read card runs whole, so it is never "played by hand" (`runsWhole`, `ON_A_READ`). `lib/byHand.test.ts` fails on any other spelling in the sources and specs.
- The words a player reads spell "color" the American way, as the rules, cards and deck issues do (`spelling.test.ts`); identifiers keep theirs.
- Server-held state is shown, never predicted: ready, yields, stops and Full Control change on screen only when the server says so.
- Colour never carries meaning alone, and live regions are polite. A row of cards, a ladder row or a list is one tab stop (arrows, Home, End); a control that must keep focus when it cannot act is `aria-disabled`, not `disabled`.
- Every animation sits inside `@media (prefers-reduced-motion: no-preference)`, and a CSS test per stylesheet (`*Css.test.ts`) fails when one leaves it; under `reduce` an effect is a still highlight, the clock bar is not drawn, the turn banner only fades, and phase themes, the focus board and the tab title change without motion. JS reads `useReducedMotion` or `prefersReducedMotion`.
- Colours are tokens with a light and a dark value (`tokens.test.ts` checks their contrast); Tailwind class names are written whole so Tailwind can see them.
