# Data sources

Verified against live data on 2026-10-17.

- **Scryfall bulk** (`GET https://api.scryfall.com/bulk-data`, send `User-Agent` and `Accept`): files are now **gzipped JSONL** (`jsonl_download_uri`). Use `oracle_cards` for the card catalogue and `rulings`. Parse with `mtg_import::scryfall::{cards_jsonl, rulings_jsonl}` behind a gzip decoder; the JSON-array readers remain for older dumps.
- **MTGJSON** `https://mtgjson.com/api/v5/DeckList.json` indexes ~3,100 decks of many types (`Commander Deck`, `Starter Deck`, `Planeswalker Deck`, ...). A deck file is `https://mtgjson.com/api/v5/decks/<fileName>.json`.
- Real-data quirks handled: reversible cards are listed by MTGJSON as `A // A` but Scryfall names them `A`; memorabilia `front_card` placeholders share names with real cards and are not deck cards.

## Mana cost strings

Verified on the oracle-cards file of 2026-10-17 (38,753 cards). `mana_cost` is written per face (`{2}{W/P}{G/U/P}`); the card-level text of a split or adventure card joins its faces as `{2}{B} // {B}` (`ManaCost::parse_faces`), and a transform or modal card has none there (the importer's `CardRecord.mana_cost` falls back to the front face). The file uses 61 distinct symbols: the numbers 0 to 16 and 1000000 (Gleemax), `{W}{U}{B}{R}{G}` and `{C}`, the monocolored hybrids `{2/W}` to `{2/G}`, the ten colour pairs (`{W/U}`, `{U/B}`, `{B/R}`, `{R/G}`, `{G/W}`, `{W/B}`, `{U/R}`, `{B/G}`, `{R/W}`, `{G/U}`: the orientation cards print, which `ManaCost` keeps), the Phyrexian symbols (`{W/P}` to `{G/P}` and `{C/P}`, on Kozilek, Compleated and That Which Was Compleated), four hybrid Phyrexian ones (`{G/U/P}`, `{G/W/P}`, `{R/G/P}`, `{R/W/P}`), the colorless hybrids `{C/W}` to `{C/G}` (MH3), and `{X}`, `{Y}`, `{Z}`, `{S}`, `{HW}`, `{D}`, `{L}`. `ManaCost::parse` reads the first 54; the last seven are refused by name (`Unsupported`), never skipped (X waits for the M3 item "X costs"; the rest are silver-border or playtest symbols). Scryfall prints symbols in no fixed order (`{1}{G}{G/U}{U}`, `{1}{R}{W}`), so `ManaCost` sorts them. The importer keeps the text; `CardFace::cost()` is the step from it to a cost (`None` for a face with no cost, `Some` for the rest, `{0}` included, an error naming an unsupported symbol), which the card compiler will call.

`crates/mtg-import/tests/fixtures/scryfall_mana_costs.tsv` holds every distinct string of that file (864 single-faced costs with Scryfall's `cmc` and colours, 211 face costs, 297 `//` texts; made from the dump by a short script, majority value per string because a few joke cards disagree with their own cost). `tests/mana_costs.rs` reads each: the mana value and colours of every cost it parses equal Scryfall's, and a refusal must name one of the seven symbols. The 290 `manaCost` strings of 56 MTGJSON precon decks are all among them. The local Postgres of `docker compose up -d db` holds no imported cards yet (the importer CLI is an open M1 item), so there is nothing more to check there.

## Running the real-data tests

```sh
mkdir -p /tmp/mtgdata && cd /tmp/mtgdata
# download oracle-cards-*.jsonl.gz, rulings-*.jsonl.gz, DeckList.json and some decks/<fileName>.json
MTG_REAL_DATA_DIR=/tmp/mtgdata cargo test -p mtg-import --test real_data -- --ignored
```

## Deck export formats (checked against real exports)

Verbatim exports of two Commander decks (cEDH Najeela, Warhammer 40K Tyranids) live in `crates/mtg-import/tests/fixtures/real/<site>/`; never reformat them. `tests/real_exports.rs` pins detection, section counts and exact entries. The Arena and MTGO files are Moxfield's export-menu output, the Archidekt lists were edited separately.

A corpus of 29 public decks (16 Moxfield, 13 Archidekt, 183 export files, each deck with the card lists its own site reports) lives in `crates/mtg-import/tests/fixtures/corpus/`; its README says how it was made. `tests/corpus_parse.rs` parses every export with the format a user would name and compares the cards with the site's lists, `corpus_detect.rs` pins what `detect` can and cannot know, `corpus_export.rs` writes every parsed deck out and reads it back.

- **Moxfield text** (`Moxfield`): `N Name (SET) num *F*|*E* #tag`, blank line, `SIDEBOARD:`, sideboard, then `STICKERS:` when the deck has stickers. Commanders (and an oathbreaker's signature spell) are the first lines, unmarked and out of alphabetical order, so `parse` keeps them in Main. `#tag` suffixes may hold spaces, parentheses and `!` (`#Card Advantage #!Wheel`, `#Lands (LOCKED)`) and are dropped. Multi-face cards are `A / B`. Detected by `*F*`/`*E*`, or an all-caps header together with printings.
- **Archidekt text** (`Archidekt`): `Nx Name (set) num *F*|*E* [Category{flags},Category] ^Label,#color^`, lowercase sets; `N` without the `x` reads the same. **The first category decides the board** and later ones never change it: the `{top}` flag is the command zone, a category named Sideboard the sideboard (even with `{noDeck}`), any other `{noDeck}` category the maybeboard, the rest the main deck (`[Ramp,Maybeboard{noDeck}{noPrice}]` is Main). Tag labels hold spaces and commas. An oathbreaker's planeswalker and signature spell both sit in the Commander category. Optional headers are generic roles (`Commander`, `Mainboard`, `Sideboard`, `Maybeboard`), category names or card types (`5: Lands`, `🟢 Main Deck`); a line that cannot be an entry, alone above a block of entries, is a header and never an error. Without brackets on the lines the generic role headers decide the board, with brackets the first category does. Some exports write only the front face of multi-face cards.
- **Arena** (`Arena`, as Moxfield writes it; no real Arena client export yet): `About`/`Name` preamble (emoji and brackets allowed), then `Commander`, `Deck`, `Sideboard` headers and no printings, optionally with `#tag` suffixes. The commander is under its header. Multi-face cards are written by their front face, split cards `A /// B` (`A // B` in one deck).
- **MTGO text** (`MtgoText`, Moxfield's MTGO menu; not the XML `.dek`): `N Name` lines without printings, blank line, `SIDEBOARD:`, sideboard, blank line, then a headerless block that is the commander. **That trailing block is the command zone with or without a sideboard**, for one, two or more commanders, so MTGO text needs no promotion; `STICKERS:` may come before it. Split cards are `A/B`, other multi-face cards the front face. Detected by an all-caps header with no printing anywhere; a text without such a header is plain `N Name` lines, and plain text reads the trailing block as the sideboard.
- Collector numbers are free text (`1492★`, `187p`, `2023-8`, `NPH-123`, `TMP-315`, `2026-2`, `2016`, `we313`, `tvdl345`) and set codes may start with a digit or hold five characters (`40K`, `PAL00`). Flags, categories and tags never reach names; `_____ Goblin` is a card.
- **Stickers are not deck cards.** Moxfield lists its sticker sheets (set `SUNF`) in a `STICKERS:` section. The parser keeps them out of every section and reports `ParsedDeck::ignored`, one `IgnoredSection { name, count }` per section name (as written, count = copies), never a line error. `export` does not write them. Only `STICKERS` is known: other all-caps lines such as `LANDS:` stay what they were, because plain lists use them as group labels.
- **Arena's export is lossy**: it drops cards that are not on Arena (Najeela 75 of 109 cards, Tyranids 72 of 131 and its commander). That is the site, not a parser bug; the tests pin the counts and require the parsed cards to be a subset of the deck.
- Commander imports call `decklist::promote_implied_commander(format, deck)`, which only moves Moxfield's first line (a single copy, with no commander marked). Moxfield's text does not say how many lines are commanders: for a partner pair or a Background it moves the first and leaves the second in Main, which the deck-builder UI has to fix; the tests pin both outcomes. Signature spells are deck cards and stay in Main. A Moxfield list with no foil or etched card and no sideboard or stickers reads as plain text and is not promoted, so the endpoint should let the user name the site.
- `detect` is decisive for Moxfield text with a foil or etched flag or an all-caps header, MTGO text with an all-caps header, every Arena export with an `About` block and Archidekt text with brackets. It cannot know, and falls back to plain text, for Moxfield lists with neither flag nor header (a `full-nofinish` export without sideboard), MTGO text without header, and Archidekt lists without brackets (`names-only`, `sets-only`; with a foil flag the latter reads as Moxfield, whose flag syntax it shares). A bracketless Archidekt list that opens with a header word (`headers-generic-plain`) reads as Arena. Every fallback reads the same cards in the same sections except an MTGO commander block, which plain text takes for the sideboard.
- Names the parser leaves as written and the resolver must map: Moxfield's flavor names (`The Ball` is Fellwar Stone, SLD 1040; `Rick, Steadfast Leader` is Greymond, Avacyn's Stalwart, SLD 143; `Skittering Kitten` is Masked Meower, OM1 96), the digital names Arena and MTGO exports give Universes Beyond cards (`Phenomena Recorder` is Peter Parker's Camera), the face notations above and front faces alone. The tests learn these from each deck's own data (printings shared with the site's list, leftovers by elimination), not from a list.
- The ignored test in `real_exports.rs` checks that every name of the eight real files except the flavor name `The Ball` resolves against Scryfall (needs `MTG_REAL_DATA_DIR`).
