# Card DSL and effect pipeline

Rules data for cards (`mtg-cards`) and the pipeline that runs it (`mtg-engine`).

Scope: the data model, loader, validation, support records, the corpus and card assembly are implemented in `crates/mtg-cards`, with the engine's capabilities in `mtg-engine` and the card source in `mtg-server`. The pipeline core ("Execution", "Decisions the effects need", "Snapshots") is implemented in `mtg-engine` for targets, modes, cards chosen by a player and put in an order, yes or no, payments, options, drawing, discarding, sacrificing, destroying, exiling, countering, scrying, looking at, revealing, searching for, moving (onto the battlefield too) and shuffling cards, life, damage, mana, tokens and counters (put, removed and moved on permanents and players); "Triggers, replacement and layers" is implemented for triggers (detection, the queue, order, delayed triggers, the intervening "if" and the limit) and for the layer rows of continuous effects that pump power and toughness or grant a keyword (durations, timestamps, derivation); the replacement step (tokens, damage, zone changes, counters put, life gained, cards drawn and entering, with ChooseReplacement) is implemented; the other layer rows and "Tasks" are the contract of the other M3 engine tasks. Related: `engine.md`, `protocol.md`, `deck-check.md`, `arena-flow.md`.

## Summary

| Area | Rule |
|---|---|
| Printed side | Name, cost, types, power, toughness and oracle text come from the imported Scryfall record. |
| Rules file | One JSON file per oracle card: abilities per face, keyed by oracle id, with the fingerprint of the oracle text they match. |
| Vocabulary | Verbs (`Effect`, `TriggerPattern`, `CostItem`, `Modification`, `Keyword`) and values (`Ref`, `Selector`, `Amount`, `Condition`). A primitive is one enum variant. |
| Execution | An effect list runs as a journal: each step is a pure function of state that yields events or asks one `Decision`; answers are logged as events. |
| Stack | Abilities are stack objects. Targets are chosen on announcement and rechecked on resolution (CR 608.2b). |
| Triggers | Detected from events (look-back ones against the state before the event), queued in state, put on the stack in APNAP order. |
| Replacement | A step in front of the fold; the affected player orders several (CR 616.1). |
| Static abilities | Derived when characteristics are derived (CR 613); never stored as effects. |
| Keywords | Enum variants with parameters; behaviour in one engine file each. |
| Support | `Verified`, `Partial`, `Manual`, `Stale` and `Unplayable` are computed from the file, the imported text and the engine's capabilities. |

## Decisions

| # | Decision | Reason | Rejected |
|---|---|---|---|
| D1 | Format: JSON, one file per oracle card. Serde's externally tagged enums, PascalCase variants, snake_case fields; unknown fields are errors; defaults are omitted. Short forms: a mana cost is a string (`"{X}{R}"`), a fixed `Amount` a number, a mana-only `Cost` a string | The database stores JSON, the M6 compiler emits data, the web reads it, errors carry a path (`serde_path_to_error`) | RON (no jsonb, no TypeScript reader), YAML and TOML (typing traps, awkward trees), Rust builders like `vanilla.rs` (not data), a text script (needs its own parser) |
| D2 | Identity: the key is the Scryfall `oracle_id`; the file is `cards/<slug>.json` at any depth; a predefined token is `cards/tokens/<id>.json` | `cards.oracle_id` is the database key; names change and collide with face names | A slug as key (a rename breaks joins), per-printing ids (rules belong to the oracle card), a sharded layout now (sharding is a rename of files) |
| D3 | Multi-face: one file per oracle card, `faces` in Scryfall order; a whole-card property (Fuse) is a keyword on face 0 | Decks and imports name the card; faces share identity and status | One file per face, a `layout` field (a copy of import data) |
| D4 | Characteristics: the printed side always comes from the import record; the file holds abilities and a per-face `oracle_fingerprint`; a token carries its own characteristics | Cards without a file need the record anyway, so there is one source; errata surface as drift; M6 generates thousands of entries | Copying cost, types and P/T into each file (a second source, silent typos) |
| D5 | Shape: verbs and values are separate; sequences are lists; results are named (`as`, `Bound`) | Names are validated; a new mechanic is one verb over existing values | Implicit anaphora (`last created`), one flat enum, a class per card |
| D6 | Support is computed, never stored | `Verified` cannot go stale or ignore an engine that lacks a primitive; no engine run | A stored flag, running tests per lookup |
| D7 | Execution is a journal of pure steps | State stays the fold of the log; a restart asks the same question; each step is testable | Blocking callbacks per choice, unlogged resolution flushed at the end, replay from the start on every answer |
| D8 | Triggers: detection from events, a queue in state | Detection is a function of events and data; the log shows why an ability appeared; a resume keeps the queue | Detection inside the fold, a queue outside state |
| D9 | Replacement: a step in front of the fold | The fold stays dumb; the log holds what happened | A `replaced` flag on events, replacement inside each primitive, a fixed global order |
| D10 | Static abilities are derived | Characteristics are already derived; layer dependencies come from the data | Registering statics as `ContinuousEffect`s, a per-card layer table |
| D11 | Keywords: one enum, one engine file each | An exhaustive `match` flags a forgotten keyword; parallel tasks touch separate files | Keywords as strings, a shared registry file |
| D12 | Validation in three levels; all errors are collected | A file is judged where the information is | Checking when the engine uses a card, stopping at the first error |
| D13 | The compiler writes the same files; an unreadable clause becomes a `Manual` ability | One reader and one validator; a deck is never blocked | A second format, refusing decks with unimplemented cards |

## Files

| Path | Content |
|---|---|
| `crates/mtg-cards/cards/<slug>.json` | Rules of one oracle card |
| `crates/mtg-cards/cards/tokens/<id>.json` | A predefined token (Treasure, Clue, Food, Gold, Blood, Junk, Powerstone, Vibranium, Map, Mutagen) |
| `crates/mtg-cards/tests/fixtures/corpus/<slug>.json` | The imported Scryfall object of one corpus card |
| `crates/mtg-cards/tests/fixtures/reproduced.txt` | The ratchet list: the corpus cards the compiler reproduces, one name per line, sorted |

- `mtg_cards::builtin::library()` is the library of these files, embedded at build time (`build.rs`), so a server needs no directory and a deploy carries the rules it was tested with.
- Canonical text: compact JSON in serde's field order, laid out by `mtg_cards::pretty` (a value stays on one line up to 100 columns, otherwise one entry per line).
- `MTG_UPDATE_CARDS=1 cargo test -p mtg-cards corpus::` rewrites the files and their fingerprints; the test fails on a file that is not canonical.
- `cargo test -p mtg-cards hand_written::` checks every rules file as a file of its own (`Library::check_generated`) against its fixture record and against the newest `oracle-cards-*.jsonl.gz` of `MTG_REAL_DATA_DIR` or the `mtg-cli` cache; without a download it checks the fixture only and says so. An erratum fails the card it changed: fix the rules, or refresh the fingerprint when they still fit.
- `cargo test -p mtg-cards fixture_real::` compares the fixture records with the same download; without one it says so and passes.

## Adding a corpus card

No test holds a count of cards, sources, compiled sources, reproduced cards or fingerprints; each is derived from the card directory and the fixture, and a test asserts what the number stood for. A new card needs:

1. Its rules file `crates/mtg-cards/cards/<slug>.json` (the slug is the card's name lowercased with every run of non-alphanumerics as `_`, `mtg_cards::load::slug`). A `Full` or `Partial` face starts with an empty `oracle_fingerprint`.
2. Its Scryfall object as the new file `crates/mtg-cards/tests/fixtures/corpus/<slug>.json`, with the same slug: pretty-printed JSON of one object and a final newline (a multi-face or split card is one file named after the whole card name). The rules file and the fixture file share the `oracle_id`, and each card has exactly one of each. No other file changes for this step, so branches adding different cards never conflict here.
3. `MTG_UPDATE_CARDS=1 cargo test -p mtg-cards corpus::` writes the rules file in canonical form with the fingerprints of the fixture's text and adds every card the compiler reproduces to `crates/mtg-cards/tests/fixtures/reproduced.txt`. It never removes a name: a listed card that stops being reproduced fails.
4. `cargo test -p mtg-cards -p mtg-testkit`. A card the engine plays whole needs no row. A card it does not (Manual or Partial) is a row of `NOT_VERIFIED` in `crates/mtg-testkit/tests/it/corpus_cards.rs` with its state and the number of abilities it carries; a Verified card carries the abilities of its file, and each basic land type adds its mana ability.

`reproduced.txt` is a plain list in sorted order, one name per line, and the update inserts a name at its sorted position. Two branches that add different names conflict only where the names are adjacent; the resolution keeps both lines, and the update command restores the order if it is off.

The tests report a card without its record or file, a fixture file that is not named after its card or lacks the final newline, two files with one oracle id, a stale or missing fingerprint, an unlisted reproduced card and an unexpected state with the card's name, the file to add and this section. The fixture directory loads in file-name order and no test depends on that order. `tests/it/adding_a_card.rs` adds a card to a copy of the directory and the fixture directory and shows that no count or table needs an edit.

## Printed side and rules

The printed side of every card comes from the import record (`mtg_import::CardRecord`, stored in the `cards` table). The rules file adds abilities. A deck of oracle ids becomes `CardDefinition`s in the server (`CardSource`, `DeckRef::Oracle`):

| Step | Action |
|---|---|
| 1 | `mtg-db` reads one `cards` row per distinct oracle id of the deck (`CardRepo::get_many`); every id without a row is named in the error. |
| 2 | The server adapts each stored row to `mtg_cards::PrintedCard` (`mtg_server::printed_card`; strings only, `mtg-cards` does not depend on `mtg-import`). The testkit does the same from the record itself. |
| 3 | `assemble(&PrintedCard, Option<&Card>, &Caps) -> Assembled { definition, support }` reads the front face: cost (`mana_cost` without its `{X}` symbols, and `x_in_cost`), type line, power, toughness, loyalty, defense and colours (`color_indicator` only where the record's colours differ from the cost's). It gives a land the mana abilities of its basic land types (CR 305.6) and attaches the rules the support record says the engine runs. A card with no file is `Verified` when it has no rules text once reminder text (parentheses) is removed, such as a vanilla creature or a basic land, and `Manual` otherwise. |
| 4 | `PlayerSetup.library` gets one `Arc<CardDefinition>` per deck line; copies share it. `CardDefinition`, `AbilityDef` and `ManaAbility` live in `mtg-cards`; `AbilityDef::Mana` is the lowered plain `{T}: Add {X}`; every other ability the engine runs is an `Arc<Ability>` in `CardDefinition.rules`, named by its index there (`lower` gives `Lowered::Mana` or `Lowered::Rules`). The field is left out of the serde form while it is empty. |
| 5 | The recipe's deck fingerprint (`recipe/fingerprint.rs`) hashes the serde form of the definitions, so a corrected record, changed rules or a change in what the engine runs changes it and a resumed game fails as a changed deck does. Fields added to `CardDefinition` are left out of that form while unused, so `FINGERPRINT_VERSION` stays 1. |

A printed gap makes the card `Manual` and attaches no rules. `support` computes it, so the deck check and the game agree; a `Caps` name lifts it once the engine plays the value.

| Printed value | In the definition | Lifted by |
|---|---|---|
| `*`, `1+*` or `X` as power, toughness, loyalty or defense | `None` | `Card.VariableStats` |
| `{X}` in the cost | `x_in_cost`; the engine asks X as the spell is cast and the spell, its permanent, its enters trigger and the delayed triggers it sets up remember it; its cast triggers read it | `Card.XCost` |
| A second face | A split card, an Adventure, a modal double-faced card and a transforming double-faced card (`PrintedCard.layout`: `split`, `adventure`, `modal_dfc`, `transform`, `flip`, two faces) are played with their faces, each face assembled like a card of its own (`CardDefinition.layout` and `faces`; a split card's definition is both halves, the others their front face, and the bottom half of a flip card has the mana cost and colour of its top half; a split card with `Fuse` also carries the spell of both halves, their targets in order and the effects of the left half then the right half with its targets renumbered); any other card with a second face (meld) is only its front face and names the face | `Card.Faces` |
| A mana symbol the engine does not know, an unreadable cost, a type word that is no card type | No cost, or the word dropped | Nothing |

## The type tree

All types are in `crates/mtg-cards/src`. Notation: `Name { field: Type = default }`.

**Card and face**
```
Card      { oracle_id, name, impl_status: ImplStatus, faces: [Face], notes? }
Face      { name, oracle_fingerprint, abilities: [Ability] }
ImplStatus = Full | Partial | Manual | Unplayable          declared by the file
TokenFile { id, token: TokenSpec }
TokenSpec { name, colors, supertypes, types, subtypes, power?, toughness?, abilities }
```

**Abilities** (`Spell`, `Activated`, `Loyalty` and `Triggered` carry `targets` and `effects`)
```
Spell      { targets, effects }                                  instants and sorceries
Activated  { cost: Cost, timing = Instant|Sorcery, condition?, limit?, from = Battlefield, targets, effects }
Loyalty    { cost: Plus(n) | Minus(n) | Zero | MinusX, targets, effects }     planeswalkers only
Triggered  { when: TriggerPattern, intervening_if?: Condition, limit?, from = Battlefield, targets, effects }
Static     { affected: Ref, mods: [Modification], condition?, defining = false, from = Battlefield }
Rule       { rule: GameRule, condition?, from = Battlefield }   a static ability that changes a rule of the game
Replacement{ when: ReplaceWhen, by: ReplaceBy, condition?, from = Battlefield }
CostModifier{ applies_to: Selector, change: Increase|Reduce, mana: ManaCostX, per = 1, condition? }
AdditionalCost{ cost: Cost, required = false }                    "As an additional cost to cast this spell, [you may] ..."; an optional one is read as Condition AdditionalCostPaid
FreeCast{ condition? }                                             "If [condition], you may cast this spell without paying its mana cost"; an alternative cost of no mana (`CastWay.Free`) while the condition holds
Keyword(Keyword)
Manual     { reason: String, span: Span }                        an unmodelled clause
```
An activated ability is a mana ability (CR 605.1a) when it has no targets and one of its effects is `AddMana`; the effects after the mana (a painland's damage, an egg's draw) are part of it. Loyalty timing (CR 606.3) is engine code. The reader gives an "Activate only if you control a Swamp." sentence to the ability as its `condition`; "{T}: Add one mana of any color in your commander's color identity." is `CommanderIdentity` and "... of any color (or type) that a land an opponent (or you) controls could produce." is `ProducedBy` (`colorless` for "type"). "Add {G} for each creature you control." is `AddMana` with `times` counted by `Amount::Count`, read and written after the mana and before the spending restriction; "Activate only once each turn." is the `limit`, which a mana ability keeps (the engine logs a use and does not offer it again that turn); "Tap an untapped creature you control", "Sacrifice a Goblin" and "Exile a card from your hand" (Cadaverous Bloom) are cost parts of a mana ability the payment picks. A `OneOf` or `OneOfLists` choice has at most six ways (`assemble::MANA_WAYS`); the validator refuses more. "Add two mana in any combination of colors" (also "of {R} and/or {G}", "of {U}, {B}, and/or {R}") is `AnyCombination{count, among}` (none listed means the five colors); a mana ability runs it when its ways (`assemble::combinations`) fit in `MANA_COMBINATIONS`, and on the stack it asks for the type of each mana.

A `CostModifier` changes the total cost of the spells `applies_to` selects (the selector is read against a spell on the stack: `Spell`, a type, `ControlledBy(You)` for "you cast") by `mana` (fixed symbols, never `{X}`) as many times as `per` counts ("for each target beyond the first" is `Sum[TargetCount(0), -1]`). `This` selects the spell with the ability, the one place a card in a hand has a static ability. Increases come before reductions, and a reduction takes generic mana only down to nothing and a colored symbol only where the cost has it (`engine.md`, Announcement). Strive ("Strive — This spell costs {2}{U} more to cast for each target beyond the first.") is this ability: the compiler reads it with its ability word, a cost of several symbols included, and keeps it only beside a spell ability it reads.

A `FreeCast` is the printed "If you control a commander, you may cast this spell without paying its mana cost." (the condition is a count of what the caster controls: `Pred::Commander` is a player's commander, whoever controls it now). While the condition holds for the caster, the card has the alternative cost `CastWay.Free` beside its mana cost in every zone it is cast for that cost from; the additional costs, the commander tax and the cost modifiers stay (CR 118.9d). The compiler reads and writes the sentence for any "you control" condition it reads.

| Item | Rule |
|---|---|
| Life of players | `Players(who)` counts the players in the game a reference names; `LowestLife(who)` and `HighestLife(who)` are the least and the greatest life total among them. Written as a comparison they say "a player" or "an opponent" has a total (`LowestLife <= n`, `HighestLife >= n`) and "each opponent" or "each player" has one (`HighestLife <= n`, `LowestLife >= n`). With no player named, `LowestLife` is the largest number and `HighestLife` the smallest, so "an opponent" is false and "each opponent" true of no one; a player who has left is not named. |
| `Target(i)` | The set chosen for the i-th `TargetSpec`: one object for a plain spec, several for "any number". An effect on a set applies to each member. |
| Defaults | `who` is `You`; `source` is `This`; an `Amount` is 1; a `Bounds` is 1..1 and `max: null` is any number. |
| `Search` | The filter picks the cards of the searcher's own zone (`zone`, a library unless it says otherwise); the searcher alone is asked for between `count.min` and `count.max` of them. `count.min` does not bind in a library or a hand: a player may find fewer cards than match, or none. | Small enums | `ZoneKind` (Battlefield, Hand, Library, Graveyard, Stack, Exile, Command), `Step`, `Cmp`, `StatKind` (Power, Toughness, ManaValue, Loyalty, Colors: how many colors an object has), `Destination` (Hand, Graveyard, Battlefield{tapped, under?, transformed, counters}, Library{place: Top, Bottom or Shuffled, order?: Chosen or Random}), `CounterKind`, `Timing`, `Limit`, `Produce`. |

## Execution

State is the fold of events; the engine is a pure function from state to `Progress` (events or a decision).

| Topic | Rule |
|---|---|
| Ability objects | `GameObject` has a kind: `Card`, `Token`, `Ability`. An ability lives in `Zone::Stack` with an id from the same counter and holds its source, a `Snapshot` of it, the controller, an `Arc` to its rules (it resolves without its source, CR 113.7a), its `Choices` and, for a trigger, the cause. A spell is the card object. An ability of an object is named by `AbilityRef { object, ability, source }` and read with `abilities_of` and `ability` in `ability_reader` (`engine.md`, Spells and abilities). |
| Identity | Every object has a zone-change counter bumped by the fold (CR 400.7). A stored reference is `(ObjectId, counter)`. |
| Announcement | One procedure (`announce/`, `engine.md`, Announcement) in the order of CR 601.2b to 601.2h: modes, the alternative cost, optional costs, X, targets, division, the legality check, the total cost, the payment. Each is a decision asked while the cast or activation is pending outside state: nothing is logged until the cast is paid, cancel is free. A specification that allows no target is skipped, one that cannot be met rewinds the cast. A mode with an unmeetable specification is not offered, and a modal ability with too few legal modes cannot be cast (a trigger is removed). The final batch carries `Choices { modes, x, targets per spec, division, optional costs }` (a field left out of the wire form while empty). A trigger chooses its targets when it goes on the stack (CR 603.3d); those answers are logged. |
| Activation | An ability whose cost is nothing, or any of `{T}`, sacrificing (`SacrificeSelf`), exiling (`ExileSelf`) or discarding (`DiscardSelf`) the source and mana, is activated from `PriorityOptions.abilities`: `PermanentTapped` (for `{T}`), `ZoneChanged` with `ZoneCause::Sacrificed` or `Exiled` (from the zone the source is in) or `CardDiscarded`, `AbilityActivated`, then `AbilityPutOnStack`, with the source photographed before the costs; an ability works from the zone its `from` names, so the owner of a card in a hand, a graveyard, exile or the command zone is offered its activated abilities there, and one that returns its card (`Move` of `This`) does nothing when the card has changed zones by the time it resolves (CR 400.7); the mana is paid in the same step by the `PayMana` decision (`engine.md`, Spells and abilities), whose sources leave out the source of an ability that taps or sacrifices it. An ability with `timing: Sorcery` is offered only to the active player in a main step with an empty stack. A token sacrificed this way has ceased to exist and its ability still resolves: Clue is `{2}` and sacrifice, Food `{2}`, `{T}` and sacrifice. A mana ability of the shape `mana_shape` reads (`{T}` and/or the sacrifice, mana of one type added some number of times, effects that ask nothing: Treasure, Sol Ring, Gaea's Cradle, the painlands) is not put on the stack: `ActivateMana`, or the tap of a payment, does the cost, adds the mana and runs the effects that follow in one batch. Other costs wait for their primitives in `Caps`. |
| Target recheck | On resolution each target is tested again with the spec that chose it: same object, same zone, selector matches, not protected. If the object had targets and every one is illegal, it does nothing (`ResolutionEnded { Fizzled }`), including parts that do not use the target (CR 608.2b). Otherwise it resolves and ignores the illegal targets, except one that an earlier step of the same resolution moved: it stays named for the steps after it and is read as it was (CR 608.2h). One function, `legal_targets(state, spec, source, controller)`, serves choosing and rechecking. |
| Journal | `GameState.resolving: Option<Resolving { object, position, bindings, snapshots, journal }>`; `position` is a path of indices into the effect tree. `step(&GameState)` reads state and journal, never mutates, and returns `Done(events)` (ending with `StepDone { position, bound, snapshots }`) or `Ask(decision)`. An answer is validated, logged as `ChoiceMade { player, choice }` and appended to the journal by the fold; the same step runs again and consumes it. `StepDone` folds the next position, bindings and snapshots and clears the journal. A step with k decisions runs k+1 times. Random numbers come from the seeded substream, whose counter moves only when events fold. |
| Events | `AbilityTriggered`, `AbilityPutOnStack`, `AbilityActivated`, `ResolutionBegan`, `ChoiceMade`, `StepDone`, `ResolutionEnded { Resolved, Fizzled, Countered }`, and one per primitive without an event: `ZoneChanged { object, from, to, cause }`, `LifeGained`, `LifeLost`, `CountersChanged`, `TokenCreated`, `LibraryLooked`, `CardsFound`, `Scried`, `Surveilled`, `Revealed`, `LibraryBottomed`, `ChosenAtRandom { cards }` (the cards of a public zone that a pick at random took; public, and its fold spends a substream of the generator), `Entered { object, tapped, controller }`, and `Cycled { player, object }`, logged after the `CardDiscarded` of the cost of cycling and public like it. Each has a fold arm and a redaction arm in the protocol's `redact`: a library peek, a search, a scry and a surveil are private to the seat that did them (a scry also puts the cards back, and `LibraryBottomed` moves cards of a library to its bottom; other seats see counts), a reveal is public, `Entered` is public (it follows the `ZoneChanged` that put a card onto the battlefield tapped or under another player's control), and `ZoneChanged`, `ChoiceMade` and `StepDone` reach a seat whole only when every card they name is visible to it. The folds of `LibraryLooked`, `CardsFound`, `Scried`, `Surveilled` and `Revealed` also record the cards in the resolution (`Resolving.shown`: the seat that looked, found or scried, or every seat for a reveal), which the views read until the resolution ends or the card changes zones (`engine.md`, Library effects). |
| Spell resolution | A spell with a `Spell` ability or any ability runs `ResolutionBegan`, its steps and `ResolutionEnded`. For a card `SpellResolved` follows `Resolved` and moves it (a permanent to the battlefield, an instant or sorcery to the graveyard); a fizzled or countered spell goes to the graveyard with `ResolutionEnded`, and an ability ceases to exist with it. A permanent spell has no steps and is only `SpellResolved`. A resolution whose controller has left the game ends `Countered`. |
| Cast during resolution | The cast sub-procedure runs inside a step; its decisions are journal decisions; the spell goes on the stack above the resolving object. |
| Nothing to choose | An attack or block with no legal option is not asked and logs `NothingToDo`. A choice of cards with no more candidates than must be taken (`Discard`, `Sacrifice`) is not asked either: the engine takes them all, or nothing when there are none, and logs only the move. Any other decision with one legal answer and no "may" is answered by the engine unless the seat has Full Control (`arena-flow.md`); a payment that cannot be made is the exception, asked with No the only answer so the pace shows nothing. |

### Decisions the effects need

`Decision.player` names who answers, so a decision may go to any seat. Every effect decision carries `source` (the object that asks). Decisions for a seat that is not the active player have a response clock (`server.md`). `ChooseTargets` and `OrderTriggers` are asked and have their prompts in the web; `ChooseCards` is asked by `Discard`, `Sacrifice`, `Proliferate` (the permanents that hold counters), `Explore` (the revealed card), `Connive` (the card to discard), `Choose` over objects, `Scry`, `Search`, `Move` of an Aura onto the battlefield (what it enchants) and the legend rule of the state-based actions (the permanent to keep) (its question carries `text`, "Discard a card." or "Search your library for a basic land card."; a search offers the matching cards, between 0 and the most that may be found), `OrderCards` by `Scry` and `Move` (the controller puts cards in one library in an order, top first), `YesNo` by `Proliferate` (one question for each player who holds counters) and by `May` ("Draw a card?"; the players `who` names are asked in turn order until one says yes) and by `Pay` ("Pay {2}?"; the same order until one pays, those who cannot pay are asked too, with No the only answer), `PayMana` by `Pay` after a yes (the payment cannot be backed out of), `ChooseOption` by `Choose` over players ("Choose an opponent."; a player with one option is not asked) and `ChooseMode` at announcement by `Modal`; `YesNo`, `ChooseOption`, `ChooseMode`, `ChooseCards` and `OrderCards` have their prompts and response clocks; `ChooseNumber` (X), `ChooseCosts` (optional costs) and `DivideAmount` (a target specification with `divide`) are asked at announcement, answered and given a response clock like the others (their options carry `can_cancel`, and `text` in the words of a card for the number and the division; the answer can be `Cancel`), and `ChooseNumber` is the answer to an effect that asks for a number (`Choice::Number` in the journal); no card has an `{X}` for the announcement until (g2), and the optional costs are those of `Kicker` and `Multikicker`: the keyword makes `ChooseCosts` list a kicker the player can pay for and `ChooseNumber` ask the times a multikicker is paid (`engine.md`, Announcement); `Condition::Kicked` and `Amount::Kicks` read what was paid, in the spell, in the permanent it becomes and in its triggered abilities. The four kinds without a prompt (`ChooseNumber`, `DivideAmount`, `ChooseCosts`, `ChooseReplacement`) have a placeholder in the web, which M5 replaces. The questions of `YesNo`, `ChooseOption`, `ChooseCards` and `OrderCards` carry `text` in the words of a card, and `ChooseMode` says whether the cast can be backed out of (`can_cancel`).

### Snapshots (last known information)

`Snapshot { id, counter, controller, owner, zone, characteristics, keywords, counters, attachments }` is built by `snapshot(state, id)` and kept in three places only. `counter` names the object it describes, `characteristics` has every continuous effect applied, `keywords` are those it had after layer 6 (none that an effect removed), and `counters` and `attachments` are the permanent's own (empty off the battlefield).

| Place | Content |
|---|---|
| Stack ability | Its source and, for a trigger, the objects of its cause, taken at detection (CR 603.10a: look-back uses the state before the event). |
| Resolution | Every object a step moves off the battlefield or stack, carried by `StepDone`, so "its power" and "its controller" in Swords to Plowshares read the creature as it was when exiled (CR 608.2h). `Target(i)` still names a target that an earlier step moved, so those later steps find it. |
| `Choices` | The value of X, which outlives the spell. |

`Amount::Stat`, `Amount::Counters`, `ControllerOf`, `Matches`, `HasKeyword` and `HasCounter` read the live object when its counter matches and the snapshot otherwise; the damage a source that has left deals reads the keywords and the controller of its snapshot.

## Triggers, replacement and layers

| Topic | Rule |
|---|---|
| Detection | After a batch is folded, `triggers::detect(pre, events, post)` returns `Triggered { source, ability, controller, cause, snapshot, delayed }`, logged as `AbilityTriggered`. A move out of the battlefield (dies, leaves, sacrificed) is judged against `pre`: the abilities that worked then and the objects as they were (CR 603.10a); every other event against `post`. | Derived statics | `layers.rs` works through the layers once for a state: the effects of resolved spells and abilities and the `Static` abilities the permanents have at that point of the pass, found through `ability_reader`, apply layer by layer to every permanent at once, so a static's `affected`, `condition` and amounts read the other objects as the earlier layers and earlier effects left them (Favorable Winds finds the flying Levitation gives). | Timestamps | A static ability takes its permanent's entry time (an Aura's or Equipment's effects, the time it became attached), or the time of the effect that gave it when that is later (CR 613.7a); a resolved effect takes its creation time (CR 613.7), one for each modification in the order of the card's text. ## Compiler and Manual fallback

- The oracle-text compiler writes `Card`s with `mtg_cards::load::canonical`, validated by the same functions, with the fingerprint of the text it read.
- `compile::compile(&PrintedCard) -> Compiled { card, clauses }` is pure: reminder text and the card's own name (`~`) are stripped with a map back to the original text, the text splits into clauses (one per line, but "This land enters tapped. As it enters, choose a color." is two; a keyword list one per keyword; modes, level blocks and ability words stay whole), each clause has a `ClauseKind` (keyword, spell, triggered, activated, loyalty, modal, static), and `clauses` lists every clause, read or not, for the coverage report.
- "That much" and "that many" name the amount of an event (`Amount::Triggering`), so only a triggered ability reads them: in a spell or an activated ability ("Target opponent loses 3 life. You gain that much life.") they stay with the table, as no amount stands for what an earlier effect did. The X of a stat in the filter of a cost ("sacrifice an artifact or creature with mana value X") is the value of the permanent the cost takes, not an X the caster announces, so such a cost, and the X in the effects that follow it, stay with the table.
- Keyword lines are read into `Ability::Keyword` when the DSL declares the keyword and its parameter reads (`Enchant` on an Aura only; the filter after "Enchant" is an object phrase of the selector reader: "creature you control", "creature an opponent controls", "permanent", "nonland permanent", "artifact or land", "creature, land, or planeswalker", "Forest", and "player" and "opponent" are `EnchantPlayer`; a zone, "noncommander" and "with another Aura attached" stay with the table); the card is `Full` when every clause is read, `Partial` when some are, `Manual` with no abilities when none is, and `card` is `None` when no face has rules text or the data cannot hold the card (over four faces, two faces with one name).
- Hand-written files win over generated ones for the same oracle id. Generated rules are `card_rules` rows (oracle id, JSON, status, fingerprint, compiler version); hand-written ones are repository files. `Library::from_sources` loads the files; `Library::with_generated(&[GeneratedRules])` adds the rows: a file wins, and a row that does not parse or fails the structure checks is left out and reported, so rules of another build never stop the rest.
- `generated::generate(printed, hand_written, names)` compiles a card among the `names` (`compile::compile_among`) and checks the result with the checks of a file (`Library::check_generated`: levels 1 and 2 as a file of its own next to the predefined tokens, then level 3 against the imported card): `Rules` (`Full` or `Partial`), `Nothing` (no rules text, nothing read, or a card the data cannot hold) or `Invalid` with the problems. `generated::input_fingerprint(printed)` digests what the compiler reads (names, costs, type lines, oracle text, characteristics, colors, keywords) and `generated::COMPILER_VERSION` digests the compiler's sources and the rules data types at build time; a row with another fingerprint or version is read again.
- `mtg-cli compile [--all | --card <name>]` writes the rows (`data-sources.md`). A modal ability whose mode has no label offers the renderer's wording of the mode (`render_mode`, with `~` as the card's name) in `ChooseMode`.
- `compile/read/` holds the templates for mana, spell effects (draw, discard, mill, life, damage, destroy, exile, counter, tap, untap, regenerate, scry, until-end-of-turn pumps; one target per clause) and the library and counter effects below. A template reads a whole clause or nothing, `render_variants` writes the result back as English, and the clause counts as read only when one of those wordings is the clause's own, compared after whitespace, the closing period, `~` for "this creature", ", then" for a new sentence, "enters" for the older "enters the battlefield", "precombat" and "postcombat" main phase for "first" and "second", "it" and "them" for "that card" and "those cards" after "put" and "reveal", and without "of their choice". The effects of one player in a row are written both as separate sentences and as one compound sentence, so either wording of a card matches.
- The spell lines of an instant or sorcery are one `Spell` ability, read when every line reads; "it", "its controller" and "it can't be regenerated" refer to the clause's target. A line without a closing period that no template reads (`Mayhem {1}{B}`) is a keyword-like clause kept `Manual`; the effect lines around it still read as the `Spell`. "Choose one —" and its bullets are one `Effect::Modal` (also after the comma of a trigger): each mode is read by the effect templates with targets of its own and no label, and the `Modal` is the only effect of its ability; "choose two", "one or both", "up to" and Spree stay with the table.
- A triggered clause is an event, a comma, an optional intervening "if" on a life total, and sentences read by the effect templates; an ability word before the dash is flavor. The events are `enters`, `dies`, `leaves the battlefield` and `attacks` of the card or of an object phrase ("another creature you control"), `casts` and `sacrifices` by you, an opponent or a player, the beginning of a step, and several joined by "or" (`AnyOf`). The card and a second subject doing the same ("Whenever ~ or another Elf you control enters", "Whenever this creature or another creature dies or deals combat damage to a player", "Whenever ~ or equipped creature attacks") are an `AnyOf` of the card's event and the second subject's for each verb in turn, written with "Whenever" only; a second subject without "another" or "equipped", a count of one event ("for the first time each turn") and "enters from your graveyard" stay with the table. "You may" and one step is `Effect::May`. Beyond the spell templates it reads "return target card from your graveyard to your hand", "return a land you control to its owner's hand" (a `Choose` bound as `returned` and a `Move`), tokens (Treasure, Clue and Food, described creature tokens that may enter tapped, attacking or tapped and attacking, counted by a number, by the X of the cost, by "that many" or by "where X is the number of", created by you or by another player ("target opponent creates", "its controller creates"); "with flying", "with flying and vigilance" and "with flying, vigilance, and haste" are the token's keyword abilities, any of the plain keywords the readers know; keywords with a parameter and a predefined token with a keyword stay with the table) and "you win the game". Delayed triggers, damage, life and counter events and other conditions stay with the table.
- Tokens with an amount (`compile/read/create.rs`, tests in `tests/token_sizes.rs`): "an X/X black Horror creature token, where X is ..." is `TokenRef::Sized` (a characteristic of an object, a count, a life total, a spell's mana value, the creatures that died this turn); "a number of ... tokens equal to its power", "X tokens, where X is the number of +1/+1 counters on it" and "a token for each creature put into your graveyard from the battlefield this turn" are counts of the tokens; a static ability in quotes ("This token can't block.") is a token ability beside the activated and triggered ones; "They have ..." and "It has ..." as a sentence of their own give the same abilities as "with ...".
- A sentence that acts on the tokens just created (`compile/read/token_binds.rs`, written by `render/bound.rs`, tests in `tests/token_binds.rs`): the `CreateToken` binds them as `tokens` and the effect after it reads `Bound("tokens")`: "Put X +1/+1 counters on it, where X is ...", "Put a +1/+1 counter on each of them", "then attach this Equipment to it" (`Effect::Attach`), "That token gains haste until end of turn" and "Those tokens gain haste ..." (`Effect::Continuous`) with "and attacks this combat if able" (`GameRule::MustAttack`). Two kinds of tokens in a row bind nothing. An intervening "if you control ..." (`Condition::Compare` over a count, as a static reads it: "if you control your commander") guards a trigger.
- One subject with several verb phrases ("target opponent sacrifices a creature, discards a card, and loses 3 life") is the effects of its sentence in order, "you create a 2/2 green Wolf creature token and that player mills ten cards" adds the player of the event as a second subject after "and", and a later sentence has its own subject; "unless ... pays {M}" after a sentence is an `Effect::Pay` whose unpaid effects are that sentence, for the controller of a countered spell ("its controller") and for the caster after a spell-cast event ("that player"). The effects "exile ~", "return target creature to its owner's hand", "all creatures get -N/-N until end of turn" and "put two cards from your hand on top of your library in any order" (a `Choose` bound as `back` and a `Move`) are read.
- An activated clause is a cost, a colon, sentences read by the effect templates and the restrictions on when it may be activated (`compile/read/costs.rs`, `abilities.rs`). The cost parts are read and written in the printed order: `{T}`, `{Q}`, a run of mana symbols, "Pay N life", "Sacrifice ~", "Sacrifice a creature" / "another creature" / "two artifacts" / "a Cleric creature" (a kind only, never who controls it; a subtype before a type word in the singular is a qualifier, as in the plural), a run "Sacrifice a Swamp and a Forest" (one `Sacrifice` part for each permanent, written back as one clause) and "Discard a card" / "Discard a land card" / "Discard two creature cards" (a `Discard` with a filter, the noun must be "card"); an `{X}` in the cost lets the effects use X. Mana ("Add {G}{G}", "Add one mana of any color") is an effect like any other, so it also reads in a spell and a trigger. "Activate only as a sorcery", "Activate only once each turn" and both joined by "and only" set `timing` and `limit`. "Activate only if", costs that remove counters, tap other permanents or pay energy, and abilities from another zone stay with the table. A mana ability with other effects ("{T}: Add {W} or {U}. ~ deals 1 damage to you.") is read whole, as the rules play it without the stack.

- "Spend this mana only to cast creature spells." after the sentence that adds mana is its restriction (`only`): one use per sentence, "cast" a spell or spells of a card type, two joined by "or", "noncreature", "multicolored" or "legendary" (or any spell), "activate abilities", or "on costs that contain {X}". The renderer writes the singular and the plural of "spell"; "of the chosen type" is the creature type the source chose as it entered (`SpendFilter.chosen_type`; the engine puts the type in `subtypes` when the mana is added, and the mana is none while no type is chosen), alone for a spell or with "or activate an ability of a creature source of the chosen type"; a subtype or a list of them ("Vampire, Cleric, and/or Demon spells", `SpendFilter.subtypes`) and a card type or a list of them ("instant and/or sorcery spells") are read for a spell, and the abilities of the same kind follow in any of the wordings the cards use ("or activate abilities of Dragons", "of Elemental sources", "or activate an ability of a Dinosaur source", "abilities of artifacts"); the facts about a spell are read after its noun in any order: "with mana value 5 or greater" (`min_value`), "with {X} in their mana costs", "you don't own" and "from your graveyard" (`facts`: `XInCost`, `NotOwned`, `FromGraveyard`), and a second kind of spell follows "or" ("or a legendary creature spell", "or spells with {X} in their mana costs"). Any other two uses stay with the table. "Add X mana in any combination of colors" (or of two or three listed types) counts X as "Remove X storage counters from this land" (`CostItem::RemoveCounters` of `Amount::X`) or ", where X is ..." names it (`Produce::AnyCombination.count` is an `Amount`; `mana_shape` requires the X of the mana and of the cost to go together). An ability word before an activated ability is left out when it is Ferocious (`ACTIVATED_WORDS`); a quoted mana ability is given by a static ability like any quoted activated ability ("Enchanted land has "{T}: Add one mana of any color."").

- A search is "Search your library for" a filter, an optional ", reveal it", the move of what is found and ", then shuffle" (`Search`, `Move`, `Shuffle`; one sentence on the card), also after "you may" (an `Effect::May` of the three) and as "then shuffle and put that card on top". Another player searches their own library after a removal: "Its controller may search their library for a basic land card, put it onto the battlefield tapped, then shuffle" is a `May` of the controller of the target holding their `Search`, the move and their `Shuffle`. A search for two cards is two searches in a row, the second leaving out the first card (`Not(Is(Bound))`), a move for each and one shuffle: "a Forest card and a Plains card", and "up to two basic land cards that share a land type" (each search finds up to one; the second adds `SharesSubtype` of the first, bound as `land2`). The filter is adjectives, one or more subtypes joined by "or", card types joined by "or" (or "permanent"), "card" and "with mana value N or less" (also "X or less" when the mana cost has an `{X}`, a `Compare` against `X` that the search reads with the X the spell or ability announced); the count is "a", "up to N" or "any number of", found as `land` for a land filter and `card` otherwise. "Look at the top N cards of your library" is `LookAtTop` bound as `top`; with "Put one of them into your hand and the rest on the bottom of your library in any order" (or "in a random order", or "into your graveyard") it adds `Choose` (`kept`, `rest`) and two `Move`s. "Shuffle your library", "target player shuffles their library" and "Put target card from your graveyard on the bottom of your library" (also "on top of", and a permanent "of its owner's library") are read. Names, other zones and other orders stay with the table.
- Counters are put (`+1/+1`, `-1/-1` and a named kind such as charge, poison or time), removed and moved by number words on the card, on one target or, for putting, on "each creature you control": "Remove a +1/+1 counter from ~", "Move a +1/+1 counter from target creature onto ~" (one of the two is the card). All, X, a second target and counters as a cost stay with the table, as do the counters whose effect the rules give and not the card (keyword counters, stun, shield, finality, lore, defense) and any clause whose reminder text speaks of a counter: the data holds a counter as a name, and the reminder text that defines it is dropped.
- "It" in a trigger about a creature (`compile/read/pronouns.rs`, tests in `tests/pump_wordings.rs`): when the event is the card attacking, blocking, becoming blocked or entering, "it" in the effects is the card, and for another creature that attacks, becomes blocked or enters it is the creature of the event (`Ref::Triggering`); another blocker, damage and every other event have no "it". "Whenever ~ attacks, it gets +1/+1 until end of turn", "Whenever a creature you control attacks, it gets +2/+2 until end of turn" and "put a +1/+1 counter on it" are read, and the writer says "~" and "it" for the card; a sentence after "untap ~" may open with "It gains ...". "gains protection from the color of your choice until end of turn" (also after "gets +N/+N and") is `AddProtectionFromChosenColor` in a spell, an activation or a trigger, never in a static. "Whenever one or more +1/+1 counters are put on <subject>" (or "one or more counters") is a `Batch` of `CountersPut`; a noun "with a +1/+1 counter on it" is `HasCounter`, and "Each creature you control with a +1/+1 counter on it has trample." a static of that group, written as "Each ..." or as the plural; a pump of a group counted by the sentence before may say "Those creatures". "creatures with +1/+1 counters on them", "you gain protection" and "put a +1/+1 counter on it" after damage (the cause holds the damaged player) stay with the table.
- "Surveil N", "Proliferate" and "you become the monarch" are effects; "if you're the monarch", "if an opponent is the monarch" and "if there is no monarch" (`Not` of `Monarch(EachPlayer)`) are intervening conditions (`Condition::Monarch`), and the same three after or before a static ("Creatures you control get +1/+1 as long as you're the monarch.", "As long as you're the monarch, permanents you control have hexproof.") are its `condition`; "Whenever you become the monarch" (also "an opponent", "a player") is `BecomesMonarch` with "that player" the new monarch; the monarch is `Ref::Monarch`: "the monarch's end step", "attacks the monarch" (`AttacksPlayer`, where "that player controls" is the monarch's) and "creatures the monarch controls" (`ControlledBy(Monarch)`); "Add {W} or {U}", "Add {B}, {R}, or {G}", "Add {W}{W}, {W}{U}, or {U}{U}" and "Add one mana of the chosen color" and "Add {R} or one mana of the chosen color" are mana (`OneOf`, `OneOfLists`, `ChosenColor`, `OrChosenColor`); "Pay {E}" is a cost (`PayEnergy`) and "you get {E}{E}" an effect (`PutCounters` of the energy counter on you; its reminder text does not keep the clause from being read); an X in a cost counts the value announced ("Pay X life", "Remove X ki counters from ~", "Sacrifice X creatures", "Discard X cards", "Exile X cards from your graveyard", "Tap X untapped artifacts you control", "Pay X {E}") and the walker no longer names `Cost.<part>.Counted` for it, only for an amount that is neither fixed nor X; and "Whenever you gain life", "lose life", "draw a card", "discard a card" and "cycle a card" (by you, an opponent or a player) are events (`LifeGained`, `LifeLost`, `Drew`, `Discarded`, `Cycled`). "Your commander" before a verb is a commander its owner designated (`[Commander, OwnedBy(You)]`, written "When" or "Whenever"); "that player" after an attack at "one of your opponents" is the player attacked (`Ref::Defending`); "while you're the monarch" after an event other than damage is its intervening condition, and "if you were the monarch as the turn began" is `MonarchAtTurnStart`. A card that uses one is `Partial` or `Manual` until the engine runs it; the report names it (`Effect.Surveil`, `Effect.AddMana.ProducedBy`) instead of the unread wording.
- Counting wordings of the mana permanents: an intervening "if ~ has no charge counters on it" is a `Compare` of the counters on the card with zero, "it" after it is the card ("return it to its owner's hand" is a `Move` of `This` to the hand), "for each of that spell's colors" counts `Stat { of: Triggering, stat: Colors }`, and "Exile a card from your hand" is a cost part (`ExileFromHand`); Mana Bloom, Ramos and Cadaverous Bloom are read whole.
- The templates of the events (`compile/read/triggers.rs`): "whenever ~ deals [combat] damage [to a player, an opponent]", "whenever you tap a land for mana", "whenever ~ becomes tapped, untapped, blocked, attached to a creature", "whenever a creature blocks", "whenever a +1/+1 counter is put on ~ / removed from ~", "whenever you cycle another card" and "when you cycle this card" (an ability that works from the graveyard, `from: Graveyard`). In the effects, "that player" is the player of the event (`Triggering`) and "that permanent's controller" the controller of the permanent of a tap or an untap. Also read: "equipped creature" or "enchanted creature" as the subject (`Is(Attached)`, written back in both ways), "one or more creatures you control deal combat damage to a player", "one or more cards are put into your graveyard from your library" (`Batch`), "one or more creatures you control attack" (`GroupAttacks`), "you draw your second card each turn" and "you cast your first spell each turn" (`Nth`, first to fifth), "~ becomes the target of a spell or ability [you control / an opponent controls]", "~ is dealt damage" (`DealsDamage` into the object) and, after "attacks", "becomes the target of a spell or ability you control" or "is dealt damage", "for the first time each turn" (`Nth` of the object, first to fifth; a count of targets by an opponent's spells stays unread). "It" is the card itself in the effects of a trigger on the card becoming a target ("put a +1/+1 counter on it"). And "that much" and "that many" for life, damage, cards and counters (`Amount::Triggering`). "For the first time each turn" (first to fifth) counts the events of a player after "you gain life", "you lose life" or "an opponent loses life", "you cycle another card" (not the card itself), "you surveil" and "you create one or more tokens" (first only), and of an object after "one or more counters are put on ~" (any kind), written back the same way. "Is put into a graveyard from anywhere other than the battlefield" and, with "your graveyard", the same for the cards its owner owns, is a `ZoneChangeExcept`; a subject with the noun "card" (Disa the Restless, Syr Konrad) stays unread. The condition "a counter was put on ~ this turn" (`facts.rs`) is read after "if".
- A noun is followed by who controls it or a number it has ("with power 2 or less", "with mana value X" when the mana cost has an X): `Pred::Compare` with a fixed number or `X`. "It deals 1 damage to any target" opens an activated ability for the source, and only as the first thing it does.
- "Whenever a creature attacks enchanted player" is `AttacksPlayer` of `AttachedPlayer`: "it" is the attacker (`Triggering`) and "its controller" the attacking player. A group "creatures enchanted player controls" is `Each` with `ControlledBy(AttachedPlayer)` in a static ability or a rule.
- Block restrictions and granted mana (`compile/read/evasion.rs`, `selectors.rs`, tests in `tests/evasion.rs`, `tests/granted_mana.rs`): "with power less than this creature's power" and "with greater power" are a `Pred::Compare` of the stat against `Amount::Stat{of: This}` (the source of the static ability); "Creatures with power less than this creature's power can't block it" (also "... can't block creatures you control") and "~ can't be blocked by creatures with greater power" are `CantBeBlockedBy` of that selector, written in each wording. "Can't be blocked except by creatures with flying" (also "artifact creatures", "Slivers") is `CantBeBlockedBy` of the negated quality (`Not`, or `AnyOf` of `Not` for several; every blocker is a creature, so the type is dropped). A mana ability in quotes after "has" or "have" is a `GrantAbility` of the activated mana ability, for a group, a subtype or what an Aura is attached to.
- Limits on blockers and "your commander" (`compile/read/evasion.rs`, `statics.rs`, tests in `tests/block_limits.rs`, `tests/commander_statics.rs`): "~ can block only creatures with flying." (also "Enchanted creature", a group) is `CanBlockOnly` of the attackers it names; "~ can't be blocked by more than one creature." is `MaxBlockers(1)` and "can't be blocked except by two or more creatures" `MinBlockers(2)`, for the card, what an Aura or Equipment is attached to or a group ("Each creature you control with power 4 or greater ..."), and `MaxBlockers(1)` also ends a list of what a creature gets and has ("Equipped creature gets +1/+2, has reach, and can't be blocked by more than one creature."). "melee" and "myriad" are keywords a static ability can give ("Other creatures you control have melee."). "you control your commander" is a count of the commander cards the player owns and controls (`Pred::Commander` with `OwnedBy(You)`), so "As long as you control your commander, ..." is the `condition` of a static, and a Lieutenant ability word is flavor.
- Player keywords, quoted triggers and paired statics (`compile/read/player_keywords.rs`, `static_pairs.rs`, `statics.rs`, tests in `tests/player_keywords.rs`, `tests/granted_triggers.rs`, `tests/static_pairs.rs`): "You have hexproof." and "You have shroud." (also both, and under a leading "As long as ...") are a `Static` of `You` with `AddKeyword`; a triggered ability in quotes after "has" or "have" is a `GrantAbility` like the activated ones (the writer gives the inner ability in each wording, so "it deals" and "~ deals" both read); "creature defending player controls" is `ControlledBy(Defending)`; "As long as you control your commander, ~ gets +2/+2 and creatures you control have vigilance." is two `Static`s with the same condition, one clause that reads into two abilities as a level block does (`compile::read::static_pair`).
- A static clause is one sentence read by `compile/read/statics.rs`. How the card enters is a `Replacement` of `Enters`: "~ enters tapped", with "unless you control" a count (`Not` of a `Compare` on a `Count`: "two or more basic lands", "two or fewer other lands", "a planeswalker", "a Forest or a Plains", "a Mount or Vehicle"; "your opponents control eight or more lands"), "~ enters with three +1/+1 counters on it" (X when the mana cost has one; "~ enters tapped with two charge counters on it" is the same replacement with `tapped`), "As ~ enters" (or "As it enters"), "choose a color", "a color other than red" or "a creature type" and "As ~ enters, you may pay N life. If you don't, it enters tapped". Rules are "~ can't be countered" (from the stack), "~ attacks each combat if able", "All creatures attack each combat if able" and "Play with the top card of your library revealed". A `Static` is "~ can't block" (or attack, or both), and "gets +N/+N" and "has" or "have" keywords (`and`-joined) for "Equipped creature" or "Enchanted creature" (both `Attached`, so the renderer writes both wordings), "Creatures you control", "Other creatures you control", "All creatures" and "... of the chosen type" or "color"; "other" stands after the other adjectives, where the hand-written files put it. A `CostModifier` is "Noncreature spells cost {1} more to cast.", "Artifact spells you cast cost {1} less to cast.", "Spells your opponents cast cost {1} more to cast." and "This spell costs {1} more to cast for each target beyond the first." (read only beside a spell ability that has targets, else the table keeps it); "for each" a counted group changes the cost by its mana once for each thing counted ("This spell costs {1} less to cast for each creature card in your graveyard.", "{2} less ... for each land you control", "Creature spells you cast cost {1} less to cast for each +1/+1 counter on ~."); "This spell costs {X} less to cast, where X is the total power of creatures you control." (also "the greatest toughness among", "the total mana value of Dragons you control") is one mana changed as many times as the number says; and "Spells you cast from anywhere other than your hand cost {2} less to cast." selects `Not(CastFrom(Hand))` (`Pred::CastFrom`, a hand or a graveyard). A count of a party, of a quantity of this turn, two groups joined by "and", a "the number of" after an X and a condition stay with the table. A group of permanents that "enter tapped" ("Creatures your opponents control enter tapped.", "Artifacts and creatures your opponents control enter tapped.") is a `Replacement` of `Enters` with the group as `what`. A condition after "as long as" (a `Static` with `condition`: "an opponent has 10 or less life", "a player has 13 or less life", "you control a Plains", "it's your turn") lets the card itself get a bonus or a keyword ("This creature has haste as long as an opponent has 10 or less life"); without it a card is given nothing; a restriction ("can't be blocked", "can't block") may stand under one, and "isn't a creature" is read only under one (`RemoveType`). A keyword list also holds protections: "has protection from white and from black" is one `Protection` for each quality (a colour, "colorless", a plural card type or "everything"), also after "gains" in a pump. A line of two sentences or needing two replacements ("enters tapped with two charge counters on it"), a condition other than those ("for each", "if you attacked"), an X without an X in the mana cost, counters the rules define, the number of opponents and a player's life stay with the table.
- Conditions after "as long as" (`compile/read/as_long_as.rs`, tests in `tests/as_long_as.rs`) are one `Condition` of a `Static`, before the subject or after the predicate, and "it" names the card or its host: the state of the card or its host ("~ is untapped", "it's attacking", "equipped creature is legendary", a color), counters on the card ("has four or more +1/+1 counters on it", "has five or more quest counters on it", "has a divinity counter on it"; charge and level counters belong to `stations.rs` and `levels.rs`; with them "it's an artifact creature" is the predicate of a Vehicle), cards in the controller's graveyard ("there are seven or more cards in your graveyard", "fewer than eight", "four or more card types among cards in your graveyard" as `CardTypes`) or hand ("you have no cards in hand", "seven or more", "one or fewer"), devotion ("your devotion to green and white is less than seven" as `Devotion` `Lt`), and "you control no other creatures", besides the life, turn, monarch and "you control" counts read before. - Counted mana (`compile/read/effects.rs`, tests in `tests/counted_mana.rs`): "Add X mana of any one color, where X is ..." is `AnyColor(X)` with the where clause bound like any other, "Add an amount of {G} equal to ..." is `Fixed` added `times` the amount, and "Add {G}. - Triggered mana abilities (CR 605.1b; `compile/read/mana_trigger.rs`, `mana_trigger.rs` in `mtg-cards`, tests in `tests/triggered_mana.rs`): a `Triggered` ability on `TappedForMana` with no target, no limit and one `AddMana` for the player who tapped is a mana ability. - "Whenever enchanted player is attacked" is `PlayerAttacked` and "whenever a player attacks enchanted player with one or more creatures" is `PlayerAttacks` (`by`, `at`). "Each opponent attacking that player does the same" repeats the effects with `ControllerOf` of `Each` over `AttackingPlayer(AttachedPlayer)` and `ControlledBy(Opponents)` as `who`; the reader repeats a draw, a gain or loss of life, a token or "untap all nonland permanents you control" (Curse of Bounty spells out the untapping). `AttackingPlayer` is judged when the effect runs, so a creature put onto the battlefield attacking counts. - Counted amounts (`compile/read/amounts.rs`): "for each ..." counts a selector (`Count`: "creature you control", "Goblin on the battlefield", "card in your hand", "creature card in your graveyard"; a group no one holds stands on the battlefield), the opponents (`Players(Opponents)`) or the counters on the card (`Counters`); "N ... for each" is `Times{by: N, of}`, and a plain "a ... for each" is the count itself. - The number of (`compile/read/defining.rs`, `where_x.rs`, tests in `tests/number_of.rs`): "the number of creatures you control" (`Count`, also "on the battlefield", "in your graveyard", "in all graveyards", "the total number of cards in all players' hands"), "the number of opponents you have" (`Players`), "the number of +1/+1 counters on ~" (`Counters`), "the number of times this creature has mutated" (`Mutations` of `This`), "twice the number of ..." (`Sum` of two), "the number of card types among ...", "the greatest power among ..." and "the total power of ..." are one amount reader, shared with the characteristic-defining abilities. - Damage (`compile/read/damage.rs`): "~ deals 3 damage to any target" with one recipient (a target, "each opponent", "each player", "you", "each creature [without flying]", "each other creature"); one group of objects and one of players are two `DealDamage` ("each creature and each player"); "and you gain 3 life" is a `GainLife` after the damage; "it deals" stands for the card in a trigger on its own entering, attacking or dying and in an activation. "You draw a card and you lose 1 life" names the subject again. A run of mana symbols has no order: `{G}{W}` and `{W}{G}` are one cost (`same_text`).

- The creatures that paid for the source (`selectors::suffix`, `effects::return_any_number`, tests in `tests/crew_record.rs`): "that crewed it this turn" and "that saddled it this turn" after a creature phrase are `Pred::Crewed(This)` and `Pred::Saddled(This)`, as a target ("target creature that crewed it this turn explores") and as a group; "[Then] you may return any number of creatures that saddled it this turn to their owner's hand" is a `Choose` of none or more of them bound as `returned` and a `Move` to the hand (a card of another kind or of another group stays unread). "Mill two cards, then ~ gets +X/+X until end of turn, where X is ..." is a chain whose second step is the pump of the card itself, so the size counts what the mill left.
- Permanents that entered this turn (`selectors::suffix`, tests in `tests/entered_this_turn.rs`): "that entered this turn" and "that entered the battlefield this turn" after a phrase are `Pred.EnteredThisTurn` (written back as the first; the second is a variant of `render::variants`), for a target ("put a +1/+1 counter on target creature that entered this turn") and a group ("each green creature that entered this turn"). A single token is named as a target ("target creature token", "target token"), and "create a tapped token that's a copy of target token" is a `CreateToken` of `CopyOf` with `tapped`; Octomancer, Romana II, Oran-Rief, the Vastwood, Novijen and Deathleaper are Verified, and "entered the battlefield under your control this turn" stays unread.
- Removal and return (`compile/read/selectors.rs`, `effects.rs`, `create.rs`, tests in `tests/removal_and_return.rs`): the card types of a phrase may be a list ("artifact, creature, or planeswalker", "all artifacts, creatures, and enchantments"; a "with" qualifier after three or more types stays with the table), two negations take a comma ("nonartifact, nonblack creature") and "another target X" is a target with `Other`. "Return target creature card from your graveyard to the battlefield" is a `Move` onto the battlefield (under its owner, who is you); "When ~ enters, sacrifice it unless you pay {R}" is a `Pay` whose unpaid effect sacrifices the card (also on an attack); "Its controller creates a 3/3 green Beast creature token.", "That creature's controller creates ..." and "Its controller investigates." after a destroy or an exile are a `CreateToken` of `ControllerOf(Target)`. Another owner's graveyard, "tapped", "under your control", "that player" or "its owner" who creates and a count of what the destroy did stay with the table.
- Granted keywords and the skipped step (`compile/read/selectors.rs` and `statics.rs`, tests in `tests/group_statics.rs`): a granted keyword is also `skulk` and `ward` with a mana cost, in a static or a pump ("Other creatures you control have ward {2}."); "Skip your draw step." is the rule `SkipDrawStep(You)`. Another cost of ward and another player's draw step stay with the table.
- Aura grants (`compile/read/statics.rs`, `effects.rs`, `actions.rs`, `counters.rs`, `pronouns.rs`, tests in `tests/aura_grants.rs`): "Enchanted creature has flying and \"...\"" is an `AddKeyword` and a `GrantAbility` of the quoted activated or triggered ability on `Attached` (also after a bonus: "gets +1/+1 and has lifelink and \"...\""; one keyword only), and the ability belongs to the controller of the host, not of the Aura. "lose(s) all creature types" is `SetCreatureTypes([])`, alone or after a size ("have base power and toughness 3/3 and lose all creature types"). In an ability of an Aura "enchanted creature" is `Ref::Attached` for the objects a verb acts on (tap, untap, destroy, exile, counters put on it) and for `Effect::Fight`, whose second creature is "up to one target" or one target ("When this Aura enters, enchanted creature fights up to one target creature you don't control."). "When enchanted creature dies" is written beside "Whenever", and "they lose 2 life" stands for "that player loses 2 life" in a trigger about a player (`Drew` of `AttachedPlayer`).
- Static grants (`compile/read/selectors.rs`, `statics.rs`, `lands.rs`, tests in `tests/static_grants.rs`): the keywords a static gives are the plain words of `KEYWORDS` (also fear, intimidate, exalted, extort, evolve, persist, undying, wither, flash and shadow), a landwalk by its word ("islandwalk": `Landwalk` of the land subtype) and a keyword with a number (`fabricate 1`, `annihilator 2`, `toxic 1`, `afterlife 1`); "Enchanted land has shroud" is `Attached` as well as "Enchanted creature" (the writer says land, artifact and permanent for every keyword grant of an Aura); "Commander creatures you control" is `Commander` among the card types and "Non-Archon creatures" is `Not(Subtype)`; a subtype written the same in the plural (Merfolk, Kor, Kithkin, Djinn, Moonfolk, Sheep, Deer, Kavu) reads in a group; "During your turn, ..." opens a static as `YourTurn` beside "As long as it's your turn, ..."; "You may play Forests from your graveyard" is the land permission of a basic land type. The ward reminder ("counter it unless that player pays") is not the reminder of a counter, so a clause that grants ward reads.
- Counted, chosen and remade statics (`compile/read/selectors.rs`, `statics.rs`, `amounts.rs`, `aura_forms.rs`, tests in `tests/grants_counted.rs`, `tests/aura_forms.rs`): "for each artifact and/or enchantment you control" is the count of `AnyOf` types (the writer also says "or"), "for each opponent you have" is `Players(Opponents)`, and "gets +10/+10 and loses flying" is a `ModifyPT` and a `RemoveKeyword`. Protection from "the chosen color" is `Protection([ChosenColor])` and from "creatures of the chosen type" is `Protection([Type(Creature), ChosenSubtype])`, read in a static only (a spell's effect has no choice to read); a creature type in the plural ("Rats") is `Protection([Subtype])`. The engine writes the color or type the source chose as it entered into the keyword when the static grants it (`resolve::prim::continuous::chosen_in`), so an Aura's host or a lord's creature holds protection from the color the source chose; a card gives itself the chosen protection without a keyword line. An Aura that remakes its creature ("Enchanted creature is a Treefolk with base power and toughness 0/4 and loses all abilities.") is one list in the order of the layers: `SetColors`, `SetTypes` when the words name a card type (creature, artifact creature), `SetCreatureTypes`, `SetPT`, `LoseAbilities`, the `AddKeyword`s it has, `Goaded`; the writer says it "is ..." first or, with nothing else given, "loses all abilities and is ..." first, and "has indestructible, and it loses all other abilities, card types, and creature types" when keywords follow the loss.
- Cards taken from among the top cards (`compile/read/among.rs`, tests in `tests/among.rs`): "Look at the top five cards of your library. You may reveal a creature card from among them and put it into your hand. Put the rest on the bottom of your library in a random order." is `LookAtTop` bound as `top`, a `Choose` of `kept` from `Each` of `In(Library)`, `Is(Bound(top))` and the filter (`min` 0), a `Reveal` of `kept`, a `Move` of `kept` and a `Move` of `top` (the cards that left are other objects and are passed over). "Reveal the top N cards" adds a `Reveal` of `top` and drops the reveal of `kept`; "You may put a land card from among them into your hand / onto the battlefield [tapped]", "Put up to two land cards from among them ...", "Put a land card from among them ..." (one card, not optional) and "Put all land cards revealed this way into your hand and the rest ..." (a `Move` of the `Each`) are the same shape; the rest goes into the graveyard or on the bottom in any or a random order. The filter is the one of a search (land types and card types as "A or B" or "A, B, or C": "a basic Forest, Plains, or Island card"); a count of X, another library, a chosen type, "Then put the rest", a cast or an exile from among them stay with the table. "You may cast creature spells from the top of your library." (a card type, a subtype, "non" and two joined by "and") is a `MayCast` permission from the library over the cards the group names (`lands::cast_from_the_top`); a rider, "lands and spells" and the other zones stay with the table.
- Mass moves (`compile/read/mass_moves.rs`, tests in `tests/mass_moves.rs`): "Put all creatures on the bottom (or on top) of their owners' libraries.", "Return all nonland permanents to their owners' hands." and "Return all artifact and enchantment cards from your graveyard to the battlefield." are a `Move` of `Each(selector)`; a selector with no zone names the battlefield. A token moved to a library ceases to exist (CR 111.7) and is not put in the order of the cards. "Each player (or opponent) discards their hand" is a `Discard` of the count of cards in those hands, more than any one hand holds, so each hand is taken whole; "Each player discards their hand, then draws seven cards." reads and writes as one sentence (`draws::wheel`); "..., then draws cards equal to the greatest number of cards a player discarded this way" stays with the table.
- Draws and discards (`compile/read/draws.rs`, tests in `tests/draws.rs`): "draw an additional card" and "draw two additional cards" in a draw step are a plain `Draw`, and "each player's" before a step is `StepBegins` of `EachPlayer`, whose "that player" is the player whose step it is (also after "each opponent's"); "You draw a card and you lose 1 life." is the effects of "you" with the subject said again for each verb; "Whenever you attack with two or more creatures" is `GroupAttacks` of the creatures you control; "Whenever an opponent casts their second spell each turn" and "draws their second card" are an `Nth` of that player (also "a player"); "Discard your hand." and "target player / that player discards their hand" are a `Discard` of a `Count` of the cards in that player's hand, and "each player discards their hand" stays with the table.
- `tests/it/compile_corpus.rs` is the ratchet: every ability the compiler reads equals one of the hand-written file (mode labels aside, which the compiler leaves empty), and the corpus cards it reproduces whole (`tests/fixtures/reproduced.txt`) never shrink in number.
- `coverage::analyze(cards, caps) -> Report` judges each distinct card of a deck list: the hand-written rules when the embedded library has them, else the compiler's (rules that fail `check_printed` count as `Manual` with the blocker `rules: invalid`), its `Support` from `Library::support`, and its blockers, which are the unread clauses (kind and shape: numbers and the words one to ten as `N`, a run of mana symbols as `{M}`, the card's name as `~`), the primitives of its rules that `Caps` lacks and the printed gaps. A blocker holds a card back alone when it is the card's only one.
- `mtg-cli coverage [--deck <code or name part>] [--top <n>]` runs it over the stored precons with `mtg_engine::caps()` and prints about 70 lines: the cards by state, distinct and by copies, the five best and worst precons by the share of their copies that are `Verified`, and the `n` (20) blockers that alone hold back the most cards, then the `n` that hold back the most in all.
- `mtg-cli audit [--count 100] [--seed N] [FILE]` lists a seeded sample of the stored cards whose clauses the compiler reads beyond keyword lines: for each clause the oracle text, the reading (`render_variants`) and the JSON, and the unread clauses. The cards are put in the order the seed and their oracle ids give and the first `count` that are read are taken, so the same seed lists the same cards and a smaller count is a prefix of a larger one. A reader compares the lines for a wrong target, amount, owner or timing, a dropped clause and a reading true only for some cards; each disagreement is fixed in the template or the wording is left to the table, with a golden in `compile/read/tests/audit.rs`.
- A line the compiler cannot read becomes `Ability::Manual { reason, span }` and the card `Partial`; if nothing is read the card is `Manual`. Each compiled card is rendered back to English and compared with its oracle text in the golden tests.
- A card the engine does not run whole is cast and resolved without effects for the clauses it leaves out, and its controller does them by hand with the generic logged actions (`engine.md`, Manual actions). `assemble` copies the left-out text into the definition: `CardDefinition.manual` holds a `ManualClause {text, reason}` for each clause the support record names on a face (the text its span covers, so a `Partial` card shows the clauses of its `Manual` abilities and, for an ability the engine lacks a primitive for, the whole face text), and a card with no rules attached (`Manual`, `Stale`) one clause of the whole rules text of each face that has any outside reminder text. A `Verified` card has none. Every seat reads the clauses on the card (`ObjectView.manual`, `protocol.md`) and sees the card's support (`deck-check.md`). The field is left out of the serialized form while empty, so the deck fingerprint of a card without clauses does not change.
- Prior art for the templates: phase.rs's oracle parser (`crates/engine/src/parser` in its repository; MIT or Apache-2.0) and XMage (MIT). Forge and Magarena are GPL-3.0: study only, copy nothing.
- Moves between zones by a choice (`compile/read/zone_moves.rs`, written back by `render.rs` and `mass_moves.rs`): "Return up to two target creature cards from your graveyard to the battlefield tapped." (a type, a subtype, "permanent card", "nonland permanent card", "with mana value N or less", up to N targets; a move to the hand or the battlefield, the owner's), "Put target creature card from a graveyard onto the battlefield under your control." (a graveyard of any player, an opponent's or the defending player's; `Destination::Battlefield.under`), "Return all land cards from your graveyard to the battlefield tapped.", "Exile target player's graveyard." and "You may put a land card from your hand onto the battlefield tapped." (a `May` of a `Choose` and a `Move`). "Return target creature card from your graveyard to the battlefield with a -1/-1 counter on it." (`Destination::Battlefield.counters`; a counter the rules give, such as lifelink or finality, stays with the table), "Return six target nonland permanents to their owners' hands." and "Exile two target creatures." (a count above one is `Bounds { min: n, max: n }`). The older two-trigger exile ("When ~ enters, exile target creature." with "When ~ leaves the battlefield, return the exiled card to the battlefield under its owner's control.") is read by `compile/linked.rs` as the one exile `until ~ leaves the battlefield`, the second trigger read into the first. "That many" is read only in a triggered or activated ability, where `Amount::Triggering` is valid.

## Model-assisted reading

A language model writes the rules of a card and a deterministic checker accepts them only when they are valid, read back as the printed text and have a support state. The text of the card is the only ground truth; the checker never trusts the rules.

- `mtg_cards::proposal::check(json, &PrintedCard, &Library, &names, &Caps) -> Report`; `mtg-cli check-rules [--card NAME] [--bundle] [--verbose] [--write DIR] FILE...` (a file is named `<slug>.json` after its card unless `--card` names it; a bundle is one object from a card name to its rules).
- A proposal may leave out the oracle id, the names, the status and the fingerprints: they come from the card, and the status is derived from what is modelled (a declared status counts for nothing). A clause no ability stands for becomes a `Manual` ability, so the state is `Partial`; abilities are put in printed order. `--write` stores the completed rules in canonical form.

| Check | How | Result |
|---|---|---|
| Valid | `Library::check_generated`: levels 1 to 3 (`Validation`) | The problems, each with its path |
| Reads back | The clauses of the printed text (`compile::compile`) are paired with the abilities by kind; a wording of `render_variants` equal to the clause by `same_text` reads, a keyword reads by the keyword reader, two statics under one condition, a line of Saga chapters and a Backup count as in the compiler | Each clause: reads, differs (the closest wording is shown), unwritten (an ability stands for it and no writer exists; the construct is named by writing each part alone), manual or open; an ability with no clause is a stray |
| Support | `support` with `mtg_engine::caps()` | `Verified`, `Partial` or `Manual`, with the blockers |

The verdict is `Invalid` (a problem of the first check), `Mismatch` (a clause differs or an ability has no clause), `Unchecked` (valid and nothing contradicts the text, but a construct has no writer) or `Accepted`. Only an accepted proposal is vouched for. The 1,313 hand-written files are the calibration: 1,221 are accepted `Verified`, 3 accepted `Partial`, 89 unchecked, none invalid or mismatching (`proposal::no_hand_written_file_is_invalid_or_mismatches_and_the_state_is_the_librarys`). The writers invert the readers, so a card is checked only as far as the compiler's templates reach.

**Writers.** The checker compares the clause with `written_variants`: the wordings of `render_variants`, which the templates read (the compiler's own reads stay on those), and the wordings of the oracle text that no template reads. The latter are `compile/read/event_wordings.rs` ("you" after another player's event: "Whenever an opponent draws their second card each turn, you draw a card."; "Then" opening a sentence; "that creature" for the creature of an event; a characteristic after "equal to": "deals damage equal to its power") and the effect writers in `compile/read/render/`: divided damage (`divided.rs`: "deals 3 damage divided as you choose among one, two, or three targets", "any number of target creatures and/or planeswalkers", "up to X target creatures"), the exile of a graveyard (`graveyards.rs`: "exile target player's graveyard", "each opponent's"), a card put onto the battlefield from the hand (`put_onto.rs`: "you may put a land card from your hand onto the battlefield tapped"), damage by the creature of an event (`damage_by.rs`: "it deals ...") and a pump the player may choose (`may_have.rs`: "you may have other attacking creatures get +X/+X until end of turn"). A token has its keywords as a pump words them ("with protection from black"), `Pay` of life with an amount is "pay X life" with the amount named after it (", where X is its power"), and a card of a subtype in a zone ("Spirit card from your graveyard") and a nonland permanent card (the permanent types without land) have a phrase. Each wording has a golden in `compile/read/tests/written_effects.rs` with the near-misses that do not read back (a wrong player, count, quality or target). Of the 17 proposals written for the sample, none was accepted before the writers and 14 are after: 13 `Verified` corpus cards and Mask of Griselbrand, accepted `Partial` for `Cost.PayLife.Counted` and a corpus card once the engine plays it; Flaming Tyrannosaurus (a spell cast from anywhere other than the hand) stays unchecked.

The loyalty abilities (`render/loyalty.rs`: "+1: ...", "−3: ...", "0: ...", "−X: ..." with the sentences of the effects), an exile whose cards a later step counts (`amounts::for_each_text`: "put a +1/+1 counter on this creature for each creature card exiled this way", "For each artifact or land card exiled this way, create ..."), a card in its graveyard that pays to return (`from_graveyard.rs`: "if this card is in your graveyard, you may pay 1 life. If you do, return it to your hand"), a move to the hand that a basic land type changes to the battlefield (`instead.rs`: Emeria Shepherd) and the groups an earlier step named (`those.rs`: "each of those creatures", "each of them" for the attackers of a batch, "for each opponent you have", "put a +1/+1 counter on ~ and you gain 1 life") have goldens with near-misses in `compile/read/tests/model_writers.rs`. Of the sample of 40 stored precon cards that no file covers (seed 20261024), 14 had expressible rules; none was accepted before these writers and 4 are after (`Partial`: the clauses the DSL cannot say stay open), and of the named cards of the earlier samples 6 are accepted `Verified` and in the corpus (Amphin Mutineer, Canoptek Scarab Swarm, Emeria Shepherd, Malanthrope, Master of Death, Monstrosity of the Lake).

**Effect writers (second round).** The writers `render/delayed.rs` (an exile of a target that a delayed trigger returns at the next end step: "Return that card to the battlefield under its owner's control at the beginning of the next end step"), `render/multi.rs` (a clause with several targets is written target by target, each one's effects as sentences of their own, the target of a later sentence named in full), `render/each_target.rs` (counters on two or three targets in one sentence, "put a -1/-1 counter on target creature, two -1/-1 counters on another target creature, and three -1/-1 counters on a third target creature", and a fight between two targets), `render/may_have.rs` (a choice of several steps, "you may draw a card and lose 1 life") and `payments.rs` ("... unless they sacrifice a creature of their choice") give effects their wording. A target that is exiled and bound is "exile target ...", and an amount of a characteristic of what it took is X named at the end ("..., where X is the mana value of the permanent exiled this way", `where_x.rs`). Counters on a player are "target player gets four rad counters", and on the defending player a condition says "as long as defending player has a rad counter". A trigger names a spell "cast from anywhere other than your hand", "your fourth noncreature spell each turn", the return of the card "from your graveyard to your hand" and "each of your postcombat main phases"; `facts.rs` words "you gained 3 or more life this turn" (the digits and the word both) and "a creature died this turn". `shortened.rs` words a Clue token as "investigate", "Return it" after an exile and "life equal to that card's mana value". A list of subtypes and card types ("Plant, Treefolk, or land card"), "without flying or islandwalk", "artifact creature" in the singular, a keyword counter of two words ("double strike counter"), the plural of Treefolk and Aetherborn and the first name of a legendary card ("Legolas" for "Legolas Greenleaf", `compile::first_name`) have a wording too. Each has a golden with near-misses in `compile/read/tests/effect_writers.rs`.

Samples are kept as `crates/mtg-cards/tests/fixtures/proposals/<sample>/<slug>.json`, the rules a model wrote before the checker's report; `mtg-cli check-rules --verbose proposals/<sample>/*.json` re-runs one. Of the 40 stored precon cards that no file covers and the earlier samples left out (`r2l`, seed 20261026: 10 of which the compiler reads nothing, 15 partial with one unread clause, 15 partial with two or more), 33 got rules (7 need a construct the DSL lacks). Before these writers 14 proposals were accepted (2 `Verified`, 12 `Partial`); after, 23 are (10 `Verified`, 13 `Partial`, 6 of those with keywords only). The 10 `Verified` cards and the 10 of the earlier sample (`r2g`: Eureka Moment, Primaris Eliminator, Juri, Mogis, Nick Valentine, Nightkin Ambusher, Reaper from the Abyss, Roon, Ruinous Intrusion, Legolas Greenleaf) are corpus cards.

**Ability writers.** Written from the data only, each a small module with table goldens in `compile/read/tests/*_writers.rs`, which also list the near-misses that do not read back: `replacements.rs` writes the replacements of damage ("If a source would deal damage to an opponent, it deals double that damage to that player instead.", prevent, plus N), of tokens, counters and draws ("twice that many ... are put on it instead", "it puts twice that many ... on that permanent instead") and of a move between zones ("If a Warlock you control would die, exile it instead."); `batches.rs` the events of a group ("Whenever one or more other Elves you control enter", "... creature cards leave your graveyard", "... land cards are put into your graveyard from anywhere") and "Whenever you attack with one or more Birds" (also "Whenever you attack") with "each of them" and "those creatures" for the attackers; `choices.rs` the choice of modes ("choose one or both", "choose two", "choose up to one") with a mode's name before its text or not; `static_parts.rs` what a group or an Aura gives part by part (a bonus with the zero signed either way, lost keywords and abilities, base power and toughness, a type or subtype in addition to the others, "is goaded"); `spend.rs` restricted mana for a list of subtypes, a subtype with a card type, "and/or" between plural kinds and the abilities of the same kinds; `activations.rs` the sentence that limits an activation (a condition, "during your turn", "as a sorcery", "once each turn", in any order). A count over all opponents is written "your opponents control", never "an opponent controls", which is true for one opponent. These wordings are part of `render_variants`, so the compiler's own reads are checked against them too.

**Pilot.** Forty stored precon cards that no hand-written file covers, chosen by a seed over the oracle ids (20261023): 10 of which the compiler reads nothing, 15 partial with one unread clause and 15 partial with two or more. A model wrote each card's rules with no new template and no engine change and fixed a rejected file at most twice. The outcomes:

| Pool | Cards | (a) accepted `Verified` | (b) accepted `Partial` | (c) no writer | (d) DSL gap | (e) invalid or mismatching |
|---|---|---|---|---|---|---|
| Nothing read | 10 | 0 | 0 | 5 | 5 | 0 |
| One unread clause | 15 | 1 | 0 | 6 | 4 | 4 |
| Two or more | 15 | 0 | 0 | 4 | 10 | 1 |
| All | 40 | 1 (2.5%) | 0 | 15 (37.5%) | 19 (47.5%) | 5 (12.5%) |

- Effort: 9 model turns for the 40 cards. 22 cards were written (the other 18 lack a construct, which the enum lists show); 21 of those 22 were valid, 2 after one fix (a cost part is `{"Mana": ...}` in a list) and 1 invalid for a missing construct. Of the 16 proposals in (a) and (c), 14 are `Verified` by the engine and 2, which need `Cost.PayLife.Counted`, `Partial`.
- (a) Winged Boots, stored with its fixture; the mechanics it uses (an Equipment granting flying and ward, Equip) have scenario tests already. The 15 in (c) are valid and kept as notes.
- Without a writer, by cards: `CreateToken` (3, with a chosen player, a counted number or a bound result); `Move`, `Pay` with life, `May` and `DealDamage` (2 each, the damage divided or beside a monarch); one each: `Exile` of a graveyard, `Continuous` on a count, `If` after tokens, a labelled mode of a trigger, restricted `AddMana`, a batch trigger, a static over `Each`, `Goaded`, a replacement of damage or of a zone change, an activated ability with a condition.
- Wording the writers do not produce (5 in (e), the rules are right): "you draw" after an opponent's event, "each of those creatures", "Whenever you attack with one or more X" with "on each of them", "deals damage equal to its power" and "nonland permanent card" with "this creature's power".
- DSL gaps, by cards: a condition on what happened this turn ("the first time each turn" for any event, "a counter was put on it this turn", "dealt damage to you this turn") (3); one each: exactly X targets (`Bounds.min` is a number, so "X target creatures" has no form), "from anywhere other than the battlefield", a token with characteristic-defining stats, a named option chosen as it enters, Rooms, a total mana value limit on chosen cards, a controller that differs for each affected object, a cost whose X is the discarded card's mana value, "must be blocked if able", an object that becomes foretold, a duration "until you exile another card", counting counters removed, phasing, granting suspend, a cost reduction for the first spell each turn, a choice of one of each type for each player, mana restricted to the chosen color.
- Missing capability: `Cost.PayLife.Counted` (2 cards).

An automated proposer (a command that sends the card, the DSL reference and examples to a model and keeps only what the checker accepts) is not worth building yet: the model's rules are valid in 21 of 22 attempts with 1.1 attempts for a card, but the checker accepts 1 of 40 unread cards (2.5%; 0.1% to 13% at 95%), because a card the compiler cannot read uses constructs without a writer. It becomes worth building when the writers cover the effects the unread cards use (writers for the 15 cards of (c) and the wordings of the 5 of (e) would lift the accepted share from 1 to 21 of 40), and it needs as context the card's text, the DSL reference with every enum's variants (the type tree lists a part), the ten nearest hand-written files by the effects they use, and the checker's report for the two fixes.

`mtg-cli forge-check --forge <Forge checkout>` sets the stored precon cards against Forge's scripts, which are read at run time and never stored: the verbs Forge names that the rules lack, and the unread tail grouped by Forge API and key (`reference-engines.md`, Cross-check report). Its map from Forge names to the verbs of this DSL is `crates/mtg-cli/src/forge/map.txt`.

(d) Decision kinds are built with the first task that asks for them: `ChooseNumber`, `ChooseCosts` and `DivideAmount` with (g1), `ChooseReplacement` with (j). Their web prompts follow in M5.

The tasks run one at a time in the order of the table; (h) fills stub files and may run in any order. Rules data leads the engine: a compiled card is `Partial` until the engine runs its primitives. From (q) on, a task ends with the templates and goldens for its wordings, and tasks that do not need each other run in the order of the cards the coverage report says they free.

- Scope of (f), the keyword actions of CR 701: draw, discard, mill, shuffle, scry, surveil, fateseal, search, reveal, sacrifice, destroy, exile, counter, create tokens, populate, investigate, fight, explore, proliferate, amass, connive, learn, transform, meld, attach, regenerate, goad, monstrosity, adapt, bolster, support, venture. Arena-only digital actions (conjure, seek, specialize) are out of scope; a card that needs one is `Unplayable` (`deck-check.md`). An action that belongs to a cluster is built there: attach (m), regenerate (j), proliferate (l), transform and meld (n), populate (o); the others are (h).
