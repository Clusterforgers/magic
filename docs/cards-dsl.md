# Card DSL and effect pipeline

Rules data for cards (`mtg-cards`) and the pipeline that runs it (`mtg-engine`).

Scope: the data model, loader, validation, support records, the corpus and card assembly are implemented in `crates/mtg-cards`, with the engine's capabilities in `mtg-engine` and the card source in `mtg-server`. The pipeline core ("Execution", "Decisions the effects need", "Snapshots") is implemented in `mtg-engine` for targets, modes, cards chosen by a player and put in an order, yes or no, payments, options, drawing, discarding, sacrificing, destroying, exiling, countering, scrying, looking at, revealing, searching for, moving (onto the battlefield too) and shuffling cards, life, damage, mana, tokens and counters (put, removed and moved on permanents and players); "Triggers, replacement and layers" is implemented for triggers (detection, the queue, order, delayed triggers, the intervening "if" and the limit) and for the layer rows of continuous effects that pump power and toughness or grant a keyword (durations, timestamps, derivation); the replacement step (tokens, damage, zone changes, counters put, life gained, cards drawn and entering, with ChooseReplacement) is implemented; the other layer rows and "Tasks" are the contract of the other M3 engine tasks. Related: `engine.md`, `protocol.md`, `deck-check.md`, `arena-flow.md`.

## Summary

| Area | Rule |
|---|---|
| Printed side | Name, cost, types, power, toughness and oracle text come from the imported Scryfall record. |
| Rules file | One JSON file per oracle card: abilities per face, keyed by oracle id, with the fingerprint of the oracle text they match. |
| Vocabulary | Verbs (`Effect`, `TriggerPattern`, `CostItem`, `Modification`, `Keyword`) and values (`Ref`, `Selector`, `Amount`, `Condition`). A primitive is one enum variant. |
| Execution | An effect list runs as a journal: each step is a pure function of state that yields events or asks one `Decision`; answers are logged as events. |
| Stack | Abilities are stack objects. Targets are chosen on announcement and rechecked on resolution (CR 608.2b). |
| Triggers | Detected from events (look-back ones against the state before the event), queued in state, put on the stack in APNAP order. |
| Replacement | A step in front of the fold; the affected player orders several (CR 616.1). |
| Static abilities | Derived when characteristics are derived (CR 613); never stored as effects. |
| Keywords | Enum variants with parameters; behaviour in one engine file each. |
| Support | `Verified`, `Partial`, `Manual`, `Stale` and `Unplayable` are computed from the file, the imported text and the engine's capabilities. |

## Decisions

| # | Decision | Reason | Rejected |
|---|---|---|---|
| D1 | Format: JSON, one file per oracle card. Serde's externally tagged enums, PascalCase variants, snake_case fields; unknown fields are errors; defaults are omitted. Short forms: a mana cost is a string (`"{X}{R}"`), a fixed `Amount` a number, a mana-only `Cost` a string | The database stores JSON, the M6 compiler emits data, the web reads it, errors carry a path (`serde_path_to_error`) | RON (no jsonb, no TypeScript reader), YAML and TOML (typing traps, awkward trees), Rust builders like `vanilla.rs` (not data), a text script (needs its own parser) |
| D2 | Identity: the key is the Scryfall `oracle_id`; the file is `cards/<slug>.json` at any depth; a predefined token is `cards/tokens/<id>.json` | `cards.oracle_id` is the database key; names change and collide with face names | A slug as key (a rename breaks joins), per-printing ids (rules belong to the oracle card), a sharded layout now (sharding is a rename of files) |
| D3 | Multi-face: one file per oracle card, `faces` in Scryfall order; a whole-card property (Fuse) is a keyword on face 0 | Decks and imports name the card; faces share identity and status | One file per face, a `layout` field (a copy of import data) |
| D4 | Characteristics: the printed side always comes from the import record; the file holds abilities and a per-face `oracle_fingerprint`; a token carries its own characteristics | Cards without a file need the record anyway, so there is one source; errata surface as drift; M6 generates thousands of entries | Copying cost, types and P/T into each file (a second source, silent typos) |
| D5 | Shape: verbs and values are separate; sequences are lists; results are named (`as`, `Bound`) | Names are validated; a new mechanic is one verb over existing values | Implicit anaphora (`last created`), one flat enum, a class per card |
| D6 | Support is computed, never stored | `Verified` cannot go stale or ignore an engine that lacks a primitive; no engine run | A stored flag, running tests per lookup |
| D7 | Execution is a journal of pure steps | State stays the fold of the log; a restart asks the same question; each step is testable | Blocking callbacks per choice, unlogged resolution flushed at the end, replay from the start on every answer |
| D8 | Triggers: detection from events, a queue in state | Detection is a function of events and data; the log shows why an ability appeared; a resume keeps the queue | Detection inside the fold, a queue outside state |
| D9 | Replacement: a step in front of the fold | The fold stays dumb; the log holds what happened | A `replaced` flag on events, replacement inside each primitive, a fixed global order |
| D10 | Static abilities are derived | Characteristics are already derived; layer dependencies come from the data | Registering statics as `ContinuousEffect`s, a per-card layer table |
| D11 | Keywords: one enum, one engine file each | An exhaustive `match` flags a forgotten keyword; parallel tasks touch separate files | Keywords as strings, a shared registry file |
| D12 | Validation in three levels; all errors are collected | A file is judged where the information is | Checking when the engine uses a card, stopping at the first error |
| D13 | The compiler writes the same files; an unreadable clause becomes a `Manual` ability | One reader and one validator; a deck is never blocked | A second format, refusing decks with unimplemented cards |

## Files

| Path | Content |
|---|---|
| `crates/mtg-cards/cards/<slug>.json` | Rules of one oracle card |
| `crates/mtg-cards/cards/tokens/<id>.json` | A predefined token (Treasure, Clue, Food, Gold) |
| `crates/mtg-cards/tests/fixtures/corpus/<slug>.json` | The imported Scryfall object of one corpus card |
| `crates/mtg-cards/tests/fixtures/reproduced.txt` | The ratchet list: the corpus cards the compiler reproduces, one name per line, sorted |

- `mtg_cards::builtin::library()` is the library of these files, embedded at build time (`build.rs`), so a server needs no directory and a deploy carries the rules it was tested with.
- Canonical text: compact JSON in serde's field order, laid out by `mtg_cards::pretty` (a value stays on one line up to 100 columns, otherwise one entry per line).
- `MTG_UPDATE_CARDS=1 cargo test -p mtg-cards corpus::` rewrites the files and their fingerprints; the test fails on a file that is not canonical.
- `MTG_REAL_DATA_DIR=<dir> cargo test -p mtg-cards corpus:: -- --ignored` compares the corpus with an `oracle-cards-*.jsonl.gz` download.

## Adding a corpus card

No test holds a count of cards, sources, compiled sources, reproduced cards or fingerprints; each is derived from the card directory and the fixture, and a test asserts what the number stood for. A new card needs:

1. Its rules file `crates/mtg-cards/cards/<slug>.json` (the slug is the card's name lowercased with every run of non-alphanumerics as `_`, `mtg_cards::load::slug`). A `Full` or `Partial` face starts with an empty `oracle_fingerprint`.
2. Its Scryfall object as the new file `crates/mtg-cards/tests/fixtures/corpus/<slug>.json`, with the same slug: pretty-printed JSON of one object and a final newline (a multi-face or split card is one file named after the whole card name). The rules file and the fixture file share the `oracle_id`, and each card has exactly one of each. No other file changes for this step, so branches adding different cards never conflict here.
3. `MTG_UPDATE_CARDS=1 cargo test -p mtg-cards corpus::` writes the rules file in canonical form with the fingerprints of the fixture's text and adds every card the compiler reproduces to `crates/mtg-cards/tests/fixtures/reproduced.txt`. It never removes a name: a listed card that stops being reproduced fails.
4. `cargo test -p mtg-cards -p mtg-testkit`. A card the engine plays whole needs no row. A card it does not (Manual or Partial) is a row of `NOT_VERIFIED` in `crates/mtg-testkit/tests/it/corpus_cards.rs` with its state and the number of abilities it carries; a Verified card carries the abilities of its file, and each basic land type adds its mana ability.

`reproduced.txt` is a plain list in sorted order, one name per line, and the update inserts a name at its sorted position. Two branches that add different names conflict only where the names are adjacent; the resolution keeps both lines, and the update command restores the order if it is off.

The tests report a card without its record or file, a fixture file that is not named after its card or lacks the final newline, two files with one oracle id, a stale or missing fingerprint, an unlisted reproduced card and an unexpected state with the card's name, the file to add and this section. The fixture directory loads in file-name order and no test depends on that order. `tests/it/adding_a_card.rs` adds a card to a copy of the directory and the fixture directory and shows that no count or table needs an edit.

## Printed side and rules

The printed side of every card comes from the import record (`mtg_import::CardRecord`, stored in the `cards` table). The rules file adds abilities. A deck of oracle ids becomes `CardDefinition`s in the server (`CardSource`, `DeckRef::Oracle`):

| Step | Action |
|---|---|
| 1 | `mtg-db` reads one `cards` row per distinct oracle id of the deck (`CardRepo::get_many`); every id without a row is named in the error. |
| 2 | The server adapts each stored row to `mtg_cards::PrintedCard` (`mtg_server::printed_card`; strings only, `mtg-cards` does not depend on `mtg-import`). The testkit does the same from the record itself. |
| 3 | `assemble(&PrintedCard, Option<&Card>, &Caps) -> Assembled { definition, support }` reads the front face: cost (`mana_cost` without its `{X}` symbols, and `x_in_cost`), type line, power, toughness, loyalty, defense and colours (`color_indicator` only where the record's colours differ from the cost's). It gives a land the mana abilities of its basic land types (CR 305.6) and attaches the rules the support record says the engine runs. A card with no file is `Verified` when it has no rules text once reminder text (parentheses) is removed, such as a vanilla creature or a basic land, and `Manual` otherwise. |
| 4 | `PlayerSetup.library` gets one `Arc<CardDefinition>` per deck line; copies share it. `CardDefinition`, `AbilityDef` and `ManaAbility` live in `mtg-cards`; `AbilityDef::Mana` is the lowered plain `{T}: Add {X}`; every other ability the engine runs is an `Arc<Ability>` in `CardDefinition.rules`, named by its index there (`lower` gives `Lowered::Mana` or `Lowered::Rules`). The field is left out of the serde form while it is empty. |
| 5 | The recipe's deck fingerprint (`recipe/fingerprint.rs`) hashes the serde form of the definitions, so a corrected record, changed rules or a change in what the engine runs changes it and a resumed game fails as a changed deck does. Fields added to `CardDefinition` are left out of that form while unused, so `FINGERPRINT_VERSION` stays 1. |

A printed gap makes the card `Manual` and attaches no rules. `support` computes it, so the deck check and the game agree; a `Caps` name lifts it once the engine plays the value.

| Printed value | In the definition | Lifted by |
|---|---|---|
| `*`, `1+*` or `X` as power, toughness, loyalty or defense | `None` | `Card.VariableStats` |
| `{X}` in the cost | `x_in_cost`; the engine asks X as the spell is cast and the spell, its permanent, its enters trigger and the delayed triggers it sets up remember it; its cast triggers read it | `Card.XCost` |
| A second face | A split card, an Adventure, a modal double-faced card and a transforming double-faced card (`PrintedCard.layout`: `split`, `adventure`, `modal_dfc`, `transform`, two faces) are played with their faces, each face assembled like a card of its own (`CardDefinition.layout` and `faces`; a split card's definition is both halves, the others their front face; a split card with `Fuse` also carries the spell of both halves, their targets in order and the effects of the left half then the right half with its targets renumbered); any other card with a second face (meld) is only its front face and names the face | `Card.Faces` |
| A mana symbol the engine does not know, an unreadable cost, a type word that is no card type | No cost, or the word dropped | Nothing |

## The type tree

All types are in `crates/mtg-cards/src`. Notation: `Name { field: Type = default }`.

**Card and face**
```
Card      { oracle_id, name, impl_status: ImplStatus, faces: [Face], notes? }
Face      { name, oracle_fingerprint, abilities: [Ability] }
ImplStatus = Full | Partial | Manual | Unplayable          declared by the file
TokenFile { id, token: TokenSpec }
TokenSpec { name, colors, supertypes, types, subtypes, power?, toughness?, abilities }
```

**Abilities** (`Spell`, `Activated`, `Loyalty` and `Triggered` carry `targets` and `effects`)
```
Spell      { targets, effects }                                  instants and sorceries
Activated  { cost: Cost, timing = Instant|Sorcery, condition?, limit?, from = Battlefield, targets, effects }
Loyalty    { cost: Plus(n) | Minus(n) | Zero | MinusX, targets, effects }     planeswalkers only
Triggered  { when: TriggerPattern, intervening_if?: Condition, limit?, from = Battlefield, targets, effects }
Static     { affected: Ref, mods: [Modification], condition?, defining = false, from = Battlefield }
Rule       { rule: GameRule, condition?, from = Battlefield }   a static ability that changes a rule of the game
Replacement{ when: ReplaceWhen, by: ReplaceBy, condition?, from = Battlefield }
CostModifier{ applies_to: Selector, change: Increase|Reduce, mana: ManaCostX, per = 1, condition? }
AdditionalCost{ cost: Cost }                                     "As an additional cost to cast this spell, you may ..."; read as Condition AdditionalCostPaid
Keyword(Keyword)
Manual     { reason: String, span: Span }                        an unmodelled clause
```
An activated ability is a mana ability (CR 605.1a) when it has no targets and one of its effects is `AddMana`; the effects after the mana (a painland's damage, an egg's draw) are part of it. Loyalty timing (CR 606.3) is engine code. The reader gives an "Activate only if you control a Swamp." sentence to the ability as its `condition`; "{T}: Add one mana of any color in your commander's color identity." is `CommanderIdentity` and "... of any color (or type) that a land an opponent (or you) controls could produce." is `ProducedBy` (`colorless` for "type"). "Add {G} for each creature you control." is `AddMana` with `times` counted by `Amount::Count`, read and written after the mana and before the spending restriction; "Activate only once each turn." is the `limit`, which a mana ability keeps (the engine logs a use and does not offer it again that turn); "Tap an untapped creature you control" and "Sacrifice a Goblin" are cost parts of a mana ability the payment picks.

A `CostModifier` changes the total cost of the spells `applies_to` selects (the selector is read against a spell on the stack: `Spell`, a type, `ControlledBy(You)` for "you cast") by `mana` (fixed symbols, never `{X}`) as many times as `per` counts ("for each target beyond the first" is `Sum[TargetCount(0), -1]`). `This` selects the spell with the ability, the one place a card in a hand has a static ability. Increases come before reductions, and a reduction takes generic mana only down to nothing and a colored symbol only where the cost has it (`engine.md`, Announcement).

```

          | ControllerOf(Ref) | OwnerOf(Ref) | Each(Selector)

          | Attacking | Blocking | ControlledBy(Ref) | OwnedBy(Ref) | In(zone) | HasKeyword | HasCounter(kind) | Named
          | Compare{stat,op,to} | Not(Pred) | AnyOf([Pred])

          | Divided | EvenShare(Amount) | TargetCount(i) | Devotion([Color]) | Greatest{of,stat} | Total{of,stat}
          | CardTypes(Selector) | Players(Ref) | LowestLife(Ref) | HighestLife(Ref) | Triggering
Condition = Not | All | Any | Compare{left,op,right} | Matches{subject,selector} | Kicked | AdditionalCostPaid | CastWith(Flashback|Evoke|Overload|Madness|Suspend|Foretold|Escape|Free) | YourTurn | Performed
          | Monarch(Ref) | CitysBlessing(Ref) | NewlyControlled(Ref)
```

| Item | Rule |
|---|---|
| Life of players | `Players(who)` counts the players in the game a reference names; `LowestLife(who)` and `HighestLife(who)` are the least and the greatest life total among them. Written as a comparison they say "a player" or "an opponent" has a total (`LowestLife <= n`, `HighestLife >= n`) and "each opponent" or "each player" has one (`HighestLife <= n`, `LowestLife >= n`). With no player named, `LowestLife` is the largest number and `HighestLife` the smallest, so "an opponent" is false and "each opponent" true of no one; a player who has left is not named. |
| `Target(i)` | The set chosen for the i-th `TargetSpec`: one object for a plain spec, several for "any number". An effect on a set applies to each member. |
| Defaults | `who` is `You`; `source` is `This`; an `Amount` is 1; a `Bounds` is 1..1 and `max: null` is any number. |
| `Search` | The filter picks the cards of the searcher's own zone (`zone`, a library unless it says otherwise); the searcher alone is asked for between `count.min` and `count.max` of them. `count.min` does not bind in a library or a hand: a player may find fewer cards than match, or none. The cards found are bound to `as` and revealed to every seat only when `reveal` is set; a shuffle and the move to where they go are effects of their own. |
| Small enums | `ZoneKind` (Battlefield, Hand, Library, Graveyard, Stack, Exile, Command), `Step`, `Cmp`, `StatKind` (Power, Toughness, ManaValue, Loyalty), `Destination` (Hand, Graveyard, Battlefield{tapped, under?, counters}, Library{place: Top, Bottom or Shuffled, order?: Chosen or Random}), `CounterKind`, `Timing`, `Limit`, `Produce`. |

## Support records

| State | Meaning | From |
|---|---|---|
| `Verified` | Rules cover the whole text, the text is unchanged, the engine runs every primitive used; or there is no text to cover | `impl_status: Full`, equal fingerprints, `Caps` cover the primitives; or no file and no rules text on any face once reminder text is removed, and no printed gap |
| `Partial` | Rules exist except the listed clauses | `impl_status: Partial`, or `Full` with primitives the engine lacks |
| `Manual` | No rules, or the engine runs none of them | No file and rules text, `impl_status: Manual`, or no primitive covered |
| `Stale` | The oracle text or the face list changed since the rules were written; counts as `Manual` | `Full` or `Partial` with a different fingerprint |
| `Unplayable` | The engine cannot host the card | `impl_status: Unplayable` |

| Item | Rule |
|---|---|
| Declared and computed | The file declares `impl_status` (`Full` is the database enum `full`). `support(Option<&Card>, &PrintedCard, &Caps) -> SupportRecord` computes the state. A file says `Full` only with a scenario test or compiler golden; CI enforces it. |
| Clause | An `Ability::Manual { reason, span }`. `reason` is plain language; `span` is `{start, end}` in Unicode scalar values of the face's imported oracle text, end exclusive. |
| Status and abilities | `Full` has no clause; `Partial` has at least one clause and one modelled ability; `Manual` and `Unplayable` have no abilities. Clauses do not overlap and lie inside the text. |
| `Caps` | The primitives the running engine implements, named by enum and variant: `Effect.DealDamage`, `Keyword.Flying`, `Trigger.ZoneChange`, `Cost.Tap`, `Mod.ModifyPT`, `ReplaceWhen.TokenCreation`, `ReplaceBy.Multiply`, `Ability.Loyalty`; an ability with a `limit`, a zone other than the battlefield, sorcery timing or a `condition` ("activate only if") also uses `Ability.Limit`, `Ability.From`, `Ability.Sorcery` or `Ability.Condition` (a mana ability from another zone also `Ability.ManaAbility.From`), a discard at random also uses `Effect.Discard.Random`, a token that copies an object `Effect.CreateToken.Copy`, and a mana ability the engine activates (a cost of `{T}`, sacrificing the source, mana and fixed life, energy or counters of the source; an optional "Activate only if you control ..." condition; mana added some number of times, mixed or chosen from the commander's colours or from what lands could produce; then effects that ask nothing) that is not the plain one or one mana of a fixed type or any colour (Treasure) `Ability.ManaAbility.Complex`, and one of another shape (a limit, a mana cost with an X or without a `{T}`, tapping or sacrificing another permanent, an effect that asks) `Ability.ManaAbility.Other`. A plain `{T}: Add {X}` (cost exactly `{T}`, one fixed mana, added once) is the one primitive `Ability.ManaAbility`, since the engine runs that shape and not the general ability. The printed gaps have names too (`Card.XCost`, `Card.Faces`, `Card.VariableStats`). `mtg_engine::caps()` supplies it; each primitive task adds its entry there, and `lower` carries every ability the `Caps` cover into the definition. A choice of mana other than any one colour names its kind (`Effect.AddMana.OneOf`, `.OneOfLists`, `.ChosenColor`, `.CommanderIdentity`, `.ProducedBy`). Mana added with a restriction names `Effect.AddMana.Restricted`. ## Execution

State is the fold of events; the engine is a pure function from state to `Progress` (events or a decision).

| Topic | Rule |
|---|---|
| Ability objects | `GameObject` has a kind: `Card`, `Token`, `Ability`. An ability lives in `Zone::Stack` with an id from the same counter and holds its source, a `Snapshot` of it, the controller, an `Arc` to its rules (it resolves without its source, CR 113.7a), its `Choices` and, for a trigger, the cause. A spell is the card object. An ability of an object is named by `AbilityRef { object, ability, source }` and read with `abilities_of` and `ability` in `ability_reader` (`engine.md`, Spells and abilities). |
| Identity | Every object has a zone-change counter bumped by the fold (CR 400.7). A stored reference is `(ObjectId, counter)`. |
| Announcement | One procedure (`announce/`, `engine.md`, Announcement) in the order of CR 601.2b to 601.2h: modes, the alternative cost, optional costs, X, targets, division, the legality check, the total cost, the payment. Each is a decision asked while the cast or activation is pending outside state: nothing is logged until the cast is paid, cancel is free. A specification that allows no target is skipped, one that cannot be met rewinds the cast. A mode with an unmeetable specification is not offered, and a modal ability with too few legal modes cannot be cast (a trigger is removed). The final batch carries `Choices { modes, x, targets per spec, division, optional costs }` (a field left out of the wire form while empty). A trigger chooses its targets when it goes on the stack (CR 603.3d); those answers are logged. |
| Activation | An ability whose cost is nothing, or any of `{T}`, sacrificing (`SacrificeSelf`), exiling (`ExileSelf`) or discarding (`DiscardSelf`) the source and mana, is activated from `PriorityOptions.abilities`: `PermanentTapped` (for `{T}`), `ZoneChanged` with `ZoneCause::Sacrificed` or `Exiled` (from the zone the source is in) or `CardDiscarded`, `AbilityActivated`, then `AbilityPutOnStack`, with the source photographed before the costs; an ability works from the zone its `from` names, so the owner of a card in a hand, a graveyard, exile or the command zone is offered its activated abilities there, and one that returns its card (`Move` of `This`) does nothing when the card has changed zones by the time it resolves (CR 400.7); the mana is paid in the same step by the `PayMana` decision (`engine.md`, Spells and abilities), whose sources leave out the source of an ability that taps or sacrifices it. An ability with `timing: Sorcery` is offered only to the active player in a main step with an empty stack. A token sacrificed this way has ceased to exist and its ability still resolves: Clue is `{2}` and sacrifice, Food `{2}`, `{T}` and sacrifice. A mana ability of the shape `mana_shape` reads (`{T}` and/or the sacrifice, mana of one type added some number of times, effects that ask nothing: Treasure, Sol Ring, Gaea's Cradle, the painlands) is not put on the stack: `ActivateMana`, or the tap of a payment, does the cost, adds the mana and runs the effects that follow in one batch. Other costs wait for their primitives in `Caps`. |
| Target recheck | On resolution each target is tested again with the spec that chose it: same object, same zone, selector matches, not protected. If the object had targets and every one is illegal, it does nothing (`ResolutionEnded { Fizzled }`), including parts that do not use the target (CR 608.2b). Otherwise it resolves and ignores the illegal targets, except one that an earlier step of the same resolution moved: it stays named for the steps after it and is read as it was (CR 608.2h). One function, `legal_targets(state, spec, source, controller)`, serves choosing and rechecking. |
| Journal | `GameState.resolving: Option<Resolving { object, position, bindings, snapshots, journal }>`; `position` is a path of indices into the effect tree. `step(&GameState)` reads state and journal, never mutates, and returns `Done(events)` (ending with `StepDone { position, bound, snapshots }`) or `Ask(decision)`. An answer is validated, logged as `ChoiceMade { player, choice }` and appended to the journal by the fold; the same step runs again and consumes it. `StepDone` folds the next position, bindings and snapshots and clears the journal. A step with k decisions runs k+1 times. Random numbers come from the seeded substream, whose counter moves only when events fold. |
| Events | `AbilityTriggered`, `AbilityPutOnStack`, `AbilityActivated`, `ResolutionBegan`, `ChoiceMade`, `StepDone`, `ResolutionEnded { Resolved, Fizzled, Countered }`, and one per primitive without an event: `ZoneChanged { object, from, to, cause }`, `LifeGained`, `LifeLost`, `CountersChanged`, `TokenCreated`, `LibraryLooked`, `CardsFound`, `Scried`, `Surveilled`, `Revealed`, `LibraryBottomed`, `Entered { object, tapped, controller }`, and `Cycled { player, object }`, logged after the `CardDiscarded` of the cost of cycling and public like it. Each has a fold arm and a redaction arm in the protocol's `redact`: a library peek, a search, a scry and a surveil are private to the seat that did them (a scry also puts the cards back, and `LibraryBottomed` moves cards of a library to its bottom; other seats see counts), a reveal is public, `Entered` is public (it follows the `ZoneChanged` that put a card onto the battlefield tapped or under another player's control), and `ZoneChanged`, `ChoiceMade` and `StepDone` reach a seat whole only when every card they name is visible to it. The folds of `LibraryLooked`, `CardsFound`, `Scried`, `Surveilled` and `Revealed` also record the cards in the resolution (`Resolving.shown`: the seat that looked, found or scried, or every seat for a reveal), which the views read until the resolution ends or the card changes zones (`engine.md`, Library effects). |
| Spell resolution | A spell with a `Spell` ability or any ability runs `ResolutionBegan`, its steps and `ResolutionEnded`. For a card `SpellResolved` follows `Resolved` and moves it (a permanent to the battlefield, an instant or sorcery to the graveyard); a fizzled or countered spell goes to the graveyard with `ResolutionEnded`, and an ability ceases to exist with it. A permanent spell has no steps and is only `SpellResolved`. A resolution whose controller has left the game ends `Countered`. |
| Cast during resolution | The cast sub-procedure runs inside a step; its decisions are journal decisions; the spell goes on the stack above the resolving object. |
| Nothing to choose | An attack or block with no legal option is not asked and logs `NothingToDo`. A choice of cards with no more candidates than must be taken (`Discard`, `Sacrifice`) is not asked either: the engine takes them all, or nothing when there are none, and logs only the move. Any other decision with one legal answer and no "may" is answered by the engine unless the seat has Full Control (`arena-flow.md`); a payment that cannot be made is the exception, asked with No the only answer so the pace shows nothing. |

A task replaces its stub, adds its name to `RUNS` in `caps.rs` and to the expected list of `the_capabilities_name_exactly_the_effects_that_run` in `resolve/prim/mod.rs` (the fast check skips that test: run `cargo test -p mtg-engine --lib`). |
| Destroy, exile, counter | Each names its objects with a `Ref` (a target, `Each(selector)` for "all", a bound name) and acts on all of them together, in the order the reference lists them, in one step. The moves carry `ZoneCause::Destroyed` and `Exiled`; a counter is `ResolutionEnded { Countered }`, which triggers read as a move from the stack with `ZoneCause::Countered`. Each step carries a snapshot of every object it moved. A destruction that `regenerate` allows carries `ZoneCause::Destroyed`, which a regeneration shield replaces; `regenerate: false` ("can't be regenerated") carries `ZoneCause::Buried`. |
| Regenerate | `Effect::Regenerate` gives each permanent it names that is on the battlefield a regeneration shield (CR 701.19) until end of turn: the next time the permanent would be destroyed it is tapped, loses all its damage and the deathtouch mark and leaves combat instead (`Event::Regenerated`), and the shield is used up. A cost that removes counters from the source waits for the costs of (g). |

| Explore | Each creature `what` names that is on the battlefield explores in turn (one that has left, with no snapshot of it in the ability, does not): its controller reveals the top card of their library (`Revealed`, public) after an `Explored { object, player }`. ### Decisions the effects need

`Decision.player` names who answers, so a decision may go to any seat. Every effect decision carries `source` (the object that asks). Decisions for a seat that is not the active player have a response clock (`server.md`). `ChooseTargets` and `OrderTriggers` are asked and have their prompts in the web; `ChooseCards` is asked by `Discard`, `Sacrifice`, `Proliferate` (the permanents that hold counters), `Explore` (the revealed card), `Connive` (the card to discard), `Choose` over objects, `Scry`, `Search`, `Move` of an Aura onto the battlefield (what it enchants) and the legend rule of the state-based actions (the permanent to keep) (its question carries `text`, "Discard a card." or "Search your library for a basic land card."; a search offers the matching cards, between 0 and the most that may be found), `OrderCards` by `Scry` and `Move` (the controller puts cards in one library in an order, top first), `YesNo` by `Proliferate` (one question for each player who holds counters) and by `May` ("Draw a card?"; the players `who` names are asked in turn order until one says yes) and by `Pay` ("Pay {2}?"; the same order until one pays, those who cannot pay are asked too, with No the only answer), `PayMana` by `Pay` after a yes (the payment cannot be backed out of), `ChooseOption` by `Choose` over players ("Choose an opponent."; a player with one option is not asked) and `ChooseMode` at announcement by `Modal`; `YesNo`, `ChooseOption`, `ChooseMode`, `ChooseCards` and `OrderCards` have their prompts and response clocks; `ChooseNumber` (X), `ChooseCosts` (optional costs) and `DivideAmount` (a target specification with `divide`) are asked at announcement, answered and given a response clock like the others (their options carry `can_cancel`, and `text` in the words of a card for the number and the division; the answer can be `Cancel`), and `ChooseNumber` is the answer to an effect that asks for a number (`Choice::Number` in the journal); no card has an `{X}` for the announcement until (g2), and the optional costs are those of `Kicker` and `Multikicker`: the keyword makes `ChooseCosts` list a kicker the player can pay for and `ChooseNumber` ask the times a multikicker is paid (`engine.md`, Announcement); `Condition::Kicked` and `Amount::Kicks` read what was paid, in the spell, in the permanent it becomes and in its triggered abilities. The four kinds without a prompt (`ChooseNumber`, `DivideAmount`, `ChooseCosts`, `ChooseReplacement`) have a placeholder in the web, which M5 replaces. The questions of `YesNo`, `ChooseOption`, `ChooseCards` and `OrderCards` carry `text` in the words of a card, and `ChooseMode` says whether the cast can be backed out of (`can_cancel`).

### Snapshots (last known information)

`Snapshot { id, counter, controller, owner, zone, characteristics, keywords, counters, attachments }` is built by `snapshot(state, id)` and kept in three places only. `counter` names the object it describes, `characteristics` has every continuous effect applied, `keywords` are those it had after layer 6 (none that an effect removed), and `counters` and `attachments` are the permanent's own (empty off the battlefield).

| Place | Content |
|---|---|
| Stack ability | Its source and, for a trigger, the objects of its cause, taken at detection (CR 603.10a: look-back uses the state before the event). |
| Resolution | Every object a step moves off the battlefield or stack, carried by `StepDone`, so "its power" and "its controller" in Swords to Plowshares read the creature as it was when exiled (CR 608.2h). `Target(i)` still names a target that an earlier step moved, so those later steps find it. |
| `Choices` | The value of X, which outlives the spell. |

`Amount::Stat`, `Amount::Counters`, `ControllerOf`, `Matches`, `HasKeyword` and `HasCounter` read the live object when its counter matches and the snapshot otherwise; the damage a source that has left deals reads the keywords and the controller of its snapshot.

## Triggers, replacement and layers

| Topic | Rule |
|---|---|
| Detection | After a batch is folded, `triggers::detect(pre, events, post)` returns `Triggered { source, ability, controller, cause, snapshot, delayed }`, logged as `AbilityTriggered`. A move out of the battlefield (dies, leaves, sacrificed) is judged against `pre`: the abilities that worked then and the objects as they were (CR 603.10a); every other event against `post`. An ability works from the zone its `from` names (the battlefield unless it says otherwise): a triggered ability of a card in a graveyard, a hand, exile, the command zone, a library or the stack is tried against the same events as a permanent's, in id order after the permanents, and a trigger that triggers an additional time (`TriggerAgain`) is a permanent's alone. |
| State triggers | `TriggerPattern::State { condition }` is the whole pattern of a triggered ability (CR 603.8), read by `Scope::holds` like any condition. It is looked for where a player would receive priority, after state-based actions and before triggers go on the stack, and is logged as `AbilityTriggered` with a cause that names nothing. It triggers when its source is in the zone its `from` names, the condition holds and no instance of that ability of that object waits in the queue or is on the stack; once that instance has resolved, been countered or been removed it triggers again if the state still holds, and a source that changed zones is a new object that triggers on its own (CR 400.7). `limit` and `intervening_if` apply as for any trigger. |
| Pattern events | `ZoneChange`: `LandPlayed`, `SpellResolved`, `CreatureDied`, `CardDiscarded`, `CardDrawn`, `ZoneChanged` and the end of a spell that did not resolve. `Attacks`: each attacker of `AttackersDeclared`. `SpellCast`: `SpellCast`, with the caster and the spell as subjects. `Sacrificed`: `ZoneChanged` with cause sacrifice, with the permanent and who sacrificed it. `StepBegins`: `StepBegan`, with the active player. `BecomesTarget`: each object among the targets of `SpellCast` and `AbilityPutOnStack`, with the object, what targets it and the controller of that. `DealsDamage`: each `DamageDealt`, `combat` true in the damage steps with nothing resolving, with the recipient as the one subject. `LifeGained`: `LifeGained`. `LifeLost`: `LifeLost`, `LifePaid` and each `DamageDealt` to a player (CR 120.3a), with the player. `Drew`: `CardDrawn`, with the player. `Discarded`: `CardDiscarded` and a move from a hand with cause discard, with the player and the card. `Cycled`: `Cycled`, with the player and the card; the discard that pays for cycling is also a `Discarded`. `Tapped`, `Untapped`: `PermanentTapped`, `PermanentUntapped`. `TappedForMana`: the `ManaAdded` that follows the `PermanentTapped` of its source in a batch, once for the tap, with the player as the one subject. `CountersPut`, `CountersRemoved`: `CountersChanged` of a permanent with a positive or negative delta. `Blocks`: each pair of `BlockersDeclared`, with the blocker and the attacker; `BecomesBlocked`: each attacker blocked, once. `GroupAttacks`: `AttackersDeclared`, once, with the attackers that match. `Attached`: `Attached`, with the attachment and what it is attached to. `BecomesMonarch`: `MonarchChanged`, with the new monarch as the one subject (`Triggering` is that player). `Proliferated`: `Proliferated`, with the player as the one subject. `Explored`, `Connived`: `Explored`, `Connived`, with the controller and the creature as subjects. `AttacksPlayer` also names the monarch (`at: Monarch`). |
| Attached subject | An Equipment or an Aura names the permanent it is attached to by `Is(Attached)` in the selector of a pattern ("whenever equipped creature dies, attacks, becomes tapped, deals combat damage to a player"). It is judged against the same state as the pattern, so a host that leaves the battlefield is still the attached creature as it was before the batch. |
| `Batch` | `Batch(pattern)` is the whole pattern of a triggered ability: the events of one `detect` call that the inner pattern matches (one damage step, one effect) trigger it once, once for each player the events are about ("one or more creatures you control deal combat damage to a player" hurts each player in a batch of its own), after the single events of the batch. The inner pattern is one event that can happen to several things at once (damage, a zone change, taps, counters); `Triggering` names the players and objects of all its events. `GroupAttacks` is the batch of attackers. |
| `Nth` | `Nth { event, nth }` triggers on the nth card drawn (`Drew`), spell cast (`SpellCast`) or life gain (`LifeGained`) of a player in a turn. The fold counts them in `GameState.tallies` by player and kind, clears the counts when a turn begins and hashes them with the state; `detect` finds the place of each event in its batch from the count after it. |
| `Nth` of an object | `Nth` also counts for the object: its `Attacks` ("attacks for the first time each turn"), its `BecomesTarget` with `by` empty (by anything) or `[ControlledBy(You)]` (by what its controller controls: Seedglaive Mentor's valiant) and `DealsDamage { source: [], to: Some(object), combat: None }` (damage to the object from any source, "is dealt damage for the first time each turn"). The fold counts them in `GameState.object_tallies` by object (an `ObjectRef`, so a permanent that changed zones starts again), the player whose spell or ability targets it and kind, clears them when a turn begins and hashes them when not empty. An object named twice by one spell becomes a target once; damage of 0 is not counted. A target counted for what an opponent controls, for a kind of spell, damage to a player and damage from one source are refused by validation. |
| `Amount::Triggering` | The amount of the event that triggered the ability, in `Cause.amount`: the damage dealt, the life gained or lost, the counters put or removed, the attackers of a `GroupAttacks` and the events of a `Batch`; zero for any other event. |
| Queue and order | `GameState.pending_triggers` fills at detection. Before a player would receive priority (CR 117.5, 603.3) the active player's triggers go on the stack, then each other player's in turn order (CR 101.4). A controller with two or more asks `OrderTriggers` once, unless they are all of one source and ability; otherwise they go on in the order they triggered. Each trigger chooses its targets as it goes on (CR 603.3d, logged) and is removed if it cannot. State-based actions run before each sweep; the sweep repeats until none is pending, and a trigger that triggers during a sweep waits for the next round. |
| Intervening if | `intervening_if` is checked when the event happens, against the same state as the pattern, and again as the ability begins to resolve; if false then, the ability does nothing and ends `Lapsed` (CR 603.4). |
| `AnyOf` | Joins patterns ("enters or attacks"); one event triggers the ability once. |
| `limit` | `OncePerTurn` is kept per object in state, reset at the turn, and holds for triggered and activated abilities. |
| Delayed triggers | `Effect::DelayedTrigger` logs `DelayedTriggerCreated` and adds a `Delayed` to `GameState.delayed`: its pattern, effects, controller, the names the resolution had bound (the ability starts with them) and a duration. It triggers on the next event its pattern describes and is then gone (`once`), else it lasts until the end of the turn it was set up in. A duration that ran out, or a controller who left the game, drops it. |
| Replacement step | Effect steps and rules code propose events; `replace::process` returns the events that happen or the question it needs answered. It sees the abilities of the permanents in play through `ability_reader` (printed, granted, added by a keyword; `from` names the zone an effect works from) and, for a card that enters, the `Enters` effects it prints itself. A replacement is a `Replacement` ability and applies at most once to an event and to the events that replace it (CR 614.5). |
| Events replaced | `TokenCreation`: the tokens one effect makes for a player are one event (a run of `TokenCreated`). `Damage`: a `DamageDealt`, with `combat` true in the damage steps with nothing resolving; the life a lifelinker gains with it follows its damage. `ZoneChange`: `ZoneChanged`, `CreatureDied`, `CardDiscarded`, `Discarded` is the `CardDiscarded` (or its `ZoneChanged` with `ZoneCause::Discarded`) that puts a card into a graveyard, a spell that resolves as an instant or sorcery and a spell that does not resolve; a card drawn, a land played, a spell cast and a card entering are not zone changes here. `CountersPut`: a `CountersChanged` that puts counters, planeswalker loyalty as it enters included and a loyalty cost paid to activate not. `LifeGain`: `LifeGained`. `Draw`: `CardDrawn` and `DrewFromEmptyLibrary`. `Enters`: a land played, a permanent spell that resolves and a card put onto the battlefield; a token that is created does not enter here. |
| Applying | `Multiply` and `Add` change the number in the event (a draw twice is two draws, the cards the top of the library in order); `MoveTo` sends the object elsewhere (a death, a discard or a spell becomes a `ZoneChanged` to the new zone, so nothing reads it as a death or as a card put into a graveyard); `Tapped`, `WithCounters` and `Choose` add to the `Entered` event of the card and propose the counters as an event of their own, which other effects then change (CR 616.2); `PayLifeOrTapped` asks yes or no and logs `LifePaid`. `Prevent` removes the event and `Instead` is not run yet, so neither is in `Caps`. |
| Replacement choice | When two or more effects apply to an event the affected player, or the controller of the affected object, picks the one that applies first (`ChooseReplacement`, CR 616.1); an effect about its own object applies before the others without a question (CR 614.15). The answers to the questions of one batch are its journal: the engine holds the batch, adds each answer and runs `process` again, which asks the same questions in the same order, so `process` is a pure function of state, batch and journal. |
| As it enters | `Choose` asks the controller with `ChooseOption` (the five colours, or the creature types of the creature cards in the game) and logs the choice in `Entered.chosen`; the permanent keeps it (`PermanentState::chosen`) and `Pred::ChosenColor` and `Pred::ChosenSubtype` read it for the source of the ability. |
| Rules of the game | `Effect::Rule` (with a duration) and `Ability::Rule` (while its source has it) change a rule through a `GameRule`. `MustAttack` and `MustBlock` name creatures that attack or block each combat if able (CR 508.1d, 509.1c: a requirement on the declaration, so only a creature that can attack or block is required). `CantBeCountered` names spells, `CantGainLife`, `CantDraw`, `CantSearch` (libraries) and `RevealTop` (play with the top card of the library revealed to every seat) players. `TriggerAgain` makes a triggered ability of a permanent the rule's controller controls trigger an additional time when the event `cause` describes (a pattern as a triggered ability writes it: "an artifact or creature entering", "a creature dying", "a Wizard you control entering") makes it trigger; one limited to once each turn is not repeated. "This spell can't be countered" is `Ability::Rule` with `from: Stack`; any other rule works from the battlefield. An effect fixes the players and objects it names when it resolves; a static ability finds them whenever the state changes. A rule is not granted by `GrantAbility`. Each rule is in `Caps` as `Rule.<Name>`, with `Effect.Rule` and `Ability.Rule`; `DamageCantBePrevented` names the sources whose damage it covers (a selector judged when the damage would be dealt, any source when empty) and whether it is combat damage (`combat`); the rule is `Rule.DamageCantBePrevented` in `Caps`. |
| Prevention | `ReplaceBy::Prevent` prevents all of the damage of an event, `ReplaceBy::PreventUpTo(n)` up to `n` of it. `Effect::Shield` makes a prevention shield (CR 615) for a duration: `when` is a `ReplaceWhen::Damage` whose recipient `to` is fixed when the effect resolves (the players and objects it names then; a shield that names none begins nothing) and whose `source` and `combat` are judged when the damage would be dealt. `Prevent` makes it prevent everything it covers ("prevent all combat damage that would be dealt this turn"); `PreventUpTo(n)` prevents `n` in all ("the next 3 damage"), takes the damage of the events of a batch in the order the affected player picks (`ChooseOption`, asked only when the events differ and it cannot cover all of them), and remembers what is left (`Event::ShieldUsed`) or ends when it has none. A shield applies to an event once and takes part in the order the affected player picks like any replacement effect (`ChooseReplacement`, whose candidate names the shield); shields that prevent everything are never asked about. A shield of another `when` or `by` refuses by the name `Effect.Shield.<ReplaceWhen>`. `GameRule::DamageCantBePrevented` wins over any prevention effect and any shield: they do not apply to the damage it covers and are not used up. When the damage of a lifelinker is prevented in part the life it gains is what is left. |
| Derived statics | `layers.rs` works through the layers once for a state: the effects of resolved spells and abilities and the `Static` abilities the permanents have at that point of the pass, found through `ability_reader`, apply layer by layer to every permanent at once, so a static's `affected`, `condition` and amounts read the other objects as the earlier layers and earlier effects left them (Favorable Winds finds the flying Levitation gives). A static ability works while its source is in the zone its `from` names and its `condition` holds; one that works from a graveyard, a hand, exile, the command zone, a library or the stack (Anger: "as long as this card is in your graveyard and you control a Mountain, creatures you control have haste") affects the objects a selector names, never itself, and has the timestamp 0 since only permanents are stamped; one whose first modification comes after layer 6 (7b and later, restrictions) is dropped when its source has lost it by then, and one that has begun to apply goes on applying to the permanents it began with, so Humility stops a lord's pump but not "creatures you control are artifacts and get +1/+1" (CR 613.6). `affected` is `This`, `Attached` (the host) or `Each`, tested against the characteristics built so far; the amounts and the player of `SetController` are worked out when the modification applies. |
| Layers | `SetController` 2; `AddType`, `RemoveType`, `AddSubtype`, `SetCreatureTypes`, `AddAllCreatureTypes` 4 (`SetCreatureTypes` replaces the creature types and leaves the other subtypes, CR 205.1b: Turn // Burn); `SetColors` 5; `AddKeyword`, `AddProtectionFromChosenColor`, `RemoveKeyword`, `GrantAbility`, `LoseAbilities` 6; `SetPT` 7b, or 7a in a characteristic-defining `Static`; `ModifyPT` 7c; `SwitchPT` 7d; `CantAttack`, `CantBlock`, `CantBeBlocked` and `CantBeBlockedBy(Selector)` are restrictions without a layer. `Modification::layer()` returns it. Every modification runs from `Effect::Continuous` and from a `Static`, each with its name in `Caps` (`Mod.SetPT`, ...). `GrantAbility` gives an activated, a triggered or a static ability, validated as the ability it is in a scope of its own (a given static ability gives no abilities in turn and does not define characteristics); a keyword is `AddKeyword`. A given static ability applies in the layers after layer 6. `LoseAbilities` takes away what the object has so far, the plain mana abilities and keywords included, and what is granted after it stays. |
| Locked or live | A resolving spell or ability that modifies characteristics or control fixes its object set when it begins (CR 611.2c): `Effect::Continuous` evaluates `affected` once, to the permanents it names then, each as the incarnation named (a permanent that leaves and returns is a new object, CR 400.7), and works out its amounts then. A `Static` evaluates its selector at every derivation. |
| Timestamps | A static ability takes its permanent's entry time (an Aura's or Equipment's effects, the time it became attached), or the time of the effect that gave it when that is later (CR 613.7a); a resolved effect takes its creation time (CR 613.7), one for each modification in the order of the card's text. Both are counters assigned by the fold. |
| Durations | `UntilEndOfTurn` ends in the cleanup step with the damage (CR 514.2); `UntilEndOfCombat` after the end of combat step; `UntilYourNextTurn` when the controller's next turn begins; `WhileSourceOnBattlefield` follows the source named on the effect; `Forever` ends only when every object it names is gone. All five run. |
| Dependencies | Within a layer an effect follows those it depends on; otherwise effects apply by timestamp, after the characteristic-defining abilities of the layer (CR 613.3). A depends on B when applying B to what it applies to changes whether A exists (its source has the ability, its condition holds), which objects A applies to or what A does to them (CR 613.8a); the engine finds it by trying B on copies of those objects and asking A again, for the pairs where one reads (`Pred::Type`, `Subtype`, `Color`, `HasKeyword`, `Compare`, `ControlledBy` and the amounts and conditions around them) what the other writes (the characteristics its modification changes). The order is chosen again after each effect applies; a loop of dependencies goes by timestamp (CR 613.8b). The modifications of one `Static` never depend on each other. |
| Characteristic-defining | A `Static` with `defining: true` (CR 604.3) is a characteristic-defining ability: `affected` is `This`, no `condition`, no `from`, and its modifications are `SetPT` (layer 7a), `SetColors`, `AddType` or `AddSubtype`, so Nightmare's power and toughness are each the number of Swamps its controller controls. It works in every zone, so a card in a hand, a graveyard, exile, a library or on the stack has the characteristics it defines, with its controller the owner, and a printed `*` is a number once an ability defines it (`Card.VariableStats`). On the battlefield it applies first in its layer and neither it nor another effect depends on the other kind. It is `Ability.Static.Defining` in `Caps`. |

## Compiler and Manual fallback

- The oracle-text compiler writes `Card`s with `mtg_cards::load::canonical`, validated by the same functions, with the fingerprint of the text it read.
- `compile::compile(&PrintedCard) -> Compiled { card, clauses }` is pure: reminder text and the card's own name (`~`) are stripped with a map back to the original text, the text splits into clauses (one per line; a keyword list one per keyword; modes, level blocks and ability words stay whole), each clause has a `ClauseKind` (keyword, spell, triggered, activated, loyalty, modal, static), and `clauses` lists every clause, read or not, for the coverage report.
- Keyword lines are read into `Ability::Keyword` when the DSL declares the keyword and its parameter reads (`Enchant` on an Aura only; the filter after "Enchant" is an object phrase of the selector reader: "creature you control", "creature an opponent controls", "permanent", "nonland permanent", "artifact or land", "creature, land, or planeswalker", "Forest", and "player" and "opponent" are `EnchantPlayer`; a zone, "noncommander" and "with another Aura attached" stay with the table); the card is `Full` when every clause is read, `Partial` when some are, `Manual` with no abilities when none is, and `card` is `None` when no face has rules text or the data cannot hold the card (over four faces, two faces with one name).
- Hand-written files win over generated ones for the same oracle id. Generated rules are `card_rules` rows (oracle id, JSON, status, fingerprint, compiler version); hand-written ones are repository files. `Library::from_sources` loads the files; `Library::with_generated(&[GeneratedRules])` adds the rows: a file wins, and a row that does not parse or fails the structure checks is left out and reported, so rules of another build never stop the rest.
- `generated::generate(printed, hand_written, names)` compiles a card and checks the result with the checks of a file (`Library::check_generated`: levels 1 and 2 as a file of its own next to the predefined tokens, then level 3 against the imported card): `Rules` (`Full` or `Partial`), `Nothing` (no rules text, nothing read, or a card the data cannot hold) or `Invalid` with the problems. `generated::input_fingerprint(printed)` digests what the compiler reads (names, costs, type lines, oracle text, characteristics, colors, keywords) and `generated::COMPILER_VERSION` digests the compiler's sources and the rules data types at build time; a row with another fingerprint or version is read again.
- `mtg-cli compile [--all | --card <name>]` writes the rows (`data-sources.md`). A modal ability whose mode has no label offers the renderer's wording of the mode (`render_mode`, with `~` as the card's name) in `ChooseMode`.
- `compile/read/` holds the templates for mana, spell effects (draw, discard, mill, life, damage, destroy, exile, counter, tap, untap, regenerate, scry, until-end-of-turn pumps; one target per clause) and the library and counter effects below. A template reads a whole clause or nothing, `render_variants` writes the result back as English, and the clause counts as read only when one of those wordings is the clause's own, compared after whitespace, the closing period, `~` for "this creature", ", then" for a new sentence, "enters" for the older "enters the battlefield", "precombat" and "postcombat" main phase for "first" and "second", "it" and "them" for "that card" and "those cards" after "put" and "reveal", and without "of their choice". The effects of one player in a row are written both as separate sentences and as one compound sentence, so either wording of a card matches.
- The spell lines of an instant or sorcery are one `Spell` ability, read when every line reads; "it", "its controller" and "it can't be regenerated" refer to the clause's target. A line without a closing period that no template reads (`Mayhem {1}{B}`) is a keyword-like clause kept `Manual`; the effect lines around it still read as the `Spell`. "Choose one —" and its bullets are one `Effect::Modal` (also after the comma of a trigger): each mode is read by the effect templates with targets of its own and no label, and the `Modal` is the only effect of its ability; "choose two", "one or both", "up to" and Spree stay with the table.
- A triggered clause is an event, a comma, an optional intervening "if" on a life total, and sentences read by the effect templates; an ability word before the dash is flavor. The events are `enters`, `dies`, `leaves the battlefield` and `attacks` of the card or of an object phrase ("another creature you control"), `casts` and `sacrifices` by you, an opponent or a player, the beginning of a step, and several joined by "or" (`AnyOf`). The card and a second subject doing the same ("Whenever ~ or another Elf you control enters", "Whenever this creature or another creature dies or deals combat damage to a player", "Whenever ~ or equipped creature attacks") are an `AnyOf` of the card's event and the second subject's for each verb in turn, written with "Whenever" only; a second subject without "another" or "equipped", a count of one event ("for the first time each turn") and "enters from your graveyard" stay with the table. "You may" and one step is `Effect::May`. Beyond the spell templates it reads "return target card from your graveyard to your hand", "return a land you control to its owner's hand" (a `Choose` bound as `returned` and a `Move`), tokens (Treasure, Clue and Food, described creature tokens that may enter attacking or tapped and attacking, counted by "where X is the number of"; "with flying", "with flying and vigilance" and "with flying, vigilance, and haste" are the token's keyword abilities, any of the plain keywords the readers know; quoted abilities, keywords with a parameter and a predefined token with a keyword stay with the table) and "you win the game". Delayed triggers, damage, life and counter events and other conditions stay with the table.
- One subject with several verb phrases ("target opponent sacrifices a creature, discards a card, and loses 3 life") is the effects of its sentence in order, "you create a 2/2 green Wolf creature token and that player mills ten cards" adds the player of the event as a second subject after "and", and a later sentence has its own subject; "unless ... pays {M}" after a sentence is an `Effect::Pay` whose unpaid effects are that sentence, for the controller of a countered spell ("its controller") and for the caster after a spell-cast event ("that player"). The effects "exile ~", "return target creature to its owner's hand", "all creatures get -N/-N until end of turn" and "put two cards from your hand on top of your library in any order" (a `Choose` bound as `back` and a `Move`) are read.
- An activated clause is a cost, a colon, sentences read by the effect templates and the restrictions on when it may be activated (`compile/read/costs.rs`, `abilities.rs`). The cost parts are read and written in the printed order: `{T}`, `{Q}`, a run of mana symbols, "Pay N life", "Sacrifice ~", "Sacrifice a creature" / "another creature" / "two artifacts" (a kind only, never who controls it) and "Discard a card"; an `{X}` in the cost lets the effects use X. Mana ("Add {G}{G}", "Add one mana of any color") is an effect like any other, so it also reads in a spell and a trigger. "Activate only as a sorcery", "Activate only once each turn" and both joined by "and only" set `timing` and `limit`. "Activate only if", costs that remove counters, tap other permanents or pay energy, and abilities from another zone stay with the table. A mana ability with other effects ("{T}: Add {W} or {U}. ~ deals 1 damage to you.") is read whole, as the rules play it without the stack.

- "Spend this mana only to cast creature spells." after the sentence that adds mana is its restriction (`only`): one use per sentence, "cast" a spell or spells of a card type, two joined by "or", "noncreature", "multicolored" or "legendary" (or any spell), "activate abilities", or "on costs that contain {X}". The renderer writes the singular and the plural of "spell"; a restriction of a subtype, of two uses ("or activate abilities of artifacts") or of a chosen type stays with the table.

- A search is "Search your library for" a filter, an optional ", reveal it", the move of what is found and ", then shuffle" (`Search`, `Move`, `Shuffle`; one sentence on the card), also after "you may" (an `Effect::May` of the three) and as "then shuffle and put that card on top". The filter is adjectives, one or more subtypes joined by "or", card types joined by "or" (or "permanent"), "card" and "with mana value N or less" (also "X or less" when the mana cost has an `{X}`, a `Compare` against `X` that the search reads with the X the spell or ability announced); the count is "a", "up to N" or "any number of", found as `land` for a land filter and `card` otherwise. "Look at the top N cards of your library" is `LookAtTop` bound as `top`; with "Put one of them into your hand and the rest on the bottom of your library in any order" (or "in a random order", or "into your graveyard") it adds `Choose` (`kept`, `rest`) and two `Move`s. "Shuffle your library", "target player shuffles their library" and "Put target card from your graveyard on the bottom of your library" (also "on top of", and a permanent "of its owner's library") are read. Names, other zones and other orders stay with the table.
- Counters are put (`+1/+1`, `-1/-1` and a named kind such as charge, poison or time), removed and moved by number words on the card, on one target or, for putting, on "each creature you control": "Remove a +1/+1 counter from ~", "Move a +1/+1 counter from target creature onto ~" (one of the two is the card). All, X, a second target and counters as a cost stay with the table, as do the counters whose effect the rules give and not the card (keyword counters, stun, shield, finality, lore, defense) and any clause whose reminder text speaks of a counter: the data holds a counter as a name, and the reminder text that defines it is dropped.
- "Surveil N", "Proliferate" and "you become the monarch" are effects; "if you're the monarch", "if an opponent is the monarch" and "if there is no monarch" (`Not` of `Monarch(EachPlayer)`) are intervening conditions (`Condition::Monarch`), and the same three after or before a static ("Creatures you control get +1/+1 as long as you're the monarch.", "As long as you're the monarch, permanents you control have hexproof.") are its `condition`; "Whenever you become the monarch" (also "an opponent", "a player") is `BecomesMonarch` with "that player" the new monarch; the monarch is `Ref::Monarch`: "the monarch's end step", "attacks the monarch" (`AttacksPlayer`, where "that player controls" is the monarch's) and "creatures the monarch controls" (`ControlledBy(Monarch)`); "Add {W} or {U}", "Add {B}, {R}, or {G}", "Add {W}{W}, {W}{U}, or {U}{U}" and "Add one mana of the chosen color" are mana (`OneOf`, `OneOfLists`, `ChosenColor`); "Pay {E}" is a cost (`PayEnergy`) and "you get {E}{E}" an effect (`PutCounters` of the energy counter on you; its reminder text does not keep the clause from being read); an X in a cost counts the value announced ("Pay X life", "Remove X ki counters from ~", "Sacrifice X creatures", "Discard X cards", "Exile X cards from your graveyard", "Tap X untapped artifacts you control", "Pay X {E}") and the walker no longer names `Cost.<part>.Counted` for it, only for an amount that is neither fixed nor X; and "Whenever you gain life", "lose life", "draw a card", "discard a card" and "cycle a card" (by you, an opponent or a player) are events (`LifeGained`, `LifeLost`, `Drew`, `Discarded`, `Cycled`). A card that uses one is `Partial` or `Manual` until the engine runs it; the report names it (`Effect.Surveil`, `Effect.AddMana.ProducedBy`) instead of the unread wording.
- The templates of the events (`compile/read/triggers.rs`): "whenever ~ deals [combat] damage [to a player, an opponent]", "whenever you tap a land for mana", "whenever ~ becomes tapped, untapped, blocked, attached to a creature", "whenever a creature blocks", "whenever a +1/+1 counter is put on ~ / removed from ~", "whenever you cycle another card" and "when you cycle this card" (an ability that works from the graveyard, `from: Graveyard`). In the effects, "that player" is the player of the event (`Triggering`) and "that permanent's controller" the controller of the permanent of a tap or an untap. Also read: "equipped creature" or "enchanted creature" as the subject (`Is(Attached)`, written back in both ways), "one or more creatures you control deal combat damage to a player", "one or more cards are put into your graveyard from your library" (`Batch`), "one or more creatures you control attack" (`GroupAttacks`), "you draw your second card each turn" and "you cast your first spell each turn" (`Nth`, first to fifth), "~ becomes the target of a spell or ability [you control / an opponent controls]", "~ is dealt damage" (`DealsDamage` into the object) and, after "attacks", "becomes the target of a spell or ability you control" or "is dealt damage", "for the first time each turn" (`Nth` of the object, first to fifth; a count of targets by an opponent's spells stays unread). "It" is the card itself in the effects of a trigger on the card becoming a target ("put a +1/+1 counter on it"). And "that much" and "that many" for life, damage, cards and counters (`Amount::Triggering`).
- A noun is followed by who controls it or a number it has ("with power 2 or less", "with mana value X" when the mana cost has an X): `Pred::Compare` with a fixed number or `X`. "It deals 1 damage to any target" opens an activated ability for the source, and only as the first thing it does.
- "Whenever a creature attacks enchanted player" is `AttacksPlayer` of `AttachedPlayer`: "it" is the attacker (`Triggering`) and "its controller" the attacking player. A group "creatures enchanted player controls" is `Each` with `ControlledBy(AttachedPlayer)` in a static ability or a rule.
- "Whenever enchanted player is attacked" is `PlayerAttacked` and "whenever a player attacks enchanted player with one or more creatures" is `PlayerAttacks` (`by`, `at`). The first triggers once for a declaration with a creature attacking that player (an attack at only their planeswalkers is not one) and has the attacked player as `Triggering`; the second triggers once for each attacking player, who is `Triggering` ("that attacking player"). "Each opponent attacking that player does the same" repeats the effects with `ControllerOf` of `Each` over `AttackingPlayer(AttachedPlayer)` and `ControlledBy(Opponents)` as `who`; the reader repeats a draw, a gain or loss of life, a token or "untap all nonland permanents you control" (Curse of Bounty spells out the untapping). `AttackingPlayer` is judged when the effect runs, so a creature put onto the battlefield attacking counts. Gold is a predefined token.
- A static clause is one sentence read by `compile/read/statics.rs`. How the card enters is a `Replacement` of `Enters`: "~ enters tapped", with "unless you control" a count (`Not` of a `Compare` on a `Count`: "two or more basic lands", "two or fewer other lands", "a planeswalker", "a Forest or a Plains", "a Mount or Vehicle"; "your opponents control eight or more lands"), "~ enters with three +1/+1 counters on it" (X when the mana cost has one), "As ~ enters, choose a color" or "a creature type" and "As ~ enters, you may pay N life. If you don't, it enters tapped". Rules are "~ can't be countered" (from the stack), "~ attacks each combat if able", "All creatures attack each combat if able" and "Play with the top card of your library revealed". A `Static` is "~ can't block" (or attack, or both), and "gets +N/+N" and "has" or "have" keywords (`and`-joined) for "Equipped creature" or "Enchanted creature" (both `Attached`, so the renderer writes both wordings), "Creatures you control", "Other creatures you control", "All creatures" and "... of the chosen type" or "color"; "other" stands after the other adjectives, where the hand-written files put it. A `CostModifier` is "Noncreature spells cost {1} more to cast.", "Artifact spells you cast cost {1} less to cast.", "Spells your opponents cast cost {1} more to cast." and "This spell costs {1} more to cast for each target beyond the first." (read only beside a spell ability that has targets, else the table keeps it); a count other than that one, an X and a condition stay with the table. A condition after "as long as" (a `Static` with `condition`: "an opponent has 10 or less life", "a player has 13 or less life", "you control a Plains", "it's your turn") lets the card itself get a bonus or a keyword ("This creature has haste as long as an opponent has 10 or less life"); without it a card is given nothing, and a restriction under a condition stays with the table. A keyword list also holds protections: "has protection from white and from black" is one `Protection` for each quality (a colour, "colorless", a plural card type or "everything"), also after "gains" in a pump. A line of two sentences or needing two replacements ("enters tapped with two charge counters on it"), a condition other than those ("for each", "if you attacked"), an X without an X in the mana cost, counters the rules define, the number of opponents and a player's life stay with the table.
- Counted amounts (`compile/read/amounts.rs`): "for each ..." counts a selector (`Count`: "creature you control", "Goblin on the battlefield", "card in your hand", "creature card in your graveyard"; a group no one holds stands on the battlefield), the opponents (`Players(Opponents)`) or the counters on the card (`Counters`); "N ... for each" is `Times{by: N, of}`, and a plain "a ... for each" is the count itself. It follows the amount of a draw, a mill, a gain or loss of life, the counters put, the tokens created ("a Goblin token for each Goblin you control", also written "X tokens, where X is the number of ..."), the mana added (`AddMana.times`) and the change of power and toughness of a pump or a static ("gets +1/+1 for each artifact you control", a change that is zero stays zero and both stats take the same factor). The card itself may get a counted bonus. A count held by a target ("creature target opponent controls"), another player's zone ("in their graveyard"), a quantity ("different power") and two verbs with one count stay unread.
- Prevention (`compile/read/prevention.rs`): "Damage can't be prevented." and the forms "Combat damage can't be prevented.", "Damage that would be dealt by this creature can't be prevented." and "Combat damage that would be dealt by creatures you control can't be prevented." are an `Ability::Rule` of `DamageCantBePrevented` (a source selector, `combat` true for combat and false for noncombat damage); "Damage can't be prevented this turn." is the `Effect::Rule` of it until end of turn and "Prevent all [combat] damage that would be dealt this turn." an `Effect::Shield` of `Prevent` on a `Damage` event. A recipient, a target source and "the next N damage" stay with the table. "planeswalker that player controls" in a trigger about a damaged player is `ControlledBy(Triggering)`, and a trigger about damage the card deals may say "it deals" for the card. Questing Beast and Fog are reproduced.

- "If you do, ..." after a sentence that was a "you may" ("You may draw a card. If you do, discard a card.") is an `If` of `Performed` that follows the `May` (`payments::after_may`); after any other sentence it stays with the table.
- Payments in an effect (`compile/read/payments.rs`): "You may pay {1}. If you do, draw a card." is a `Pay` of the controller whose `paid` effects are the sentence after "if you do"; "... unless that player pays 3 life" and "... unless you discard a card" are a `Pay` whose `unpaid` effects are the sentence before "unless". The cost is one part: mana, life, energy or a discard, and after "you may" a sacrifice. Two parts, an X, a number the game counts, "if you don't" and a sacrifice after "unless" stay with the table, as does "you" as the payer of a counter or of a choice.

- Transform and conditions (`compile/read/transform.rs`, `conditional.rs`, `reveal.rs`): "Transform ~", "transform it" (after a sentence that acted on the card) and "transform target creature you control" (one target on the battlefield) are `Effect::Transform`, also after "you may" and in an activation with its "Activate only" restrictions. "If there are five or more hatchling counters on ~, remove all of them and transform ~." is an `Effect::If` on a `Compare` of the counters on the card ("or more" or "or fewer" with two or more, a counter the rules do not define); "Then if" after another sentence and "it" for the card are wordings of the same effect. The effects after the comma are steps joined by "and" or in a list ("remove all of them" is the count the condition made) or one sentence of the other templates; "otherwise" and other conditions stay with the table. "Look at the top card of your library. You may reveal that card. If an instant or sorcery card is revealed this way, transform ~." is a `LookAtTop` and a `May` of the `Reveal` and an `If` on a `Matches` of the bound card, for any card filter a search reads. Delver of Secrets and Ludevic's Test Subject are reproduced.

- A capitalized word inside a sentence is a subtype when it is one of the game's types (`compile/read/subtypes.rs`, from the Oracle type lines) or one on the type line of the card being read (`clause_with`); any other is a name and is not read. A group is the plural ("Heroes you control", "Elves", "Wolves", "Spies": `plural_subtype`, which the reader accepts only for the plurals it writes), read for a trigger, a spell or a static; at the start of a sentence the capital is grammar and the word is not read as a subtype. A trigger of another permanent's event may return the card itself from the graveyard ("Whenever a land you control enters, you may return this card from your graveyard to the battlefield", `from: Graveyard`).
- Copies (`compile/read/copies.rs`): "Create a token that's a copy of target creature you control" is a `CreateToken` of `CopyOf`; the copied object is a target permanent, "~", "enchanted creature" or "equipped creature" (`Attached`), or "it" and "that creature" once the sentence before named the target. "Create two tokens that are copies of ..." (X when the mana cost has an `{X}`) sets the count. The exceptions follow a comma and are joined by "and": "it's a Zombie in addition to its other types" (`AddSubtype`, `AddType`), "it's blue and black" or "colorless" (`SetColors`), "it's 7/7" (`SetPT`), "it has flying and haste" (`AddKeyword`) and `it has "When ~ becomes the target of a spell or ability, sacrifice it."` (`GrantAbility` of a triggered ability read in the quotes); several tokens say "they have haste". "..., except it has haste. Exile it at the beginning of the next end step." (also "Sacrifice") binds the token as `copy` and adds a `DelayedTrigger` on the end step. "Populate", also after "..., then", is the `Choose` and `CreateToken` of the Copies table, and "You may have ~ enter as a copy of any creature on the battlefield" or "of a creature you control", with the same exceptions, is an `AsCopy` replacement. A copy of a spell, a card in a graveyard, "tapped and attacking" and any other exception stay with the table. "Sacrifice ~" (and "sacrifice it" in an ability about the card) is a `Sacrifice` of the card, and "When ~ becomes the target of a spell or ability" is written with "When" and "Whenever". Clone, Mirror Image, Phantasmal Image, Cackling Counterpart, Rootborn Defenses, Growing Ranks, Followed Footsteps and Sundering Growth are reproduced.
- Copies of spells and abilities (`compile/read/copy_spells.rs`): "Copy target instant or sorcery spell [you control]", "target permanent spell you control" (a spell that is neither an instant nor a sorcery) and "target triggered ability", "activated ability" or "activated or triggered ability" ("you control" optional) are a `CopySpell` or `CopyAbility` of the clause's one target. ". You may choose new targets for the copy" sets `new_targets` and ", except that the copy is red" (colors or "colorless", spells only) sets `except`. "Choose a nonlegendary creature on the battlefield. Target creature becomes a copy of that creature until end of turn." is a `Choose` bound as `copied` and a `BecomeCopy`, and "~ becomes a copy of target creature until end of turn" a `BecomeCopy` of the card. "Choose" opens a `Modal` clause only when its line has an em dash. A player's sentence may continue with "and you" ("Target player loses 2 life and you gain 2 life"), and an Aura or Equipment may give one activated ability that is not a mana ability in quotes ("Enchanted creature has \"{R}, {T}: Copy target instant or sorcery spell you control. ...\"", also "Enchanted land", "artifact" or "permanent"). "Copy it", a spell copied more than once, "copies", and other exceptions stay with the table. Twincast, Reverberate, Reiterate, Fork, Dualcaster Mage, Dual Casting, Grapeshot, Brain Freeze, Tendrils of Agony, Strionic Resonator, Lithoform Engine, Cytoshape and Squirrel Nest are reproduced.
- Groups and lords (`compile/read/selectors.rs`, tests in `tests/lords.rs`): in a plural phrase a subtype or a card type in the singular qualifies the plural noun after it. "Sliver creatures" is `[Type(Creature), Subtype(Sliver)]`, "artifact creatures" `[Type(Artifact), Type(Creature)]`, "creature tokens" `[Type(Creature), Token]`, "Dragon spells" `[Spell, Subtype(Dragon)]`; the card types come first, then the subtype, "other" and who controls them. The word that opens a sentence is a subtype too ("Sliver creatures you control get +2/+0", "Zombies you control get +1/+1"). The writer says "All Sliver creatures get +1/+1" and "Sliver creatures get +1/+1" for a group no one controls, and "Dragon spells you cast cost {1} less to cast" is a `CostModifier` over such a selector. A group of a subtype and an unknown noun, two subtypes and a singular token stay with the table.
- Land plays (`compile/read/lands.rs`, tests in `tests/lands.rs`): "You may play an additional land on each of your turns" (also "two additional lands", and "during" for "on"; "Each player may ..." for every player) is `Rule.AdditionalLandPlays`, "You may play an additional land this turn" and "You may play up to three additional lands this turn" the effect of it until end of turn, "You may play lands from your graveyard" and "... from the top of your library" a `MayCast` permission over `Type(Land)` with `play`, and "You may look at the top card of your library any time" is `LookAtTopAnyTime`. The engine plays all four (`engine.md`, Rules of the game).
- Characteristic-defining abilities (`compile/read/defining.rs`, tests in `tests/defining.rs`): "~'s power and toughness are each equal to ...", "~'s power is equal to ... [and its toughness is equal to ... / that number plus N]" and "~'s toughness is equal to ..." are a `Static` of `This` with `defining` and one `SetPT`; a stat the sentence leaves out is the number printed on the card (`read::Own`, taken from the face), and the sentence stays with the table when that stat is `*`. The value is a count of "the number of" a group ("creatures you control", "Forests on the battlefield", "cards in your hand", "creature cards in your graveyard / in all graveyards / in your opponents' graveyards", "instant and sorcery cards in your graveyard"), "the number of card types among" such cards, "your life total", "your devotion to black and red", "the greatest mana value among" a group or "the total power of" it, "twice" a count, or counts and numbers joined by "plus". The engine evaluates every one but devotion (it needs the copiable mana cost, so it is a restructure of `Characteristics`). Group words that are not read: a subtype with "cards" ("Elf cards in your graveyard"), two zones in one count, "the chosen player's graveyard", counters, party size and numbers noted by the card.
- Life gain (`compile/read/life_gain.rs`, tests in `tests/life_gain.rs`): "If you would gain life, you gain that much life plus N instead." is a `Replacement` of `LifeGain` by `Add(N)`, "... twice that much life instead." `Multiply(2)`, and "Players can't gain life.", "Your opponents can't gain life." and "You can't gain life." are the rule `CantGainLife`. "As long as you have 25 or more life" (or "or less") after or before a static is its `condition`. Another player's loss, "draw that many cards instead", a life total in the condition of the replacement and "for the rest of the game" stay with the table.
- Cards taken from among the top cards (`compile/read/among.rs`, tests in `tests/among.rs`): "Look at the top five cards of your library. You may reveal a creature card from among them and put it into your hand. Put the rest on the bottom of your library in a random order." is `LookAtTop` bound as `top`, a `Choose` of `kept` from `Each` of `In(Library)`, `Is(Bound(top))` and the filter (`min` 0), a `Reveal` of `kept`, a `Move` of `kept` and a `Move` of `top` (the cards that left are other objects and are passed over). "Reveal the top N cards" adds a `Reveal` of `top` and drops the reveal of `kept`; "You may put a land card from among them into your hand / onto the battlefield [tapped]", "Put up to two land cards from among them ...", "Put a land card from among them ..." (one card, not optional) and "Put all land cards revealed this way into your hand and the rest ..." (a `Move` of the `Each`) are the same shape; the rest goes into the graveyard or on the bottom in any or a random order. The filter is the one of a search; a count of X, another library, a chosen type, "Then put the rest", a cast or an exile from among them stay with the table. "You may cast creature spells from the top of your library." (a card type, a subtype, "non" and two joined by "and") is a `MayCast` permission from the library over the cards the group names (`lands::cast_from_the_top`); a rider, "lands and spells" and the other zones stay with the table.
- `tests/it/compile_corpus.rs` is the ratchet: every ability the compiler reads equals one of the hand-written file (mode labels aside, which the compiler leaves empty), and the corpus cards it reproduces whole (`tests/fixtures/reproduced.txt`) never shrink in number.
- `coverage::analyze(cards, caps) -> Report` judges each distinct card of a deck list: the hand-written rules when the embedded library has them, else the compiler's (rules that fail `check_printed` count as `Manual` with the blocker `rules: invalid`), its `Support` from `Library::support`, and its blockers, which are the unread clauses (kind and shape: numbers and the words one to ten as `N`, a run of mana symbols as `{M}`, the card's name as `~`), the primitives of its rules that `Caps` lacks and the printed gaps. A blocker holds a card back alone when it is the card's only one.
- `mtg-cli coverage [--deck <code or name part>] [--top <n>]` runs it over the stored precons with `mtg_engine::caps()` and prints about 70 lines: the cards by state, distinct and by copies, the five best and worst precons by the share of their copies that are `Verified`, and the `n` (20) blockers that alone hold back the most cards, then the `n` that hold back the most in all.
- `mtg-cli audit [--count 100] [--seed N] [FILE]` lists a seeded sample of the stored cards whose clauses the compiler reads beyond keyword lines: for each clause the oracle text, the reading (`render_variants`) and the JSON, and the unread clauses. The cards are put in the order the seed and their oracle ids give and the first `count` that are read are taken, so the same seed lists the same cards and a smaller count is a prefix of a larger one. A reader compares the lines for a wrong target, amount, owner or timing, a dropped clause and a reading true only for some cards; each disagreement is fixed in the template or the wording is left to the table, with a golden in `compile/read/tests/audit.rs`.
- A line the compiler cannot read becomes `Ability::Manual { reason, span }` and the card `Partial`; if nothing is read the card is `Manual`. Each compiled card is rendered back to English and compared with its oracle text in the golden tests.
- A card the engine does not run whole is cast and resolved without effects for the clauses it leaves out, and its controller does them by hand with the generic logged actions (`engine.md`, Manual actions). `assemble` copies the left-out text into the definition: `CardDefinition.manual` holds a `ManualClause {text, reason}` for each clause the support record names on a face (the text its span covers, so a `Partial` card shows the clauses of its `Manual` abilities and, for an ability the engine lacks a primitive for, the whole face text), and a card with no rules attached (`Manual`, `Stale`) one clause of the whole rules text of each face that has any outside reminder text. A `Verified` card has none. Every seat reads the clauses on the card (`ObjectView.manual`, `protocol.md`) and sees the card's support (`deck-check.md`). The field is left out of the serialized form while empty, so the deck fingerprint of a card without clauses does not change.
- Prior art for the templates: phase.rs's oracle parser (`crates/engine/src/parser` in its repository; MIT or Apache-2.0) and XMage (MIT). Forge and Magarena are GPL-3.0: study only, copy nothing.

```json
        {
          "Triggered": {
            "when": {
              "AnyOf": [
                { "ZoneChange": { "what": ["This"], "to": "Battlefield" } },
                { "Attacks": { "what": ["This"] } }

            },

            "effects": [
              {
                "Sacrifice": {
                  "who": { "Target": 0 },
                  "filter": [{ "AnyOf": [{ "Type": "Creature" }, { "Type": "Planeswalker" }] }]
                }
              },
              { "Discard": { "who": { "Target": 0 } } },
              { "LoseLife": { "who": { "Target": 0 }, "amount": 3 } },

```

This is `crates/mtg-cards/cards/archon_of_cruelty.json`; a test keeps the two equal. Oracle text: `Flying` / `Whenever this creature enters or attacks, target opponent sacrifices a creature or planeswalker of their choice, discards a card, and loses 3 life. You draw a card and gain 3 life.`

| Feature | In the file |
|---|---|
| One ability, two events | `when: AnyOf [ZoneChange to Battlefield, Attacks]` |
| Target opponent | `targets: [{ what: Opponent }]` |
| Actors differ | `who: Target(0)` for the first three effects; the default `You` for the last two |
| Choice by the target player | `Sacrifice` filters the target's own creatures and planeswalkers; the target player chooses |

| Phase | Engine behaviour |
|---|---|
| Detection | `SpellResolved` or `ZoneChanged { to: Battlefield }` matches the `ZoneChange` arm against the state after the event; `AttackersDeclared` matches `Attacks`. `AbilityTriggered` names the Archon, ability 1, its controller and a snapshot of it. One event triggers once. |
| On the stack | At the next sweep, before a player receives priority: `ChooseTargets` goes to the controller (`triggered`, with no cancel); `AbilityPutOnStack` creates the ability object with the chosen player. |
| Recheck | If the opponent is no longer a legal target (left the game, gained hexproof) the ability fizzles and nothing happens, including the controller's draw and life gain (CR 608.2b). |
| Step 0 `Sacrifice` | `ChooseCards` to the **target** player (not the controller) over their creatures and planeswalkers ("Sacrifice a creature or planeswalker."); with none, or one, nothing is asked. Then `ChoiceMade`, `ZoneChanged { cause: Sacrificed }`, `StepDone`. |
| Step 1 `Discard` | `ChooseCards` from the target's hand ("Discard a card."), addressed and private to them; with an empty hand, or one card, nothing is asked. Then `ChoiceMade` (shown to the other seats without the card), `CardDiscarded`, `StepDone`. |
| Step 2 `LoseLife` | `LifeLost` through the replacement step; `StepDone`. |
| Steps 3, 4 | `Draw` and `GainLife` for the controller; no decisions. `ResolutionEnded { Resolved }`. |
| Afterwards | Triggers caused by the sacrifice, discard and life loss go on the stack at the next sweep (CR 603.3b). |

| The engine needs | Item |
|---|---|
| `Triggered` kind, `AnyOf`, `ZoneChange` and `Attacks` with their events; detection with snapshots | (i) |
| Ability stack object, `AbilityPutOnStack`, journal events, `ChooseTargets` with `Opponent` legality | (c) |
| `ChooseCards` addressed to a non-controller with a response clock | (d) |
| `Sacrifice`, `Discard`, `LoseLife`, `Draw`, `GainLife` with `LifeGained` and `LifeLost` | (f) |
| `Flying` (blocking restriction) | (e) |

(d) Decision kinds are built with the first task that asks for them: `ChooseNumber`, `ChooseCosts` and `DivideAmount` with (g1), `ChooseReplacement` with (j). Their web prompts follow in M5.

The tasks run one at a time in the order of the table; (h) fills stub files and may run in any order. Rules data leads the engine: a compiled card is `Partial` until the engine runs its primitives. From (q) on, a task ends with the templates and goldens for its wordings, and tasks that do not need each other run in the order of the cards the coverage report says they free.

- Scope of (f), the keyword actions of CR 701: draw, discard, mill, shuffle, scry, surveil, fateseal, search, reveal, sacrifice, destroy, exile, counter, create tokens, populate, investigate, fight, explore, proliferate, amass, connive, learn, transform, meld, attach, regenerate, goad, monstrosity, adapt, bolster, support, venture. Arena-only digital actions (conjure, seek, specialize) are out of scope; a card that needs one is `Unplayable` (`deck-check.md`). An action that belongs to a cluster is built there: attach (m), regenerate (j), proliferate (l), transform and meld (n), populate (o); the others are (h).
